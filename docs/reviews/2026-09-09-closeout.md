# HIR/AST 重构有界收尾复核

复核日期：2026-09-09。代码基线：`e5803b29`；本次性能修复：`337028a9`。

本轮完成一处已指定的性能测量及修复，再按仓库主要层次进行一次边界复核。
结论是：核心管线本轮未新增确认的必修问题；Web 交付路径确认 **3 项必须修、尚未修复**的问题。
另保留 **2 项需要具体收益证据才值得推进**的核心优化方向。无需据此继续无界 HIR/AST 重构。

这是有范围的代码复核与运行验证，不是逐行审计完全部 pass，也不证明没有其他缺陷。
报告中的未完成项是本轮明确的剩余工作，不能用核心测试通过掩盖。

## 性能测量与已完成修复

位置：`src/ast/readability/function_sugar/constructor.rs` 的字段接线。

真实源码族：声明 callee 和 N 个空表，依次为每个表安装一个 `read` 函数，最后
`return callee(a1, ..., aN)`。官方 Lua 5.4 编译，分别保留及剥离 debug；N 为
1、2、4、8、16、32、64。原源码与生成源码执行结果一致。

旧实现对每条字段语句重新遍历参数表，并重复解析同一个目标。新实现先借用目标 binding、
字段与函数，在当前候选首次需要时建立首个同身份 table 的位置索引。函数体只在接线接受后复制。

| N | 旧参数检查总数 | 新建索引访问数 | 新索引查询数 |
| --- | ---: | ---: | ---: |
| 1 | 4 | 2 | 2 |
| 2 | 10 | 4 | 4 |
| 4 | 28 | 8 | 8 |
| 8 | 88 | 16 | 16 |
| 16 | 304 | 32 | 32 |
| 32 | 1,120 | 64 | 64 |
| 64 | 4,288 | 128 | 128 |

两种 debug 模式计数相同。次数包含该次反编译中的重复 pass 查询，不是唯一语句数。
N=64 的旧检查中，成功安装字段的扫描占 4,160 次；即使最终容量许可拒绝整个候选，
这部分工作仍然发生。新查询使用 BTreeMap，表中没有把内部比较计为一次参数遍历。
这证明消除了字段逐次寻找参数的二次扫描，不代表整个 pass 或管线变成线性。

无插桩 debug 产物交替运行，各预热一次后取 15 次进程级耗时中位数：

| N | 修改前 | 修改后 |
| --- | ---: | ---: |
| 8 | 40.67 ms | 41.20 ms |
| 32 | 71.82 ms | 71.08 ms |
| 64 | 114.08 ms | 113.91 ms |

耗时包含进程启动、读写与整个反编译流程。差异很小，**不能宣称端到端有显著提速**。
保留这项修改的收益是已验证的扫描复杂度下降和目标解析复用。生产 Rust 净增加 8 行，
属于有测量支持的索引成本；测试与文档新增不计作生产实现精简。

保留的不变量：

- 同 binding 的前面非表参数仍跳过，选首个 table；首个匹配 table 追加失败就拒绝。
- 已接入其他 table、`pass_to_sink=false` 的参数仍参与字段目标查询。
- 接线只追加字段，不改变参数值种类；索引只在当前候选内有效。
- 嵌套表接线的“首个任意参数”语义独立保留，不能复用本索引改变匹配域。
- 自捕获、原分配容量、binding 删除权限、使用次数、生命周期与调用 provenance 条件不变。

## 必须修：3 项 Web 问题，均待修复

### W1：官方 Luau 字节码被当成源码

位置：`packages/unluac-web/src/components/layout/FilePanel.vue` 的 `isLuaSource`。

该函数只把版本 2～6 且第二字节为 0 的 Luau 输入识别成字节码。当前仓库官方
`luau-compile --binary` 对 `print("supported Luau input")` 的输出头为 `[7, 3, 2, 5]`，
实际执行当前分类函数返回源码。随后 `decompileFile` 直接 TextDecoder 解码并标记 skipped，
不会进入 WASM。相同字节交给当前 Rust 核心可以正常反编译，生成源码与原源码运行结果一致。

根因是 Web 重写了 Parser 的输入识别规则且已经漂移；核心已有公开的
`src/parser/mod.rs::detect_dialect`，应先复用它并通过 WASM 发布识别结果，不继续维护前端版本表。
字节码识别和“结构完全合法”仍应分开，不能把解析失败的字节码静默当作源码。

验收：官方支持方言的真实字节码进入反编译；普通文本仍按源码展示；截断字节码给出明确错误。

### W2：文件身份被当成请求身份，Promise 会丢失

位置：`packages/unluac-web/src/composables/useDecompiler.ts`，以及 WorkerRequest/WorkerResponse。

`pendingMap.set(fileId, ...)` 和返回时 `pendingMap.get(msg.fileId)` 无法区分同一文件的两次请求。
`MainContent.vue` 在文件选中时发起 rich 分析，A→B→A 且 A 的首次分析未完成时可重复请求 A。

本轮执行当前 TypeScript 函数体，以可控 Worker 事件复现：连续发出同 fileId 的两个 rich 请求，
注入第一个请求的响应后，第二个 Promise 得到第一个结果，而第一个 Promise 一直 pending。
这是实际请求关联错误，不只是 Map 的潜在复杂度问题。

修复应由请求创建处签发独立 requestId，并原样穿过 Worker 协议；fileId 只用于归属和取消。
同批应核对设置变更、缓存等待阶段和提交结果时的请求有效性，以及参数快照，避免仅修 Map key。

验收：同文件重入、取消后重发、交错 source/rich 响应均不串结果，每个请求都能完成或明确取消。

### W3：缓存未记录引擎身份，更新后仍返回旧结果

位置：`packages/unluac-web/src/composables/useDecompileCache.ts::computeCacheKey`。

缓存只使用文件与选项 hash，固定数据库 `unluac-cache` / version 1；没有核心构建或 WASM 产物身份。
该缓存确实由 FilePanel 读写。注释所说“版本升级时自然淘汰”在当前实现中没有对应机制。

本轮执行当前缓存实现并替换 IndexedDB 为受控存储：旧引擎结果写入后，更换版本上下文，
同字节和参数仍命中旧结果。验证覆盖缓存语义，没有用真实浏览器跨发布部署复现。

修复应消费构建阶段已有的 WASM 产物身份，并在任务开始时冻结文件、参数与缓存 key；
写回消费同一个 key，避免后层再次从可变设置重建事实。仅手动递增 DB_VERSION 不能形成长期约束。

验收：相同引擎/文件/参数命中，任一变化失效；运行期间改设置不能把旧结果写到新参数 key。

## 值得做：2 项有条件的核心优化

| 方向 | 当前结论 | 开工条件 |
| --- | --- | --- |
| `branch_pretty.rs` 的 scope-end 值证明 | HIR initializer profile 只证明初值，binding 后续被写时当前拒绝下沉 continuation；没有确认错误接受路径 | 支持的 Lua 输入能稳定到达该拒绝点，并显示实际可读性收益，再由 HIR 发布 endpoint certificate |
| `temp_inline/mod.rs` 的多读取依赖批处理 | 现有批处理缺少展开后的 sibling 前缀时停止，后续仍走逐站点证明；不是因为未批量处理就语义错误 | 真实输入测得逐站点证明成为热点，再扩大现有批处理 owner；没有测量前不新增平行分析器 |

这两项不是“剩余两个 bug”，也不承诺一定值得实施。当前证据不足以把它们列为收尾阻塞项。

## 收益很低或语义必需，应保留

- 7 处 `ProofIncomplete` 不能按数量等价为 7 个错误：除上面 2 个方向外，3 处属于
  label/区域后继不完整的拒绝，2 处属于 debug cleanup/return 的来源与资源归属验证。
  本轮核对的是这些拒绝路径，不声称全部接受证明均已重新逐项审计。
- 原始 VM root、捕获 cell、结果宽度、预分配与 cleanup 事务的不同事实域不能仅因代码相似而合并。
  缺失证明时保留原语句，比删除事实、在 AST 用语法猜测更符合分层目标。
- HIR/AST 在各自已经变化的树上重新建立词法位置、当前写入/使用和命名范围，是新快照分析；
  不能跨 Normal/Deferred 或跨层复用旧坐标来追求“只算一次”。
- CLI、WASM、JS/Web 的类型投影服务不同接口。没有真实漂移证据的字段声明重复，暂不引入生成器。
  W1 的输入版本判断已经漂移，故明确不属于这一保留项。
- 不按大文件行数拆模块，不为没有命中证据的扫描另建索引，不把保留的 provenance 字段当作冗余数据删除。

## 本轮覆盖与边界

| 范围 | 本次核对内容 | 结论边界 |
| --- | --- | --- |
| Parser / Transformer | detect_dialect、共享 BinaryReader、LoweredProto 的常量/debug/capture/子 proto 事实 | 入口与事实传递抽查；发现 Web 旁路识别错误，未重审所有 opcode 解码 |
| CFG / Dataflow / Structure | 子树位置对齐、compact 后 Move 值冻结、StructurePlan 与 DebugBindingFacts | 核对最早 owner 与公开产物；没有新增确认的问题 |
| HIR | HirFlowGraph/LexicalCfg、LuaValueFacts、身份/退出要求/physical roots、7 处拒绝标记 | 控制流与值事实已有共享入口；没有把“搜索无标记”当成完整证明 |
| AST / Naming / Generate | HIR 退出要求消费、constructor 接受与提交、快照坐标、AST→Doc 输出职责 | AST 无直接 Structure/Transformer 导入及 LowInstr/Reg 查询命中；这只是边界证据之一 |
| 公共设施 / 测试驱动 | 阶段调度、invalidation 调度、Cargo executable 与 case 实例 ID 传递 | 驱动消费本次构建产物；核心全矩阵实际运行 |
| CLI / WASM / JS / Web | 核心调用、类型投影、Worker 关联、缓存及文件输入路由 | Web 3 项通过函数级受控复现确认；未执行完整浏览器交互、npm 发布或线上部署验证 |

没有开展恶意输入穷举、全仓每个函数复杂度证明、发布平台测试或所有浏览器组合测试。
此次“全仓”指覆盖主要层和交付入口的有界复核，不意味着所有文件都逐行重读。
