# HIR

> **职责**：严格消费 `StructurePlan`，把控制流和值流计划降低成带稳定 binding 身份的语义树，
> 再通过 simplify pass 消除 bytecode lowering 留下的机械 carrier。
>
> **不负责**：重选 Structure 候选、重新扫描 CFG 猜控制 owner、决定最终名字或文本布局。

## 入口与数据流

```text
src/hir/analyze/mod.rs::analyze_hir

LoweredChunk + Cfg/Graph/Dataflow + StructureFacts
  -> region / edge / value lowering
  -> HirModule
  -> simplify_hir fixed point
  -> repeat trailing-root provenance finalization
  -> stable HirModule
```

proto tree 使用显式 postorder frame。每个 proto 只消费与自己对应且已验证的 plan；child 数量、
proto identity 或 plan query 不一致时返回 `HirError`，不回到 CFG 临时推断。

## 模块 owner

```text
src/hir/
  common.rs                  HIR 节点、binding、value-pack 与 origin
  analyze/mod.rs             模块/proto 调度和失败边界
  analyze/lower.rs           proto lowering 上下文与调度
  analyze/structure/         RegionPlan、edge、loop 与 island 执行
  analyze/exprs/             SSA/value 与 value-pack 表达式 lowering
  analyze/instrs.rs          普通 low instruction 到 HIR 语句
  analyze/bindings/          数据流身份到 HIR binding
  analyze/shared_closures/   reusable closure 的词法 factory
  promotion.rs               后续 rewrite 可消费的 provenance
  simplify/mod.rs            pass 描述符与 invalidation 调度
  simplify/                  各 simplify pass 与共享分析
  debug.rs                   HIR dump 与 pass snapshot
  error.rs                   HirError
```

`analyze/` 执行前层 plan；`simplify/` 只改写已经合法的 HIR。任何需要 CFG ownership、phi incoming
归属或 loop partition 的新判断都应先补进 StructurePlan，而不是在 simplify 中重建。

## 核心合同

### Region 与 Edge

- 每个 `RegionPlan` 只降低一次，并严格按 containment 与 layout 顺序产生语句。
- 每条物理 edge 的 transfer、forward route 和 value action 只来自 `EdgePlan`。
- `Break`、`Continue`、`Goto`、normal tail 与 synthetic single-pass fence 的词法 owner 必须保持
  Structure 冻结的祖先关系；HIR 不按当前位置猜最近循环。
- island 保留必要 label/goto 与局部 CFG 顺序，不把不可规约控制伪装成 structured branch。

### Value 与 Binding

- `TempId` 表示机械 SSA carrier；`LocalId` / `ParamId` / `UpvalueId` 表示源码生命周期身份。
- fixed、open 与 exact tail 通过 `HirValuePack` 显式区分，任何 rewrite 都必须保持值宽度、求值
  次数和顺序。
- debug binding、capture mode、PhysicalRoot、close/TBC epoch 与 closure identity 是生命周期事实，
  不能仅因表达式相同或 use-count 为一而删除。
- 原始 home 在值的最后一次表达式读取后是否仍跨过用户代码/GC 事件，也属于 HIR 生命周期
  事实：low CFG 证明 home 区间，HIR 按目标方言的求值顺序区分 operand 临时 handoff 与仍需
  独立保留的 root，并将后者显式物化为 PhysicalRoot；AST 不从最终表达式形状反猜寄存器存活。
  只消费 scope-end 的分析必须区分“所有路径都到 frame end”与“部分路径在精确 overwrite
  结束”的 mixed transaction；后者只能由同步提交 overwrite endpoint 的 owner 消费。条件
  handoff 若证明旧 root 的非 nil 路径已进入另一个稳定 home，还必须把 PhysicalRoot provenance
  重新锚定到结构合流后的真实 owner，不能只删除旧 root 标记。
- `repeat ... until` 的 body local 在条件求值期间仍占用原物理 home；fixed-point 后的
  `repeat_root_lifetimes` 以稳定 binding、value-pack、allocation identity 与 closure capture
  分析最后强根，把已逃逸对象或 opaque collectable 的必要 home 写入 `physical_root_*`。
  closure effect 按词法 child-first 汇总：已知 child 调用中以 upvalue origin 表达的
  escape/return 经 capture 映射回 parent binding；经 upvalue 调用的 closure 保留符号化 call
  effect，在拥有实际 capture environment 的 root activation 中解析。每个 proto 的 effect state
  与最终 root state 都复用 HIR CFG worklist，只有真实 loop/goto 回边才能把后续 origin 传播到
  先前调用。AST collective 只能消费该 provenance，不能另建对象流、closure effect 或 CFG
  fallback。
- table、method、fastcall、generic-for 等 protocol 只消费 Transformer/Structure 已冻结的身份；
  HIR 不从相邻语句文本形状反猜 opcode。
- cleanup 的词法位置和对象 root 生命周期由 plan 与 HIR binding 共同保持，不能后移、跨 scope
  或并入普通 dead-code 删除。

### Lua 5.5 `global` 初始化

- initialized-global matcher 只能整体 claim RHS producer 和全部 target
  `GETTABLE` / `ERRNNIL` / `SETTABLE` item；未证明完整协议时不得生成部分声明。
- 一旦恢复为 `HirGlobalDecl`，owner 必须保留 source-order names 和完整
  `HirValuePack`：RHS 先整体求值，target item 按 bytecode 顺序（source target 逆序）
  probe/store，输出恢复为单个多目标声明。每个 result slot 只保持到其最后一次物理
  使用或覆盖，不能通过物化额外 local 延长 GC root 生命周期。
- `ERRNNIL` 只证明 initialized-global 的 target 协议，不携带源码 global attribute；
  HIR 和 AST 不得据此伪造 `<const>`。

## Simplify 调度

HIR 与 AST 共用 `src/scheduler.rs::run_invalidation_loop`。每个 pass 声明 phase、依赖与可能产生的
`HirInvalidation`；Normal 收敛后运行 Deferred，Deferred 若产生新 invalidation 会重新触发 Normal。
预算耗尽是内部收敛错误，不能静默返回半收敛结果。

结构改写收敛后、进入 residual/AST 之前运行 `repeat-root-lifetimes` provenance finalizer。
它只追加 `physical_root_*`，不改变 HIR 形状，因此不参与 invalidation 回环；分析状态必须是
有限 allocation-site/binding/closure-site 集合。跨 proto effect 依赖按词法 child DAG 后序求值，
proto 内循环与 goto 由 CFG worklist 收敛，不能靠重复扫描整块、递归深度或 AST 形状兜底。

`simplify/lexical_cfg.rs` 是 block 级 label/goto 摘要的单一 owner：它区分外部入口、外部出口、
可达回边与可由线性 walker 消费的 direct forward label。嵌套 block 内部自含的回环由嵌套
consumer 自己分析，不应让外层 pass 丢失回环之前已经证明的 reaching-value 或生命周期事实。

当前 pass 名称只在这里作为调试导航列出，具体职责、输入输出示例和 guard 理由见对应源码文件头：

| Phase | Pass |
| --- | --- |
| Normal | `decision`、`boolean-shells`、`logical-simplify`、`table-constructors` |
| Normal | `temp-inline`、`generic-for-iterators` |
| Normal | `branch-values`、`locals`、`branch-control` |
| Deferred | `eliminate-decisions`、`close-scopes`、`carried-locals` |
| Deferred | `dead-unresolved-temps`、`dead-labels` |

pass 的拒绝 guard、接受证明与检索方式统一遵守 `../design.md#pass-guard-合同`。

## 失败与输出边界

Structure 已失败的 proto 在 HIR 中成为稳定失败节点。Strict 在消费失败节点时返回 residual；
Permissive 保留失败层、最后完成产物和 child identity，交给 AST/Generate 生成明确诊断。成功
proto 的 simplify 错误仍是模块级错误，因为跨 proto promotion/capture 事实可能已参与改写。

HIR 输出必须满足：控制节点可直接映射到目标 AST 能力，binding 身份稳定，值包宽度明确，所有
仍不可表达的 carrier 都是 typed residual，而不是伪造的普通表达式。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| region、loop 或 goto 位置错误 | 先核对 StructurePlan，再查 `analyze/structure/` |
| 表达式值或多返回宽度错误 | `analyze/exprs/` 与 `HirValuePack` |
| closure/capture 身份错误 | `analyze/bindings/`、`shared_closures/` 与 `promotion.rs` |
| 机械 temp/local 未消除 | 对应 `simplify/` pass，使用 pass dump |
| cleanup 或 `<close>` 生命周期错误 | Structure cleanup disposition 与 HIR scope lowering |
| 查看最终 HIR | `unluac --debug --dump hir --stop-after hir <file>` |
| 查看 pass 变化 | `unluac --dump-pass <pass-name> <file>` |
