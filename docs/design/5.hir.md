# HIR

> **职责**：消费前层所有事实，做正式恢复决策，产出 AST 可以直接消费的语义树。
>
> **不负责**：重建前层事实、AST sugar、最终命名。
>
> **例子**：`StructureFacts::BranchCandidate { header, merge, arms }` → `HirIf { cond, then_block, else_block }`

## 入口

```
src/hir/mod.rs
  analyze_hir(state, options, timings) -> HirModule
```

## 结构化 loop 的局部出口

HIR 的 loop lowering 只消费 `StructureFacts` 给出的 loop/branch 候选，但在具体降树时会处理两类局部边界：

- break exit pad 可以包含 cleanup 语句、短路条件或小型 if 结构；lowering 复用已有 branch plan，把 pad 降成 `if ... end; break`，不会在 loop 层重新识别短路。
- while 体内的分支如果同时存在 break 出口和本轮共享收尾块（例如 `elseif ... then ... break end; i = i + 1`），分支会先停在共享收尾块，再由外层 loop body 统一消费一次，避免两条分支臂重复 visit 同一个 continuation。
- `while true` 型 jump latch 的前缀语句属于循环体尾部；HIR 需要把这段 tail 追加到 body，而不是为 Lua 5.1 目标制造 continue/goto。
- 无出口循环里的短路 if/else 可能没有共同后支配点；当 Structure 已把 loop header 标成两臂的本轮 merge 时，HIR 应在两臂自然回到 header 后结束当前 branch，不再把 header 当作后续 region 重复降低。

输入形状：`while cond do if a then ... elseif b then ... break end; step = step + 1 end`  
输出形状：`while cond do if a then ... elseif b then ... break end; step = step + 1 end`

## HIR Simplify Pass 清单

调度器由 `src/scheduler.rs::run_invalidation_loop` 驱动，9 个 invalidation tag（`HirInvalidation`）：
`DecisionShape` / `BooleanPattern` / `LogicalExpr` / `TablePattern` / `TempChain` /
`LocalBinding` / `BlockStructure` / `LabelGoto` / `ClosureCapture`。

|---|---|---|---|
| `decision` | Normal | Decision 节点 → 结构化条件 / 逻辑表达式 | `simplify/decision/mod.rs` |
| `boolean-shells` | Normal | 布尔物化壳消除 | `simplify/boolean_shells.rs` |
| `logical-simplify` | Normal | 逻辑表达式规范化 | `simplify/logical_simplify.rs` |
| `table-constructors` | Normal | 表构造器收敛 | `simplify/table_constructors/mod.rs` |
| `closure-self-capture` | Normal | 递归闭包自捕获解析 | `simplify/closure_self_capture.rs` |
| `temp-inline` | Normal | 临时变量内联（受 ReadabilityOptions 阈值控制） | `simplify/temp_inline/mod.rs` |
| `multiret-assignments` | Normal | 精确宽度调用结果与赋值目标收敛 | `simplify/multiret_assignments.rs` |
| `generic-for-iterators` | Normal | generic-for 消费的 iterator value pack 接管 | `simplify/generic_for_iterators.rs` |
| `locals` | Normal | temp 提升为源码 local，并收回由此暴露的入口参数别名 | `simplify/locals.rs` / `simplify/locals/branch_merge.rs` / `simplify/locals/rewrite.rs` / `simplify/locals/param_alias.rs` |

| `eliminate-decisions` | Deferred | 残余 Decision 节点物化为 if 壳 | `simplify/decision/mod.rs` |
| `close-scopes` | Deferred | TBC close 作用域物化 | `simplify/close_scopes.rs` |
| `carried-locals` | Deferred | carried-state 身份收敛 / 握手清理 | `simplify/carried_locals/mod.rs` |

**Normal phase**：dirty-set 驱动，重复直到收敛。  
**Deferred phase**：Normal 收敛后执行一遍；若产出新 dirty → 再次触发 Normal 收敛。
达到轮数上限不视为收敛，HIR stage 会返回错误，禁止把 fixed-point 中间态交给 AST。

### 新增 pass 步骤

1. 在 `simplify/PASS_DESCRIPTORS` 数组添加 `PassDescriptor { name, phase, depends_on, invalidates }`。
2. 在 `simplify_hir` 的 `match index` 分支添加调用。
3. 在 `simplify/` 新建对应文件，优先使用 `walk.rs::HirRewritePass` 或 `visit.rs::HirVisitor`。

## 应优先复用的共享设施

| 设施 | 用途 |
|---|---|
| `analyze/structure/overrides.rs` | entry/phi override 管理，不在各路径平行复制 |
| `analyze/structure/rewrites.rs` | 共享表达式重写，不在各路径平行复制 |
| `analyze/short_circuit/` | 短路决策 / guard lowering / recovery，DAG 事实来自 StructureFacts |
| `simplify/walk.rs::HirRewritePass` | 后序 rewrite，所有子节点先完整递归再执行当前 hook |
| `simplify/visit.rs::HirVisitor` | 只读 collector，收集 label/temp/binding 一类事实 |
| `simplify/mention.rs` | local/temp 提及与 temp 写入查询；pass 不各自复制 visitor |
| `simplify/local_shapes.rs` | local 声明/左值基础形状判断；pass 不把通用 helper 挂在某个语义 pass 上 |
| `simplify/temp_touch.rs` | temp 引用集合、逐语句 temp refs 缓存、控制头部消费、非局部控制流查询，以及进入子作用域时的前后缀保护集 |
| `expr_safety.rs` | 表达式是否可丢弃、可合并重复求值、会观察求值序的共享谓词；analyze / simplify 不各自维护副作用口径 |

`simplify/carried_locals/` 内部继续按关注点拆分：`mod.rs` 只做后序遍历与 block 调度，`adjacent.rs` 只处理结构化相邻 `seed local + empty carried local`，`boundary.rs` 只收敛显式 `label/goto` 边界快照的 carried binding 等价类，`handoffs.rs` 只判断并执行普通 seed/update handoff，`seeds.rs` 只解析和重写 seed 语句，`reads.rs` 只收集 carried binding 读取事实，`binding.rs` 只提供 local/temp carried binding 表示和 rewrite pass，`prune.rs` 只裁掉已证明由本次合并制造出的冗余 self-assign。

`simplify/decision/` 内部按 Decision DAG 责任拆分：`mod.rs` 保留 pass 入口、通用 reduce、value/condition collapse 与 graph remap，`helpers.rs` 只构造普通 Lua 逻辑表达式，所有逻辑形状整理统一归 `logical_simplify`，`synthesize/` 负责把可证明等价且可稳定重复求值的 Decision 合成为可读逻辑表达式，`eliminate.rs` 只负责最终残余 Decision 的 block/stmt 遍历，`eliminate_materialize.rs` 只负责表达式抽取和值物化，`eliminate_state.rs` 只保存物化期间追加 synthetic local 的状态。沿路径枚举 known-test 状态的 `specialize` 已删除，不得恢复平行的路径事实 pass。

`simplify/locals/` 内部保留单一 `locals` pass owner：`locals.rs` 决定哪些 temp 可以提升、何时复用 closure 已捕获的 local；`branch_merge.rs` 只汇总 if/else 两侧都 fallthrough 的 temp 写回候选；`rewrite.rs` 只消费已确认的 `TempId -> LocalId` 映射改写表达式、左值和 closure capture；`param_alias.rs` 只处理函数入口参数机械别名的后置收敛。

**walker 契约**：所有子节点必须先完整递归；不能因为前一子树 `changed=true` 就短路跳过后续子树；当前节点 hook 也必须总是执行。

## 维护规范

1. **HIR 决策依赖 StructureFacts**：branch 合流 / loop binding / short-circuit leaf 等证据从 StructureFacts 读，不从 dataflow 裸存储重新推断。
2. **fallback 只处理"仍然没有 owner"的情况**：不重新覆盖 branch / loop / short-circuit 已经接管的事实。
3. **simplify 只做 HIR 内部收敛**：不替 StructureFacts 漏掉的事实兜底。
4. **branch-value collapse 在 HIR**：`if cond then x=v; goto L end; x=d; label L`、`local x; if cond then x=a else x=b end` 与 nil-only fallback alias 这类值壳，应在 HIR 先收回结构化 if/else，再用 `Decision->Expr` 或保守 nil-check 改写处理；Readability 只处理语法外观，不重新判断这类值合流语义。
5. **branch stop 分层**：`branch_stop_for_region` 描述整个 branch 回到外层 region 的边界；单条 arm 降低时可使用更窄的 arm stop，避免一条臂提前消费外层 stop 之后的共享尾块。典型形状：`if guard then ... elseif handled then return ... end; return ...`。
6. **carried-locals 保守**：结构化相邻 `seed local + empty carried local`、fallback label/goto 握手都由 HIR 认回同一状态身份；只有 seed 在后续不再可观察、carried 不被闭包捕获、且写回形状可证明时才改写。`assign(t0,t1) = call(...)` 多值赋值不能按 zip 截断。
7. **locals pass 边界**：只物化真正"局部、一次性"的 temp；loop/branch-carried update（`t1 = t1 * t0`）不应被提升成新 local。
   入口参数别名是 locals 的后置收敛步骤：只处理函数体入口 `local L = param` / `local L; L = param`、且参数原值不会在 `L` 写入后继续被读取的形状；它不替 phi/loop state 重新分类，也不把循环累加器写回参数。普通 `local; assign` 的语法合并留给 Readability `statement_merge`。
8. **不要按基础类型恒等式改写二元运算**：`x << -1` 与 `x >> 1` 对整数结果等价，但 table/userdata 的 `__shl` / `__shr` 可观察到不同 event 和原始参数；Transformer 已恢复的 op 与 operand 必须原样进入 HIR，不能为了源码外观做跨 metamethod 的 canonicalization。
9. **短路的 single-eval 只覆盖未物化节点**：`if A and B then` 这类 branch-exit 短路在入口 header 会先通过 `lower_block_prefix` 物化前缀语句；若为了后续被吞掉的 header 需要 single-eval 展开，只能展开那些不会单独 lower 的节点，入口 header 仍应引用已物化 temp，避免 `local x = f(); if f() and ...` 这类重复求值。value-merge 短路同理：`assert(a() == 1 and b() == 2)` 这类布尔合流应在 HIR 恢复成 `LogicalAnd/LogicalOr`，但 single-eval 不能把已经物化的外部调用或作为取表 base 的调用结果重新展开成 `build()[1]()`。
10. **表达式物化要保持求值序**：Lua 会先求 call callee，再求参数；bytecode 因此常见 `t_f = assert; t_arg = <短路表达式>; t_f(t_arg)`。HIR 可以把它恢复成 `assert(<短路表达式>)`，但不能只把 callee 内联成 `t_arg = <短路表达式>; assert(t_arg)`，否则全局读取会被挪到参数副作用之后。反过来，如果源码形状是 `local v = source(); sink(v)` 或 `local v = source; sink(v)`，也不能在 callee 已物化到 call 后继续把更早的调用、全局/表读取、运算或短路参数折回 `sink(...)`，否则这些可被元方法或副作用观察到的求值会被挪到 callee 读取之后。同理，loop header prefix 中先执行的 `side()` 不能被折到条件里位于更早求值的 `guard()` 之后；遇到这类重排时应保留 prefix 并回退成 `while true + if break`。
11. **试探式 lowering 必须可回滚**：conditional reassign、value merge、loop continue/break、cross escape 等 branch 快捷路径，以及 numeric/generic for preheader 这种会先试降 loop body 的路径，如果失败都必须恢复 visited / override / active loop / 输出语句状态，再交给下一种结构化策略。
12. **shared continuation 不是普通 fallthrough**：`if cond then gated end; shared` 这类结构只有在 gated 的所有非终止路径都到 shared，或在当前 active loop 边界上 break/continue，才可恢复成共享 continuation；loop escape 必须显式留在 gated block 内。短路出口的 gated entry 若由 Structure 明确识别为 `else=None、then=shared、merge=active loop escape` 的单臂 branch，可直接沿用该 owner，不能先把 shared 降进 gated arm 后再重复消费。
    当 repeat header 被临时当作普通 branch 降低，且其 region 内存在无 label、非 branch/loop header 的多臂共享线性 tail，但部分路径需要先跳到 region merge 来跳过 tail 时，HIR 应合成 `repeat ... until true` fence：跳向 merge 的路径降成 fence 内的 `break`，tail 仍作为单一 continuation 降在 fence 末尾，不复制 tail，也不退回 label/goto。LuaJIT 还可能把这层单次 fence 与外层 retry loop 压成同一个 `Unknown` natural-loop header；只有同一候选已是 active loop、fence merge 仍在其 loop blocks 内时才可复用既有 state/value owner，并让 tail predecessor 的 phi 写回同一 target。普通 branch 不凭相似 CFG 新造 fence，避免把结果 phi 隔在未证明的词法边界两侧。
13. **loop exit pad 可以是小型结构**：numeric/generic/while 的 break exit pad 不只可能是线性 cleanup，也可能是多层 `if/elseif` 与透明 jump 串联后再到 post-loop。线性 pad 可以跨多个 basic block，例如 Luau O2 展开的固定轮数循环；每个后续块都必须只有当前块一个可达前驱，且整条单后继链最终进入 post-loop，不能借共享 tail 猜测 `break` owner。branch pad 只沿 Structure 给出的 `structured_blocks` 递归，最终统一追加一次 `break`；loop context 同时记录 pad 消费的所有 block，避免 coverage 阶段误以为 pad body 未被结构化。
14. **非空 continue target 不能简单继续**：numeric-for continue target 的普通前缀属于源码 body 共享尾，所有分支只能自然汇入该 target，并由 loop owner 单次追加前缀；不得把某条边提升为 `continue` 后跳过共享尾。只有 `GenericForLike` 的非空 header 前缀是迭代控制协议，可天然承载 continue。短路 branch 若 `truthy` 正好跳到安全的 continue target，应先取反并交换出口，恢复成 `if cond then body end`；若 `falsy` 跳到 target，则可以按 if-then guard 处理。repeat/while 默认保持保守，避免把循环条件边界吞进短路表达式；active repeat 的非 continue 臂必须由当前 natural-loop core 或词法域内 nested loop 的 preheader 持有，且其所有路径都在本轮到达 repeat condition、终止或退出 active repeat，才能恢复成“条件跳过完整本轮 tail”的 if-then guard。active repeat 的显式 exit 不属于 tail owner，不能仅因它会退出循环就通过路径证明。Luau O2 可能把固定轮数 nested loop 完全展开，此时展开块仍由当前 loop core 持有。
15. **被短路吞掉的 header prefix 要先重写**：扩展 branch-exit short-circuit 后，后续被消费 header 的 prefix temp 不会再单独 lower。HIR 需要用已有 prefix temp override 把这些 temp 内联进合成条件；仍残留不可解析 prefix temp 时才回退，避免生成引用未定义 temp 的条件。
16. **loop state 初值允许使用 preheader 出口表达式**：generic/numeric loop 可能紧跟在一串已结构化 branch-value merge 后面，preheader 边上的同一寄存器会保留多个原始 def。只要这是进入 loop 前的 block 出口值，就可以用 `expr_for_reg_at_block_exit(preheader, reg)` 作为 state 初值，而不是在 loop state 里重新拆这些 branch merge。
17. **closure capture 的 sticky local 以词法槽位为边界**：`locals` pass 可以把 closure 已捕获的同槽位后续 def 写回原 local，但这个“同槽位”必须包含 `close from rX` 形成的 epoch。close 后 VM 复用同一个寄存器号时已经是新的词法槽位，不能继续写回已关闭 upvalue；同一条赋值 RHS 捕获当前槽位时，也要先激活 sticky 身份再决定该赋值是否复用原 local。若 closure 捕获的是非参数、非入口 local、且捕获点没有 reaching value 的父级槽位，bindings 需要先分配空 local，并把同 epoch 后续 def 直接写回该 local，避免分支写入因没有普通读者而被清理。
18. **fallback label/goto 的 loop-carried 更新可以认回同一 binding**：当无法安全结构化成 `while/repeat` 时，`carried-locals` 仍可在 HIR 内保守合并 `state = next; ::entry:: ... next = state + 1; if cond(next) then goto handoff end` 这类回边交棒。前提是 `next` 没有前缀读取、handoff 紧贴一个可被外部路径直接进入的 label、后续回边确实跳回 handoff label，且 `next` 的定义只依赖这一组 carried binding；这样可以恢复单一源码 local，同时不重新触发“goto 跳进 local 作用域”问题。
19. **while header prefix 不能默认丢弃**：`while-like` header 里位于 branch 前的指令只有在确实属于条件计算时才可以被内联进条件并省略；如果 prefix 定义不参与条件、但在 header 出口仍 live（例如 guard 前声明一个会被循环体 closure 捕获的 `local x`），HIR 必须回退成 `while true do <prefix>; if break-cond then break end; <body> end`。这样保留每轮迭代 guard 前初始化的词法槽位，避免 closure 结果临时和被捕获 local 混成同一绑定。
20. **closure capture 需要稳定父级绑定**：`temp-inline` 不能删除跨出 `if`、`block`、`unstructured` 等嵌套结构后仍被 closure capture 引用的 temp；这类 temp 不只是普通表达式临时值，还会成为子 proto 的 upvalue provenance，删除后会让 naming 指向不存在的父级 synthetic local。
21. **exit-only loop state 可以从 preheader 取初值**：`found = false; for ... do found = true; break end; if found then ... end` 这类形状的 exit phi，所有 incoming 可能都来自 loop body 或 break pad，CFG 上没有单独的“循环外 predecessor”。HIR 应在确认 incoming 全部属于 loop/break-pad 后，用 preheader 出口值作为 state 初值，让 break pad 写回同一状态槽位。
22. **for-binding 作用域消费 StructureFacts**：generic/numeric for 的自然 loop blocks 不包含 `break` 前的 cleanup tail，但 Lua 词法作用域仍覆盖这些 tail。Structure 的 `LoopCandidate.body_scope_blocks` 已包含被 header 支配且尚未到达正常 loop exit 的提前退出块，bindings 层只据此注册 for 变量可见性，避免 `table.remove(list, i); break` 里的 `i` 退回成未初始化 temp/local。
23. **短路出口的透明 jump pad 属于短路结构**：StructureFacts 的短路候选只记录条件 header 和语义 truthy/falsy 出口；Lua 5.1 字节码可能在某个出口前插入只含 `JMP` 的空 pad。HIR 构建 branch plan 时应把这类无 phi、无前缀语句、唯一流向短路出口的 pad 标记为已消费，但不能把它当作条件 header 参与 prefix 重写。
24. **多入口 loop state 先看共同原始初值**：没有唯一 preheader 的 while-like loop 可能来自 `if a or b then while ... end end`，多个外部 predecessor 都跳到同一个 header。HIR 计算 header/exit state 初值时应先用 raw incoming defs 判定是否是同一个表达式；若这些入口还共享同一个可写 lvalue，则 loop state target 应复用这个入口槽位，而不是新建只在分支内部赋值的 phi temp。这样跳过 loop 的外层路径仍能看到源码初值。
25. **带 closure 的 terminal tail 不能复制**：共享 terminal return block 若前缀里创建 closure，应作为单一 continuation 消费，不能为了避免重访 terminal block 把整段 tail 克隆进多条分支。closure capture 依赖父级词法槽位身份；复制 raw `CLOSURE` 会让同一个 child proto 在 HIR 中出现多个互不兼容的 capture 来源。
26. **generic phi 不猜测值**：short-circuit value merge 恢复失败时应显式保留 unresolved；没有 branch/loop/short-circuit owner 的 generic phi 只消费 Structure 给出的 `GenericPhiSource`。未被 branch 接管的 loop exit phi 即使与 header state 使用同一寄存器也保留 generic 候选；HIR 只有在 state 初值和 target 对齐成功时才通过 override 抑制它，否则继续走 generic 物化。`IdomExit` 才可用对应 block 出口表达式物化，`Unresolved` 必须继续暴露 unresolved，不能在 HIR 重新猜测某个支配块近似值。
27. **路径覆盖不把未知回环当成功**：branch shared continuation、loop continuation 和 stop/escape 截断这类 all-paths 判定统一由 `body/path_checks.rs` 持有，只接受闭包显式分类的边界；遇到已有 `LoopCandidate` owner 的 header 时只检查该 loop 的显式 exits，递归中遇到尚未被 loop/branch owner 分类的回环时应视为未证明，不能把它当作所有路径都已到达目标边界。同一 header 有多个 loop 候选时，必须用进入前驱匹配 candidate preheader，或沿用 active candidate identity；路径访问与 memo 都要把前驱纳入状态，无法唯一选择时不得回退到任意 header 候选。调用方不得平行维护自己的递归遍历和回环口径。
28. **value-merge header 不能随便取第一个候选**：branch-lowering 的 value-merge 快捷路径只允许消费同一 header 下唯一候选，或同一棵短路树上的多 result phi；若同一 header 下出现多棵不同 value-merge 树，应退回普通 branch/merge lowering，避免某个 phi 被候选选择器静默丢掉。普通 BranchValueMerge 的 HIR 快捷消费同样只能在同 header 唯一候选时启用；`conditional-reassign` 只能消费单个 result phi；同树多输出必须退回普通 branch，一次性保留所有赋值，不能把同一条件拆成多段补写。
29. **method fact 必须满足目标方言标识符规则**：`SELF` / `NAMECALL` 留下的 method 名只有在常量确实是字符串，且可作为目标方言裸字段名时，HIR 才能丢弃 method-load `GetTable` 并把 call 标成 method sugar。`global`、`continue` 这类 dialect keyword 即使前端编译器允许出现在冒号调用里，也应保留普通 `obj["name"](obj, ...)` 形状，避免前层把可表达的表访问调用提前丢掉。
30. **Vector 是纯且恒真字面量**：`HirExpr::Vector` 保留四个 `f32` 的原始位模式，遍历、安全性、truth facts 与 Decision 综合都把它当作无子节点、无副作用、Lua truthy 的稳定原子；不得提前降低为 `Call`。
31. **退化 generic-for 可以没有独立 body block**：Luau 会把空循环体或只含 `continue` 的 generic-for 编译成 loop header 自回边，即 `body_target == header`。Structure 已确认 generic-for 候选后，HIR 应生成空 body 并消费 header，不能因缺少独立 body block 而让整颗 proto 回退成 label/goto。
32. **循环体局部 continuation 先于函数尾 merge**：循环内 `if/else` 的一条嵌套路径可以 `break`，其余路径仍先汇合到本轮 tail。后支配 merge 因 break 常落到循环后的 terminal block；HIR 应先用 active loop 证明本轮局部 continuation，并让嵌套 break 尊重调用方给出的近端 stop。常规 all-paths 证明失败时，仅当显式 then/else 两臂都能在不穿过本轮 stop 时到达同一 branch header，且该 branch 的 Structure merge 正是 stop，才能把它补认为共享 tail；单臂候选扫描必须把 nested loop 的 header、preheader 与内部块全部留给该 arm，不能凭可达性抢占 owner。只有不带 cleanup 前缀的纯 terminal block 才能作为 arm 的本地终止；带 `Close` 等作用域清理的尾块仍保持单一 owner。repeat 的条件若由多个短路 header 组成，这些 header 整体属于循环条件，不属于 body branch；active loop context 要保留首个条件 header 作为 body stop，不能只记录末端 VM continue target。已被短路计划消费的 header 同样不能再被选成下游 continuation。局部 stop 上的 generic phi 只有在全部 incoming def 都已被显式 `target_overrides` 统一到同一 lvalue 时才能继承该 owner，否则继续保留 unresolved。
33. **相邻 loop 共享 header phi 时沿用 entry identity**：前一个 numeric/generic/while loop 在退出点已经把寄存器状态安装成后继 header 的 entry override，紧邻的后一个 loop 必须优先继承这份初值与 lvalue。entry identity 在 header 首条指令前始终有效，即使该块随后重定义同一寄存器；只有继续向更后继传播时才要求 carried identity。不能再从同时混有前一 loop exit 和自身 backedge 的原始 incoming defs 重新推导，否则两个可规约 loop 会一起回退成 unresolved/goto。
34. **同 header loop 按候选身份从外到内降低**：HIR 不能用 `header -> LoopCandidate` 覆盖同 header 的内外层候选。for preheader 按类型、preheader 和 exit 精确选择外层候选；普通入口按覆盖域选择尚未 active、未被精确抑制的最外层候选，外层 active 后再进入同 header 内层。active loop context、continue 判断与试探式抑制都保存候选身份，不能再用 header 反查另一个循环。Structure 标出的 `control_blocks` 由对应 loop lowering 直接计入覆盖，不再生成源码语句。
35. **active loop 使用 Structure 的源码 body 边界**：numeric/generic-for 的 natural-loop `blocks` 可能只覆盖能回到 header 的核心，经 break/return 离开的嵌套结构仍属于源码 body；repeat 的分支也可能先进入 nested loop，再回到尾条件。因此 active loop、loop-state inside-set 和候选嵌套关系统一消费 `body_scope_blocks`；while/while-true 的该集合仍等于 natural-loop core。for-like core 的出口若进入 nested loop 的 header/preheader，仍是 body 内控制流；其余非 post-loop 出口即使位于词法域内，也可能携带 `赋值 + break`，必须继续按 break pad 降低。分支选择本轮 continuation 时可以落到 nested loop 的 header/preheader，但不能跳进其内部 body，也不能把外层 for 反认成内层 loop。内层 loop 若携带与 active 外层相同寄存器状态，应复用最内层 active state target，避免更新落入一次性临时 local。
36. **规范化终止出口沿用唯一入口 lvalue**：通常带 preheader 的 loop 可以建立独立 state temp；但 Structure 已把等价单指令 return 记入 `control_blocks` 时，numeric-for 的复制出口被规范化到另一分支的共同 continuation，header outside incoming 若能唯一映射到已有 lvalue，就必须复用该身份。否则 state temp 只在 then 臂初始化，else 臂与 loop 后返回仍读取旧变量。无 header merge 的内层 live-out state 也应优先继承 active 外层同寄存器 target，避免进入内层时把外层状态重置为 nil。
37. **break 出口允许直接分成 post-loop 与 terminal return**：编译器可能把某条 `break` 复制成循环后的 `return`，使 break exit branch 没有共同 merge。HIR 只在两臂分别直接落到 post-loop/downstream post-loop 或 clone-safe terminal block 时，把它降成 `break/return` 分支；任一 arm 还需穿越普通结构时仍应拒绝，不能把任意无 merge branch 当作 break pad。
38. **多入口 loop state 优先消费显式 target owner**：loop 嵌在 BranchValueMerge 或外层 loop 内时，多个 predecessor 的原始 SSA 表达式可以不同，但调用方已通过 `target_overrides` 把它们归一到同一可写状态槽位。入口 expr/lvalue 必须先按该 owner 归一；仅在没有显式 owner 时才比较 raw incoming，避免 branch 内后续 loop 因旧 def 形状回退成 unresolved。
39. **退化 generic-for 的无 owner body 是立即 break**：Structure 已确认 `GenericForLoop` 的 body/exit 同目标，或 exit 通过透明 jump pad 汇入 body 时，候选都不会拥有独立 body block；HIR 必须据此生成只含 `break` 的 loop body。空 body 只适用于 `body_target == header` 的自回边形状；混用两者会把“最多取一个元素”错误扩大成完整遍历。
40. **已建立的 header state 必须接管全部回边定义**：header phi 可能只被内层 loop phi 间接消费，此时指令级 `phi_use_count` 为零，但它仍是实际的外层循环状态。一旦 state plan 接受该 merge，就必须把所有 inside defs 写回同一 target；不能用直接 use 数量跳过，否则内层循环后的本轮更新会落入孤立 temp。
41. **多出口 loop 的 state 绑定覆盖共享终止出口**：body exit 与主 post-loop 可能再次合流到同一个 terminal block；该 terminal phi 的 incoming 若全部来自 loop blocks、主出口或主出口已有的结构化 branch region，仍表示当前 loop state。HIR 应把候选的其他 exit merge 一并绑定到同一 target，不能只处理所选 post-loop 后留下 unresolved，更不能据此把真实 terminal 路径猜成 break。
42. **间接 continue 只消费 Structure 的 edge owner**：`if cond then continue end` 可能指向共享 jump pad 而不是直接指向 while header。目标方言支持 `continue` 时，HIR 才按 active candidate 的 `continue_edges` 选择条件臂并消费 pad；同一 pad 从自然尾路径再次到达时也按该 owner 生成 continue。不得仅凭“单 jump 可达 header”扩大识别，否则同 header 嵌套 loop 会互相抢占控制边。
43. **short-circuit 只能省略无返回值的隐式 terminal**：短路 falsy 出口与 truthy 内部早返回共享函数尾时，可把仅含空 `return` 的 falsy block 留给自然落空；若 terminal 返回显式值或带前缀副作用，必须保留为分支臂或共享 continuation。把任意 terminal 当隐式 return 会令条件失败路径从 `return value` 静默变成 `nil`。
44. **loop 内 branch-value merge 继承已有 state owner**：分支一臂保留当前 loop state、另一臂产生新 def 时，新 def 可能要到更内层 loop lowering 才会获得 target override。只要 merge 中至少一个 def 已明确映射到同寄存器的 active loop state，其余 arm defs 与 preserved seed 都应复用该 state；不能要求所有 def 预先同 target 后再认领，也不能只凭寄存器号猜 owner，否则会分别留下未初始化 phi 或误伤循环内复用的寄存器槽位。
45. **缺省 else 必须沿 merge 参与路径证明**：`if-then` 没有显式 else 时，缺席的一臂代表直接进入 merge，不能在 all-paths 判断中按空路径自动通过。编译器可能把同条件的嵌套 while/repeat 折叠成同一 header 的多条回边；若显式 arm 在 merge 前回到当前 loop header，且 merge 路径也只会回边、终止或退出当前 loop，HIR 应恢复成方言无关的显式 `if/else`，而不是只为支持 `continue` 的目标生成提前 continue，或让 Lua 5.1 退回 goto。
46. **repeat 的共享 continuation 消费内层 loop owner**：repeat body 的一条分支可以先执行完整内层 loop，再选择进入本轮共享 tail 或直接 break。shared-continuation 的 all-paths 证明统一由 `body/path_checks.rs` 处理；当分支入口本身是已确认的内层 loop header 时，只检查该候选的显式 exits，不再由 `branches.rs` 维护另一套遇回环即失败的 DFS。shared 必须在不穿过 active continue target 的当前迭代内可达；若一臂就是 continue target，另一臂又会先到达调用方的近端 stop，必须保留 early continue 的分支 owner，不能把另一臂一直降到 loop condition。该 owner-aware 例外只用于 active repeat；while/for 的 header 与 iterator 边界仍由各自 loop lowering 接管。
47. **短路 continue 保留出口前缀与本轮共享 tail**：多节点 short-circuit 的一个语义出口可以先更新 loop state，再直接回到当前 continue target；HIR 只有在目标方言支持 `continue`、出口属于当前 loop 且另一出口不直接回边时，才把合成条件降成 early continue，并先正常降低 continue 出口上的前缀。若同一外层 branch 还包含 break，后支配 merge 会落到 post-loop；此时只能把 branch region 内“至少两个前驱、非 branch/loop header、唯一后继为 continue target”的线性块认作本轮共享 tail，并要求两臂所有路径都到 tail、原 merge 或终止，不能从任意直达 header 的回边猜 tail。
48. **loop state 沿同寄存器 SSA 输入链归一**：header backedge def 可能先读取内部 branch phi，再计算下一轮值。state plan 建立后应沿同寄存器 use-value/phi incoming 反向遍历，把候选 loop 内参与该值链的 def 与 phi 统一到 state target；链外定义只作为入口 identity，不继续递归。identity 映射不计作显式 override，stop/shared-tail phi 只有在每个 incoming 经显式映射或自身 identity 后都等于 active state 时才可抑制，避免一边留下 unresolved，一边让 value-merge 快捷路径误判已有 owner。
49. **continue merge pad 只在当前循环尾消费**：Luau O2 会把源码循环尾的 `if cond then body end` 编译成“header 条件边直接进入 continue pad，body 的多个出口也汇入同一 pad”。HIR 只有在调用方 stop 就是当前 continue target、BranchRegionFact 证明 body 有多个真实 merge predecessor，且 body entry 不是另一个 continue source 时，才把该 merge 当作自然循环尾消费；否则保留原 owner，避免外层尝试吞掉嵌套 continue。
50. **statement value-merge 复用已有 state target**：短路 statement value-merge 的结果 phi 已被外层 loop/branch owner 纳入 `target_overrides` 时，叶子写回应直接复用该 lvalue，不能固定写入短路 phi temp。目标和值经 loop rewrite 后相同的恒等赋值直接省略；保留它会让后续 locals 把同一循环状态误切成分支内未初始化 local。
51. **短路臂跨内层 loop 后退出当前 loop**：Structure 的线性短路跟随若越过真实 `or` 条件链进入 body branch，只补回沿 falsy 边推进且仍能自洽收敛到两个出口的最长前缀；沿 truthy 边推进的 `and` 可由嵌套 if 保持正确结构，不凭不完整尾链扩候选。HIR 在当前 loop body stop 上确认短路一臂只到 post-loop、另一臂只到 continue target 时，先把退出臂降到 post-loop 边界，再在内层 loop 之外追加当前 loop 的 `break`；不能让内层 loop 抢走外层 break owner，也不能用目标方言不支持的 goto 跨过内层 loop。
52. **repeat 的共享 tail 可以是嵌套 loop preheader**：外层分支后的本轮共享 tail 若从 preheader 进入完整嵌套 loop，且该候选非空的全部出口都回到当前 repeat continue target、候选 blocks 也完全属于 active loop，则 tail 由外层分支统一消费一次。early-continue 证据除短路计划外，也可来自 `else_entry=None && merge=continue_target` 的 plain if-then，但其显式臂仍须由统一路径查询证明能到共享 tail、外层边界或终止；不能把任意 nested loop 或仅凭可达性的 branch 当作 continue owner。
53. **branch-value arm 在 Structure 区分 entry 与 update**：Structure 以 branch header 出口的 canonical `SsaValue` 为入口身份，并沿 Phi incoming 传递判断某个 arm value 是否仍携带该入口；同一传递 Phi 可以同时属于 entry 与 update。定义块被 header 严格支配的叶子 def 证明本轮存在 update；未携带入口的来源也属于 update。HIR 只消费这份分类选择共享 lvalue 或继承外层 loop state，不再把 Phi 压成 defs 后重判。只要最终 target 与入口表达式不同，就先在 branch 前 seed 一次；seed 之后 preserved/update 的叶子 def 都重定向到该 target，使 nested loop 不会再次初始化同一状态槽。若多个 entry value 中存在一个传递包含其余值的 Phi，且本 branch 没有拥有其更新，则沿用该 Phi owner，不能抢回 header 的旧槽位。
54. **same-header while 保留嵌套 numeric-for preheader owner**：numeric-for 的 body 可因入口条件形成同 header 的 while-like 子候选；该子候选两臂若在 early continue 之外汇入完整的嵌套 numeric-for，shared continuation 必须停在内层 preheader，不能跳到更晚的回边 pad。该例外只接受 Structure 已确认的 same-header numeric-for owner，并要求两臂能避开当前 continue target 到达候选的不同真实前驱，且全部路径只能进入候选、当前 loop escape 或 terminal。结构恢复后，`locals` 的普通赋值与 branch fallthrough merge 都必须排除 `outer_used_temps`；否则 `PromotionInit::Empty` 会在子分支声明未初始化 local，切断外层 loop state 写回。
55. **repeat 的 continue arm pad 与共享 tail 分属不同 owner**：Luau O2 可把 `if cond then continue else body end` 表示为 branch arm 的透明 pad 跳向非空 repeat condition，另一臂先经过本轮共享 tail。只有 Structure 已将该 pad 标记为当前 loop 的 `UnstructuredContinueLike` source、且它唯一跳向 condition target 时，HIR 才能把 pad 作为显式 continue arm；pad 必须真实降低到 target 前并追加 `Continue`，不能把 target 当成 arm entry。O2 再编译还可能消掉透明 pad，此时只接受“branch 的缺席 else merge 就是 condition、显式臂在 condition 前必经共享 tail”的直接 owner。外层 branch 只有在其语义 merge 是 tail、condition 的其余前驱全由这些 continue owner 占有时，才能把 merge 留给外层统一消费；repeat condition 继续由 loop owner 单独降低。
56. **early-continue guard 不能抢占后续 nested loop tail**：repeat 分支的一条路径可在共享 tail 前通过 if-then 的隐式 merge 跳到 condition，另一条路径进入完整 nested loop。常规 early-continue 搜索可能先命中这个 guard header；只有该 header 的缺席 else merge 正是当前 condition、显式臂入口是 Structure 已确认的 nested loop preheader 或无 preheader header、外层双臂在排除当前 header/condition 的本轮图内分别到达该入口的不同真实前驱，且全部路径只能进入该入口、当前 loop escape 或 terminal，才能把共享 continuation 提升到 nested loop owner。guard 仍属于原分支臂，不能作为外层共享 tail 被重复消费。
84. **branch-value seed 只消费进入分支前的 target owner**：branch header 自身可能先更新 active loop state，再以该出口值作为缺省 arm 的 preserved entry。seed 的目标使用当前 branch 已收敛的完整 override，入口表达式却只能应用降低 header prefix 时已经生效的调用方 override；若两者相等才可省略赋值。把当前 branch 刚建立的映射反向套到入口上，会把真实初值误判成自赋值；完全不应用外层映射，又会引用已被 loop owner 吸收的旧 fixed temp。
85. **temp 内联保持求值区域与事件前缀**：调用、lookup、运算等可观察 replacement 只能进入下一语句的第一个运行时求值位置；return 后续值、call 后续参数和 for 的 limit/step 都不能让它越过前序事件，method lookup 还位于 receiver 与显式参数之间。while/repeat 条件每轮求值，循环外变量快照即使只读一次也不能内联进去；真正属于循环条件的 prefix 应由 Structure/HIR lowering 在条件 owner 内消费。不可变字面量不携带状态快照，纯引用或无副作用 closure 也不会在同一语句内新增可观察事件，可在复杂度阈值内移动。固定多值 return 的末位单值 call 保留物化 local，避免 AST 为阻止展开而生成额外括号；不能在 AST 把该 call 提前执行。
86. **close scope 消费实际覆盖当前绑定的 cleanup**：Lua 5.4/5.5 的 `CLOSE A` 会关闭所有寄存器号不小于 A 的 TBC binding，因此内层 `r5` 可以由 `CLOSE r4` 结束。`close-scopes` 为每个词法区间记录全部已证明 covering close，重建 block 时由该区间统一消费；不能只删除与 TBC 寄存器号完全相等的 close，否则 goto 重入形状会在每轮 fixed-point 再套一层 block。若 `<close>` 声明之前已有 goto 指向声明之后的 label，且该目标 block 以 covering Close 开始，该 label 是不能被包入 local 作用域的硬边界；区间还只能消费自身内部 goto 所指出口的对应 Close，不能按同一寄存器号删除后续 sibling cleanup。普通区间末端之外的组合 close 仍归外层 scope，不能被内层提前吞掉。
57. **多节点短路 continue 使用 Structure 语义出口**：同一 header 可以同时存在正反两个可规约短路候选；HIR 只在所有多节点 `BranchExit` 候选对当前 continue target 给出同一个非 continue 出口、候选完全属于 active loop 词法域且不包含 target 时，才用该出口选择 nested tail 或补全 if-then 的隐式 merge 臂。非 continue 出口若先经过一块非 branch/loop 的单后继线性前缀，可以把其唯一后继上的 nested loop 作为 tail owner，前缀仍由原分支臂消费。单节点候选与 plain branch 重叠，不参与这项 owner 提升；候选冲突时必须回退，不能取第一个结果。
58. **continue 与 break 同时出现时 break owner 优先**：短路的两个语义出口若分别是 active loop 的 continue target 与 post-loop，必须保留显式双臂并交给 loop break lowering；continue 快捷路径不得先把 post-loop 当普通非 continue body。短路扩展也不能继续吞入 active continue target，或吞入“显式臂回 header、merge 到 post-loop”的 same-header loop condition；这些 block 自身就是 loop control owner。
59. **repeat shared continuation 只接受本轮可达路径**：nested loop 可以作为 repeat 分支的共享 continuation，但入口到 shared 的证明必须避开 active repeat header。经 post-loop、外层 loop 下一轮再回到 sibling arm 的全图可达性不属于本轮 shared tail，否则一条臂会先消费另一条臂仍需进入的 nested loop。
60. **透明 continue pad 不能走自然 fallthrough**：`branch_continue_pad` 已由 Structure 标为当前 loop 的 continue arm 时，后续所有分支形状必须复用统一计算的 `prefer_natural_fallthrough`；不得绕开 pad-owner 约束重新调用基础谓词。否则 pad 不会被降低或标记 visited，最终让整个 proto 回退。
61. **repeat 的隐式 continue 臂尊重近端 tail**：O2 可把 `if cond then continue end; tail` 表示成 `else=None、merge=condition、then=tail-prefix`，且不再产生独立 continue edge。只有调用方给出不同于 condition 的近端 stop、显式臂被统一路径证明在 condition 前必达该 stop 时，HIR 才恢复显式 continue，并把显式臂降低到近端 stop 后交还外层；不能把非空 condition merge 当作自然 fallthrough，否则会执行本应被 continue 跳过的 tail。
62. **同一限定域内的多目标可达性只遍历一次 CFG**：shared continuation 需要判断两臂分别能到达哪些真实前驱时，先在 CFG 层批量求每条臂的可命中目标集，再做集合判定，不能按前驱嵌套重复 BFS。该目标集必须与 `can_reach_within` 合同一致：入口恒可命中，限定域内节点的一层直接边界后继也可作为目标但不能继续穿越；`avoiding` 调用方仍须显式剔除被排除的 block。
63. **loop-control branch 入口先继承已证明的外层 state owner**：branch header 可能同时是内层 break branch 与外层 state 的共享 merge。降低 header prefix 前，只有 phi 全部 incoming def 经当前 target overrides 都指向同一 lvalue 时，才安装 entry override；否则保持 generic phi。不能等递归降低非 break 臂或外层 continuation 再接管，因为 generic phi 此时已经物化。
64. **repeat condition 的非条件副作用属于共同 continuation**：短路一臂直达 repeat condition、另一臂继续执行局部 tail 时，只有 condition prefix 完全由条件表达式消费，才可把直达臂恢复成源码级 continue。若 prefix 还包含调用、写入等不属于条件依赖的副作用，两臂必须分别降低到 condition 后自然合流；否则 continue 会跳过这些共同副作用。
65. **Unknown retry 允许额外 terminal exit**：可规约循环若只有一个非终结 post-loop，其余 exits 都是 `return/tailcall`，仍可由 `while true` owner 消费；只有一个 terminal exit 的旧形状也继续以该块作为循环边界。额外 terminal exits 保持在原分支中直接终止，不是第二个 post-loop，也不应迫使整个 proto 回退到 label/goto；出现两个普通 continuation 时才保持未证明。
66. **环境表 key 只有合法标识符才能升级为 global**：`_ENV["name"]` 可在 HIR 恢复成 `GlobalRef`，但 key 必须满足目标方言的标识符与关键字规则。`_ENV["end"]`、`_ENV["a-b"]` 及版本专属关键字必须保留 `TableAccess`；Generate 已无法从裸 global 反推出原始环境表访问，不能把合法性检查推迟到后层。
67. **全图可达性缓存按入口而不是目标组织**：structured body lowering 会从同一 branch arm 扫描多个 continuation 候选，普通 `can_reach(from, to)` 应按 `from` 一次求完整目标集，避免每个 `to` 重跑 BFS。排除单块的查询直接在 CFG 遍历谓词中跳过该块，不能为每次查询克隆整套 reachable blocks；限定域的批量查询仍遵守规则 62。
68. **repeat 条件保护嵌套 local 提升边界**：`repeat` 条件与本层 body 共享词法作用域，因此本层直接定义的 temp 可以提升并继续改写条件；但条件引用也是 body 内更深子块的外部消费者。`locals` 必须把这些 temp 作为 child-only 保护集传入嵌套 block，不能在内层 repeat / branch 声明 local 后只改写赋值、把外层条件留成未初始化 temp。
69. **carried handoff 的 seed target 必须是新身份**：pure local / binding handoff 只有在目标 temp 此前未被读写时才能把后缀统一到来源 binding。若目标已在更早的 goto 臂写入，当前 seed 可能被其他路径绕过；只改写后缀会切断这些前置写入。此类 label mesh 只能由完整边界等价类证明后统一，普通 handoff 应保守拒绝。
70. **repeat 首轮定义的 live-out 不读取 preheader**：repeat 至少执行一次；若 live-out 寄存器不在 header 的 live-in 集合中，说明进入 header 后一定先定义再使用。HIR 为它新建 state 时以 nil 占位即可，不能从多路合流的 preheader 猜不可观察的旧值；已有 local / upvalue / global owner 仍沿用原初始化链，避免凭空增加可观察写入。
71. **table constructor 的后缀查询复用 occurrence index**：同一 block 的 binding use 与 mention 以稳定 stmt id 建立有序位置索引；seed 扫描只查询当前位置之后是否仍出现，region 删除同步移除对应位置。不能为每个 seed 重建完整 suffix summary，也不能为 trailing handoff 递归扫描全部后续语句。
72. **loop 的空 outside defs 仍应解析函数入口值**：参数、命名 vararg 参数槽和普通未初始化栈槽在 Dataflow 中都可能没有 reaching def；HIR 先通过既有 entry binding 解析参数/入口 local，只有没有任何入口身份的寄存器才是 nil。numeric/generic-for 携带函数参数时不得把空 defs 直接降成 nil，也不得为每种 loop 另加参数特判；有观察者的携带值若无法解析 entry owner，应拒绝该候选，不得猜测 nil。
73. **跨 home slot 的 alias 是值快照**：`local original = current; while current > 0 do current = current - 1 end` 中，move 到另一 concrete `HomeSlotKey` 的 `original` 保存赋值当时的值，不能合并。无 slot 的 phi 可以接入唯一 concrete state；但 concrete slot 一旦被 closure capture，`None -> Some(slot)` 的 staging alias 必须保留原位置写回，不能把它吸收到新 local 后丢掉被捕获 binding。普通规模或存在 debug local 证据时，slot 尚未 sticky 的 candidate 随顺序更新为最新支配 local，capture 只锁定当时 candidate；若 stripped proto 的 home-slot 定义数已经超过源码 local 上限，则同一 `(slot, close epoch)` 复用稳定 binding，物理覆盖保证旧值已死，epoch 仍隔离 close 后的新词法槽。`carried-locals` 同样不得把跨槽值快照折回来源 local。
74. **generic-for state 接管中间 phi 后不得重复物化**：同寄存器的 loop defs 已统一映射到 state target 时，generic-for 候选域内所有 incoming defs 都指向该 target 的中间 phi 也归同一 owner；每个候选只扫描一次 phi 集合，其引用和写回都按 target override 改写，不再生成旧的 generic phi，尤其不能物化 `Unresolved` 后让整颗 proto 回退。repeat 的多节点条件只有在被跳过 header 的 prefix 可安全并入表达式时才可整体消费；否则保留 prefix 在 body。若该短路的一端是 plain if-then merge、另一端是带非条件副作用的 active continue target，应保留单臂 merge 身份，不能把 merge 当显式 else 重复消费。
75. **短路链不能覆盖一致的 plain if-then merge**：loop 内多节点短路的共同后支配点可能因 break 被推到 post-loop；若首尾 plain branch 都确认同一个单臂 merge，另一语义臂能在不穿过本轮 continue target 时到达该 merge，且 merge 无需回到 header 就能继续到 target，HIR 应保留这一本轮 owner。链尾若是独立 IfElse 或不同 merge，必须继续按短路双臂处理，不能用外层候选跨过嵌套分支。
76. **break header 作为隐式 else merge 时必须被消费**：loop 内 if-then 的 merge 可以正好是后续 break branch header；只有该 header 缺席 else、正常臂就是调用方 stop、另一臂 merge 到当前 loop post-loop 或 terminal exit，且全部路径只到 stop 或 active-loop escape 时，才把它作为隐式 else 完整降低。nested loop/header 与普通多后继 merge 不套用此规则，不能用宽泛“结构 owner”证明跨过既有边界。
77. **post-loop cleanup pad 允许空前缀 fallthrough**：Lua 5.5 generic-for 的 `break` 与正常退出会各自产生一个 `CLOSE` pad，再汇入同一后续块。HIR 只有在 scope facts 已吸收 pad 前缀、且 CFG 证明它只有唯一后继时，才把无控制终结指令的 fallthrough 后继视为 downstream post-loop；普通语句、分支或多后继 pad 不得被跨过。这样 break pad 可以归一为源码 `break`，而不会把 VM cleanup 暴露给 AST 或生成跨词法块的 goto。

78. **嵌套 loop 复用外层 for binding state**：外层 generic/numeric-for 的绑定寄存器在 `body_scope_blocks` 内已有稳定 local owner；内层 while/repeat 对同一寄存器建立 loop state 时，初值按 preheader block、写回目标按 inner header block 共同查询该 local，不得另建“条件读 for local、body 写 temp”的状态。numeric-for 与内层 loop 共用 header 时，外层 binding phi 仍保留 state owner 用于传播 override，但 binding 由 `for` 语法本身逐轮初始化，不得在循环前额外赋值。
79. **跨子块存活检查覆盖完整 alias group**：`locals` 在扩张 temp alias group 后必须重新检查组内任一身份是否被外层消费，不能只检查 root temp；`carried-locals` 递归进入 repeat body 时还要把执行在 body 之后的条件引用计入外部活跃集。否则内层 promotion/handoff 会吞掉外层 loop state，只改写 body 内写入却留下未初始化的条件 temp。
80. **table constructor checkpoint 不复制增长中的整数索引**：构造器候选的推测扩展只记录字段长度、数组下标和恢复日志边界；回滚时以字段长度删除本次新增的 pending index，再反向恢复 checkpoint 前被 drain 的字段。事务内新增后又被 drain 的字段已随字段截断删除，不能越界恢复；也不能为每次扩展克隆完整 `BTreeMap`，否则大量逆序整数写入会退化为平方级开销。
81. **结构恢复的 visited checkpoint 使用插入日志**：同一 branch 会依次试降多种语义形状，失败必须精确撤销本次新增的 visited blocks；checkpoint 只记录插入日志长度，rollback 反向清除该边界后的成员。不能为每次尝试克隆随已降低 region 增长的完整集合，否则大量顺序 branch 会仅因回滚状态复制退化为平方级开销。
82. **环境表身份沿 reaching def 规范化全局访问**：Lua 5.4/5.5 的宽常量 key 会把全局读写展开成 `GETUPVAL Env + LOADK + GETTABLE/SETTABLE`。HIR 需确认 table base 的唯一到达定义是 `Env`、key 的唯一到达定义是合法标识符字符串后，统一产出 `GlobalRef` / global lvalue；普通 upvalue、local `_ENV` 或多来源寄存器保持表访问，不能依赖 debug 名字猜环境身份。
83. **被结构接管的 Phi 保存全局 alias 身份**：branch/loop 证明某个 Phi 已拆成稳定 lvalue 后，override state 同时记录 `phi temp -> owner expr`。block-entry 传播只覆盖当前活跃寄存器；后续 short-circuit/generic phi 可能从 predecessor def 重建表达式并再次引用已不 live 的旧 phi temp，因此 phi 物化、普通指令和 branch 条件都要先应用该 alias，再应用局部 entry/target override。不同 owner 的接管顺序可能形成 alias 链，表达式重写必须传递解析 replacement；新 alias 在插入前要沿现有映射证明不会回到自身，无法证明 DAG 时拒绝 suppress 并保留原 Phi 物化，不能把 cycle guard 当作悬空 temp 的 fallback。该映射只能来自已经完成的结构所有权证明，不能把未解决的 generic phi 猜成某个近似值。
84. **标量与 value pack 类型分离**：`HirExpr`、`TempId` 和源码 local 永远只表示一个值；只有显式 `HirPackTail` 槽位可以展开，普通列表使用 `HirValuePack::tail`，表构造器使用 `trailing_multivalue`。`Open` 表示开放宽度，`Exact(width)` 表示字节码已按目标数截断且 width 大于 1；0/1 个结果分别走 ignore/标量，不得再压成 call 上的布尔标记。`HirValuePack::expr_len` 只统计源码表达式槽，exact 结果宽度必须查询 `exact_result_len`。可变 walker 只遍历 fixed 表达式和 tail Call 的内部字段，不得把 tail 根暴露成 `&mut HirExpr`；tail 重建也只能使用保持 Call/VarArg 根的 typed API。Structure 的 `OpenDefId` 由 HIR analyze 的同块唯一 consumer owner 直接接管：通常必须相邻；只允许跨 return/tail-call 的 lifecycle `Close`，或已由 `GetTableKind::Method` 明确标记的 method setup 协议，不能跨一般求值或可观察 cleanup。不得先物化成普通 temp，也不得把未证明的 carrier 留给 AST 猜测。
85. **generic-for 接管完整 source pack**：HIR 初建的 iterator/state/control 引用与 Lua 5.4+ 相邻 TBC closing slot 共同定义 generic-for 的 source owner。`generic-for-iterators` 必须按目标身份接管连续初始化序列，保留显式 fixed 前缀，把最终 exact tail 恢复为 open，并把第 4 个非 nil closing 表达式留在 source pack；不能只识别“整组三元组来自 call”或“scalar call + nil”两种形状。
86. **显式 TBC 与 generic-for cleanup marker 分型**：Transformer 的 `TbcKind::Explicit` 才代表源码 `<close>`；`TbcKind::GenericFor` 是 TFORPREP 协议。Structure 对显式 TBC close 以 CFG forward dataflow 跟踪活跃寄存器，`close from rA` 覆盖所有不小于 A 的活跃 TBC，并把结论写入唯一 `CleanupDisposition`；generic marker 归精确的 generic-for owner，不能阻止普通 captured-binding close 归词法 scope。HIR 只消费该 disposition，不重跑 owner 分析；不可达 cleanup 即使因退化 loop 候选被语法性访问也直接忽略。composite close 可同时结束多个已收集的嵌套 interval，最内层消费 VM cleanup，外层由词法 block 结束表达。
87. **可丢弃与可重复求值是不同事实**：未使用值清理只消费 `expr_is_discard_safe`；逻辑去重、吸收和因式分解只在整个被跨越区域均满足 `expr_is_repeatable` 时执行。全局读取会触发环境表 `__index`，算术/比较可能触发元方法，表构造器/闭包会产生新身份，因此不能仅凭节点结构相等删除第二次求值。即使操作数都稳定，Lua 的 `and/or` 仍返回原值且操作数有优先级；`(a and b) or (c and b)` 不能改成 `(a or c) and b`，`c or (a and (b or c))` 也不能交换后再提取 `c`。前者会混淆 `nil`/`false`，后者会把先返回的 `c` 换成 `b`。Decision 的 `lhs == rhs` 同样不能推出运行时相等：NaN 与新对象都反例。
88. **同目标 branch 仍须保留条件求值**：CFG 的 then/else 指向同一 block 只说明控制结果相同，不说明 branch 条件无语义。HIR 以空 `if cond then end` 保留一次任意条件求值；不能直接跟随 successor，否则全局读取、比较元方法和运行时错误都会消失。
89. **环境基址定义由全局访问 owner 消费**：宽 key 全局访问恢复成 `GlobalRef` / global lvalue 后，若 `GETUPVAL Env` 的全部 SSA use 都是这些已确认的全局访问且没有 phi use，HIR lowering 直接抑制该机械定义。不得先额外发射 `_ENV` temp，再依赖 dead-temp 把它误判为普通纯 global 删除。
90. **不可规约流只局部降低**：mixed walker 仍按 `StructurePlan` 的直接 block owner 分派；不可规约 membership 只界定需要保留显式边的 island，不能覆盖其中已有的 Branch/Loop owner。plain branch/loop island 按稳定 block 顺序从真实入口旋转布局，只有目标恰好是同层下一个 block 时才能省略 goto；其余边使用精确 `EdgeRef` 物化 phi copy，并在真正生成非 fallthrough 边时确保目标 label 存在。分支入口臂可以透明穿过唯一可达前驱、无前缀的纯 jump pad，但两段 edge 的 phi copy 都必须保留。island 的 continuation 取后支配链上第一个位于 island 外的 block，不能把内部 loop header 当成出口。continuation 有外部 predecessor 时仅允许不存在 live phi；仅由 island 消费且不是 active loop escape 时才抑制其 phi。物理 island exit 可以把仅含 `ExplicitTbcBoundary` Close 的线性 pad 纳入布局，再由该 pad 跳到共同 continuation；不能同样穿过 `ExplicitTbc` 声明、普通赋值或调用。指向 active loop post-loop/downstream 的边降低为 `break`，因此外层 numeric/generic-for owner 不因 body 内 island 丢失。`CleanupDisposition::LexicalScope` / `Unreachable` 的 cleanup 由前层 owner 省略，`ExplicitTbc` / `ExplicitTbcBoundary` 保留成 HIR cleanup 交给 `close-scopes`；numeric/generic-for 协议只允许交给既有 loop candidate，局部 raw block 拒绝 `GenericFor` cleanup 与循环 terminator，不能以损失 cleanup、循环控制或 phi 语义为代价强行生成源码。
91. **前向 goto 控制折叠归 HIR**：`branch-control` 只消费已经存在的 `HirStmt::If/Goto/Label`，不重新解释 CFG，也不接管同一 lvalue 选值。每个 block 每轮只建立一次顶层 label 位置和递归引用计数；可移动区间不得跨顶层 local/goto/label，不同目标的区间必须不交叉，同一 label 的多个 guard 在一次倒序改写中直接嵌套。紧邻目标 label 的 nop goto 同轮清理。AST 不再维护第二套 label 索引或控制壳恢复，避免 Lua 5.5 `GlobalDecl` 已生成后再改变声明作用域。

92. **truthy ternary 规范化归 HIR**：`logical-simplify` 只有在两个结果臂的 HIR truthiness 均已证明恒真时，才把 `not a and x or y` 整理成 `a and y or x`。两种形状都先且仅求值一次 `a`，随后在同一条件下选择同一结果臂，因此不要求 `a/x/y` 可重复求值，也不会改变调用、查询、构造器或元方法的可观察顺序。AST 不再维护另一套 truthiness 事实或重组短路表达式。
93. **pass 以显式改写结果报告 changed**：HIR 含 `f64` 数值字面量，`NaN != NaN`，因此 pass 不得通过比较改写前后的整棵 `HirStmt/HirExpr` 树判断是否发生变化。局部改写函数应返回 `Option<新节点>` 或等价的显式命中结果；未命中直接返回 `None`，命中后由调用方安装新节点并报告 changed，避免无改写的 NaN 常量让 fixed-point 永不收敛。
94. **open pack 可跨已标记的 Luau import setup**：Luau `GETIMPORT` 可能位于末位 open 参数 producer 与消费 call 之间，但源码语义仍是普通嵌套 call。open-pack owner 只在 producer/consumer 同块且唯一、producer 起始寄存器不早于 open args 起点、between 全部是同一 callee 槽的 `GetTableKind::Import` 路径时接管 producer；起点之间的寄存器继续作为固定参数前缀。普通 `GetTable`、cleanup 或其他可观察指令继续拒绝。Import 身份只来自 Transformer，HIR 不按访问形状猜测。
95. **VarArg open tail 可跨同块 setup**：`...` 只读取当前函数入口值包，没有调用、查表或状态快照副作用；唯一 consumer owner 可把同块 `VarArg Open` 从原指令位置移到最终 value-pack tail，即使中间存在 callee Move/Upvalue setup 或其他语句。该例外只适用于 `VarArg` producer；普通 open call 仍须通过相邻、lifecycle Close、Method 或 Import 协议证明，不能借此跨越可观察事件。
96. **open call 可跨单 callee Move**：Luau 可先求值末位 open call，再把此前保存的 callee 搬到 consumer 调用槽。owner 只接受 between 恰为一条 Move、源槽早于 producer open 覆盖区、目标就是 consumer callee 且位于 args 起点之前的形状；producer 起点仍不得早于 open args。这样只移动寄存器副本，不把 callee 的原始全局/表读取跨过 producer，也不放宽其他普通事件。
97. **空 self-loop header 首次进入仍是循环体**：`while true do end` 的 header 可能只有一条指向自身的 jump，同时又是候选的 continue target。active-loop escape 只有在该 header 已被本轮 walker 消费后再次到达时才能生成 `continue`；首次进入必须正常消费 header。否则 coverage 会遗漏唯一 reachable body block，并让包在 numeric-for 中、控制块已不可达的无限循环把整颗 proto 回退成 label/goto。
98. **丢弃的新表仍由 HIR 接管 open SETLIST**：多赋值的多余 RHS 也必须完整求值；若 fresh table seed 已内联成 `TableSetList` 的 base，且 SETLIST 从当前连续数组索引开始、末尾是 open call/vararg，table-constructor pass 将两者合成一个带 `trailing_multivalue` 的构造器，并用恢复 local 承载这个被丢弃的值。AST 不重新解释 SETLIST，也不把 open tail 拆成有限个索引赋值；base 不是已证明的新表、索引不连续或 tail 是 exact-width 时继续保守拒绝。
99. **多 terminal exit 的 Unknown loop 复用 non-empty-latch owner**：natural loop 可能因至少两条 `return`/隐式函数尾出口未被 Structure 精化成 `WhileTrueLike`，但所有出口均终止且已有唯一 continue target 时，仍可安全恢复为 `while true`。continue target 非 header 时必须作为 body stop，并在 body 后单次追加其普通前缀；不能走 header-retry 快捷路径，否则会把 terminal guard 当成空 fallthrough，并跳过 latch 上的 state 写回或词法 cleanup。零出口和单出口候选继续使用各自已有 owner，不能利用空集合的 vacuous truth 改道。
100. **可写 child upvalue 反向固定父 capture 槽**：proto lowering 自底向上汇总直接 `SetUpvalue`，并沿后代 closure 的 `CaptureSource::Upvalue` 传播 mutability。父 closure 的某个寄存器 capture 若对应可写 child upvalue，且该槽低于所有 `Close.from`、生命周期覆盖整个函数，则必须绑定为稳定 entry local；后续 call 之后的读取不能继续使用 capture 前的 SSA 常量。受 `Close` 管理的逐迭代槽不能走函数级提升，否则会把 capture 前复用同一寄存器的旧定义和本轮 local 合并；但 `Close` 只限制跨 epoch 提升，当前 epoch 内的可写 capture 仍须从捕获点的 reaching def 开始分配唯一 local，并把后续 def 写回同一 upvalue。物理寄存器在 reaching def 之前可能保存另一个 closure/temporary，不能仅凭同一 Close epoch 反向吞并。只读 child upvalue 不触发该提升，避免把所有 capture 都无差别物化；该事实在 HIR binding 层完成，AST 不补偿错误的 `nil()`/`false()`。
101. **terminal loop exit 可以穿过词法 cleanup pad**：Structure 在 cleanup owner 冲突消解前可能把含 `Close` 的无限循环保守标为 `Unknown`；HIR refinement 判断多出口是否全部终止时，必须沿出口 region 走到真实 `Return`/`TailCall`，不能只检查入口块末条指令。LuaJIT `UCLO` 常把源码级 return/break 拆成 `Close + Jump`；只要完整出口 region 不回到 loop/post-loop，且 `CleanupDisposition` 已让词法 scope 消费 Close，就可复用 while-true owner。AST 不接收残留 Close，也不通过 label/goto 补偿这一前层缺口。
102. **命名 vararg 槽只在入口值被观察时保留 entry 身份**：`has_vararg_param_reg` 说明调用帧为命名 vararg 预留了物理槽，不保证该槽始终属于入口参数；Lua 5.5 的 `PF_VAHID` 函数可以从未读取入口表，随后把同一寄存器复用于普通 local。HIR 仍保留首个 placeholder local 供 AST 判断是否生成命名 vararg 参数，但只有真实指令 use 或其 Phi 传递链能到达 `SsaValue::Entry(reg)` 时才写入 `entry_local_regs`。入口值未被观察时，后续 def/capture 必须按普通词法槽处理，不能被签名 flag 抢占。
103. **loop exit 的 source identity 穿过 liveness 裁剪**：loop state 已接管的寄存器可以在 post-loop 短路 header 中被读取，而对应 value-merge 表达式延后到下游 merge 才重建。entry override 沿无重定义、无 Phi 的 CFG 边传播时必须携带上游 source temp；即使 Dataflow 因寄存器不再 live 而省略下游 block-entry value，重建表达式仍能把旧 def temp 归一到 loop state。同一表达式经多条路径到达时，每个新增 source temp 都继续传播，不能用“表达式相同”提前截断。statement/conditional value-merge 直接生成的 node 条件和 leaf 值也必须先应用各自 block-entry override，再应用局部 target override；AST 不负责把退出后的空 local 猜回循环变量。
104. **island 内 for 协议继续由 loop candidate 接管**：mixed walker 到达 numeric-for init 或 generic-for preheader 时，必须事务式调用原有结构化 for lowering，并跳过它已经消费的 core/control blocks；自然出口若不是下一个文本布局块，要显式跳到该出口，不能让 for 结束后误落入 island 的另一入口。active loop 只在自身 header 与当前 island 同属一个 region 时暂时遮蔽 membership，避免把包含 island 的外层 for 也错误改道。loop core 的侧出口若仍落在同一 island，保留为带 state snapshot 的 goto，不能伪装成 break。可重入 preheader 上未被重定义的 Phi 是 island 的稳定状态槽：loop state 直接写回该 Phi temp，并抑制同一 preheader 的 generic materialization；否则会生成重复 unresolved Phi 或让侧入口看不到循环写回。Lua 5.4+ 的 generic-for TBC 仍由 `CleanupDisposition::GenericFor` 随 candidate 消费；显式 TBC/Close 则只按自己的 cleanup disposition 进入 HIR，不与 for owner 混用。
105. **Unknown loop 的退出前缀保持在显式 close 之前**：goto 重入 `<close>` local 可形成“循环出口先读取本轮 TBC，再经过 `ExplicitTbcBoundary` Close 进入循环外 continuation”的形状。HIR 只有在 exit 没有外部 predecessor/live phi、前缀确实读取候选内显式 TBC，且前缀不含 `Close/Tbc` 时，才把前缀移入该出口的 `break` 臂，并从 loop live-out state 排除被边界覆盖的 TBC 槽；否则保持未证明。边界可以与前缀同块，也可以位于 exit 唯一跳转、无 live phi 且首条就是该边界的后继块；后继在边界前还有指令时不得跨越，因为词法 `break` 会提前析构并改变可观察顺序。被接管的前缀与内层边界只消费一次，外层 cleanup 和边界后的 continuation 仍在循环之后降低。

106. **locals 候选扩张只访问真实 temp touch**：每个 block 先建立 `temp -> ordered stmt indices` occurrence index；从 root temp 出发按最小语句下标推进 worklist，遇到合法 alias 才把新 temp 的后续 touch 合入。非 touch 语句不参与扫描，已删除 alias 与真实 consumer 分开记录，保持原来的顺序判定而把复杂度从“每个定义扫描完整后缀”降为与实际 touch 数相关。

107. **terminal 边界选择与真实 clone eligibility 分离**：共享 terminal block 可以作为 branch/loop 的停止边界，不代表当前 lowering 状态已经能复制它。真正 clone 前，每个 live phi 必须已被结构 owner suppress、写入不同 target，或由 Structure 证明所有 incoming 等于同一 idom exit 值；同名 temp 的 no-op target 不是 owner。`Close/Tbc` 只有已 suppress，或 disposition 为 clone 时会省略的 `LexicalScope/Unreachable` 才能跨路径复制；保留的显式 cleanup 继续拒绝。Closure 仍因唯一创建点 provenance 不可复制。`lua52_02_goto.lua` 覆盖带 loop-exit phi 的合法 terminal clone，`regress_181_generic_for_branch_phi.lua` 覆盖 terminal 边界包含词法 cleanup、但 cleanup 由前层 owner 消费的形状。

108. **phi owner 冲突按 incoming 覆盖范围消解**：branch value candidate 可以显式忽略由 loop 管理的 predecessor，因此只有其 then/else preds 覆盖该 phi 全部 incoming 时，才能从 loop-exit candidate 删除整个 phi；部分覆盖必须保留 loop owner，不能把 ignored incoming 一起丢掉。保留下来的 loop header/exit phi 已有结构 owner，不得再登记成 generic unresolved；剩余 generic owner 按稳定 `PhiId` 唯一索引在 `StructurePlan`，HIR 不维护平行 Vec，也不为 terminal clone 对每个 phi 重扫全部候选。显式 goto/island 边物化 phi copy 时直接消费该 `EdgeRef` 对应的 canonical `PhiIncoming.value`；验证 edge 后再按 predecessor block exit 猜寄存器值会丢失平行边和未来 edge-specific SSA 语义。

109. **HIR 直接消费 StructurePlan 的结构 owner**：selected branch、branch-value merge 与 loop header/candidate 只能通过 `StructureFacts` 查询 `StructurePlan`，`StructuredBodyLowerer` 不再从 raw candidates 重建 `branch_by_header`、`loops_by_header` 或平行 header 集合。路径查询需要多次选择候选时重新遍历 plan 中对应 header 的短列表，保持 preheader、active loop、唯一候选的原优先级；不能用长期缓存复制 owner 事实，否则 Structure 冲突消解后的结果会与 HIR 执行计划漂移。

110. **mixed walker 是唯一 proto lowering**：整 proto 的 `lower_label_goto_body` 已删除；所有 reachable block 必须由同一 `StructuredBodyLowerer` 按 StructurePlan 的 branch/loop/linear/unstructured owner 覆盖，遗漏直接违反前层合同。局部 island 继续保留必要 label/goto，edge phi copy 只消费 Structure 预先索引的 `PhiEdgeCopy`；block merge 不再与同一 incoming 重复写回。透明 island 出口 pad 的布局和 continuation 也只读 plan，不能在 HIR 再建第二套后支配/cleanup 判断。

111. **普通指令 lowering 不接管控制协议**：`lower_regular_instr` 只接受非 terminator，`lower_control_instr` 只处理普通 jump/branch/return/tail-call；numeric/generic-for 控制指令必须由 StructurePlan 选中的 loop owner 消费，不能在单指令层重新拼装 unresolved 条件或伪 goto。零结果 `VarArg` 在 VM 中既不读值也不写槽，直接作为 no-op 省略，不能制造 residual HIR 诊断。

112. **不可规约控制直接使用普通 HIR 节点**：mixed walker 以 `If/Goto/Label/Block` 表达局部 island，HIR 不再保留无构造点的 `Unstructured { body, summary }` 包装，也不要求每个 simplify/AST pass 平行维护该死分支。generic-for 隐式 iterator call 的结果若进入普通表达式恢复，`expr_for_fixed_def` 返回 `None` 保留已物化 temp；不能用 `Some(Unresolved)` 把“不可内联”误报成语义缺失。

113. **decision 可读性枚举先执行预算门**：pure logical naturalize 在生成任何候选前先线性收集引用，超过 `MAX_SYNTH_REFS` 立即退出；OR-of-AND 链的两两因式分解只处理至多 16 个 terms。该 pass 只在已证明等价的表达式中择优，超预算保持原表达式，不得先构造 O(n²) 个整链 clone、再做必然失败的等价性检查。

114. **Decision 线性化不得展开共享后继**：连续 conjunction 节点若共用同一 falsy target，值折叠先把整段收成一个 `and` term，再沿共享后继迭代构造 `or` 链；不能在 statement materialization 中把同一后继递归复制到每条路径。已删除以“节点 + 完整路径事实集”为 memo key 的 known-test specialization：该纯可读性 pass 会在宽 DAG 上枚举指数级事实组合，重复测试的局部消除不得重新引入路径状态树化。

115. **结构探测回滚与 locals 继承按增量成本执行**：structured body 的 speculative lowering 只以插入/改写日志长度建立 checkpoint，失败时反向撤销本次 `required_labels / merge_allowed_blocks / override / visited` 变化；不得复制随已降低 region 增长的完整 map/set。loop entry 先消费已安装的 local/carried owner，只有 owner 查询失败后才展开 SSA leaf defs。`locals` 的继承映射使用共享只读快照，子块没有新增 promotion 时不得复制全部祖先 mapping；外层 temp 保护以父级谓词、当前后缀计数和 child-only 集合组合查询，不能为每个顶层语句物化一份剩余 temp 集。以上都只改变查询与回滚成本，不得放宽 owner、词法作用域或 promotion 判定。
