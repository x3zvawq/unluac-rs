# HIR

> **职责**：执行冻结的 `StructurePlan`，把 low-IR 的普通指令和值表达式降低成 HIR。
>
> **不负责**：重新识别控制结构、选择候选、发现 label、猜 phi owner，或做 AST 命名。

## 入口

```text
src/hir/analyze/mod.rs
  analyze_hir
    -> lower proto tree
    -> build bindings / slot epochs
    -> lower StructurePlan
    -> simplify_hir
```

每个 proto 只走一条结构 lowering 路径：

```rust
lower_plan_node(RegionId) -> Result<HirBlock, HirLowerError>
```

旧 `StructuredBodyLowerer`、candidate-by-header 重选、独立 label/goto walker、结构性
checkpoint/rollback 和 `visited` ownership 已删除。debug emitted-set 只验证 plan 没有重复发射。

## 模块布局

```text
src/hir/
  common.rs                         HIR 节点与稳定 identity
  error.rs                          HirLowerError
  analyze/
    lower.rs                        proto lowering 与共享上下文
    bindings.rs                     param/local/upvalue/temp identity 总入口
    bindings/                       debug entry/name、loop binding、captured slot/temp
    shared_closures.rs              Luau captured shared factory 证明与计划入口
    shared_closures/                group、template、composite 与 lexical-scope 证明
    instrs.rs                       普通 low-IR 指令 lowering
    exprs/                          SSA def/use、访问与 value pack 表达式
    structure/
      mod.rs                        final-plan facade
      plan_body.rs                  RegionId 递归执行器
      plan_body/                    index、traversal、block/edge、branch/loop、label、syntax 与 verification
      generic_for.rs                generic-for iterator 协议辅助
    short_circuit/                  已冻结 condition/value DAG -> HIR expression
  simplify/                         只做等价 HIR 规范化与可读性准备
    carried_locals/region_results/  region result 的 assignment、condition、binding fact 与 rewrite
    table_constructors/rebuild/     table 重建的 capture 生命周期证明
  promotion.rs                     slot epoch / local promotion facts
  debug.rs                          HIR dump
```

这些子目录只拆分同一个 lowering/pass 的内部主题；例如 `plan_body/` 仍共同消费一份
`PlanBodyLowerer` 与预建 index，不能在 branch、loop 或 edge 文件里重新扫描 Structure 候选。

## Region lowering

`plan_body.rs` 对每个 `RegionPlan` 做确定性映射：

| region | HIR 行为 |
| --- | --- |
| `Block` | 按 `LabelPlacement` 在 block 前或入口 cleanup 后发射 label，再发射 unresolved 诊断和普通指令前缀 |
| `Sequence` | 按 children 顺序递归 |
| `Branch` | 消费 frozen condition、arm region 和 continuation |
| `ValueDecision` | 消费冻结的值 DAG，发射一次 result assignment |
| `Loop` | 消费 kind、preheader/control/body/normal-tail、carried values 与 exit actions |
| `Unstructured` | 按 layout 发射 block/structured child，控制边只读 `EdgePlan` |

HIR 不维护 `branch_by_header`、`loops_by_header` 或 raw candidate vector。一个 region
payload 缺失、child 类型不符或 edge action 与 owner 冲突时返回 `HirLowerError`。

## Edge lowering

每条控制边只通过 `StructurePlan::edge_plan` 降低：

1. 先按 plan 顺序执行 canonical phi copies；Structure 以精确 `(edge, phi)` 标记为
   `elided` 的 VM-for 语法值除外，同一 edge 的其它 carried copy仍照常执行。
2. 再执行唯一 `EdgeTransfer`。
3. `Break/Continue` 必须指向当前 active loop。
4. `Goto` 直接把 `LabelPlanId` 映射为同 index 的 `HirLabelId`。
5. `Return/TailCall` 的指令 payload 由原 block 降低，edge 只验证终止语义。

HIR 不再给全部 CFG block 编号，也不从 island/requirement 二次收集 label。透明 pad 的
forward route 已由 Structure 复合为入口 edge action；HIR 不沿 CFG 重走路径。

## Branch 与 condition

- 普通 branch 和短路 branch 都消费 final `ConditionPlan`；simple condition 是单节点 plan。
- condition 明确给出 truthy/falsy edge 与 polarity，HIR 不再比较 raw `then_entry` 猜反转。
- 被 condition 吸收的 block 集、exit edge 和 escaping-def 边界由 Structure 验证。
- branch arm 的 phi/value action来自对应 edge；continuation 不由 HIR 搜索。
- value decision 的 node、物理 route、leaf provenance 与 result phi 全部来自 final plan；
  被吸收 block 的依赖只允许在同一 decision region 内按单次求值语义展开。
- value decision header prefix 正常发射其中的 def；只有无副作用、无 debug/capture/local
  identity 的直接稳定字面量 def 可同时作为 leaf 表达式，原赋值是否删除仍由 dead-temp 证明。

表达式无法安全内联时允许保留 temp，但不得截断 condition、改写 edge transfer 或换用
另一棵 short-circuit candidate。

LuaJIT `TypeGuard` 没有精确 Lua 源码表达时保留 unresolved call。string/integer/number
guard 的 call result 必须写入 Dataflow 分配的 post-guard temp，后续读取不能绕回转换前的
SSA 值；function/table guard 不改槽，只保留一次有序 call residual。

## Loop lowering

`LoopPlanData` 冻结：

- `kind`
- `preheader_block / condition_header`
- `condition`
- `condition_prefix_placement`
- `continuation / continue_target`
- `control_edges`
- `normal_tail` 的入口、continuation、normal/early/completion exit events
- VM-for body 是否存在正常 latch completion
- `header / result / carried values`
- source bindings 与 cleanup scope boundary

while/repeat 可以使用 `while true + planned Break` 表达带前缀或 edge value action 的条件，
但退出动作必须来自 plan，不能生成空退出臂。numeric/generic-for 的 VM init/latch 只由
对应 loop region 消费；普通 instruction lowering 遇到残余 for protocol 必须 fail-fast。
带 `normal_tail` 的 loop 使用独立 synthetic temp 记录提前退出：loop 前初始化，冻结的 early
break edge 更新它，loop 后据此决定是否执行 normal-tail region。HIR 只按 payload 查 edge，
不扫描 CFG 或副作用。若 normal-tail 的 cleanup 已由词法 owner 消费、降低后为空，则不物化
guard 与空分支。若 VM-for exit state 同时存在 early-break 与正常出口写入，共同正常
默认值在 loop 前物化，提前 break 的精确 edge copy 负责覆盖，不能在 loop 后无条件写回。
VM-for normal-tail completion copy 只有在全部完成边由当前 loop 以 fallthrough 直接拥有、copy
完全一致，且 source 在 loop 前已支配可用时，才可提升为统一 exit action；header carried
state 在 loop 后完成最终 handoff。tail 内产生的值、带可观察语句的 normal-only tail、
祖先 owner 或跨 loop transfer 都保留原位 copy 与 guard，不能为了消除临时变量提前执行。
numeric/generic-for 的 control、iteration epilogue 与 latch epilogue 是否接在 body 尾部，
由 Structure protocol 冻结的 `body_completes_normally` 决定；HIR 不得检查已生成语句的
最后节点来反推 CFG 完成性。空 body 正常完成，全 terminal body 不完成，island 只能通过
声明的正常 latch exit port 证明完成。退化 generic-for 的空 body 若由 protocol 标记
`immediate_break`，HIR 在 iteration epilogue 后发射一次 `break`，不得把它当作普通空循环。

目标方言没有 `continue` 时，Structure 已把等价可规约形状冻结为 branch-around-tail；
HIR 不自行制造 goto。Luau 的 planned `Continue` 才生成 `HirStmt::Continue`。

## Island lowering

island 是局部图，不是整 proto fallback：

- layout 中的普通 block按计划顺序发射；
- structured child 仍递归走 `lower_plan_node`；
- 非自然 fallthrough 只使用 planned `Goto(LabelPlanId)`；
- 多入口/多出口和回边保留图语义；
- edge phi copies 在跳转前执行；
- Close/TBC、capture/local scope barrier 由 Structure 与最终 AST verifier共同保证。

支持 goto 的 Lua 5.2–5.5/LuaJIT 可以得到可编译 island。Lua 5.1/Luau 若最终仍需
goto，strict 生成明确 unsupported error，permissive 输出诊断伪源码。

## Value 与 binding

- canonical SSA identity 来自 `DataflowFacts`，HIR 不实现第二套 reaching-def。
- `RegionInput / RegionResult / LoopCarried` 决定 state temp 的建立与写回位置。
- `EdgeCopy` 只在精确 `EdgeRef` 上执行。
- edge copy 的透明 `Move` 来源由稠密 `DefId` 索引一次压缩；单条 copy 不再反复追链。
- terminal `RegionResult Move` 只有在 immediate SSA source 已是 canonical root 时才吸收；
  多跳链可能保存并行赋值的旧值，必须保留原 Move，不能把延后的 edge read 穿透回已被
  中间写覆盖的 mutable home binding。
- 未吸收且已物化的 edge-copy Move 也只有在 source block 末尾仍能从同一 HIR binding
  读取 canonical SSA 时才允许穿透；binding 已被另一 SSA 复用时读取 frozen def 快照。
  SSA rename 一次冻结 live-out 与本块定义寄存器的稀疏 block-end map，并在查询时回退
  block entry，以恢复虚拟 edge use 的已知末值；两端都因 liveness 剪枝而缺项时，共享
  temp 或 mutable local 必须保守读取快照，不能把缺项误当作 `Entry(reg)`。
- `DiagnosticUnresolved` 产生显式 unresolved HIR；不能猜 `nil/false/0`。
- open result pack 继续使用独立 pack SSA，不伪装成固定寄存器 phi。
- for binding、capture 和稳定 local identity 读取 final loop/source facts；源码 debug local
  通过 Structure 冻结的 scope-entry SSA 映射成为 binding 身份证据，不回扫 CFG 或 producer。
  numeric/generic-for 的用户 binding 也从 loop body/header 的 source local 生命周期取名；
  compiler-internal for control slot 不成为输出 local。
- `bindings`、captured-slot、phi/temp promotion 共用 scope-entry anchor。同一寄存器的两个
  不相交 debug 生命周期携带不同 scope identity，`locals` promotion 按 `(home slot, scope)`
  复用或分离 `LocalId`，不能仅凭相同寄存器把源码 local 合并。
- `start_pc=0` 且 scope-entry SSA 为 `Entry(reg)` 的非参数源码 local 由 VM 的入口 nil
  初值承载。bindings 必须在函数入口直接建立并声明对应 `LocalId`，同时让该 scope 内的
  phi/def temp 写回此 identity；不能等到循环或分支前的 seed copy 才由 `locals` 提升，
  否则会把源码声明移动到前置调用之后，并阻断 generic-for iterator pack 的相邻折叠。
- closure def 优先使用其 scope-entry local 证据；缺失该 provenance 时才采用 child proto
  的显式 debug name，并继续交给 Naming 做合法性与冲突校验。
- 引用 capture 以 `(slot, close epoch)` 为词法身份。同 key 的父函数写后判定只构建一次
  block-local 最晚 def 与“经至少一条边可达 def”的反向摘要；capture 只查询稠密
  epoch-stamped workspace。反向传播从 def block 的 predecessor 开始，不能直接以 def
  block 为 seed，否则会把无环同块内 capture 之前的写入误当作后续写入。
  这条路径的精确上界是 `O((defs + captures) log K + Σ(Vk + Ek))`；workspace 只保留
  `O(blocks)` 稠密状态，不建立 `key × block` 持久矩阵，也不把跨 key 情形误称为纯线性。
- capture 的起始 epoch 仍由 normal phi ancestry 的最早 def 决定，不能改用
  capture PC 的 epoch。phi visited workspace 也按 epoch stamp 复用，不为每个 closure 重新
  分配和清零 `phis.len()` 位图。
- numeric-for binding 按 Structure 已冻结的 SSA identity 绑定，不能按 `(block, reg)` 扩大：
  被证明由循环语法承担的 exact header phi 读取直接复用 syntax local，`BodyPrologue` temp
  因而保持 dead；显式赋值产生的普通 def 仍进入独立 captured slot。为 later def 分配
  captured local 时，也不得把 header phi temp 重定向到该 local，否则会在声明前写入并
  变成全局赋值。
- 非 capture、非 for syntax binding 的 carried target，只有全部 `LoopCarried` incoming
  都是 loop body 内同寄存器 def 时才让这些 def 直接复用 carried temp；若全部 incoming
  都是同一个 body 内纯 `RegionResult` phi，该 result 与同寄存器 def 也复用此 temp。
  已冻结 nested carried-parent 的 target 继续在同 loop owner 内接受同寄存器 def 与纯
  result，以保留祖先槽复用合同；普通 target 仍只接受 body 内 source。
  唯一例外是 `LoopVmProtocol::Repeat`：它的 frozen condition control prefix 在
  `Native/TailBranchRepeat` 与两种 prefix placement 中都会进入当前 repeat 的每轮源码体，
  因此非 nested 的 direct def 允许域为 `body ∪ control`；preheader、normal-tail、祖先 owner
  与纯 `RegionResult` 仍不扩张。其它 loop 的 control prefix 可能先于 body 降低，不能直接
  合并 direct def。位于同一 loop `body ∪ control` 的 phi-only stage 只有在没有真实指令读取、
  capture、numeric-for syntax/debug identity、nested carried parent 或纯 result 身份，且全部消费者
  仅为当前 carried target 或同 owner `RegionResult` 时，才可直接复用 carried temp；来自 nested
  numeric-for `RegionResult` 的 source 继续保留独立 exit identity，避免把 VM control pack 与外围
  carried state 固化成机械 preheader local。nested carried target 还必须检查其共享 temp 上的全部
  numeric/debug identity；首版 `EdgeCopy` 只接纳没有普通指令前缀的 `NumericForLoop` source，
  且必须从 source phi block 直达同 loop 正常出口、是该 edge 唯一的 phi action、目标 binding
  独立并且没有 forward/iteration/cleanup，才可读取共址后的当前 carried 值。其它 edge copy、
  其它 owner、input 与诊断消费者仍保留独立 snapshot；
  self-retry、混合 source 与冲突 source 一律保守拒绝。候选按 carried target
  一次构建，消费者再按全部 incoming 线性核验，复杂度为 `O(phis + defs + incomings)`，不能
  按每个 result 重扫 owner 的全部 phi。别名产生的 copy 只删除 target 唯一的 self-copy；
  重复 target 必须保留并行赋值的最终写语义。
- `LuaString` 从 `RawString` 共享 bytes/text payload；HIR simplify 和 AST build 复制字面量节点时
  只复制 `Arc` 所有权，不按阶段复制字符串内容。
- Luau 带 capture 的重复 `DUPCLOSURE` 先按 child `Origin` 索引共同词法 owner，再用
  Dataflow 精确证明 closure dependency DAG 的全部 def-use。每个 group 只降低为一个
  synthetic composite factory，原位参数求值、调用和其它可观察指令不被搬动；只有已证明
  无外逃的 dependency occurrence 才被消费，root occurrence 改为零参数 factory call。
  owner 对整组 site 的支配关系先折成 dominator-tree NCA 包络，不按每个候选重新扫描
  occurrence；同时必须由最终 `StructurePlan` 证明 owner local 的 Lua block 包含全部 site。
  `while/repeat` control prefix 按最终协议映射到 loop body 词法块；numeric/generic control
  与 preheader 无法证明同一落点时直接 fail-fast，不能把 CFG dominance 当成 local 可见性。
  region 到 Lua block 的映射按稠密 `RegionId` memo；containment DFS 中每棵子树都是连续
  区间，因此每组 site scope 只保留 postorder 最左/最右端点，owner 候选做两次 Euler
  containment 查询，不重新形成 `candidate × occurrence` 或 `group × region-depth` 扫描。
- 同一 closure 指令可以既是外层 component 已消费的 dependency，又是内层 component 的
  owner；此时只在原位置声明内层 factory，不再物化原 closure value。`owner ∩ replacement`
  或 child ownership 冲突仍立即返回 `HirLowerError`，不能靠 debug assert 或 Naming 兜底。
- Luau 的 raw capture equality 对 NaN 不自反。只有 SSA 明确追溯到 NaN number/vector/complex
  literal 时才通过一次 table roundtrip 建立不可被编译器常量传播的快照；`GetTable`、调用、
  entry 等未知值本身已阻断传播，不能重复加 barrier，否则反编译重编译会逐轮膨胀。
- temp promotion 把每个恢复出的 `LocalId -> HomeSlotKey` 写入 `ProtoPromotionFacts`；
  `carried-locals` 只有在两端 home slot 相同，或 local 上限处理已显式启用 slot
  compaction 时，才允许跨结构合并身份。不能仅凭赋值形状把不同 VM slot 的结果并成
  同一源码 local。slot compaction 也不能仅因 SSA/home-slot 定义数超限就启用；还必须
  由根 HIR block 的直接 temp/local 绑定同时证明源码级局部压力超限。否则长函数的物理
  寄存器复用会把已死且词法身份不同的值恢复成同一 local，制造跨作用域名字混淆。

## Cleanup 与词法安全

`CleanupDisposition` 决定 `Close/Tbc` 是被词法 region/loop 接管，还是必须显式保留。
planned goto 已在 Structure 检查 VM TBC barrier；部分入口才活跃的 TBC join 会把
label 冻结在 canonical 入口 cleanup 之后，避免后续 `close_scopes` 把 label 包进局部块。
`HirToBeClosed` 保留原始 TBC instruction identity，`HirLabel` 同时携带 Structure
冻结的 active TBC origin 集；物理 layout 中较早的 exit cleanup 不能截断后续仍带同一
origin 的 island label。`close_scopes` 只按这份 identity 合同物化连续词法块，不按复用
后的寄存器号猜作用域。HIR 的 local promotion 仍可能恢复新的源码 local，因此 AST
lowering 后必须再次运行 goto scope verifier，禁止跳进 local 或 `<close>` 作用域。

## Simplify 边界

Simplify 只做已证明等价的 HIR 规范化，不得改变 control plan 的语义：

| pass | 作用 |
| --- | --- |
| `decision` / `boolean-shells` / `logical-simplify` | 决策表达式与布尔壳规范化 |
| `table-constructors` | fresh-table 写入收回构造器 |
| `closure-self-capture` | 递归闭包自捕获 |
| `temp-inline` | 在 use/effect/scope 约束下内联 temp |
| `generic-for-iterators` | iterator value pack 接管 |
| `branch-values` / `branch-control` | 收敛已存在的等价 HIR 壳，不重新识别 CFG |
| `locals` / `carried-locals` | temp -> local 与跨结构 identity 收敛 |
| `close-scopes` | TBC 词法块物化 |
| `dead-temps` / `dead-labels` | 删除无引用残余 |

`branch-values` 在把根 block 的机械分支收成 Temp 表达式后，只给本次新暴露的
terminal sink 一次定向内联机会：单值且无 tail 的 `return temp` 复用普通相邻内联证明；call
则必须是连续标量 materialization run、callee 为裸全局且没有 method 协议，并继续使用
`temp-inline` 的整包求值顺序、capture/debug、use-count 与 value-pack 证明。不能为此延后
整个 `locals` phase 或重跑全 proto 的普通内联，否则会把循环状态、receiver snapshot 或
deferred decision 一并暴露给下一轮。

numeric-for 的 header temp 仍归 `temp-inline` 这个原生 temp owner。连续 materialization run
中唯一用于 header 的稳定字面量可以越过同 run 内保留的状态赋值收回，因为字面量没有读取
时点或副作用；候选仍需满足 debug、capture、home-slot 与唯一 use 约束。binding、lookup、
运算和调用不能共享这条跨语句合同，继续使用相邻求值顺序证明，避免把循环外快照延后。

无环 `Decision.entry` 的 test 是每次求值整棵值决策时必定首先求值一次的条件位置；顶层标量
Decision 中相邻、唯一 use 的 temp producer 可以按普通 condition 复杂度收回该 test，单值
return 继续服从 return 站点限制，普通逻辑表达式也只把必达的最左条件纳入这条合同。entry
仍继承外层 condition/loop-head 站点；尤其 while/repeat 条件不能把循环外的可观察 producer
延后成每轮求值。求值顺序证明还必须确认 temp 位于该条件的可观察前缀中；带环 Decision、
其它 decision node、truthy/falsy target 与逻辑右支都可能重复或短路，不接收 lookup、调用或
其它可观察 producer。

table 左值只对 PUC Lua 5.2–5.5 的单 target inherited-upvalue write，允许把相邻
producer 收回 key；这四种方言会在 key 后读取最终 table upvalue。key 内部仍需通过
既有前缀顺序证明；complex/global base、Lua 5.1/LuaJIT/Luau upvalue 和并行左值继续
保留快照。

`SELF/NAMECALL` method 协议会在 HIR 同时保存 receiver temp 的 callee base 与隐式首参；
这两个语法引用只对应一次源码 receiver 求值。相邻的裸 binding 或以 binding 为根的命名
字段链 snapshot，只有在 method 名、base 与首参严格匹配、全 proto 恰有这两个 use，并继续
通过 debug、capture、home-slot 与求值前缀证明时，才能原子替换两处并删除快照。例如
`t = subject.worker; t:touch()` 可恢复为 `subject.worker:touch()`；普通 `obj.method(obj)` 没有
method 协议，字段 lookup 可能改写第二次读取的 binding，仍必须保留两次求值。

Luau `FASTCALL*` 在 HIR call 上保留 Transformer 已冻结的参数来源合同。direct fastcall
参数与 callee fallback setup 可以在同一调用内按源码顺序收回，但 fixed opcode 通过 fallback
`MOVE` 读取的旧槽仍是独立快照；嵌套调用逐层消费各自的 direct mask，外层 generic open pack
不能放宽内层参数。该事实只扩展 `temp-inline` 的相邻求值顺序证明，use-count、debug、capture、
home-slot、复杂度与整包提交门保持不变，AST 最终仍生成普通函数调用。
closure 的复杂度不能仅凭 capture 数代表 child proto 函数体，因此 `temp-inline` 不把 closure
producer 内联进 loop head；这类值保留为独立 local function，避免生成多行匿名 iterator。

`generic-for-iterators` 只允许把 `parameter + nil` iterator pack 跨过一条独立的标量
temp copy；iterator temp 必须匿名且在整个 proto 只由 for head 读取一次，所有 temp/param
还必须有已知且互不冲突的 promotion home slot。其它表达式、local/upvalue/global/table、
调用、closure、cleanup 或更宽区间不能仅凭“结果未使用”推断为可重排。
即使完整 iterator pack 与 for head 相邻，direct closure producer 也保留为独立 local
function；child proto 体量不属于 HIR 表达式复杂度，不能把它视为小型 loop-head 值。
若 closing value 已经在更早位置求值，pass 还可把紧邻 for head 的固定 `nil` assignment
收回 iterator 中间位置；目标必须全是无 debug 身份且全 proto 唯一 use 的 temp。该规则不
跨越任何语句，也不接纳非 `nil` RHS，因此不会改变其它 iterator 表达式的求值或快照时点。

`branch-control` 会删除两臂均空且可安全丢弃条件求值的分支；条件仅由 `not` 包裹的
call/method-call 则收成调用语句，调用本身仍在原位置执行一次。全局/表读取、元方法运算
或短路调用等其它 predicate 不能作为 Lua statement，也不能仅凭空分支猜测为纯表达式。
`Unresolved` 及其外层逻辑壳必须保留显式诊断。该 pass 订阅 `DecisionShape` 和 `TempChain`，
确保 deferred decision 物化或 dead-temp 删除后新暴露的空分支也能在固定点内收敛。
原始字面量或同类型原始字面量比较给出静态 truthiness，且整个条件可安全删除时，
`branch-control` 还会选择唯一可达 arm；选中 arm 先保留为独立 block，避免扩大 local/TBC
作用域。两臂结构相同时也复用同一规则。动态比较、lookup、调用与 table 构造不作常量折叠。
同一 pass 还会沿结构化 block 传播稳定词法 binding 的路径 truthiness。候选只包含当前 proto
全域无写入、不是 for binder 且未被 closure 引用捕获的 param/local；事实只专门化条件里的
direct atom、`not`、`and/or` 骨架，不能进入比较、调用参数或其它值上下文，也不能把 Lua 的
truthy 原值替换成布尔 `true`。`A and B` 仅在真臂推出两项为真，`A or B` 仅在假臂推出两项
为假；if 合流只取实际 fallthrough 臂的事实交集。循环正文可以继承稳定入口事实，但循环出口
不推出条件为假，repeat latch 也不消费正文产生的事实。proto 仍含 goto/label 时整条规则停用，
避免用词法顺序冒充尚未结构化完的控制流。删除不可达写会让后续 local 新满足全域稳定证明；
`branch-control` 在单次调度内收完这条单调解锁链，不让链长消耗全局 fixed-point 轮次预算。
事实域只收集条件骨架中的 Param/Local，最多跟踪 256 项；超限 proto 保守跳过路径专门化，
避免可读性规则产生无界重扫。
两臂末尾完全相同的单目标 direct-binding copy 可以移到 if 后统一执行；候选只接受
param/local/temp 的固定单值复制，且两臂都不得引入候选 local 或包含 TBC/Close 边界。
upvalue、global、table 左值、多返回及可观察 RHS 不移动，避免改变地址求值、资源关闭或
词法身份时点。
edge copy 判断 incoming def 是否已经落在 phi target 上时，除相同 `TempId` 外，还要识别
两个 temp 明确映射到同一 `(slot, close epoch)` reference-capture target、且最终 temp
resolver 未被 debug binding 覆盖的情况；不能泛化到普通 debug local。
引用捕获槽若沿 canonical MOVE 来源重读，会在 Close 之后错误覆盖 `__close` 对该 local
的写入。
repeat 正文尾部的单臂 `if C then break` 在没有 continue、goto/label、TBC/Close
边界或残留 Decision/Unresolved 时，可以收回为 `until C or D`；`C` 为真时仍短路跳过
原条件 `D`，两者各在原尾部位置至多求值一次。候选任一根条件已经是 `or` 时拒绝，避免
固定点继续把更早的正文 break 吞进同一退出条件；prefix 中更早或嵌套 loop 的 break
不改变尾部条件的可达性，因此不构成边界。结构化阶段若把它保留为
`if A then break else if C then break end`，只移除 nested else 并保留原位 A guard，
仍按相同合同收回 C。

禁止 simplify：

- 用后层可读性折叠补 Structure 缺失的 branch/loop owner；
- 把 unsupported goto 静默改成 dispatcher；
- 因内联失败改变 break/continue/goto 目标；
- 复制有副作用、closure identity 或 cleanup 的 terminal block。

`carried-locals` 的外层保护集使用父 scope + prefix/suffix 引用计数的分层查询，不为
每个子 block 复制全部 binding。连续 region result handoff 先在未修改的 block 上逐项
证明 home-slot、capture 和 suffix 私有性，再把传递链压成一张 canonical rewrite map
批量应用；不能每折叠一个 SSA result 就重新扫描整块。跨控制流的 path transaction 则每次
只提交一对独立 binding，再基于改写后的 HIR 重算下一对，避免把已经消费或覆写的 result
沿 canonical ancestry 继续并入 state。repeat staged result 只有在当前 repeat 确有以该祖先
phi 为 parent 的 carried child 时才能复用同一 temp。分支内允许先更新
state 后以 `result = state` 交棒，但每个终端赋值不得同时写 state，避免并行赋值重写改义。
动态 repeat 只有在每个提前 break 与可达尾条件出口都紧邻写入同一可用 state、result 在
loop 内零读取、写入数与完整出口数一致且同一赋值不再写 state 时，才能把 result 与 state
合并；含当前 loop continue 或任意嵌套层次 goto/label 的路径先保守拒绝，不能把未收集的
条件出口当作普通 fallthrough。没有提前 break 时，可达正文 fallthrough 上的尾部精确快照
就是唯一条件出口，仍按同一合同合并。
`until false` 没有尾条件出口；只需在所有真实 break 都满足上述精确快照合同后合并，
不能把永远回边的正文 fallthrough 误算成退出路径。
更一般的 branch/loop result 写回使用路径敏感 transaction。候选 result 必须是无 debug、
capture、for-binding 或 TBC 身份的单 binding local，且只能与精确相同 `(slot, close epoch)`
的既有 state 合并；不能用高压 local compaction 策略代替物理槽证明。证明器在原 HIR 上跟踪：
`Unproduced` 表示改写后的 state 仍等于原 state，`Pending` 表示它已承接原 result，`Synced`
表示三者相等。`Pending` 路径不得读取旧 state，`Unproduced` 路径不得读取 result；只有 direct
`state = result` 建立 `Synced`，`state = f(result)` 在原位消费 result 后回到 `Unproduced`。
所有抵达当前 block 后缀、break/continue/return 的路径都不得保持 `Pending`。验证区间内
提及候选的多目标或 open assignment，以及任意 goto/label、TBC/Close、残留
Decision/Unresolved 和候选 capture 全部拒绝。nested loop 只允许完全不提 state、入口不含
`Unproduced` 且没有任何控制转移的 result alpha-renaming；while/numeric/generic-for 保留
零次路径，repeat 按至少一次
求固定点。相同 home-slot 限制还保证改写不会提前丢失另一个 GC root，避免弱表、`__gc` 或
异常 cleanup 在没有显式 binding 读取时仍观察到生命周期变化。
repeat 尾部 `next -> state` temp 写回可以跨过只消费 next 的中性语句，但此时 next/state
必须属于精确相同的 `(slot, close epoch)`，中间区间不得提及旧 state、产生控制转移或引入
capture/TBC/for-binding 身份。条件直接读取 next，或先由 `guard = table[next]` 产生条件值，
都沿原位置批量改写；table lookup 的元方法、异常与 GC 观察到的槽位覆盖时点仍与 VM 一致。
精确同槽是 promotion 时记录且由 carried rewrite 继续维护的 provenance：实际 binding 合并
若两端不是同一可信 key，就持久失效目标 binding 的正向同槽证明，并在后续 handoff 中继续
传播，不能在 child/parent 或下一 scheduler 轮次重新误证。原始物理 home 事实仍保留给
reference capture/TBC 等负向保护，不能因正向证明失效而漏掉资源身份；按值 capture 只保护
其直接读取的 binding，不把后来复用同一物理槽的不同 binding 当成长生命周期 cell。slot
compaction 明确允许跨槽合并，因此即使尚未观察到污染，也不得把 provenance 用于上述
transaction 或中性区间的正向证明。
资源身份必须在 producer 处保护，而不是等改写后再修复 facts。carried-local 在冻结当前
proto 的 capture/TBC 身份后，所有 binding merge 都拒绝 direct 资源 binding，并对
ByReference capture 与 TBC 的 raw home 做 may-alias 检查；未知、冲突或已污染的一端按
“可能同槽”处理。这样 closure cell 与 close binding 从未被换壳，后续 provenance 只负责
阻止新的正向同槽误证，不承担恢复已经改变的资源语义。
该污染必须跨 fixed point 的实际身份转换传播：`locals` 为 promotion group 登记全部 raw home
供资源保护，但只有组内全部 temp 的 trusted home 完全相同才允许复用 sticky/debug local
或成为本轮 slot candidate；计划应用后逐项传播 `Temp -> Local` 污染。负向资源检查采用
may-alias 语义，任一 binding 的 raw home 未知或冲突时保守拒绝，不能把“不精确”解释成
“一定不同槽”。含 ByReference capture 的 temp 组只有在组内每个 temp 都属于同一 trusted
key 时才允许提升；无法证明 home 的 capture temp 保持原形，不能生成带冲突 provenance 的
captured local。入口参数 alias 只有在后缀确实发生 `Local -> Param` 改写时传播，纯死声明
删除不污染参数。`temp-inline` 的
open-return alias 与 `generic-for-iterators` 这类正向同槽证明也只读 trusted home；收集
reference capture 的保护槽仍读 raw home。
旧的 temp handoff、相邻 seed/carried 与参数 alias 同样会把新值提前写入
已有 state；即使后续显式读写等价，跨槽改写也会缩短旧值的 GC root 存活期。因此这类
eager overwrite 统一要求非 compaction 且 source/target 具有相同 trusted
`(slot, close epoch)`，不能只依赖“中间没有源码级 state 读取”。
guarded update 是例外：低层 VM 已在 guard 前执行 state write，只是 HIR 把 terminal arm
不再读取的 dead write 省略了；把 `next = call(); if next then state = next else return end`
收回 state 是恢复原覆盖时点，不是把写入提前。
`locals` 对已经选中的 promotion root 还可在线性同 block 内吸收后续 fixed-scalar temp
overwrite：每个新 def 必须拥有与 root 完全相同且仍 trusted 的 `(slot, close epoch)`，并且
整段前缀没有控制流、unknown/冲突 home、multi/open/parallel assignment、capture 或
TBC/Close。该规则只改 binding identity；每条 overwrite 仍在原 statement index 保留，不能
被后续 `x = x` 裁剪误删。普通 call/table write 可以跨越但不移动其 RHS；一旦边界出现，后续
同槽 def 全部退出该 chain。这样 `t2 -> t6 -> t11` 这类物理覆盖会共享一个 local，同时
不会把 loop/分支回边或不同 close epoch 误并成源码变量。
收敛结束后，精确的单目标 direct binding `x = x` 可删除；紧邻 `a = b; b = a` 的第二句
同样只把 `b` 写回原值。该裁剪只接受 param/local/temp 与固定单值，不触碰多目标/open pack、
upvalue、global 或 table 左值，避免把并行快照和可观察地址求值误判成无操作。

`locals` 的入口参数 alias 收敛使用结构化单向状态证明：`local L = P` 之后从“值同步”开始，
某条路径一旦写入 `L`，该路径后续不得再读取原 `P`。if 两臂分别传播“可能已写”状态；循环
除首轮外还以“已写”状态验证下一轮，因此 `local L = P; while L do L = ... end` 可恢复为
直接读写参数，而循环里仍读取原参数的 snapshot 必须保留。参数自身写入、参数的引用 capture、
alias local 的任意 capture、alias 参与的 TBC 资源身份以及 goto/label 都拒绝收敛，不能把两个独立
词法身份强行合并。

`temp-inline` 的 callee/argument run 必须整包恢复原求值顺序；夹在其中的零读取匿名 temp
只有在 RHS 可安全丢弃、无 debug/capture 身份时才可随 run 删除，不能把动态 producer 当空壳。
同一 run 接入开放尾调用 return 时，固定前缀只能引用 setup 前已经保存的 direct temp，
其 source/target home 不能被后半段写入或 reference capture；尾调用本身保持原位。
带 source debug scope 的 temp/local 是显式源码 binding，`locals`、`temp-inline` 和
`table-constructors` 不得删除、跨 scope 合并或移动其初始化；compiler-internal 槽位仍按
普通机械 temp 处理。
因此构造器重建只接受 direct-`NewTable` raw temp，或唯一物化的 fresh `LocalDecl`；后者
要么由 analyze 阶段建立，要么由 `locals` 从 direct temp 分配而来。raw temp 没有源码
binding 身份，`LocalDecl` 的 binding 在 RHS 内尚不可见；已有 local 上的 `x = {}` 则保留
分步字段写，避免把旧对象的覆盖推迟到字段 RHS 之后。`ProtoPromotionFacts` 使用 lowering
的 canonical `fixed_temps` 映射，并持久保存 direct allocation origin；decision 或 table
materialize 新建的 `LocalDecl` 不能仅凭语法外形冒充 fresh
owner。capture/debug/TBC 与 handoff 仍由构造器事务原有的孤儿 capture、owner 移动和
语句边界证明负责，不能拿 freshness 代替。
固定、无尾值的 `SETLIST` 另有两条保留 seed 的窄路径。canonical `NewTable` 后紧邻的
fixed batch 可以在原 seed 位置合并，但 fixed 值必须是 data-only 且静态非 nil，seed
不能有不确定的数组槽；raw `Temp` 只能走这条 canonical direct-origin 路径。源码
`LocalDecl` seed 则可以在完整 prefix proof 下只把 fixed batch 改成原位 indexed writes，
保留 seed 和所有 producer 的声明/求值点；区间内不得出现控制流、open/parallel assignment、
外部 alias 或不透明表达式。若 seed 已证明覆盖了连续的数组槽，后续 batch 可以从
`seed_array_len + 1` 开始，或覆盖该连续前缀内的槽；不能跳过未知或可能为 nil 的洞。该路径
不删除 seed，因此后续 closure/debug 使用不会改变 binding 生命周期。
构造器 region 只消费 fresh `LocalDecl` producer；已有 local/temp 的 `Assign` 必须保留真实
覆盖，不能因为结果只被一个字段读取就内联，否则旧值会继续作为 GC root 存活。raw temp seed
只允许在原 statement index 重建字段，不延后到 open `SETLIST`，也不直接 handoff 到其它
lvalue；这两种移动都会跳过 seed 物理槽的原始覆盖。无法满足这份时序合同的 open pack 保留
原始 `TableSetList`。若 seed 与 fixed `SETLIST` 之间存在 producer、别名或 exact-width
pack，或数组值可能为 nil，则继续保留节点；不能把 raw `SETLIST` 静默拆成普通赋值。open
tail 只有在真实 `LocalDecl` seed、seed 原位保持、prefix/producer/eval-order proof 全部
通过且 tail 为真正 open pack，并且表达式树不含 `Decision`/`Unresolved` 等未完成控制节点时才可合并；
普通 call/table access 仍在 fresh owner 的原 seed 位置求值。被删除的中间 `LocalDecl` 还必须没有 source-debug
或 capture 身份，避免把显式词法 owner 静默缩短。canonical raw temp、跨 producer open pack
和 handoff 一律保留。
`locals` 不提升没有 source debug、capture sticky 身份且从未被表达式读取的纯写 temp 链；
这类链保持 temp 身份，由 `dead-unresolved-temps` 在确认 RHS 可安全丢弃后删除。调用、表构造、
table access 等可观察 RHS 仍保留，不能因为结果无读取者就删除求值。
同一 block 的多个独立 run 按原 statement 索引批量判定，成功 sink 原位改写，删除区间只在
扫描结束后统一压缩，避免让预先冻结的 capture/order-sensitive def 快照与变更后索引错位。
被整句删除的零读取 RHS 还必须同步扣除其中的 temp read；本轮压缩新暴露的形状仍交给
invalidation scheduler，不能在已失效的快照上继续猜测。
单个 run 内会反复扫描 growing sink 的单读候选受固定工作预算约束；超限必须整包保留原
temp，不能部分提交，零读取且可安全丢弃的候选不消耗这份预算。该预算只封住人工超长链的
最坏工作量，不代表算法已经按 output incidence 线性化。

## 错误合同

结构执行错误统一返回 `HirLowerError` 并接入 `DecompileError::Hir`。用户输入不得触发
HIR 的 `panic!`、`assert!` 或 `expect`。宽松模式只对显式 unresolved/unsupported 继续
生成诊断树，不把内部 plan 违约降级成猜测源码。

## Debug 与维护

- `--dump structure` 先检查 region、edge、value、cleanup、label 和 requirements。
- `--dump hir --detail verbose` 只解释 final plan 的执行结果。
- 遇到错误源码，先修最早缺失/错误的 Structure disposition；不要在 AST readability
  或 naming 阶段加控制流特判。
- `plan_body.rs` 的递归应与 region/edge/value 数量线性相关，不扫描全部候选、全部 block
  或所有 CFG 路径。
