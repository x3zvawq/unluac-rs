# HIR

> **职责**：执行冻结的 `StructurePlan`，把 low-IR 的普通指令和值表达式降低成 HIR。
>
> **不负责**：重新识别控制结构、选择候选、发现 label、猜 phi owner，或做 AST 命名。

## 入口

```text
src/hir/analyze/mod.rs
  analyze_hir
    -> lower proto tree
    -> build bindings / slot epochs
    -> lower StructurePlan
    -> simplify_hir
```

每个 proto 只走一条结构 lowering 路径：

```rust
lower_plan_node(RegionId) -> Result<HirBlock, HirLowerError>
```

旧 `StructuredBodyLowerer`、candidate-by-header 重选、独立 label/goto walker、结构性
checkpoint/rollback 和 `visited` ownership 已删除。debug emitted-set 只验证 plan 没有重复发射。

## 模块布局

```text
src/hir/
  common.rs                         HIR 节点与稳定 identity
  error.rs                          HirLowerError
  analyze/
    lower.rs                        proto lowering 与共享上下文
    bindings.rs                     param/local/upvalue/temp identity
    shared_closures.rs              Luau captured shared factory 证明与计划
    instrs.rs                       普通 low-IR 指令 lowering
    exprs/                          SSA def/use、访问与 value pack 表达式
    structure/
      mod.rs                        final-plan facade
      plan_body.rs                  RegionId 递归执行器
      generic_for.rs                generic-for iterator 协议辅助
    short_circuit/                  已冻结 condition/value DAG -> HIR expression
  simplify/                         只做等价 HIR 规范化与可读性准备
  promotion.rs                     slot epoch / local promotion facts
  debug.rs                          HIR dump
```

## Region lowering

`plan_body.rs` 对每个 `RegionPlan` 做确定性映射：

| region | HIR 行为 |
| --- | --- |
| `Block` | 按 `LabelPlacement` 在 block 前或入口 cleanup 后发射 label，再发射 unresolved 诊断和普通指令前缀 |
| `Sequence` | 按 children 顺序递归 |
| `Branch` | 消费 frozen condition、arm region 和 continuation |
| `ValueDecision` | 消费冻结的值 DAG，发射一次 result assignment |
| `Loop` | 消费 kind、preheader/control/body/normal-tail、carried values 与 exit actions |
| `Unstructured` | 按 layout 发射 block/structured child，控制边只读 `EdgePlan` |

HIR 不维护 `branch_by_header`、`loops_by_header` 或 raw candidate vector。一个 region
payload 缺失、child 类型不符或 edge action 与 owner 冲突时返回 `HirLowerError`。

## Edge lowering

每条控制边只通过 `StructurePlan::edge_plan` 降低：

1. 先按 plan 顺序执行 canonical phi copies；Structure 以精确 `(edge, phi)` 标记为
   `elided` 的 VM-for 语法值除外，同一 edge 的其它 carried copy仍照常执行。
2. 再执行唯一 `EdgeTransfer`。
3. `Break/Continue` 必须指向当前 active loop。
4. `Goto` 直接把 `LabelPlanId` 映射为同 index 的 `HirLabelId`。
5. `Return/TailCall` 的指令 payload 由原 block 降低，edge 只验证终止语义。

HIR 不再给全部 CFG block 编号，也不从 island/requirement 二次收集 label。透明 pad 的
forward route 已由 Structure 复合为入口 edge action；HIR 不沿 CFG 重走路径。

## Branch 与 condition

- 普通 branch 和短路 branch 都消费 final `ConditionPlan`；simple condition 是单节点 plan。
- condition 明确给出 truthy/falsy edge 与 polarity，HIR 不再比较 raw `then_entry` 猜反转。
- 被 condition 吸收的 block 集、exit edge 和 escaping-def 边界由 Structure 验证。
- branch arm 的 phi/value action来自对应 edge；continuation 不由 HIR 搜索。
- value decision 的 node、物理 route、leaf provenance 与 result phi 全部来自 final plan；
  被吸收 block 的依赖只允许在同一 decision region 内按单次求值语义展开。
- value decision header prefix 正常发射其中的 def；只有无副作用、无 debug/capture/local
  identity 的直接稳定字面量 def 可同时作为 leaf 表达式，原赋值是否删除仍由 dead-temp 证明。

表达式无法安全内联时允许保留 temp，但不得截断 condition、改写 edge transfer 或换用
另一棵 short-circuit candidate。

LuaJIT `TypeGuard` 没有精确 Lua 源码表达时保留 unresolved call。string/integer/number
guard 的 call result 必须写入 Dataflow 分配的 post-guard temp，后续读取不能绕回转换前的
SSA 值；function/table guard 不改槽，只保留一次有序 call residual。

## Loop lowering

`LoopPlanData` 冻结：

- `kind`
- `preheader_block / condition_header`
- `condition`
- `condition_prefix_placement`
- `continuation / continue_target`
- `control_edges`
- `normal_tail` 的入口、continuation、normal/early exit events
- VM-for body 是否存在正常 latch completion
- `header / result / carried values`
- source bindings 与 cleanup scope boundary

while/repeat 可以使用 `while true + planned Break` 表达带前缀或 edge value action 的条件，
但退出动作必须来自 plan，不能生成空退出臂。numeric/generic-for 的 VM init/latch 只由
对应 loop region 消费；普通 instruction lowering 遇到残余 for protocol 必须 fail-fast。
带 `normal_tail` 的 for 使用独立 synthetic temp 记录提前退出：loop 前初始化，冻结的 early
break edge 更新它，loop 后据此决定是否执行 normal-tail region。HIR 只按 payload 查 edge，
不扫描 CFG 或副作用。若 normal-tail 的 cleanup 已由词法 owner 消费、降低后为空，则不物化
guard 与空分支。若普通 for exit state 同时存在 early-break 与正常出口写入，共同正常
默认值在 loop 前物化，提前 break 的精确 edge copy 负责覆盖，不能在 loop 后无条件写回。
numeric/generic-for 的 control、iteration epilogue 与 latch epilogue 是否接在 body 尾部，
由 Structure protocol 冻结的 `body_completes_normally` 决定；HIR 不得检查已生成语句的
最后节点来反推 CFG 完成性。空 body 正常完成，全 terminal body 不完成，island 只能通过
声明的正常 latch exit port 证明完成。

目标方言没有 `continue` 时，Structure 已把等价可规约形状冻结为 branch-around-tail；
HIR 不自行制造 goto。Luau 的 planned `Continue` 才生成 `HirStmt::Continue`。

## Island lowering

island 是局部图，不是整 proto fallback：

- layout 中的普通 block按计划顺序发射；
- structured child 仍递归走 `lower_plan_node`；
- 非自然 fallthrough 只使用 planned `Goto(LabelPlanId)`；
- 多入口/多出口和回边保留图语义；
- edge phi copies 在跳转前执行；
- Close/TBC、capture/local scope barrier 由 Structure 与最终 AST verifier共同保证。

支持 goto 的 Lua 5.2–5.5/LuaJIT 可以得到可编译 island。Lua 5.1/Luau 若最终仍需
goto，strict 生成明确 unsupported error，permissive 输出诊断伪源码。

## Value 与 binding

- canonical SSA identity 来自 `DataflowFacts`，HIR 不实现第二套 reaching-def。
- `RegionInput / RegionResult / LoopCarried` 决定 state temp 的建立与写回位置。
- `EdgeCopy` 只在精确 `EdgeRef` 上执行。
- edge copy 的透明 `Move` 来源由稠密 `DefId` 索引一次压缩；单条 copy 不再反复追链。
- `DiagnosticUnresolved` 产生显式 unresolved HIR；不能猜 `nil/false/0`。
- open result pack 继续使用独立 pack SSA，不伪装成固定寄存器 phi。
- for binding、capture 和稳定 local identity 读取 final loop/source facts；源码 debug local
  通过 Structure 冻结的 scope-entry SSA 映射成为 binding 身份证据，不回扫 CFG 或 producer。
  numeric/generic-for 的用户 binding 也从 loop body/header 的 source local 生命周期取名；
  compiler-internal for control slot 不成为输出 local。
- `bindings`、captured-slot、phi/temp promotion 共用 scope-entry anchor。同一寄存器的两个
  不相交 debug 生命周期携带不同 scope identity，`locals` promotion 按 `(home slot, scope)`
  复用或分离 `LocalId`，不能仅凭相同寄存器把源码 local 合并。
- `start_pc=0` 且 scope-entry SSA 为 `Entry(reg)` 的非参数源码 local 由 VM 的入口 nil
  初值承载。bindings 必须在函数入口直接建立并声明对应 `LocalId`，同时让该 scope 内的
  phi/def temp 写回此 identity；不能等到循环或分支前的 seed copy 才由 `locals` 提升，
  否则会把源码声明移动到前置调用之后，并阻断 generic-for iterator pack 的相邻折叠。
- closure def 优先使用其 scope-entry local 证据；缺失该 provenance 时才采用 child proto
  的显式 debug name，并继续交给 Naming 做合法性与冲突校验。
- 引用 capture 以 `(slot, close epoch)` 为词法身份。同 key 的父函数写后判定只构建一次
  block-local 最晚 def 与“经至少一条边可达 def”的反向摘要；capture 只查询稠密
  epoch-stamped workspace。反向传播从 def block 的 predecessor 开始，不能直接以 def
  block 为 seed，否则会把无环同块内 capture 之前的写入误当作后续写入。
  这条路径的精确上界是 `O((defs + captures) log K + Σ(Vk + Ek))`；workspace 只保留
  `O(blocks)` 稠密状态，不建立 `key × block` 持久矩阵，也不把跨 key 情形误称为纯线性。
- capture 的起始 epoch 仍由 normal phi ancestry 的最早 def 决定，不能改用
  capture PC 的 epoch。phi visited workspace 也按 epoch stamp 复用，不为每个 closure 重新
  分配和清零 `phis.len()` 位图。
- numeric-for binding 按 Structure 已冻结的 SSA identity 绑定，不能按 `(block, reg)` 扩大：
  被证明由循环语法承担的 exact header phi 读取直接复用 syntax local，`BodyPrologue` temp
  因而保持 dead；显式赋值产生的普通 def 仍进入独立 captured slot。为 later def 分配
  captured local 时，也不得把 header phi temp 重定向到该 local，否则会在声明前写入并
  变成全局赋值。
- 非 capture、非 for syntax binding 的 carried target，只有全部 `LoopCarried` incoming
  都是 loop body 内同寄存器 def 时才让这些 def 直接复用 carried temp；若全部 incoming
  都是同一个 body 内纯 `RegionResult` phi，该 result 与同寄存器 def 也复用此 temp。
  已冻结 nested carried-parent 的 target 继续在同 loop owner 内接受同寄存器 def 与纯
  result，以保留祖先槽复用合同；普通 target 仍只接受 body 内 source。
  control prefix 可能在 HIR 中先于 body 降低，不能直接合并；self-retry、混合 source 与
  冲突 source 也一律保守拒绝。候选按 carried target 一次构建，复杂度为
  `O(phis + defs + incomings)`，不能按每个 result 重扫 owner 的全部 phi。别名产生的
  copy 只删除 target 唯一的 self-copy；重复 target 必须保留并行赋值的最终写语义。
- `LuaString` 从 `RawString` 共享 bytes/text payload；HIR simplify 和 AST build 复制字面量节点时
  只复制 `Arc` 所有权，不按阶段复制字符串内容。
- Luau 带 capture 的重复 `DUPCLOSURE` 先按 child `Origin` 索引共同词法 owner，再用
  Dataflow 精确证明 closure dependency DAG 的全部 def-use。每个 group 只降低为一个
  synthetic composite factory，原位参数求值、调用和其它可观察指令不被搬动；只有已证明
  无外逃的 dependency occurrence 才被消费，root occurrence 改为零参数 factory call。
  owner 对整组 site 的支配关系先折成 dominator-tree NCA 包络，不按每个候选重新扫描
  occurrence；同时必须由最终 `StructurePlan` 证明 owner local 的 Lua block 包含全部 site。
  `while/repeat` control prefix 按最终协议映射到 loop body 词法块；numeric/generic control
  与 preheader 无法证明同一落点时直接 fail-fast，不能把 CFG dominance 当成 local 可见性。
  region 到 Lua block 的映射按稠密 `RegionId` memo；containment DFS 中每棵子树都是连续
  区间，因此每组 site scope 只保留 postorder 最左/最右端点，owner 候选做两次 Euler
  containment 查询，不重新形成 `candidate × occurrence` 或 `group × region-depth` 扫描。
- 同一 closure 指令可以既是外层 component 已消费的 dependency，又是内层 component 的
  owner；此时只在原位置声明内层 factory，不再物化原 closure value。`owner ∩ replacement`
  或 child ownership 冲突仍立即返回 `HirLowerError`，不能靠 debug assert 或 Naming 兜底。
- Luau 的 raw capture equality 对 NaN 不自反。只有 SSA 明确追溯到 NaN number/vector/complex
  literal 时才通过一次 table roundtrip 建立不可被编译器常量传播的快照；`GetTable`、调用、
  entry 等未知值本身已阻断传播，不能重复加 barrier，否则反编译重编译会逐轮膨胀。
- temp promotion 把每个恢复出的 `LocalId -> HomeSlotKey` 写入 `ProtoPromotionFacts`；
  `carried-locals` 只有在两端 home slot 相同，或 local 上限处理已显式启用 slot
  compaction 时，才允许跨结构合并身份。不能仅凭赋值形状把不同 VM slot 的结果并成
  同一源码 local。

## Cleanup 与词法安全

`CleanupDisposition` 决定 `Close/Tbc` 是被词法 region/loop 接管，还是必须显式保留。
planned goto 已在 Structure 检查 VM TBC barrier；部分入口才活跃的 TBC join 会把
label 冻结在 canonical 入口 cleanup 之后，避免后续 `close_scopes` 把 label 包进局部块。
`HirToBeClosed` 保留原始 TBC instruction identity，`HirLabel` 同时携带 Structure
冻结的 active TBC origin 集；物理 layout 中较早的 exit cleanup 不能截断后续仍带同一
origin 的 island label。`close_scopes` 只按这份 identity 合同物化连续词法块，不按复用
后的寄存器号猜作用域。HIR 的 local promotion 仍可能恢复新的源码 local，因此 AST
lowering 后必须再次运行 goto scope verifier，禁止跳进 local 或 `<close>` 作用域。

## Simplify 边界

Simplify 只做已证明等价的 HIR 规范化，不得改变 control plan 的语义：

| pass | 作用 |
| --- | --- |
| `decision` / `boolean-shells` / `logical-simplify` | 决策表达式与布尔壳规范化 |
| `table-constructors` | fresh-table 写入收回构造器 |
| `closure-self-capture` | 递归闭包自捕获 |
| `temp-inline` | 在 use/effect/scope 约束下内联 temp |
| `generic-for-iterators` | iterator value pack 接管 |
| `branch-values` / `branch-control` | 收敛已存在的等价 HIR 壳，不重新识别 CFG |
| `locals` / `carried-locals` | temp -> local 与跨结构 identity 收敛 |
| `close-scopes` | TBC 词法块物化 |
| `dead-temps` / `dead-labels` | 删除无引用残余 |

禁止 simplify：

- 用后层可读性折叠补 Structure 缺失的 branch/loop owner；
- 把 unsupported goto 静默改成 dispatcher；
- 因内联失败改变 break/continue/goto 目标；
- 复制有副作用、closure identity 或 cleanup 的 terminal block。

`carried-locals` 的外层保护集使用父 scope + prefix/suffix 引用计数的分层查询，不为
每个子 block 复制全部 binding。连续 region result handoff 先在未修改的 block 上逐项
证明 home-slot、capture 和 suffix 私有性，再把传递链压成一张 canonical rewrite map
批量应用；不能每折叠一个 SSA result 就重新扫描整块。repeat staged result 只有在当前
repeat 确有以该祖先 phi 为 parent 的 carried child 时才能复用同一 temp。分支内允许先更新
state 后以 `result = state` 交棒，但每个终端赋值不得同时写 state，避免并行赋值重写改义。

`temp-inline` 的 callee/argument run 必须整包恢复原求值顺序；夹在其中的零读取匿名 temp
只有在 RHS 可安全丢弃、无 debug/capture 身份时才可随 run 删除，不能把动态 producer 当空壳。
带 source debug scope 的 temp/local 是显式源码 binding，`locals`、`temp-inline` 和
`table-constructors` 不得删除、跨 scope 合并或移动其初始化；compiler-internal 槽位仍按
普通机械 temp 处理。
同一 block 的多个独立 run 按原 statement 索引批量判定，成功 sink 原位改写，删除区间只在
扫描结束后统一压缩，避免让预先冻结的 capture/order-sensitive def 快照与变更后索引错位。
被整句删除的零读取 RHS 还必须同步扣除其中的 temp read；本轮压缩新暴露的形状仍交给
invalidation scheduler，不能在已失效的快照上继续猜测。
单个 run 内会反复扫描 growing sink 的单读候选受固定工作预算约束；超限必须整包保留原
temp，不能部分提交，零读取且可安全丢弃的候选不消耗这份预算。该预算只封住人工超长链的
最坏工作量，不代表算法已经按 output incidence 线性化。

## 错误合同

结构执行错误统一返回 `HirLowerError` 并接入 `DecompileError::Hir`。用户输入不得触发
HIR 的 `panic!`、`assert!` 或 `expect`。宽松模式只对显式 unresolved/unsupported 继续
生成诊断树，不把内部 plan 违约降级成猜测源码。

## Debug 与维护

- `--dump structure` 先检查 region、edge、value、cleanup、label 和 requirements。
- `--dump hir --detail verbose` 只解释 final plan 的执行结果。
- 遇到错误源码，先修最早缺失/错误的 Structure disposition；不要在 AST readability
  或 naming 阶段加控制流特判。
- `plan_body.rs` 的递归应与 region/edge/value 数量线性相关，不扫描全部候选、全部 block
  或所有 CFG 路径。
