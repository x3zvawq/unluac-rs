# HIR

> **职责**：严格消费 `StructurePlan`，把控制流和值流计划降低成带稳定 binding 身份的语义树，
> 再通过 simplify pass 消除 bytecode lowering 留下的机械 carrier。
>
> **不负责**：重选 Structure 候选、重新扫描 CFG 猜控制 owner、决定最终名字或文本布局。

## 入口与数据流

```text
src/hir/analyze/mod.rs::analyze_hir

LoweredChunk + Cfg/Graph/Dataflow + StructureFacts
  -> region / edge / value lowering
  -> distill Structure requirements into typed HIR exit requirements
  -> HirModule
  -> simplify_hir fixed point
  -> repeat root provenance 与词法 owner 共同收敛
  -> stable HirModule
```

proto tree 使用显式 postorder frame。每个 proto 只消费与自己对应且已验证的 plan；child 数量、
proto identity 或 plan query 不一致时返回 `HirError`，不回到 CFG 临时推断。

`HirModule.protos` 按父先子后分配，`id` 等于 arena 下标，所有 `children` 边指向更大的下标。
降低时先预留 owner，再预留其合成 factory，最后分配 physical children；factory 只引用这些
后续 child。失败恢复删除 factory 占位时对所有保留引用做同一单调重编号，simplify 不改变拓扑。
闭包效果、正常返回摘要与 temp-inline 直接逆序读取 arena；capture 效果只求被 `children`
引用的函数摘要，正常返回分析还读取有 child 的 caller 以解析其调用点。函数体的后序完成与
arena 的父先子后分配是两个不同顺序；词法子树范围必须沿 `children` 边建立，不能用 arena
连续下标代替持有关系。

## 模块 owner

```text
src/hir/
  common.rs                  HIR 节点、binding、value-pack 与 origin
  analyze/mod.rs             模块/proto 调度和失败边界
  analyze/lower.rs           proto lowering 上下文与调度
  analyze/structure/         RegionPlan、edge、loop 与 island 执行
  analyze/exprs/             SSA/value 与 value-pack 表达式 lowering
  analyze/instrs.rs          普通 low instruction 到 HIR 语句
  analyze/bindings/          数据流身份到 HIR binding
  analyze/shared_closures/   reusable closure 的词法 factory
  promotion.rs               后续 rewrite 可消费的 provenance
  value_facts.rs             正常结果值域：truthiness、boolean 与 GC 惰性
  visit.rs                   HIR 与 AST 消费者共用的 proto 内只读遍历
  rewrite.rs                 已证明站点的定点代换与精确替换计数
  simplify/mod.rs            pass 描述符与 invalidation 调度
  simplify/object_flow.rs    binding、allocation 持有关系与对象逃逸的共享正向分析
  simplify/object_flow/      child-first capture/返回值摘要、确定字段身份与私有构造窗口
  simplify/                  各 simplify pass 与共享分析
  debug.rs                   HIR dump 与 pass snapshot
  error.rs                   HirError
```

`HirBinding` 是当前 proto 的 Param/Local/Temp/Upvalue 共享身份，对象流以同一类型索引状态。
`HirProto::source` 用 `LuaString` 共享原始源码名及解码视图，保留字节身份，不为每个继承同一
source 的 proto 物化文本副本；其相等性也按字节定义。dump 和 Generate 注释通过
`display_text` 优先借用已解码文本，无视图时才采用 UTF-8 替换显示。
闭包捕获保存创建点父级的 `HirBinding`，与 ByValue/ByReference 模式独立。lowering 消费已有寄存器绑定事实，无法获得身份时在该层产生 Unresolved 诊断；
全函数的 Reg 捕获模式直接消费 Dataflow 查询；SlotEpochFacts 只持有 Close epoch 与路径上的
开放 cell 状态，ProtoBindings 的绑定身份与原寄存器捕获模式分别表达。
原 nil 声明绑定已接受的未捕获 debug scope 时，捕获排除按完整 home 与 source scope
查询；旧 epoch 的关闭 cell 不阻止同槽新 scope。集合包含全部 ByValue/ByReference 捕获，
不能从“不需要分配 cell local”反推没有捕获，也不能遗漏同一 scope 的其它 epoch。
合法 nil 局部变量仍捕获其 cell；同 epoch 后续写和前向声明统一消费 `captured_slots` 的身份，
不能按寄存器扫描后续定义并跨越 Close。捕获不能保存复合表达式，后层不再从表达式形状重建身份。
同一物理 `(slot, close epoch)` 还可能对应互斥分支内分别创建、关闭的 cell；
`captured_slots` 用已证明的单块 CLOSE 窗口或原 RETURN 激活终点区分绑定，不伪造不同的物理 home。
窗口首写必须有该原槽的真实 fixed Def，并在本块支配该 cell 的全部捕获；Entry/no-reaching 的坐标
不是初始化写，仍由入口 cell owner 处理。入口没有旧的打开 cell，fixed/phi 读取不得逃出；
CLOSE 核对整个关闭后缀，RETURN 包含本条返回读取且不新增 `do`。未关闭的共同外层 cell 保持共享。
同一 cell 的真实 fixed 初始化若支配全部捕获和其后映射的 fixed/normal Phi 写，则直接由该初始化
声明；后续 reaching Phi 不再另建空声明。已接受 source scope 可给出更早的真实 nil 初始化，
但 Entry 活读、旧 cell 已打开或任一分支不受支配时仍保留原前向声明 owner。
捕获按原指令顺序加入当前块的 pending 槽组，CLOSE 按槽范围退休一次，避免兄弟分支、未来激活
污染当前声明，也不为每条 CLOSE 重扫全部历史捕获。按激活区间查询 fixed/phi 写和 capture 的同一 LocalId。
`visit.rs` 通过 `traverse.rs` 唯一解释 HIR 子节点；closure 仅将捕获身份投影为一次父级引用，
不进入 child body，value-pack tail 仅遍历一次。AST lowering 的 temp 首现顺序、
命名变参引用与 HIR root finalizer 的 capture 收集都复用该接口，不各自复制 HIR 递归骨架。
`HirVisitor<'hir>::visit_closure` 在普通 expr hook 后、capture hooks 前提供真实 closure 的稳定借用；
对象流索引及 NamingEvidence 直接借用原 capture 切片，不能跨源 HIR 的修改存活。其它 hook
仍接受短借用，capture/root-release 的默认临时 binding 投影不属于可保存的语法节点。
Promotion 的捕获槽收集也通过 capture hook 读取按引用捕获的 Temp 身份；进入嵌套块前
只读取 if/while/for 的 header，不把 repeat 尾条件或块内捕获提前到入口。
表达式存在性查询使用 `any_expr`，它与完整事实收集共用 visitor，先检查当前节点，命中即停止；
binding 与 pending-producer 消费者只提供谓词。visitor 的完成状态在每个 hook 和子节点边界消费，
不继续枚举剩余兄弟节点；tuple 独立停止已完成分量，全部完成才停止遍历，因此事件查询命中后
仍会收齐其它分量需要的写入与 capture。Decision 仍按已有节点序列访问 test 与 Expr 叶，不沿 Node 边重复展开，
也不按运行可达性删去语法引用；语句的声明和写入角色另由相应 visitor 查询。
只需语句结构的 label 收集使用 `visit_stmt_structure`，通过同一 traverse 定义进入嵌套块，
跳过求值子树；存在性查询通过同一骨架的 `any_stmt_structure` 在首个命中处停止。
`simplify/label_refs.rs` 共享 label/goto 存在性查询并按顶层 owner 发布引用集合，carried-local、debug-scope 与
close-scopes 消费[共享词法索引](../design.md#pipeline-总览)：carried-local 检查嵌套目标，后两者
只检查直属 label。索引保留精确 goto 来源位置；close-scopes 的声明前入边和区间内出口查询
共享同一 block 快照，不为每个 TBC 候选重扫前缀或重建出口集合。

一般 pass 的可变遍历统一使用 `simplify/walk.rs::HirRewritePass`；表达式 pass 直接实现值与条件回调，
不另设适配接口。影响遍历深度的表达式外壳可先在 `rewrite_expr_before_children` 归一，再执行
子节点与后序回调；逻辑整理据此一次压缩整条 NOT 链，消费共享布尔结果事实，未知值的偶数链
保留两层布尔转换。条件的 truthiness 改写在值等价整理之后执行，不能代替值语境的证明。
捕获使用独立 `rewrite_capture` hook，仅由已证明的绑定身份改写消费；
Decision 消解和表布局不进入捕获。block 入口将 body 的可变借用与 proto 只读事实分开，作用域 pass 借用
同一 proto 的 debug 映射。generic-for 事务保留是 pass 的静态能力，只有需要逐段失效
校验的改写才保存旧 iterator 快照；该能力不替代具体 pass 的语义证明。

Normal 与 Deferred 联合稳定后，Final 阶段才把已证明可索引展开的固定 SETLIST 降低；
完整帧 owner 因而先消费原 batch occurrence、缓冲槽和 initializer 身份。Final 的变化仍回到
同一失效循环，并计入原轮数预算。debug initializer 查询只匹配 seed 的实际 scope、direct
allocation 与原 home；它不签发根删除许可，捕获、字段事件和前缀仍由各自 owner 核对。
已完成的 Luau 内层数组仍由原 allocation 和唯一 Batch 证明其输出槽与连续字段缓冲，
外层完整帧消费这些来源，不将内层表展开成另一套索引写入。
未折叠的单层数字 Neg 还须核对原结果位于该字段槽、原输入位于整批缓冲末端；
Promotion 在已有操作扫描中保留一元输入 home，不从内联后的数字反推原 scratch。
Deferred 死写清理暂时保留当前 CALL 发布的 Boolean 预写 Temp，完整帧仍须消费实际事件；
Final 再用原死写证明清理未消费者。这是一次审理期间的需求集合，不是永久 inline retention，
也不允许 native 在缺失预写时跳过 guard。需求与其它死写输入共享一次树遍历，借用原预写列表。

debug scope 的单条 Def initializer 与分支合流 initializer 分别持有事实。后者只有在 scope
从同一 Branch continuation 开始、两条布尔写属于该 region result 时，才携带原 phi 与具体
比较 predicate 身份。布尔壳折叠核对 scope、promoted local、home 和 predicate 后，可将
为合流临时建立的相邻空声明还原成 initializer；条件求值前已经可见的声明仍不得后移。

已证明站点的 Temp 代换由 `rewrite.rs` 共享一套 traverse 骨架，并返回精确替换次数。
单个代换不进入新插入的值，批量代换按已证明的 DAG 展开并计入递归匹配；相邻子树之间
恢复活动路径。同一 key 在不同输出位置分别展开，不按身份去重。capture 仅接受最终绑定
身份，普通左值定义和协议身份元数据不参与表达式代换。assignment 的目标替换按次数撤销
producer，generic-for 继续按具体 iterator span 的前后内容失效，不能统一成一个 changed 标志。

temp-inline 的纯调用 materialization 与相邻依赖链共享候选检查和 DAG 提交。
赋值、callee、参数与 return 均在原相邻提交点沿连续的单读取依赖链消费原 producer，
逐级复用站点分类与求值前缀 query，保留 FASTCALL direct 参数上下文和 callee 物化位置；
不扫描累计展开后的 sink，也不把 repeatable 解释为来源 binding 不可变。
根、捕获与 debug 身份仍按同一未压缩语句坐标检查，无关前缀保留；一般分支依赖继续
由原逐站点证明处理。最终一次完成 sink 代换并按实际消费扣减 use；语句删除仍由各自入口统一完成。

`analyze/` 执行前层 plan；`simplify/` 只改写已经合法的 HIR。任何需要 CFG ownership、phi incoming
归属或 loop partition 的新判断都应先补进 StructurePlan，而不是在 simplify 中重建。

## 核心合同

### Region 与 Edge

- 每个 `RegionPlan` 只降低一次，并严格按 containment 与 layout 顺序产生语句。
- 每条物理 edge 的 transfer、forward route、value action 和 cleanup action 只来自 `EdgePlan`。
- `Break`、`Continue`、`Goto`、normal tail 与 synthetic single-pass fence 的词法 owner 必须保持
  Structure 冻结的祖先关系；HIR 不按当前位置猜最近循环。
- island 保留必要 label/goto 与局部 CFG 顺序，不把不可规约控制伪装成 structured branch。
- 初始 lowering 直接消费每条 Close 的最终执行位置与 origin；不按相同资源集合选代表 Close。
  label 的 barrier 与入口 cleanup 是传递事实，label 自身不发射清理。
  捕获窗口遇到原 RETURN 自带的非 TBC 关闭时，须匹配同 CFG 块内紧邻、同来源的
  Return，由该 Return 承接 activation；不在返回值求值前另造词法 do。显式 CLOSE、
  TailCall 及 TBC cleanup 不适用此许可，不能借终端返回删除普通词法末端。
- close-scopes 从共享 HIR CFG 的 typed 求值事件求资源 may/must 活跃点：may 给出候选终点，
  must 检查词法范围内的实际求值。Goto 只消费目标实际越过的 cleanup origins，不能用
  must-active barrier 的补集推断关闭。相同 owner 的多个 typed 事件分别参与区间计数。
  构图时按节点 ID 发布根层语句位置；生命周期查询不另走语句树建立地址到位置的索引。
- 资源身份由 TBC origin 贯穿，当前 block 的一次逆序扫描给出绑定与同槽 epoch 搜索上界，
  epoch 不等于词法终点。cleanup 的 origin 与 binding 活动各自索引，候选复用区间查询；
  已无待消费 origin 的资源不再创建候选或保护 label，不能由原始槽位阈值重新创造清理责任。
  直属 cleanup 索引保留独立 Close 的覆盖阈值，包括合法的 Close(0)；Return/TailCall 清理
  必须与同一来源的相邻终结语句配对，才能恢复 frame 终结边界。返回快照和 open pack 合同
  不因资源 scope 物化而放宽。
  返回语句的 `pending_cleanup_source` 只保留尚待 HIR 消费的清理事务；前层已完成的清理
  不再签发该标记，HIR 删除配对清理时原子退休。独立 `frame_source` 持有原结果布局等价类的
  代表来源：同 proto、相同 home/宽度且没有开放引用的返回共享事实，避免诊断指令号阻止
  等价分支合并。清理结束不能抹掉原结果区；合成返回没有来源，不继承其它返回的帧证明。
- 资源候选保存范围选择条件，通过嵌套分量与活跃点检查后才发布 cleanup 所有权。
  直属索引按活跃条件求并集，不逐候选复制相同关闭位置。scope 提交时原子退休 Close 中已接管
  的 origins；组合 Close 保留尚未接管的部分，全部退休后才删除，避免跨嵌套 owner 遗失消费进度。
  外部 label 后的独立 cleanup 前缀必须连续，不能跨过副作用或较高槽清理。
  label 位置索引由边界保护和外部跳转查询共用，资源恢复不重新猜测 Structure 的原始 CFG。

### Value 与 Binding

- `LuaValueSemantics` 是 HIR/AST 共用的原始值语义模型：整数/浮点混合比较、数值表示区别
  和字符串顺序只定义一次。`HirExprSafety` 负责 HIR 求值事件及 root relevance，decision
  抽象值域通过它持有的值语义上下文验证比较；AST 对当前字面量调用同一模型，不复制
  混合数值算法。原始值结果可确定不代表求值可以移动，也不构成 binding 生命周期许可。
- 求值可删除性由 `HirExprSafety` 一次递归组合节点事实；是否允许未解析诊断由同一路径区分。
  已经使用共享 visitor 的观察分析只查询当前节点，不在每个节点上重复分析整棵子树。
  节点查询本身不授权删除表达式，消费者必须完整遍历子节点；GC/root、求值序与各 pass 的
  语句屏障仍按各自合同判断。
  `HirEvalEffects` 共享表达式、写目标与显式调用的观察规则；消费者选择 header 或完整块
  的遍历范围，并提供自己的额外语句屏障，不能把隐式 dispatch 提前到初始化事件。
- `HirProto::temp_count` 是 bindings 冻结的连续 Temp 编号域上界，覆盖 fixed def、phi、
  loop guard 与 repeat staging。simplify 只复用或退役已分配身份，不缩减编号域；消费者
  按此上界分配索引或枚举身份，不从剩余语句树重建容量，也不把它当成活跃 Temp 数量。
- `HirProto::local_count` 是 lowering 与 simplify 共同追加的 Local 编号域上界，声明删除或
  绑定合并不压缩身份。promotion 在候选接受后直接登记身份及其 debug 名称、scope；
  Decision 物化只推进编号域，入口按新增区间登记 home-free 并补齐空 debug 元数据。
  branch/table 改写持有旧事实快照时，保留局部分配上界，完成改写后再登记新增区间。
  源码声明、循环变量与 factory/capture 绑定列表仍表达实际 owner 顺序，不是编号全集。
- `TempId` 表示机械 SSA carrier；`LocalId` / `ParamId` / `UpvalueId` 表示源码生命周期身份。
  指令结果直接按 Dataflow 的有序 Def 列表查询冻结的 `fixed_temps` 映射，不另存逐指令
  Temp 列表；coalesce 后多个 Def 可以共享 Temp，投影仍保留原长度、顺序与重复项。
  入口 debug scope 与引用捕获参数的入口 close epoch 直接绑定已有 `ParamId`；fixed/phi 的
  读写和 loop carried 来源都消费同一 binding resolver，不能写参数却从遗留 temp 读取。
  循环体内的 Decision 也消费 block/reg 的既有 local owner：结果写入按合流位置投影，
  未更新叶及已发射 header 定义按读取位置投影。SSA 身份仍保留给旧值快照；不能把
  所有同寄存器 temp 全局替换成当前循环变量，也不能把未发射的 dispatch temp 当作叶值。
  非参数 captured local 才需要分配声明。已有 debug scope 的初始化与后续覆盖共享身份，
  locals 的匿名单次 use 策略不得延迟其首写物化、令同一 scope 分裂为两个 local。
  显式 LOADNIL 初始化且未被捕获的 debug scope 由 Bindings 在原 Def 位置发布声明，
  同 scope 的后续 fixed/phi 读写直接引用它；内层 CLOSE 不关闭的外层变量不经过
  block-local promotion 再造身份。不同 source scope 与捕获槽 owner 仍保持分离。
  没有 debug scope 时，Bindings 可消费实际发射的单块 CLOSE 窗口，把其低槽闭包输出
  接回同一父级前缀的真实 LOADNIL。只绑定 canonical nil 与低槽输出，不吞高槽 CLOSURE
  scratch；旧 nil 读取、Phi、捕获、额外覆盖或未证根终点均拒绝。候选限定向前 CFG，
  原 holder 的末次定义在后续全部根观察中仍被保留；后缀证明复用 Dataflow 区间查询。
  最终 CLOSE 必须指向紧邻的原 RETURN 并属于普通词法 cleanup，才能作为函数退出终点。
  从函数入口开始的窗口可以消费已有 EntryNil 覆盖证明：非参数/隐式变参、没有未知
  scratch 覆盖且原 Def 覆盖 Entry。它复用入口 nil 声明，不伪造 LOADNIL 或重绑旧 Entry 读取。
  `HirDebugScope::initializer_temp` 继续保存 Structure 接受的显式声明结果，Entry/phi 不伪造
  初始化指令。Luau 完整调用帧可据此核对当前 LocalDecl、原 CALL 结果与同槽身份，
  不必从后续调用位置猜测源码 initializer；此角色不替代准备事件或词法前缀验证。
- loop-carried 的 owner 与唯一入口值消费 [PhiPlan 的冻结查询](3.structure.md#final-plan-合同)，
  nested coalesce、状态写回及 repeat staging 不重新扫描 incoming 判定结构角色。
- 已物化 loop-carried 身份的无值读取 scalar 覆盖由 bindings 消费 Dataflow 的
  `def_overwritten_value` 接回原身份；只接受同槽同 close epoch，并保留 capture、debug
  与 VM-for 绑定边界。不能把清根写入变成独立死 temp，也不能据此延长新分配对象的根。
- 退出能力要求由 HIR 在 simplify 收敛后按当前树冻结；已消失的 goto/continue 要求
  随之退役，失败 proto 和 unresolved 诊断保留证据。AST 不重建或修正 Structure 的旧要求。
- `HirProto::environment_upvalues` 发布 Transformer 已证明的词法环境 role，但集合成员仍是当前
  proto 的普通 `UpvalueId`。环境读写降低为 `HirExpr::UpvalueRef` / `HirLValue::Upvalue`，因此
  mutability、closure capture、decision value、root/lifetime 与 temp-inline 只维护一套 cell
  identity；HIR 不再把环境 cell 伪装成 key 为 `_ENV` 的 `HirGlobalRef`。常量 key 的环境表访问
  仍可独立证明为真实 `HirGlobalRef`，动态环境表访问则保留 upvalue base。AST 只消费 role 集合
  决定候选源码是否可写成 `_ENV`，不重新识别 VM 环境传播链。
- `ProtoPromotionFacts` 是 binding 到完整物理 home 集合的唯一 owner。`possible_*_home_slots`
  保留 provenance 是否完整：`None` 表示该 binding 仍来自物理栈、但具体 home 已未知，
  `Some(empty)` 才表示 HIR 明确合成且 home-free；需要做 may-alias、capture、root 或写入
  生命周期判断的 consumer 必须使用 `complete_param/local/temp_home_slots`，由 Promotion 统一把
  `None` 扩成当前 proto 的全部 `(slot, close epoch)` universe。未知 physical binding 却没有
  universe 是内部事实错误，统一 fail-fast，pass 不得自行把它解释成空集、另写 fallback，或
  从当前 HIR 文本反猜槽位。紧邻 transparent MOVE 的潜在写入 home 在 temp 提升与
  carried-binding 合并时传播到最终 definition，consumer 只在 lvalue 写入点查询完整集合，不能把
  TempRef 读取误算成写入。显式 TBC 的 origin 在初始 Promotion 中绑定注册点的
  `(slot, close epoch)`；Close 后的合流 epoch 与 value 的来源 epoch 是不同事实，
  后续资源槽保护直接查询 origin，不从 Param/Local/Temp 或复合 value 反推，不按寄存器
  扩大到全部 epoch。当前 TBC value 的逻辑读取、capture 与受保护 local 仍由各自查询处理。
  这些事实通过 Promotion 查询消费，具体 pass 不得再次解释 provenance 失效或自行扫描 universe。
  查询借用 owner 中已有的集合；附加 definition 写引入新 home 时才按需复制。只读 pass
  不缓存全部 binding 的 home 映射，跨 provenance 改写保留来源时显式取得 owned 快照。
  Lowering 或 HIR pass 创建 synthetic binding 时必须在构造点登记 home-free；合成 proto 与同索引
  `ProtoPromotionFacts` 必须作为一组产物安装，不能只替换 proto 而留下默认的未知 facts。
  `SlotEpochFacts` 同时冻结当前点可能仍开放的引用捕获：Capture 建立 cell，Close 结束它，
  普通覆盖不关闭 cell，CFG 合流与回边按 may 传播。参数交接消费当前点查询，不能因未来
  另一个 scope 复用同寄存器并捕获，就否定此前的 callee 参数 home。
- 入口变参参数寄存器一旦分配为 local，`HirProto::vararg_param_local` 就冻结其 `LocalId`；AST、
  Naming 和 debug dump 直接消费该身份，不从 `locals` 顺序反猜。是否生成命名变参仍由签名种类
  和该 binding 的真实使用共同决定。
- fixed、open 与 exact tail 通过 `HirValuePack` 显式区分，任何 rewrite 都必须保持值宽度、求值
  次数和顺序。
  `result_source` 统一解释接收位置对应的 fixed / tail producer 或已知补 nil；尾部多个结果
  共享 producer 不等于共享具体值，各分析仍分别投影自己的对象、闭包或生命周期事实。
- 普通 local initializer 在 HIR -> AST 边界发布逐 binding 的
  `HirInitializerRootProfile`。该 profile 从原始 `HirValuePack`、目标 VM 的结果类别以及 proto
  常量锚定事实计算：primitive 结果、proto 持有的 String/KCDATA/Vector 常量和无 tail 时的
  nil-fill 不需要靠对应 stack slot 维持可观察生命周期；动态引用、call/vararg 结果以及展开 tail
  则保守标记为可能影响 collectable lifetime。AST cleanup 只能按槽消费这个结论，不得从已经
  树化的 `AstExpr` 重新推导多返回宽度、常量 owner 或 VM root 语义；缺失 profile 和越界查询都
  必须 fail closed。AST 新建声明或任意过滤、替换、重排 binding/value 对应关系时清空 profile，
  只删除连续尾槽时可同步截断。该证书只回答原 stack slot 生命周期问题；相邻性、完整覆盖、
  binding 顺序、RHS 求值/丢弃和目标源码作用域是否合法仍由 AST 对具体候选重新证明。
  HIR 的结果类别与求值事件同样正交：primitive 字面量算术在正常完成时只产生 number/integer，
  因此可标为 root-irrelevant；它是否可能报错、是否可移动或删除，仍必须另行满足
  `HirExprSafety::is_discard_safe` 或具体事务的事件证明。
- 已物化 call-result local 的观察保护按自身读写事件逆序计算。相邻事件之间的后续读取状态
  不变，观察位置索引回答该窗口是否需保留 root，不在每个观察点遍历全部活动 local。
  直属覆盖先消费新值后缀，再处理覆盖语句对旧值的观察；嵌套写只改变后续读取状态。
  同语句读写按读优先，显式 GC fence 不受后续读取抵消，repeat 尾条件仍使用普通观察规则。
- debug binding、capture mode、PhysicalRoot、close/TBC epoch 与 closure identity 是生命周期事实，
  不能仅因表达式相同或 use-count 为一而删除。
  temp-inline 在进入递归改写前冻结引用捕获身份，并用同轮只读 promotion 一次投影完整 home 集合，
  供各块与候选共享；此 may-alias 全集不替代逐语句的活动捕获槽和 close epoch 证明。
  HIR 初始降低消费 Structure 已接受的 debug binding 和 exclusive low 终点；同终点的
  源码绑定共同拥有一个闭合求值窗口，与 capture Close 区间共用词法块物化。跨普通
  if/else 和完整 while/repeat/for 的窗口复用共享图区间查询证明单入口、单出口；外层循环
  的 SCC 身份不否定其内部窗口。两端必须属于同一发射词法 owner，且仍在 frozen plan
  实际发射的 regular/header prefix，不能切入已吸收的表达式。
  定义区分源码 owner、VM 常量或不变外层根别名、独立 scratch。scratch 的每个 home
  （包括 Move 别名）必须由指令靠后且后支配 producer 的源码 owner 真正覆盖，或由
  末尾普通调用的 caller 排除上界退休；引用捕获的外层槽副本也按 scratch 处理。这个
  端点退休证书不能授权窗口内部的内联、移动或删根。初始化可先占结果槽，声明后的
  写入必须由非空原 PC 映射逐一证明仍属于同一源码 scope，不能借同槽接入新身份；
  末尾为无结果调用，caller 前缀紧接最高 owner 槽。callee 槽就是
  caller 排除上界，其 Def 或闭包内 Phi 复用逐槽退休证明，不再按值来源另行判断。
  cohort、常量和稳定外层持有者的别名无需独立退休；scratch 通过某个 home 的检查后，
  其后续 MOVE 仍须证明新 home 退休。callee/self 的活动调用帧保活与 caller 排除域分开解释。
  内层 binding 必须在覆盖 owner 前结束，或在调用排除的高槽上于窗口末端前结束。
  已接受的 Def/Phi debug binding 共同构成 cohort。Dataflow 的 phi 邻接闭包证明全部
  输入和使用留在窗口内；同槽输入闭包属于该 Phi 声明，不能连带认领异槽 COPY 源根。
  独立 scratch 仍单独证明 home 退休：Phi 自身不是写，只有全部直接同槽 Def 输入均晚于
  scratch 且合流块后支配其 producer 时，才可使用实际覆盖证书；嵌套 Phi/Entry 不提供
  此写下界。每个 Phi 邻接表在窗口内只扫描一次，不逐定义重建传递闭包。
  外层低槽 phi 不属于此次窗口绑定。for 指令身份直接取自冻结协议，普通 preheader
  前缀属于外围发射域；for 的 control 协议内不允许放端点，while/repeat 首条件前缀按
  单独发射边界验证。原生 generic-for 保持第四返回值的
  隐式关闭时序，额外 Close 只接纳不涉及引用捕获或显式 TBC 的已归属词法边界。
  外来高槽、未结束 binding、捕获 cell、SSA 逃逸及 open/return 协议仍拒绝。
  debug end 恢复源码作用域与槽复用边界，不表示 VM 已清空旧槽；后续查找
  元方法仍可能观察旧槽。多指令协议不能被区间边界切开，交叉区间不物化，嵌套与相邻
  区间按原顺序发射。
  原 numeric-for header 复用低槽时，Bindings 可恢复入口直线声明帧；header 首求值点
  由同一个固定 Def 依赖查询从原 init 求得，不能用 FORPREP 本身替代。参数之后的首次
  声明按原槽连续发布，同窗口的后续写保持各原 Def 身份且无高槽使用/Phi逃逸、捕获或
  open/CALL；低槽前缀限参数及单写常量。完整声明组和不交叉词法末端一起发布，
  PhysicalFramePrefix 保留真实 false/nil 占位；不插入提前清根，header 的查找、CALL
  和 for 协议仍在原槽执行各自的观察/覆盖。额外 alias 单独占槽，原 nil 继续写该 alias。
  紧邻 SETTABLE 的匿名 upvalue base 仅在当前 freereg 且唯一 base 用途时交回原
  access/temp-inline owner，不把求值临时值冒充后续同槽 alias 的声明。
  copy-root holder 先完整发布已有身份，新帧候选再按绑定冲突整体拒绝，不能在声明与
  读取映射之间交错覆盖。跨块旧窗口或未知外层前缀不由此入口猜测。
  已在窗口外声明并持续可见的源码 binding 可在窗口内更新；末次调用后的纯尾部也只允许
  更新这些外层身份，不再创建内部 scratch。观察端点按有序 cohort 共用一次前缀扫描。
  plan-body 的私有发射结果携带 scope 身份和稀疏语句间隙边界，
  Sequence 拼接保留未闭合端点，嵌入分支臂、循环体或最终 HIR 前统一物化并拒绝悬空、
  交叉边界；无语句的边界也不能丢弃。AST 只消费已有词法块。
- `HirProto::inline_dispositions` 是 HIR 向 AST 发布的 typed rewrite authority。当前第一阶段
  按最终 `TempId` / `LocalId` 聚合已证明的负向 `Preserve`，并在 temp -> local promotion 时取
  原因并集；同一 canonical temp 可对应多个 definition epoch，因此这种负向聚合可以保守，
  正向可删除证书则不能只绑定 TempId。`Unknown` 明确表示正向证明尚未迁移，不等于 HIR 已
  允许删除。reason 不携带 `HomeSlotKey`、raw register 或 CFG 节点，AST 只能消费结论，不能
  用它重跑前层证明。某个 HIR owner 因证明范围不足而拒绝候选仍是 `Unknown`，不能把
  “本事务未证明”升级成“所有后续源码改写都非法”；例如 open-return 的 fixed alias 可由
  AST 依据 Lua 从左到右的 return 求值重新证明，而引用捕获后重写同一 home 才构成
  `CapturedValueEpoch`。新增 disposition 本身也属于 pass 变化，必须让依赖 binding/temp/capture
  的消费者在 fixed point 中重审。
  `PhysicalRoot` 本身不是绝对 `Preserve`：某个原子事务可能把同一 root 精确交给稳定 source、
  callee 或其它 owner。是否完成 handoff 必须绑定具体候选证明，不能在 finalizer 中把全部
  `physical_root_*` 一刀切成 binding 级禁止改写。`BooleanValueContext` 保留原计算值进入
  条件、逻辑选择或比较前的存储边界：`v=not not f(); if v` 不能只凭 Boolean 结果无资源
  就改成 `if f()`。copy 的使用关系逆向追到原 producer，不用最终 copy 替代旧 home 覆盖。
  相邻调用融合消费独立的精确覆盖终点；是否曾选择额外保活，不改变终点证明的有效性。
  lookup 结果与布尔比较也可消费同一相邻事务：`value=owner[1]; flag=value~=nil`
  只有原 source/target 都在该精确 endpoint 的 trusted home、source 单次使用且没有
  debug/capture 阻挡时，才合并为保留值语境的 `flag=owner[1]~=nil`。候选仅覆盖直接
  root 与字面量或原 trusted 低槽直接 binding 的比较及外层 NOT；低槽读取不增加 scratch
  准备写，原根仍到同槽 Boolean 结果写回才退休。表达式形状本身不是删除许可。异槽 flag 必须保留
  原 value 根，嵌套 GETTABLE 也不能借最终同 home 推断每个中间槽已覆盖。
- 正向 certificate 即使加入，也只证明某个具体 definition/transaction 已满足 VM/HIR 前提，
  不能替 AST 决定候选 Lua 源码是否合法。会删除、移动或重排 definition 的事务，必须在 HIR
  fixed point 收敛后绑定最终 definition occurrence；不得把许可聚合到整个 `TempId` / `LocalId`，
  因为同一物理 home 可先后承载多个 definition epoch。只改变单一结构边界的事务可以由 owner
  节点承载 endpoint-specific binding facts：当前 `HirRepeat::lifetime` 仅证明“这个 repeat 的
  condition 前可结束哪些直属 binding 的 VM/HIR root”，不能拿去授权另一个 repeat、initializer
  移动或任意 assignment 删除。AST 仍需匹配实际候选 suffix，并证明目标语法的求值顺序、值宽、
  作用域和 target capability；负向 `Preserve` 可保守取并集，正向许可不可扩散到证书事务之外。
- `HirInitializerMergeTransactionId` 是当前最窄的一类正向证书：`locals` 仅在整组新分配的
  PhysicalRoot owner 与唯一 exact-width multi-result call 逐项对应时，把同一 opaque token 写到
  紧邻的空 `HirLocalDecl` 和 `HirAssign`。若任一 home 已复用旧 root owner、只匹配部分 target、
  RHS 不是唯一 exact call 或后续 HIR rewrite 改变 endpoint，均不得发布或保留 token。token 的
  `proto + ordinal` 只标识这次语句事务，不是 `LocalId` 的通用 rewrite authority。
  HIR 完整帧恢复可消费这一相邻 pair：原 CALL 的固定结果区必须逐项对应新 bindings，
  callee/参数准备和源码前缀一起核对，再把整组目标原子改成一个 initialized LocalDecl。
  不能先保留空声明抬高调用准备区，再指望 AST 在 `PhysicalFramePrefix` 保护之后缩短它。
  删除旧 producer 后的额外 `LocalRootRelease` 同时退休，未定义读取仍使整个事务拒绝。
- `HirInlineDispositions` 的只读查询借用当前结论；promotion 直接合并来源原因。
  AST lowering 在 `AstRewriteAuthority::Hir` 中显式复制独立快照，不把 HIR 查询时的
  临时副本当作新的事实来源。
- HIR 内部后续 owner 同样不得洗掉 `Preserve`。generic-for/branch-value 这类会删除 producer
  的 pass 在提交具体候选前检查其 target/guard；temp -> local promotion 保留原写入并把原因
  并入 survivor。carried-local 将 disposition 投影为独立的 transaction protection，只拒绝
  rewrite map 触及受保护 binding 的候选，不把它混入 outer-scope 可见性，也不因 proto 内
  另一个无关 binding 被保护而停用整个 pass。
- 原始 home 在值的最后一次表达式读取后是否仍跨过用户代码/GC 事件，也属于 HIR 生命周期
  事实：low CFG 证明 home 区间，HIR 按目标方言的求值顺序区分 operand 临时 handoff 与仍需
  独立保留的 root，并将后者显式物化为 PhysicalRoot；AST 不从最终表达式形状反猜寄存器存活。
  同一语句快照上的 call/lookup 配对共享 `RootLifetimeFacts` 的读写、参数交接与 GC fence
  索引。locals 和 temp-inline 在递归入口通过 `RootEventIndex` 一次冻结语句事件：
  共享 HIR 词法树发布先序语句身份、子树区间与最近 loop owner 的转移归属，Promotion
  提供 home；temp 读写、参数交接及 callee 由 HIR header 同次遍历收集。未改写子块按原
  语句位置、直属子块位置传递子域，前缀查询同时裁剪读写及唯一来源的证明域；不保存
  每个嵌套节点的后代集合。先序位置只索引事件，活读仍按直属语句坐标比较，包含同条
  语句的读写时读取优先；重复写入或参数 token 不能合并为一次唯一来源。
  读取、交接与失效查询选择较小的事件域或当前身份域。只为已绑定 alias 调度下一读写
  语句边界，移除或重新绑定撤销旧调度；Call 消费读取后状态，Lookup 消费读取前状态。
  GC fence 的 callee 位置共享，collectgarbage 别名仍按当前块的直属赋值环境解析。
  实际 HIR 改写后建立新索引，与共享子域使用相同查询，不能把旧语句坐标沿用到新布局。
  最终 lifetime 仍依赖当前映射、捕获与保护资格，不从初始树预计算。
  locals 的声明与别名组查询使用完整 block 域，包含 label 后缀；touch 合并逻辑读写，
  惰性枚举去重后的直属位置，不重建每条语句的完整引用集合。子块外部保护查询当前原
  语句的严格前缀与后缀，即使前缀语句已被本轮删除或替换，也不缩小原快照的保护域。
  控制头专用消费要求 header 存在读取、body 完全没有该组的逻辑读写；先序索引不改变
  repeat 正文先于条件执行的语义。
  分支覆盖与 copy handoff 直接查询同一事件域的物理 home 写入、未知 home 和边界，

    原 CALL 结果紧邻流向异 home 的已交接参数 COPY 时，普通内联保留两次定义；完整帧
    才能分别恢复结果槽与 receiver/参数副本。低槽结果 MOVE 属于同一个赋值事务，而流向
    更高参数槽的 COPY 不阻断已完成的低槽结果初始化，不能混成一种“下一条是 COPY”规则。
    同一基本块内的低槽初始化、callee COPY、单结果 CALL 与低槽写回，由原调用事实保存
    两端 canonical 定义。普通相邻/批量内联不单独删除两端 COPY，完整调用事务消费后才
    撤销临时绑定，避免先丢失低槽声明前缀，再让后层逐轮新增 callee/结果临时变量。
    已物化的匿名 callee 与同槽单结果 CALL 可复用身份，原开放引用、旧版本需求和 debug
    身份仍须逐项满足。完整帧使用本次 CALL 的 callee/参数/结果 Def 核对写集合，不能把
    同一 LocalId 未来版本的隐藏写反向归到当前调用；身份复用本身不授权删除准备事件。
    CALL 结果的独立副本即使未被选为额外 root，也可能因逻辑读取而物化；已配对的原结束写
    若后续存在显式 GC，必须独立保留。一般潜在元方法观察继续消费原有 observed/root 证明。
    参数交接只撤销观察代表与新增 caller 根选择，仍保留已物化 owner 到下一精确固定覆写的
    责任。已交接 home 不再证明原值仍在槽中；后续 COPY 必须建立新的物理值生命周期。
    同基本块已有原 Def 的转发源值与需要入口 nil holder 的 copy 根分开登记；两者都保留
    结束写，前者不再伪造一次入口定义，否则会阻止完整多返回值组获得统一物化 owner。
    帧恢复不能以缺少 PhysicalRoot 标签跳过普通 local；普通参数表同样可能在 caller 多保活。
    多结果 RETURN 共用帧 builder 和声明前缀事务，原结果区的 COPY 由返回语法在同槽
    重发；固定结果至少两个，或开放结果含固定前缀。单固定结果可能直接读取已有槽，不能借此
    删除准备写。待完成 cleanup、开放引用捕获、宽度或事件不匹配时保留原副本，不把 frame
    退出当作此前残值已不可观察的证明。Luau 可直接返回连续的已有 local，候选若因此跳过原
    高槽准备区 COPY 则拒绝；不能把 PUC 的多值暂存区规则直接套用于 Luau。
    单 CALL 结果紧邻被同 home 的 nil/Boolean/数值常量覆盖时，完整帧可保留调用并丢弃结果，
    原子把随后覆盖改成声明。只接受原固定单结果、匿名未捕获目标与无间隔观察的完整 pair，
    保持 callee/参数准备、原覆盖及后缀身份；字符串分配或其它 RHS 不借此得到无观察许可。
  `return outer(inner(value))` 中 inner 被调用后，outer 仍可观察其原低槽根；最终 return
  的 frame 退出不能提前为内层调用结果的生成时点。值身份仍由各自 root collector 持有。

### Lua 5.5 `global` 初始化

- initialized-global matcher 只能 claim 完整协议：多结果 call 必须同时认领 RHS producer 和
  全部 target item；标量声明 run 必须完整认领每组 `GETTABLE` / `ERRNNIL` / `SETTABLE`，
  并保留此前已经物化的 RHS carrier。未证明完整协议时不得生成部分声明。
- 协议分析集中持有载荷，并冻结每条指令的协议归属；owner 与词法边界查询共用这份
  非重叠覆盖事实。语句 lowering 不再扫描指令重建协议区间，且不能让词法边界切开协议。
- 一旦恢复为 `HirGlobalDecl`，owner 必须保留 source-order names 和完整
  `HirValuePack`：RHS 先整体求值，target item 按 bytecode 顺序（source target 逆序）
  probe/store，输出恢复为单个多目标声明。每个 result slot 只保持到其最后一次物理
  使用或覆盖，不能通过物化额外 local 延长 GC root 生命周期。
- 单结果 call 使用 fixed `HirValuePack`，多结果 call 才使用 exact tail；AST build 只消费
  typed `HirGlobalDecl`，不再从 `LocalDecl + ErrNil + Assign` 相邻形状反推协议。
- 协议匹配使用 `LuaString` 保留 VM 常量中的原始 global 字节身份，不调用 AST 的
  identifier 规则，也不用 lossy decode 文本作 identity；名字能否作为
  请求方言的声明标识符属于 AST 合法性验证，不能反向决定 HIR 是否承认完整协议。
- `ERRNNIL` 只证明 initialized-global 的 target 协议，不携带源码 global attribute；
  HIR 和 AST 不得据此伪造 `<const>`。

## Simplify 调度

`value_facts` 将当前 HIR 投影到与 AST 共用的 `value_semantics/results::LuaValueFacts`。
共享有限集合描述表达式正常完成后的单值结果：nil、false、true、普通
number/integer、锚定 string、其它锚定常量与动态资源。truthiness、boolean 和 GC 惰性
与 non-nil 都是该集合的投影，不能在消费者内部重新枚举表达式种类。表构造器的数组
空洞查询也消费该域，字段移动、模板容量和原始批次仍使用各自的独立证明。and/or 根据左值的真假部分
选择结果；Decision 按显式 DAG 边合流，CurrentValue 引用当前 test 的结果并按出口
筛选。比如 `unknown and false` 可能返回 nil，不能签发布尔身份；全数值分支的算术
正常结果仍是数值，但不能因此删除其中的调用或错误。
Decision 校验同时发布借用当前快照的拓扑顺序、入度与共享节点事实。稠密 id 对应 arena 下标，
消费者不按 id 线性搜索；值域按逆拓扑求值，payload 按正拓扑传播可达边，表达式折叠直接
消费已验证事实。无环图只有 entry 一个零入度源即证明全图入口可达，无需重复 DFS。
归约也按逆拓扑处理共享 tail；arena 的稠密重编号不能作为父子处理顺序的证明。
串联短路子图优先通过唯一 child 入边及相同 continuation 归约为 and/or，直接移动
test，不复制共享尾或在 AST 重建。CurrentValue 保留所选路径最后一次 test 的实际值，
调用的条件执行、次数与顺序由连边归约证明；原始 home 的存活仍由物理根事实单独约束。
纯稳定 test 的布尔终端可先对齐极性；只有共享值域已证明 test 返回 Boolean，才能将
相应 true/false 叶替换为 CurrentValue，不能用 truthiness 代替值身份。归约后的剩余
线性值链直接移动节点生成表达式，不从原共享 DAG 重新复制 memo 子树。
`HirDecisionTestSource` 由 subject lowering 区分原操作数 Value 与比较/If 极性 Predicate，
合流替换及混合组合保守保留 Predicate。来源与 Boolean 值域是两项独立事实：原 Value
的 Boolean test 才可严格增加外层 NOT 翻边，内部值运算仍保留；带 CurrentValue 出口时
不能把所返回的值一并取反。共同 Expr 终端与共同 Node 均先尝试图归约，避免将原值运算
放入 If 谓词后丢失原 Boolean 覆盖。一般未归约的共享 DAG 不因此获得线性物化证明。
首次 value-decision lowering 还可用原节点对应的 CALL Def、唯一测试 use 与 promotion 的
同 home 完整覆盖前沿，证明此未知值在首个观察前已结束根生命周期。图归约当场消费该
query 才能翻转此 test；组合后不继承单节点许可，失败也不向后续 pass 发布许可。
跨多个块的覆盖直接消费 `ValueDecisionPlan.call_root_frontiers`，绑定原 Def 与结果 home，
不在 HIR 重扫控制路径，也不为布尔许可枚举共享端点集合。
残余 Decision 写入现存 local/upvalue 时，测试阶段不触碰目标，选中终端值后才提交一次
赋值；终端自身的嵌套 Decision 继续遵守同一规则。因此条件赋值可直接保留原物理 owner，
无需先创建 carrier 再让 AST 猜测能否写回。逻辑值的逐步物化仍用独立 carrier，避免在
后续 RHS 观察点之前覆盖旧 root 或 capture cell。
纯逻辑因子候选只为共享首项或末项的分支建立索引，AND 子项每条只展开一次；配对流
保持原 left/right 顺序，不建立平方大小的候选集合。指纹只用于过滤，原子身份消费共享
`AtomKey`，最终仍核对完整表达式与符号值等价；碰撞不签发许可，正负零按结构比较规则
归一化。索引占用线性空间，但实际匹配候选及其验证成本仍由表达式决定。
动态查找本条的观察发生在目标槽写入之前，因此不能仅凭后继有一次写入或 CALL 签证书。
子图投影复用已验证快照，在 BFS 首次入队时签发稠密新身份；同一映射兼作访问状态，
重写边直接消费该映射。归约保留原 test，先计算两条候选边，仅在节点保留时提交边更新。

目标 VM 的字面量比较与调用者已证明稳定的路径假设通过同一 evaluator 的 resolver
输入。结果事实不会携带跨调用的 binding 稳定性许可，也不替代求值事件或 Promotion
物理根证明。表构造器、布尔化简及生命周期分析共同消费此域；动态算术/bitwise 的元方法
结果和未锚定 concat 字符串不得当成常量根。

构造器提交须区分原始 raw SETLIST 批次与逐项字段写入。空 local seed 后的一次完整
数组批次（固定前缀及可选 open tail），若 producer 事件序已由 rebuild 验证、无保留声明、无 debug/capture
观察者且直接返回该表，可保持同一批次的 nil-hole 形状；函数存在 cleanup 时不签发此
出口根证明。该路径同时保留 allocation 点和操作数求值顺序，不能推广到跨后续调用、
字段清除或多批次覆盖的 producer 生命周期。
同次 binding 遍历还区分直接写 base、单值 return 与普通值观察：无 cleanup、源码身份或
提前观察的私有 owner，可以吸收仅含 GC 惰性内容的新建子表根；资源内容或 RHS 中的
owner 读取仍拒绝此许可。它不放宽分配容量和事件顺序，也不替代一般强字段持有证明。
`object_flow/fields` 为函数直线前缀提供正向窗口：确定字段保存精确键、标量值域及
fresh allocation 身份，普通嵌套读取不再被误判为暴露整个容器；任何逃逸或未知资源存入都
记录首次可观察位置，字段清除不能撤回历史。direct may-containment 边只反向传播拒绝，
不能据此证明强持有；晚建边从当前store起传播，不回溯到子对象更早的可观察位置。
完整函数的窗口默认到函数出口；原 Temp allocation 消费 RootLifetimeFacts 在同 trusted
home 的唯一覆盖终点，已物化 local 消费 HIR 中显式保留的同 binding 覆写，包括该语句
RHS 事件。控制流之前的前缀只为已结束窗口签发许可，不把前缀末尾当作函数出口。只有
实际被完整构造事务吸收的 producer 才使用此窗口缩短根，未吸收的 owner 保留其终点。
只有多个独立 seed 需要合并时才建立私有字段分析，单 seed 数组直接走普通批次恢复。
捕获及 upvalue 的已知键由观察 epoch 惰性失效，构造器求值中出现观察事件也不能使用末尾
binding 状态重建早先字段快照。引用cell即使先以nil公开，后来安装的对象也须发布，不能
把新alias误判为私有。GC常量锚点不证明cdata比较无元方法。
构造器按子 seed 到父 seed 消费成功区域，再物化残余 SETLIST；重写后的 occurrence 摘要
同步更新，避免先丢失批次身份再尝试重建。确定覆盖后的新值读取不计入旧私有 producer 的
使用，但原 local 身份和声明位置仍保留，只移走已证明私有 initializer。运行时常量 operand
在最终存活 seed 上统一物化，不引入父 initializer 尚不可见的子 region local。
同一local的再次建表赋值还须消费原stmt的旧值证明：旧值为确定惰性值或在完整窗口中
从未可观察的allocation，才可把这次initializer纳入父区域；许可不扩为binding级通用覆盖。
固定单元素 SETLIST 的 root-copy 前缀可留在构造器之后，前提是原预分配容量精确匹配、
源仅为稳定引用且两个目标独立；只交换无事件 copy 与 raw 写，显式根赋值和释放仍保留。

构造器 scanner 的 `ConstructorRegion` 保留成功前缀的 typed steps：producer binding、
显式值或缺失槽 nil 投影、字段 key/value 与 SETLIST 引用。rebuild 直接消费这些事实，
失败后缀不会进入提交计划；`RegionRootFacts` 在一遍步骤访问中汇总删除根、精确宽度、
后续写入和强字段持有，commit 不重新识别原语句角色。步骤只借用当前不可变 HIR，
安装构造器或删除原语句前借用结束；不作为跨 pass 持久身份。
scanner 的后缀读屏障消费同次预处理的 `StmtBindingSummary`，保留变量只维护身份集合，
不按变量重新遍历字段表达式。声明前缀的逐槽 nil 查询在每个候选内按需共享一次，
遇到可调用 initializer 时停止向前传播；赋值的 capture cell 与物理根交接仍保留原位。

`analyze/exprs/tables` 统一语句与单次定义的 NewTable lowering：模板常量进入字段，
nil 数组槽和 nil 值 hash 项保留，`HirTableConstructor::allocation` 记录 PUC 批次预分配、
索引预分配或模板复制及其容量与原始 hash 键集合。在 Decision 消除、内联和 builder 重建中保留该事实，
AST 不重建 TNEW/TDUP 协议。Luau 模板由 lowering 标记隐式预置零值的
`implicit_template_fields` 位置，与真正模板常量和原显式 SETTABLE 保持不同角色。
完整构造器候选仅跨无事件的初始常量/字面量写，把原运行写填回对应隐式位置；其它
实际写保持相对顺序，完整字段仍须满足 DUPTABLE 裸名字段上限。原模板前缀位置不删除，
未消费角色的索引因此保持稳定；每个角色仅消费一次，混合模板的真正常量字段不会被删除。
字段重建和互斥来源合并保留这项状态，不能按值为 0 重新猜测模板角色。索引预分配的数组与 hash 容量须由完整字段形状复现；
`Indexed` 和 `PucBatched` 容量不匹配时不能转用普通数组的 non-nil 证明，初始化全部非 nil 也不能
消除后来清空字段时的扩容差异；保持原分步写入，由同一个构造器事务拒绝融合。
模板数组容量按编译器序列化保留的最后非 nil 常量核对，不能套用 TNEW 最小容量。
PUC 的候选数组/hash 容量由共享分配查询核对，open tail 不计入固定预分配槽数；
数字 record 保留原 hash 字段角色，原 SETLIST 的批次与写入顺序另证。scanner 复用
producer 的最后使用位置：同一 owner 的原批次尚未消费它时，延后提交 record 前缀，
避免把待消费声明提前冻结在区间外；容量和根证明仍对完整事务核对。
`batched_capacity_matches` 由 HIR 构造器与 AST 字段扩展共用；AST 只统计候选字段，
在完整追加批次提交前检查一次。不能因 HIR 保留了独立函数字段写入，就由后层忽略
原 hash 容量重新吸收它；参数构造器事务只核对实际扩展过的候选，失败时整体回滚。
编译器生成的共享 capture 数组盒使用 `Synthetic`，不冒充任何原始 VM 分配。
`Luau` 直接保留 NEWTABLE 的精确容量。共享 `matches_luau` 查询消费候选字段投影，
统一显式数字键优化及尾调用/vararg 计槽差异；模板复制由独立的原键身份约束。字段命名规则由
共享方言定义持有，HIR 不反向调用 AST。空表的后续写入预测不在表达式查询里重建；
builder 在已完成事务超过原容量上界时回滚该扩展，scanner 保留此前完整前缀，
最终提交再核对精确布局，不能整段拒绝后把容量不同的空表当作等价结果。
纯 hash `Luau` 分配通过 `permits_named_record_keys` 禁止把 bracket 字段改成裸名字：
这项语法变化会触发显式数字键的数组预分配或 DUPTABLE。HIR 候选计数、AST lowering、
字段 sugar 及新增函数字段都消费原分配的同一许可，不在后层猜原字段拼写。
`LuauTemplate` 则直接降低前层的有序初始项，并保留原始键身份；动态项的数值 0 占位
也进入初值，不能误作 nil 或丢掉键。`permits_record_key` 约束后续融合的键：新键会改变
模板预分配、插入历史和 `pairs` 顺序，必须保留为独立写入。HIR scanner 在新键处结束
成功前缀，AST 追加函数字段或嵌套表时逐项消费同一查询，只投影字段名，不重建布局。
整数 record 晋升还必须保持原求值/写入顺序。open tail 的起点一经核对，后续 builder
不得再晋升 record 扩大固定前缀；`{"head", [2]="old", many()}` 的覆盖起点始终是 2。
builder 的整数键索引记录首次字段位置；pending 搬移和数组降级不改变已出现键集合，
回滚按原字段边界恢复。数字身份消费共享整数键查询，不按每次晋升重扫已有字段。
未知键写入以最近字段位置一次遮蔽此前的 pending，显式同键写入保留逐键位置；
晋升时合并这两种事实，事务回滚同时恢复未知键位置，不逐次扫描所有待定字段。

分配方式同时约束常量内联：LuaJIT 的 `{a,x,c}` 若把运行时 `x` 替换成 `true`，
编译器会改用模板，序列化裁掉尾部 nil 槽后可能改变 `#table`。`table_layout` 消费
原始分配事实，temp-inline 为必要操作数发布 `TableInitialization` 保留身份；构造区域
提交若吸收了已折叠的常量，则给字面量叶子建立受保护的 local，运算和错误仍留在原字段
求值位置。若合并需要新建字段名 local，保留原字段赋值，避免为融合增加机械声明。
AST 字段扩展也按同一初始化约束核对完整候选，不能越过 HIR 保留的模板边界。
嵌套构造器逐个遵守自己的分配事实，不能借用外层模板的许可。新增 local、
debug 空槽与 inline disposition 在同一次提交中登记。原始分配方式继续传入 AST，
不由后层通过源码形状猜测。无数组预分配的 Indexed 表不适用数组裁尾约束；已有
Template 即使初始数组为空，也必须防止后续常量字段扩大其序列化数组。

模板的 `array_slots` 原样保留包含索引 0 的槽数，不能把零槽与仅含索引 0 的分配都压成
正整数容量 0；数组恢复需要正整数容量时再投影。模板 hash 键由 Transformer 常量身份直接降低成 `HirTableTemplateKey`，包含 nil marker
占位键；数字按 LuaJIT binary64 规范化零，字符串保留原始字节。不可变键成员索引随 allocation
共享，成员查询为 O(log k)，字段求值顺序仍保留在 fields；后层不重建或重排模板键。
序列化 hash 容量由原键数量确定，不再
保存可重复计算的模板 hash-bits。共享初始化约束同时限制原数组范围和新模板键：
`local x=true; {true,[5]=x}` 的稀疏写入若成为新模板项，会提前改变 hash 压力及后续
array 扩容时机，即使 5 超出源码数组字段数也不能忽略。原模板已有键继续消费原身份，
不新增运行时操作数；其它写入保持运行时 key 或 value。AST 只适配候选键语法，不回读常量池。

`value_semantics/table` 统一原分配的初始化约束、候选字段所需的运行时 key/value 操作数，
以及候选模板的精确数组容量查询。HIR builder、temp-inline、构造器提交和 AST 内联
只适配当前字段与数组下标，不各自分类常量或重新推算原容量。已有模板的容量是上界，
例如 `local x=true; {true,a,x}` 的 x 不得成为扩大模板的第 3 个常量槽。精确容量查询
保留静态重复写的最后结果，动态写不清除模板初值，未知比较结果不签发精确容量。
这个保守语法分类包含后续可折叠的比较和短路选择，不是正常结果的抽象值域，亦不证明
运算不会出错或授权移动资源。回归必须比较重新编译后的 chunk；仅执行生成源码会漏掉
模板序列化裁尾差异。测试源码可用官方 `string.dump/loadstring` 将被测函数序列化，
使源码/chunk 基线一致并覆盖已有模板的裁尾行为。

Template 的 nil 数组槽可以在完整候选中由对应运行时字段填回。builder 用单调字段终点
证明填充只跨过字面量；逆序填充、跨过其它 record、调用、分配或 binding 读取都不能
改变事件顺序。该投影不改变数组计数或开放尾包起点，仍须通过原模板容量与根生命周期
检查。Luau 的完整容量查询复用同一字段/开放尾包布局规则，不能在检查成功后再用只含
fixed 字段数的近似否定结果。

原 SETLIST 若紧接源码局部变量的 debug 区间入口，lowering 将 Structure 接受的
同一 SSA 对应 scope 身份保存在 `HirTableSetList::initializer_debug_scope`。构造器只
能为匹配该 scope、具有可信原分配身份且无 capture 观察者的 owner 恢复 initializer；
它不许可提前提交尚未完成的多批次 initializer 或吸收进入作用域后的普通表写，也不替代
producer 根、求值顺序及容量证明。
显式 root release 和纯 copy 可以保留在已完成的预分配初始化之后，但 release 不得
清空被读取的 source 或 owner；分配位置、release 与 copy 本身均保留。

table-constructors 与 temp-inline 在 Normal 阶段共同收敛，并依赖 TempChain 失效标签。
locals 声明 table-constructors 为前置 owner：后者执行后若又有输入变化，调度器必须在
locals 合并身份前刷新它，其它 pass 保持原阶段和执行顺序。
raw 调用结果 TempId 由 Promotion 提供 home 身份，提交时还需生命周期证明：可复用
最后读取后、首次观察前精确覆盖的事实，或由 `table_constructors/roots` 证明完整区域内
每个被删除的结果均直接进入互不覆盖的强字段，且无 cleanup、无保留 producer、无
debug/capture 观察者并立即返回表。后者同时检查初始字段 GC 惰性、开放批次不覆盖
先前字段及完整求值事件序。入口 temp seed 还需入口 nil 覆盖证明。只恢复字段前缀
不能删除这些 producer，也不能让 locals 先合并其不同值身份，再逆向重建版本。
原始 SETLIST 已被消费时，入口 nil seed 的参数根交接证明仍然有效；完整且单次交给
当前调用的 constructor 应继续保留 TempId 供 temp-inline 消费，不能因 residual 节点
消失而新增一个跨调用存活的 local root。

HIR 与 AST 共用 `src/scheduler.rs::run_invalidation_loop`。每个 pass 声明 phase、依赖与可能产生的
`HirInvalidation`；Normal 收敛后运行 Deferred，Deferred 若产生新 invalidation 会重新触发 Normal。
consumer 可要求同阶段、更早的 owner 按声明顺序刷新，依赖可逐级传递。HIR 的 locals
先刷新构造器，再刷新内联，消费已经消除的分配及其失效屏障。前置改写再次暴露的形状
留给后续正常轮次；不要求依赖 locals 身份才能收敛的前置 pass 先独自达到固定点。
预算耗尽是内部收敛错误，不能静默返回半收敛结果。

`object_flow` 统一解释 binding 的当前值、aggregate 持有关系、未知 collectable 值与逃逸。
持有边以 allocation-site identity 保存并做传递闭包，不随某个 holder binding 的覆盖丢失；
写入已证明未逃逸的 plain table 只添加持有边，外部存储、调用及潜在元方法再使可达对象逃逸。
原始槽及 close epoch 仍归 Promotion，不能用对象身份替代 home 身份。site key 只在当前不可变
HIR 分析内有效，任何结构改写后均重新计算，不作为跨 pass 的持久身份。

构造器与 repeat finalizer 由 simplify 入口统一取得 `ModuleEffects`，经 `RootAnalysisContext`
传递。快照区分两个证明域：`ProtoEffects` 的写入、逃逸、返回来源与调用是 may-capture
效果；`ReturnValueFacts` 则发布完整已知 callee 的正常返回值。may-holder/closure 集合非空或
只有一个成员，不代表实际 callee 必然是它。消费者不得从 capture 清单重造效果，也不得把
缺少 child 摘要解释为无效果。任一 pass 报告改写后快照失效，下一次消费时重建；连续未改写
HIR 的 pass 共享同一份摘要。`closure-effects` timing 只记录实际构建。

模块入口统一按 child-first 调度两域；每个被消费的 proto 只构建一次 CFG、直接活跃值
和捕获索引。`ProtoFlowFacts` 借用当前不可变 HIR，供两次独立求解使用后立即释放；
只有求解结果进入模块快照。两个消费者不能各自重建相同 topology 或重新收集捕获身份。

capture 域只收集会被 lexical child 身份消费的效果，无 upvalue 且无 child 的叶函数效果
确定为空；正常返回域仍须分析这种叶函数，例如 `return 1, "text"`。capture 域缺失 binding
与空来源集合均为 bottom，覆盖空值删除旧来源。正常值域缺失 binding 则为 UNKNOWN；赋值
按当前 epoch 替换，合流保留所有路径都成立的 callee 身份，未知分支不能被已知子集覆盖。
引用捕获及 upvalue 在可能执行用户代码的观察点失效；普通调用先快照 callee 再求参数，
`f(change_f())` 不能重新读取被参数回调改写的 f。FASTCALL 使用前层已发布的参数先于
fallback callee setup 顺序。未证明的捕获返回、递归与合成调用保持未知。

正常返回摘要以稀疏结果槽、最小/最大返回数量及未知尾保存 `LuaValueFacts`。实际缺槽与
显式 nil 在 Lua 的目标宽度调整前分开：空返回的数量是 0，单值调用得到 nil；`return 1, object`
的第二槽不能套用首槽的 GC-inert 事实。`call_result` 查询调用的第 n 槽，`pack_slot` 消费
固定前缀、exact/open 尾及其 offset，超出精确宽度时补 nil。字符串和其它锚定常量还携带
proto 锚点要求；只有当前执行 proto 的词法子树仍持有 callee 常量时才发布栈根无关结论，
不能将逃逸 factory 返回的常量无条件视为永久锚定。结果 GC-inert 不证明调用无事件，亦不
授权移动 allocation、改变批次布局或丢弃旧 home 的覆盖终点。

`HirCallExpr::source_site` 保存 lowering 发布的 `HirSourceSite { proto, instr }`。原 CALL、
TAILCALL 与 open-pack producer 使用同一原调用身份；合成调用没有该证书。等价 clone/rebuild
保留身份，失败恢复同步重编号 proto；改变实际 callee 或参数事件语义的调用不能继承旧证明。
同一 site 的多个 occurrence 在当前快照中合流，跨 proto 的 occurrence 不继承原 caller 的
锚点许可。调用查询不使用 Box 地址：constructor 可以在一次 pass 内释放和重建表达式，外层
pass 结束后才失效不足以防止地址复用。地址只用于单次不可变表达式求值的局部缓存，不作为
跨改写或跨层身份。正常返回值与 capture 效果的中间 binding/循环状态均留在共享 CFG 求解内。
两域共同消费 `HirFlowGraph::binding_live_out`：共享读取/写入 visitor 发布直接 gen/kill，
for 的写入只位于成功进入 body 的 binding 边。正常值域先记录返回包与 callee 副产物，
再在分支状态复制前投影掉已无后续读取的 binding。may-effect 域只投影当前 binding 的
origins/closures/call_targets，引用捕获的 cell 仍保守保留，累计 escapes/returns/calls 与
iterator 独立快照不受影响。此查询只控制分析状态大小，不删除源码 binding、对象持有边或物理根。

`repeat-root-lifetimes` 在 Deferred 阶段发布 provenance；新发现的物理根身份会失效
TempChain/LocalBinding，让 locals 为没有显式读取但仍持有可观察对象的 temp 安排原词法 owner。
不能等结构改写全部结束后才发布，否则 AST 只能把残留 temp 提升到外层，延长其存活期。
身份与形状共同收敛后，AST 消费最终 repeat endpoint certificate。分析状态限定为有限
allocation-site/binding/closure-site 集合；跨 proto effect 按词法 child DAG 后序求值，proto 内
循环与 goto 由共享 CFG worklist 收敛。没有 repeat 的 module 跳过这项端点分析。

`simplify/lexical_cfg.rs` 是 HIR 控制流 topology 的单一 owner：owner-wide `HirFlowGraph` 统一
解释控制结构，并保留未解析 goto 的 source/target 身份。`LexicalCfg` 的直属语句后继、外部
出口与支配查询只投影该图的可达出口；嵌套循环和 goto 不再经过独立递归摘要重新建边。
无论具体 pass 需要完整节点图还是 block-local 视图，分支 truthiness、break/continue owner
和 for init/dispatch 语义都由同一个 builder 决定。`HirFlowGraph` 统一
解析 label/goto/if/loop、区分 for initializer、循环 dispatch 与每轮 binding write，并保留可达
unresolved goto；完整函数图还显式区分正常函数出口与 conservative unknown-control sink，使
TBC/closure observer 能在所有 return 与落底路径上统一结算。具体 pass 只在这些节点上实现
自己的 reads/writes、must-def 或生命周期 lattice。条件边保留 If/While/Repeat 的真假极性，
真假两路落到同一后继时合并为无约束边；条件表达式由原事件 owner 借出，消费者不反查语句。
前向求解器允许消费者按条件细化状态或排除矛盾边；排除边不参加 join，后续入边削弱 must
事实时可以重新变为可达。该接口不支持撤回已传播状态，细化与 transfer 都必须单调。
`path_conditions` 在这张图上一次求稳定 Param/Local 的 must-truthiness，仅在收敛后改写条件；
不可达尾部也消费同一次求解的事件可达性，并继续保留控制入口、源码身份和诊断约束。
参数 alias 同样消费共享图，在当前快照上一次收集每个求值事件的读取、capture、回调与
最终写入。initializer 的多个表达式保留求值顺序，generic-for dispatch 独立处理隐式调用；
12 种分叉/capture 状态用位集合合流，无出口环中的拒绝也阻止身份合并，不再按嵌套 block
重建 label 索引或递归重跑整段循环。可信物理 home、debug identity 与 PhysicalRoot 的
入口约束仍先于值流分析；精确路径等价不替代旧对象存活期证明。
它不自行维护 goto/label 不动点或为不同子树重建控制流。block-local
`LexicalCfg` 继续提供外部入口、外部出口与直属语句后继等线性 rewrite 查询。
entry-nil 裁剪在候选区域上只构建一次图：构图器按需把写入节点 ID 与原始词法路径关联，
求值/capture/callback 事实与最终覆盖分别缓存，先判断覆盖前是否已知 nil，再应用写入。
四状态位集合在共享求解器上合流；区域外引用的内部 label 以 unknown 状态注入额外入口，
这些入口也保留不动点 checkpoint，不把普通入口 nil 误用于外部到达路径。没有候选 nil 写
时不启动数据流。收敛后才按快照路径提交删除，不通过语句地址或另一棵树反查位置。
区域 label 唯一性与 owner-wide 外部引用由 `validate_region_entry` 单独验证，完整 CFG 复用同一
事实；仅检查入口的 consumer 不构造 topology。验证包含不可达分支中的词法引用，不替代
出口、可达性、支配或生命周期证明，语句区域或 label 引用变化后须重新分析。
局部变量提升复用现有 Label/Goto 边界，仅在有标签控制流时构建 `LexicalCfg` 并一次取得
整块后缀支配事实：复用共享支配树的子树区间，
汇总各声明之后可达节点的 preorder 范围，不逐声明删除节点重搜；该位置向量不跨改写复用。
owner 重入边界一次计算当前可达 SCC，再筛选两端同分量的 goto；不按每条边重新遍历图。
DFS/SCC 算法与 Structure 共享，分量身份仅属于当前 HIR 快照。

carried-local 对有实际读取、同一 exact home 的 temp 组做整图后向活跃性证明；同时存活的
不同快照或并行多写形成干扰，不能合并。无读者的 producer 保留独立死写身份，由 dead-temps
处理。debug、for、物理根、reference capture、TBC、显式 Preserve 和协议 producer 身份先从
候选域排除。物理根保护同时覆盖 TempId 与 LocalId，值已物化与否不能改变合并许可；
handoff 与整图 coalesce 共用这一身份域。事务提交时保留精确 home 并合并附加定义写，同时退役原 definition 专属的正向
事实；不能把某个原 producer 的 entry-nil、table-seed 或 root-end 证书推广到整个 carrier。
后续内联仍需证明当前消费站点的 reaching write；循环 body 会写回 carrier 时，循环前赋值
不能替换循环条件中的读取。AST 只消费已简化的 binding，不负责按名字重建同槽关系。
词法 Local 可用性沿递归共享一份集合，只记录并撤销本层首次引入的身份，不复制累积声明集。
for binding 只在子块生效，普通声明在 initializer 之后生效；子块返回以及当前块后序改写前
恢复入口集合，使后序 owner 的“声明之前可用”查询仍消费原始词法边界。
递归外层保护消费入口树的一份 mention 位置索引：语句先序区间包含其全部子块，header
只收集一次，当前语句之外的前缀和后缀分别查询，保留同一身份在多条语句中的引用。
子块仅修改自身，父 owner 在全部子块返回后才执行；未处理兄弟继续使用入口快照。
后序循环 owner 在子块未变时借用原区间，子块改变时重新索引当前块，直接查询候选身份
首次和末次出现的语句；快照仅服务本次 owner 的候选批次，不交给后续 owner 复用，
也不代表运行可达性。没有直属 while/repeat 时，该循环 owner 不收集全块事实。
result/state 交棒证明在同一未改写区域共享一份 `HirFlowGraph`，各候选只提供
`Unproduced/Pending/Synced` 关系域与事件读取验证，不另建标签表、循环回边或私有 worklist。
求解失败是吸收态，终止节点的读取失败也必须拒绝整个候选；区域正常出口与外部
break/continue/goto 分别结算，内部 transfer 由图消费。恒定分支只验证可达事件，
但入口与 Unresolved 屏障仍检查整棵区域，for binding/capture/resource 合法性仍由身份门证明。


`HirFlowGraph::solve_forward` 统一维护可达入口状态与前向 worklist。`None` 表示不可达，
首次到达直接安装状态；后续只用 consumer 的有限单调 join 合流。branch-merge 的 must-def
和 GC-inert 状态使用交集，repeat root/closure effect 使用 may 合流；consumer 只解释 typed
event，不复制传播循环。`solve_backward` 从所有入口可达节点的 bottom 开始传播，
包括没有函数出口的回环，统一维护前驱和传播状态。两个方向都只重排受变化影响的节点，
同一节点在 worklist 中至多出现一次，consumer 不复制后继表或依赖节点分配顺序扫描全图。
只读的显式求值/赋值引用通过 `HirFlowNodeKind::visit_evaluation` 进入共享 HIR visitor，
只访问当前事件的语句 header 或 repeat 尾条件，不重复进入 loop body 或 for initializer。
隐式分派、for binding 写入和未知控制边界仍由各抽象域解释，不能由语法引用代替。
布尔壳分析的旧值 GC 分类、closure/TBC observer reaching 与 binding/home liveness
消费同一份完整图。前两者前向传播，liveness 后向传播；旧值分析不再递归重建
if/loop/goto 的合流、回边或保守 island。所有状态收敛后才按 shell occurrence 统一签发
删除计划。generic-for dispatch 的 raw result 写入与成功迭代的 binding 写入分开更新，
参数入口 home 直接消费 promotion 的完整可能集合，不从 binding 编号推算。
构图时仅为两臂单赋值的 shell 发布节点与语句路径，两臂身份直接消费带极性的条件后继；
常量裁掉的臂保持空 live-out，不另建全树地址索引或递归寻找 shell。
旧值写入通过 candidate home 反向索引定位受影响 binding；同一源码 local 的直接写入
始终是确定覆盖。节点仅投影 observer reads 和候选删除判定，并行 holder 写入先解析全部 RHS。
输入、输出状态都只属于当前 HIR 图快照，不能跨 rewrite 缓存。

`simplify/stmt_plan.rs` 统一提供 entry-nil、死布尔壳与 repeat 端点证书的语句路径及后序提交。
`Stmt/Then/Else/Body` 只标识分析根节点下的同一次改写前快照；各 pass 完成语义证明后
才提交，不能把路径当作跨 rewrite 身份。分析导航复用同一路径栈，返回结果（包括错误）前
恢复父路径；只有候选索引和计划保存独立路径。回边分析重复访问原坐标，否定过的删除证明
仍由计划记录，不因路径复用丢弃历史。提交器复用路径栈、按原始下标原地压缩，
不因前项删除重解释后项坐标，也不复制待删除或保留的 HIR 子树。

前向 solver 只在入口及多前驱合流点保留完整状态用于不动点比较；单前驱链直接转交状态。
最终后继键的入边分类（0/1/多条，包含不可达来源）由图首次前向求解时冻结并复用；
仅做可达性或 SCC 查询的图不构建该表。分类随 HIR 图快照销毁，不保存任何求解器状态。
每个可达环都必经入口或合流点，因此不会丢失回边的收敛条件。transfer 返回 consumer 所需的
节点结果：需要输入快照的分析显式投影输入，对象逃逸直接发布传递后的 allocation 事实，
不保存整份节点状态再重放事件。并行赋值也先从写入前状态解析各目标值的持有、类型与 root
事实，再统一写入；无需为 `a,b=b,a` 复制与这组目标无关的完整对象图。
后向 solver 在入口、分支及合流点保留收敛状态，线性链移动状态；每个入口可达环必含入口或
多前驱节点，因此没有出口的环也能收敛。consumer 在 transfer 中只投影所需结果：布尔壳按
同一快照的 arm 节点身份保存 live-out，同槽合并只累积干涉事实，不保留全图活跃集合。
布尔壳后向活跃域复用同一候选收集结果，只保留候选 Temp/Local 及完整 possible-home。
closure holder reaching、转义及 TBC 读取先完整解析，再投影 gen 集合；域外 holder 仍可能
间接读取候选。写入继续使用精确 kill，不能把完整 possible-home 集合当作必然覆写。
旧值分类状态由分析层持有，删除判定直接借用其 local/home query；不为每个 shell 复制
整张分类表来构造另一份同形事实模型。
共享 HIR 遍历以独立 capture 边保留 mode/binding。普通 visitor 默认观察绑定引用；创建点读取
分析只观察 ByValue，ByReference 由后续 observer 读取 cell。同一表达式中的直接读取不受
capture 筛选影响，无需再次扫描 closure 再按 binding 计数相减。

| --- | --- |
| Normal | `decision`、`boolean-shells`、`logical-simplify`、`table-constructors` |
| Normal | `temp-inline`、`generic-for-iterators` |

同时要求当前参数交接端点仍匹配、没有 debug/capture/物理根物化要求。非相邻或 open 区域
不冒用该 owner 的能力；字段与原始调用协议仍由各自 owner 解释。构造器 commit 删除 producer

## 失败与输出边界

Structure 已失败的 proto 在 HIR 中成为稳定失败节点。Strict 在消费失败节点时返回 residual；
Permissive 保留失败层、最后完成产物和 child identity，交给 AST/Generate 生成明确诊断。成功
proto 的 simplify 错误仍是模块级错误，因为跨 proto promotion/capture 事实可能已参与改写。

HIR 输出必须满足：控制节点可直接映射到目标 AST 能力，binding 身份稳定，值包宽度明确，所有
仍不可表达的 carrier 都是 typed residual，而不是伪造的普通表达式。AST 入口只允许读取
`HirModule`；同一模块经公共 `lower_ast` 或主 pipeline lowering 时必须得到同一退出诊断行为。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| region、loop 或 goto 位置错误 | 先核对 StructurePlan，再查 `analyze/structure/` |
| 表达式值或多返回宽度错误 | `analyze/exprs/` 与 `HirValuePack` |
| closure/capture 身份错误 | `analyze/bindings/`、`shared_closures/` 与 `promotion.rs` |
| 机械 temp/local 未消除 | 对应 `simplify/` pass，使用 pass dump |
| cleanup 或 `<close>` 生命周期错误 | Structure cleanup disposition 与 HIR scope lowering |
| 查看最终 HIR | `unluac --debug --dump hir --stop-after hir <file>` |
| 查看 pass 变化 | `unluac --dump-pass <pass-name> <file>` |
