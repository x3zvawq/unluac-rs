# Structure

> **职责**：从 low-IR 构建控制流、图事实、数据流事实，并把这些事实翻译成源码恢复候选。
>
> **不负责**：最终 HIR 语法决策、AST 语法糖、最终命名。
>
> **例子**：`branch_edges(B3) + phi_candidates_in(B5)` → `BranchCandidate { header: B3, merge: B5, arms: [B4a, B4b] }`

## 入口

```
src/structure/mod.rs
  analyze_structure_stage(state, context)      -- 依次写回 CfgGraph / GraphFacts / DataflowFacts / StructureFacts
```

CFG、GraphFacts、Dataflow 和 StructureFacts 是 Structure 内部固定子步骤；pipeline 外层只维护 `structure` 一个 stage / dump。

## 模块布局

```
src/structure/
  mod.rs          Structure 层入口 + 类型导出
  cfg/            CFG / GraphFacts / Dataflow 构建与调试
    build.rs        CFG 切块
    graph.rs        支配 / 后支配 / 回边 / 自然循环
    dataflow/mod.rs 数据流分析与事实组装
    common/         CfgGraph / DataflowFacts / GraphFacts 等共享类型
    dataflow/
      effects.rs    指令 use/def 与副作用
      liveness.rs   固定寄存器活跃性
      ssa.rs        pruned SSA 构建、重命名与 use graph
      open.rs       open result pack 的临时 SSA
    debug.rs        CFG / GraphFacts / Dataflow dump 片段
  common.rs       结构候选类型
  analyze.rs      StructureFacts 构建骨架
  helpers.rs      region / entry / exit / predecessor / reducible 共享查询
  phi_facts.rs    phi → 结构候选翻译
  branches.rs     branch 候选识别
  branch_values.rs  branch value merge 候选识别
  loops.rs        loop 候选识别
  goto.rs         GotoRequirement 识别
  regions.rs      region block 收集
  scope.rs        ScopeCandidate 识别与 cleanup owner 消解
  short_circuit/  短路条件与值合流候选
  debug.rs        dump_structure
```

## 数据流

```
LoweredProto
  └─ cfg::build_cfg_graph
       └─ CfgGraph
          └─ cfg::analyze_graph_facts
             └─ GraphFacts
                └─ cfg::compute_dataflow_facts
                   └─ DataflowFacts
                      └─ analyze_structure_proto
                         └─ StructureFacts
```

固定寄存器只有一条 canonical SSA 管线：先基于真实 use/must-def 求活跃性，再用
iterated dominance frontier 放置 pruned phi，最后沿 dominator tree 重命名。
`SsaValue::{Entry, Def, Phi}` 是 block 边界、指令 use、branch/loop/short-circuit
候选共享的唯一值身份；`SsaRegMap` 只保存活跃寄存器，不按指令复制完整寄存器状态。
Dataflow 同时保存 `Def/Phi -> instruction/Phi use` 图，跨 phi 的逃逸查询直接遍历这张图。

open result pack 的宽度由消费点决定，不能伪装成固定寄存器 SSA。`open.rs` 在 Dataflow
内部建立独立的临时 pack SSA，合流时按实际来源解析 fixed-prefix use，最终只向公共事实
投影 `OpenUseSources { has_entry, defs }` 与 open liveness。多个 pack 来源具有不同起始
寄存器时，所有路径共有的 fixed prefix 才进入 canonical SSA use，路径条件下可能读取的
更宽 prefix 只进入 liveness；不能把 may-use 伪装成唯一 SSA use。固定寄存器 SSA 与
open pack 不维护平行的 reaching-def/value 解算器，也不保留没有生产者语义的 may-def 字段。

## 关键类型

| 类型 | 说明 |
|---|---|
| `CfgGraph` / `Cfg` / `BasicBlock` / `EdgeKind` | block、边、reachable successor 形态、唯一 predecessor 和基础控制流查询 |
| `GraphFacts` / `DominatorTree` / `NaturalLoop` | 支配、后支配、回边和自然循环 |
| `DataflowFacts` / `DefId` / `PhiId` / `InstrEffect` | def-use、phi、活跃性和副作用 |
| `StructureFacts` | 所有源码恢复候选与 canonical `StructurePlan` 的统一容器 |
| `StructurePlan` / `BlockOwner` / `EdgeOwner` / `CleanupDisposition` / `PhiIncomingDisposition` | 冲突消解后的 block/edge/cleanup/phi incoming 直接 owner；按稳定 id 查询 |
| `BranchCandidate` / `LoopCandidate` / `ShortCircuitCandidate` | HIR 消费的结构候选 |
| `GotoRequirement` / `ScopeCandidate` / `GenericPhiMaterialization` | 绑定精确 `EdgeRef` 的跳转约束，以及 scope / fallback phi 候选 |

## 维护规范

1. **图和数据流事实属于 Structure**：后层需要稳定 block/edge/dataflow 查询时，优先补到 `src/structure/cfg/common/`，不要在 HIR 或 AST 重扫容器。
2. **结构证据应尽量前移**：HIR 需要的 phi 分类、merge arm、loop binding、short-circuit leaf 等事实优先补进 `StructureFacts`。
3. **候选与最终决策分开**：Structure 只回答“像不像 branch/loop/short-circuit”，最终语法选择交给 HIR。
4. **共享实现优先**：region、phi、短路和图查询先复用已有 helper；同类形状漏收时扩展 owner，不平行新建 pass。
5. **irreducible region 判定看入口目标**：同一个 SCC 可以有多条外部前驱边；只有外部入口落到 region 内多个不同 block 时，才标记为 irreducible 并要求 goto。`LoopCandidate` 只来自“目标支配来源”的 natural backedge；编译器把 latch 优化成不可达块时，退化 generic/numeric-for 也必须用 init/loop 指令身份和区域边界显式配对。Luau 的立即 `break` 还可能让不可达 numeric latch 的 exit 先经过单条 jump pad 再汇入 init exit；这种透明 pad 可视为同一边界，但不能放宽寄存器身份匹配。因此候选本身保证可规约，不再保存恒真的 `reducible` 状态；不可规约控制流由独立的 `IrreducibleRegion` 表达。
6. **generic phi 物化只排除已消费候选**：如果某个 short-circuit / branch 候选因 irreducible 等原因不会被 HIR 消费，它对应的 phi 仍要保留 generic 物化，避免候选被拒后 merge 值失去 owner。loop 静态排除 natural loop 必然接管的 header phi；如果更外层 branch 已完整覆盖某个 loop exit phi 的所有来源，该 phi 同样只归 branch，不再让 loop 重复物化。其余 exit phi 是否能复用 loop state 取决于 HIR 的初值和 target 对齐结果，因此保留 generic 候选，并在 HIR 成功安装 override 时动态抑制。Structure 同时标记 generic phi 的保守来源；只有所有 incoming 都等于 idom 出口值时才暴露 `IdomExit`，否则明确标成 `Unresolved`。
7. **同一区域候选必须稳定归并**：同一个 `(header, merge)` 可能同时被普通 branch region 和 branch-exit short-circuit 视角识别为 branch-value merge；Structure 应在前层归并为单一候选，先比较覆盖 phi 数，等长时优先保留完整短路根的精确叶子分区。共享 fallback 可以从较早条件绕过末端 header，因此不能要求末端 header 支配 merge；完整短路根在 guard 两出口单向可达时以 continuation 为 merge，双臂独立时取最近共同后支配点，再一次划分两侧到达该 merge 的 predecessor。不同分析器产出的完全相同 short-circuit 候选应精确去重，但不能合并 arm 分区互相冲突的候选。
8. **源码 body 作用域属于 loop 候选事实**：`LoopCandidate.body_scope_blocks` 除 natural loop core 外，还包含被 header 支配、仍属于源码 body 的提前退出 tail；HIR bindings 和结构降低只消费这个集合，不重新用 CFG / DominatorTree 计算词法作用域。
9. **debug 分段不等于架构层**：`structure` dump 会按 CFG / GraphFacts / Dataflow / StructureFacts 分段输出，但外层仍只有 Structure。
10. **无出口循环的分支合流以本轮边界为准**：可规约无限循环没有严格后支配点；Structure 应先寻找两臂在重入 loop header 前的局部 merge，只有不存在局部合流且两臂都能回到同一 header 时才把 header 暴露为本轮 merge，避免普通可达性沿回边把 if/else 误判成单臂分支。
11. **loop header 不是候选唯一身份**：Luau 可能让外层 numeric-for body 与内层 while 共用同一个 CFG header。Structure 应先用精确匹配的 `NumericForInit/Loop` 认领外层回边与受支配区域，再处理剩余自然回边。普通 same-header natural loops 只有在内层包含 header 外的真实 body、内层所有结构出口仍属于组合后的外层、外层有真实出口，且 header 的两个 successor 分别进入内层 core 与 `outer - inner` 时才可能拆层；内层分支若直接退出整个组合区域，这些回边只是同一 loop 的 sibling latch。互不包含的普通 latch 在 stripped bytecode 中可能同时对应等价的单 loop 与嵌套 `while/repeat`，因此 low-IR 布局只作保守的规范化 tie-breaker：outer-only entry 排在内层全部 latch 后才保留嵌套候选，反向布局合并为单 owner；该顺序不是语义证明，重排字节码只允许退化合并。outer-only successor 可直接拥有无条件回边，或先执行任意 outer body，再由独立尾条件通过直接边或透明 Close/jump pad 在 header 与 loop exit 之间分流；body 中的赋值、调用和 early break 不属于条件依赖，不应阻断外层候选。单块 retry、无出口循环和提前 continue 等普通多回边形状也仍归并成一个候选。同 header 嵌套链的 header phi 只归最外层候选，不能在多个循环间重复消费。numeric latch 正常出口上的透明 jump pad 记录在 `LoopCandidate.control_blocks`，表示它已被 for 语法吸收而不是源码 body。
12. **歧义 repeat 需要候选关系证明**：`repeat ... until cond; break` 嵌在 for 内时，条件出口可能直接越过外层 for，使内层 natural loop 的 exits 看起来全是 terminal；repeat body 的一臂进入 nested loop 时，该入口也会落在 natural-loop core 外，使 body header 看起来像 while 条件。单看 backedge pad 无法排除真实 `while + 尾部 break`。Structure 应在候选齐全后用关系证据消歧：`WhileTrueLike` 只有与词法外层 numeric/generic-for 共享出口时才精化；`WhileLike` 还要求 core 外分支进入 `body_scope_blocks` 内 nested loop 的 header/preheader，且独立尾条件与 header 分支读取相同的 predicate/operands，才精化成 `RepeatLike`。
13. **复制的单指令 return 可以规范化为同一 for 出口**：Luau 可能让 `NumericForInit` 的零轮出口和 `NumericForLoop` 的正常出口落到两个不同 block；只有两块都恰含一条且 `ReturnInstr` 完全相同时，Structure 才把 latch return 从 loop region 移出、保留 init 与 latch 两个语义出口，并把复制块记入 `control_blocks` 交给同一 numeric-for 吸收。带赋值、cleanup 或不同返回值的尾块不得套用此规则。
14. **短路 repeat 与退化 generic-for 依赖候选关系精化**：`repeat ... until a and b` 的 body prefix 可能与首个条件共用 loop header，回边前又有共享 jump pad；普通短路候选不足时，Structure 只为 loop 补充按 CFG 真假边收齐的无环候选，再用“短路两出口恰为 loop exit 与 backedge pad”把 `Unknown/WhileTrueLike` 精化为 `RepeatLike`，并记录被选中的条件入口。无自身回边的 generic-for 若 body 是唯一以该 header 为 preheader 的 nested loop，应把该 nested region 纳入候选；其 header 到 exit 的零次迭代边仍属于出口 phi 的外侧初值，不能按完整候选 blocks 误归为循环内写回，但 shared continuation 的结构所有权仍覆盖 header，避免把合法的零次迭代出口误判成循环外入口。
15. **退化 branch 的同目标边不是未结构化 continue**：若 branch 的真假边都落到同一个 loop continue target，该条件不改变控制流，HIR 会按线性 successor 消费；goto 约束不得把其中任一边标成 `UnstructuredContinueLike`。只有两臂目标不同、且 branch/loop 候选都无法吸收的提前跳转才需要保留 goto requirement。
16. **相邻 loop 的边界 phi 归后继 header 所有**：前一 generic/numeric loop 的 exit 若正好是后一 while/repeat/for 的 header，同一个 phi 可能同时落入前者的 `exit_value_merges` 与后者的 `header_value_merges`。该 phi 只归后继 loop state；Structure 应从前一 loop 的 exit values 移除它，避免前层用后继回边值反推前一 loop 的初值。
17. **退化 numeric-for 可以与 nested loop 共用 header**：Luau 会把首轮必 break 的 numeric latch 变成不可达块；若 body 以 while/repeat 开头，`NumericForInit` 的 body target 同时也是 nested natural-loop header。精确匹配的 init/latch 仍应建立外层 `NumericForLike` 候选，只需排除该 header 已有另一个 numeric-for owner，不能因任意 grouped loop 占用 header 就丢弃 for 候选。
18. **跨层 escape 只能消费直接控制边**：loop 内 branch 的隐式 else 若直接落到外层 merge，可恢复为 escape；显式 else 臂在到达 merge 前仍可能包含语句或二次分支，HIR 不得跳过该 region 直接生成 `goto`，应退回普通 branch lowering 完整消费两臂。
19. **repeat 尾条件可以只有一个节点**：`continue`/`break` 会让 natural-loop header 偏离源码 repeat body，Structure 只要确认条件候选的两个出口精确对应 loop exit 与 backedge pad，就可把 `WhileTrueLike` 精化为 `RepeatLike`；普通 `until cond` 不应因短路节点数小于二被丢弃。Luau 的 `GenericForLoop body_target == exit_target`，或 `exit_target` 只经过单条透明 jump pad 便汇入 `body_target`，都表示 `for ... do break end`；应建立仅由 header 持有的退化 generic-for 候选，不能当作空 body 或无循环。
20. **numeric-for 的尾部 continue pad 属于源码 body**：Luau 会把仅以 `continue` 收尾的 numeric-for 编译成 `NumericForInit -> body pad -> NumericForLoop`，其中 latch 的 body edge 指回 latch，而 init 仍指向前置 body pad。Structure 应沿 latch 的直接 jump 前驱寻找唯一且状态/出口匹配的 init owner，用 body pad 作为候选 header 并认领自然回边；不能把 latch 自回边留下成独立 unknown loop。
21. **共享 backedge pad 的 continue 所有权落实到 edge**：branch 的某一臂可能先进入仅含 jump 的 natural-backedge source，再回到 loop header；只记录 `continue_target=header` 无法区分该 pad 属于哪个同层/嵌套候选。Structure 应在 loop 形态精化和 branch 候选齐备后，为“branch edge -> 当前候选真实 backedge pad/target”选择词法域最小的唯一 owner，并记录到 `LoopCandidate.continue_edges`；循环自身 continue target 的条件边、同目标退化 branch、兼任条件求值的 `RepeatLike` backedge pad，以及带普通前缀的 numeric-for 共享 body tail 都不产生间接 continue edge。
22. **loop 内局部 break 不应把 one-arm merge 推到 loop exit**：branch 一臂含局部 break、另一条自然路径又穿过 nested loop 时，普通可达性会被外层回边污染，严格后支配点也可能落到 loop exit。若 loop-bounded 可达性证明一臂在本轮内进入另一臂，应优先恢复局部 one-arm merge；但进入只含 jump 的 backedge pad 表示 `continue`，不能借下一轮回边伪装成本轮局部可达。带普通语句的 loop latch 仍可作为本轮共享 merge，不能仅因它是 backedge source 就拒绝。
23. **repeat body header 的 break pad 不是 while post-loop**：repeat body 若以条件 break 开头，natural-loop 会把 body header 暂时识别成 `WhileLike`，并把该条件的外侧入口列为候选 exit。Luau 的尾条件经唯一 jump pad 回边时，若 body header 的唯一外部入口不同于尾条件出口且被其严格后支配，应恢复 `RepeatLike`；Lua 5.1–5.5 的尾条件可能直接回到 header，此时若尾条件 exit 跳过 header-exit branch pad、直接进入该 pad 的既有 merge，也应恢复同一形态，并把该关系已证明的 merge phi 按扩张后的 body scope 与全部 loop exit 精确分臂后交给 loop owner。否则结构精化虽能消费 break body，下游 live-out 仍会退回 unresolved generic phi。真实 while 的 header 直接退出到公共 post-loop，不满足这两类关系。
24. **branch 外部臂与 loop backedge 可以组合拥有 header phi**：前置条件分支直接汇入 repeat/while header 时，同一个 phi 的外部 incoming 属于 BranchValueMerge，回边 incoming 属于 LoopCandidate。BVM 分臂应先认 then/else predecessor，再跳过该 header 已有 loop owner 的其余 incoming；不能因回边不属于任一 branch arm 就丢弃整个值候选，也不能把 branch arm 自身仅因位于 loop blocks 内而忽略。
25. **双臂 early return 的 soft merge 来自共同 dominance frontier**：if/else 两臂都含 early return 时，严格共同后支配点会被推到 synthetic exit，真实 fallthrough join 也不会出现在任一臂的 ipostdom 链。Structure 应从两臂 entry 的 dominance frontier 交集中排除 synthetic exit，并要求 branch header 支配候选，防止内层分支跨 owner 或跨循环迭代抢占外层 join；若剩余多个候选，只接受能支配其余候选的唯一最近 join。不能用全图绕路可达性猜 merge，也不能把未恢复的尾部 phi 留给 HIR generic fallback。
26. **repeat backedge pad 只承载透明控制**：branch 条件经 backedge pad 回到 header 时，pad 只有在前缀为空或仅含已由词法 scope 吸收的 `Close` 才能作为 repeat 控制。赋值、调用乃至当前 effect 分类认为纯净的普通指令都属于 while/retry body 尾部；Structure 若把它误认成 repeat 条件，HIR 会在降条件时跳过本轮语义。当短路条件 header 就是 natural-loop header，或所选 continuation 位于该短路候选 blocks 之外时，回边源上的任意非 `Close` 前缀都必须阻止 `Unknown/WhileTrueLike -> RepeatLike` 精化；候选自身条件节点里的调用/比较前缀仍属于条件求值，纯 jump/close 的真实 repeat 与 goto 重入 cleanup 也保留原 owner。
27. **loop-bounded 可达性按入口选择候选身份**：分支分类把已确认 loop 当作只通向显式 exits 的结构化节点；同一 header 存在多个候选时，必须用到达 header 的 predecessor 匹配唯一 preheader，只有单候选 header 才可省略入口证明，包括查询起点本身就是该 header 的情况。无法唯一选择时保持不可达，不能取列表首项或合并 exits；每个入口一次计算完整目标集，避免为不同 merge 重复遍历 CFG。
28. **dataflow 只保留 canonical SSA**：固定寄存器活跃性的 live-in 变化只重新排入 reachable predecessors；phi 由 pruned IDF 一次放置，值身份沿 dominator tree 重命名，不再运行 reaching-def / reaching-value 双固定点。block entry/exit 和真实 instruction use 只保存稀疏活跃值，不能恢复按指令复制全寄存器状态的实现。open pack 使用独立临时 SSA，公共结果必须同时保留函数入口来源与实际 `OpenDefId`；两者合流时不能丢掉 Entry 后误认成唯一 producer，也不能与固定寄存器值混成第二套通用 value solver。
29. **多出口 loop 的共同 continuation 仍是 exit owner**：同一 loop 的多条 `break` 可以从带 live-out 写回、且全部可达前驱都属于 loop core 的专属出口块直接汇入共同 successor，此时该 successor 的 phi incoming 完整对应这些出口，仍归 loop 的 `exit_value_merges`；若路径还要继续跨越中间 pad，则 pad 只能含 `Close` 并以 `Jump` 或唯一 fallthrough 离开。赋值、调用、`Tbc` 或分支可以留在 phi 的直接 predecessor，但不得越过它们继续扩 owner；带循环外入口的共享块也不得当作专属出口扩张。
30. **普通 one-arm 优先复用后支配事实**：一臂入口严格后支配另一臂时，可直接把前者认作 merge，无需重新遍历 CFG。early return 等不满足后支配关系的剩余形状再按 `(source, target)` 做早停可达性查询，并只缓存布尔结果；不能为每个 source 保存全图目标集。loop-bounded 分类会从同一入口反复查询多个候选，仍按规则 27 共享完整目标集。
31. **for-loop 的 break/continue 分支以本轮 soft merge 为界**：branch 位于 for body 入口，且一臂 `break`、另一臂继续本轮时，严格共同后支配点会落到 loop exit，普通可达性还会沿 backedge 把下一轮入口误认成本轮 one-arm。`NumericForLike` 的源码 body 入口就是候选 header；`GenericForLike` 的 header 是迭代 latch，源码 body 入口是它唯一的 loop 内 successor。Structure 只有在同一 for owner 的源码 body 入口才能把直接 exit 臂恢复为 guard，或从共同 dominance frontier 选择本轮 soft merge。Lua 5.5 generic-for 的多个物理 cleanup exit 若都有同一唯一后继，该后继也属于 for exit boundary；若 backedge 让两臂的 merge predecessor 重叠，只按 entry dominance 剔除能唯一归属的污染 predecessor，歧义来源仍保留给保守路径。

32. **for binding 不跨越多出口的共同后继**：Lua 5.5 generic-for 可以让 `break` cleanup 与正常 cleanup 成为两个物理 exit，再共同进入 post-loop。`body_scope_blocks` 仍包含每个 exit pad，但若所有 exit 都有同一唯一后继，该后继就是提前退出 DFS 的词法边界；某个 exit 本身就是共享 continuation、且其他 exit 都唯一进入它时，该 exit 同样是边界，不能因为它自己的后继已是更下游 block 就把 continuation 纳入 binding scope。不得把 for binding 带入循环外的寄存器复用块；后继不同或存在多个候选时保持原边界，不凭可达性猜测合流。

33. **loop 内 synthetic postdom 仍允许本轮单臂证明**：嵌套 branch 的 early return 可以把外层分支两臂的严格共同后支配点推到 synthetic exit，但其中一臂仍可能在当前迭代内自然进入另一臂。只要 enclosing loop 同时持有 header 与两个 entry，且 strict merge 是该 loop 物理 exit 或 synthetic exit，Structure 就使用已有 loop-bounded 查询截断回边后判定 one-arm。查询无法证明单向可达时仍保留 if/else 或 guard，不因 synthetic exit 直接改写候选。
34. **value-merge root 由 merge 的直接支配者唯一确定**：合法短路 DAG 的 root 既支配 phi merge 的所有 predecessor，又必须在两臂间产生分叉，因此就是 merge 的 immediate dominator；若该 block 不是 branch header，或 phi 含函数入口虚拟 incoming，就不存在值合流短路候选。不得再为每个 phi 枚举全部严格支配 branch。支配/后支配使用预序子树区间做 O(1) 祖先判断，避免顺序 branch 链退化成平方复杂度。

35. **canonical SSA incoming 直接表达本地 producer**：phi incoming 若在 predecessor 内最后写入结果寄存器，其值身份必为该 block 的 `Def`；`Entry` 或另一个 `Phi` 表示该 predecessor 没有本地 producer。Structure 应直接检查这个 SSA 身份，不能为每条 incoming 递归展开完整 leaf-def 链再反查来源。

36. **repeat 条件链入口支配最终回边源**：将 `WhileTrueLike/WhileLike` 精化成 `RepeatLike` 前，被选中的完整条件链入口必须支配真实 backedge source。`a and b` 的最终节点不必支配短路失败路径，因此不能拿任意单节点候选先占位；应继续寻找入口支配回边的完整补充候选。若连条件链入口都可被绕过，它表示 while 中的提前 `continue`，不能改写成 repeat。

37. **loop 内 if/elseif 的 merge 以本轮 soft join 为准**：严格后支配把外层候选误判成 one-arm，且被当作 merge 的下游 branch 明确退出同一最小 loop owner 时，Structure 才截断 loop header 验证两臂本轮互不可达，并从共同 dominance frontier 选择两臂本轮都可达的 soft merge，精化成 `IfElse`。普通 guard、布尔短路和没有下游 loop-exit owner 的分支不得套用该规则。

38. **带语句的 continue 臂由终端 edge 持有**：`if cond then update; continue end` 的分支边先进入带普通语句的线性臂，真正 continue 是该臂末端到 loop continue target 的 edge。若该单臂路径在到达 branch merge 前始终只有唯一后继，Structure 应把终端 edge 交给最小 loop owner；goto 分析不得再把已认领 edge 标成未结构化跳转。路径穿过 merge、分支或离开 loop blocks 时保持未证明。

39. **多 terminal exit 的 sibling latch 仍归 while-true owner**：同一可规约 branch header 的多条自然回边可能来自尾部短路条件的多个 sibling latch。若区域没有 scope cleanup、存在多个且全部直接终止的出口，Structure 应保留 `WhileTrueLike`，并以 header 表示多回边共同的下一轮入口；单一 post-loop terminal、非 branch header 仍交给既有判定，不能把普通条件循环或包含内部循环的外层候选误当成 sibling latch。

40. **loop cleanup 出口同时接受 jump 与 fallthrough**：Lua 5.5 generic-for 的 break 和正常退出可以分别形成 `Close + Jump` 与 `Close-only + fallthrough` pad。两者都只有唯一后继且只含 `Close` 时，Structure 应把共同后继识别为 loop exit value owner；repeat backedge pad 仍只接受显式 jump，不能因 cleanup 规则放宽条件入口。

41. **执行 owner 必须按稳定索引唯一化**：候选和 `RegionFact` 可以为调试保留重叠视角，但 `StructurePlan` 必须让每个 block 与 edge 只有一个直接 owner。不可规约 region membership 与直接 executable owner 分开；其中仍可证明的 header 保留 `Branch/Loop` owner，其余成员才归 `Unstructured`。不可达 block 显式归 `Unreachable`，不得伪装成线性路径。same-header loop 用稳定 `LoopCandidateId` 保留候选链；`GotoRequirement` 直接保存 `EdgeRef`，同一 edge 不得出现两份 goto owner。新增 owner 时应在 plan 构建后用 O(B+E) 覆盖校验 fail-fast，不能让 HIR 再用 raw candidate map 的覆盖顺序做冲突消解。

42. **每条 cleanup 必须拥有唯一 disposition**：`StructurePlan` 为全部 `Close/Tbc`（包括不可达指令）建立按 `InstrRef` 的稠密分类。`Tbc` 只代表源码显式 `<close>`，归 `ExplicitTbc`；覆盖它的 `Close` 通常归 `ExplicitTbcBoundary`，只有已证明由唯一 loop 词法域表达的边界才归 `LoopTbcBoundary(LoopCandidateId)`。其余 reachable `Close` 只能归 entry 与所在 block 相同的唯一 `BlockScope`。`GenericForPrep` 属于 generic-for 控制协议而非 cleanup disposition，由对应 loop candidate 接管；无法唯一归属时前层立即失败，HIR 不得从 scope close-point 并集或第二套活跃性分析重建 owner。

43. **不可规约实际布局属于 StructurePlan**：irreducible membership 只含 SCC 本体，mixed lowering 的 executable layout 还可穿过通往唯一后支配 continuation 的透明出口 pad。Structure 在 cleanup disposition 完成后一次确定 `blocks + continuation`：pad 必须是 `Linear` owner、只有唯一可达后继，且不能包含尚未由 generic-for candidate 接管的 `GenericForPrep`。HIR 直接按该布局排序，不再重算后支配链或复制 cleanup 判定；layout block 另有 O(1) region 索引，供 edge/phi owner 共用。

44. **每个 phi incoming 只有一个 disposition**：死亡 phi 的全部 incoming 归 `Dead`，不可达边归 `Unreachable`，真实显式 goto 与 mixed island layout 内的边归 `EdgeCopy`，其余归目标 block 的 `Merge` owner。`UnstructuredContinueLike` 虽绑定 goto requirement，语义仍由 loop/short-circuit merge 消费，不得误列为 edge copy。含 edge-copy 的 live phi 若不是整项 edge-owned，剩余 incoming 必须已有 branch/loop/short-circuit owner，不能再登记 generic materialization。Structure 同时建立 `EdgeRef -> PhiEdgeCopy[]` 稳定索引；HIR 只按实际 copy 数线性生成，不再为每条边扫描目标 block 的全部 phi 和 incoming。

45. **结构 owner 同时接管纯 phi 中继链**：branch/loop/short-circuit owner 从目标 phi 递归消费 incoming leaf defs。若一个上游 phi 没有指令直接 use，且它的全部 phi consumers 都已归结构 owner，则 Structure 将它递归并入同一覆盖闭包，不再登记 generic materialization。只要存在直接指令 use 或尚未归属的 phi consumer，就必须保留独立 owner，不能因“最终值看起来会被覆盖”提前丢弃。

46. **寄存器写集合只消费 canonical InstrEffect**：`InstrEffect::must_define` 统一合并 `fixed_must_defs` 与从起始槽覆盖到栈顶的 `open_must_def`。loop 形态、entry override 传播、loop preheader/edge 初值判断和 wrapper use 扫描都消费该查询；不得再按 `LowInstr` 变体维护第二套 def 枚举，也不能只查 fixed def 后让 open call/vararg 错误穿透。新增 opcode 或调整 open result 语义只修改 effect 事实。

47. **大函数查询按真实 owner 键预建索引**：`body_scope_blocks` 为 numeric/generic-for 扩张被 header 支配的提前退出词法域；repeat 还可纳入从 body 分支进入的 nested loop，但必须把尾条件的循环外后继作为边界；while/while-true 保持 natural-loop core。任何候选都不能把普通 post-loop 与后续 sibling loop 纳入源码 body。支配树和后支配树在构建时同时保存 depth 与 binary-lifting ancestor table，最近公共祖先查询不得逐次重建完整祖先集合。continue edge 所有权按 `block -> LoopCandidateId[]` 反向索引只访问包含 branch header 的候选；generic phi 同时按稳定 `PhiId` 和目标 block 索引，HIR 不为每个 block 重扫全部 materialization。索引只是同一份 canonical fact 的查询形态，不能复制或重新消解 owner。

48. **跨嵌套 branch 的值候选按 region 消费**：branch 的物理 merge 可能只是共享 false block，而值真正汇入更下游的 loop header。`BranchValueMergeCandidate` 因此以 `(header, merge)` 为完整身份；所有 region 候选都计入 structured phi 覆盖，不能只保留 `branch.merge` 恰好相同的 header 快捷索引。若两臂 canonical values 相同且都没有本地 update，该候选只是 loop-carried state 的恒等中继，应在 Structure 直接删除；两臂外部初值不同的 loop-header phi 仍同时由 branch region 初始化、由 loop owner 接管回边。

49. **repeat 短路条件可以拥有多条物理回边**：`until A or (B and C)` 的多个 false leaf 可以分别直接跳回 loop header，natural-loop 因此记录多条 backedge。Structure 应按 `BranchExit` 到 header 的完整短路候选成组认领这些边：候选必须可规约、blocks 属于 loop、全部 backedge source 都是候选节点且被条件入口支配，另一出口属于 loop exits；continue target 仍取唯一 final node。只要有任一回边绕过该短路候选，就保持 while/unknown，不能把提前 continue 错当成 repeat 条件。

50. **repeat 的短路 DAG 允许共享条件节点**：`until (a or b) and c` 的 `c` 会同时接收 `a`、`b` 两条真值路径，前驱数大于一不表示它已经是条件出口。branch-exit 构造可先复用同 header 的 DAG 节点，但共享扩展必须有一条出口回到严格支配 root 的 loop header，并在完成后通过无环与 reducible region 校验；否则回退到按多前驱截断的保守 guard 前缀，不能扩大非循环 branch-exit 的识别边界或把原本可用的候选一起丢掉。完整尾条件有多个真实 backedge 时，才额外允许它与 while-like header 直接共享同一个 loop exit，或把 header 的独立 `return/tailcall` 出口作为 repeat body early exit；单一 backedge 可能只是 while body 的条件 break/return，不能套用这两条放宽。原有“不同 header exit 最终后支配汇入 repeat exit”的关系仍可独立成立。

51. **branch region 使用支配区间而非后缀集合**：普通非回环 branch 的可结构化区域等于 `DomSubtree(header) - DomSubtree(merge)`，`BranchRegionFact` 只保存边界并通过支配树查询 membership；仅当 merge 支配 header 的回环边界无法使用该差集时才保留显式 block 集合。需要枚举时只暴露支配区间上的惰性 view，不再物化 `BTreeSet`；该 view 的顺序是支配树 preorder，不是语义优先级，消费者若需要稳定选择必须显式按 `BlockRef` 或自身结构事实决策。stop-at-merge 的无支配可达闭包按定义不会产生指向 merge 以外的 reachable exit，因此不再保存 `flow_blocks` 或重复扫描伪 `CrossStructureJump`。可结构化 branch/loop/linear `RegionFact` 与空 branch/loop scope 没有执行消费者，不得为了 debug 再复制整片区域；`RegionFact` 只保留不可规约 island，词法 cleanup owner 只保留真实含 `Close` 的 block scope。

52. **只有闭合单入口线性链可以省略后缀候选**：长 `and/or` 的每个 suffix 都重建完整 nodes/blocks 会形成平方开销。Structure 只在候选可规约、所有内部 header 都只有一个 reachable predecessor、且两个最终出口都不是新的 branch header 时，把首个候选视为闭合 functional component，并跳过其内部 root 的线性/guard 重建。canonical root 自身始终保留；只要出口继续进入 branch、内部有共享前驱、回边或不可规约入口，就保留所有原分析路径，不能用 header 覆盖集合截断 `(a and b) or (c and d)` 之类共享 DAG。

53. **dominance frontier 按支配树 local/up 传播**：对每个 merge predecessor 逐级沿 idom 上爬会在长条件链上产生 `Σdepth`。GraphFacts 先为每个支配树节点加入 idom 不等于自身的 CFG successor，再按支配树后序合并 child frontier，并过滤由当前节点直接支配的成员。这样成本由真实 CFG edge 与实际 frontier 事实决定，不因单个高入度 merge 重复遍历同一祖先链。

54. **支配树使用非递归 simple Lengauer-Tarjan**：GraphFacts 先用显式栈按 CFG edge 顺序建立 DFS preorder/parent/postorder，正向计算支配树、反向计算后支配树，共享同一套实现。semi-dominator 与 path-compressed eval/link 把旧 Cooper 固定点和逐 predecessor 的 idom 链相交替换为最坏 `O((V+E) log V)` 的 simple LT；不宣称 sophisticated LT 的近线性界。支配树 preorder、不可规约 SCC 的 Kosaraju 后序也使用显式栈，超深 proto 的正确性不再依赖线程栈。不可达 block 不进入正向树；从 entry 可达但不能到 synthetic exit 的 block 不进入后支配树，现有 `parent/children/order`、支配区间、binary-lifting LCA 与 dominance-frontier 合同保持不变。

55. **for 的显式 TBC 边界由唯一词法 owner 接管**：显式 TBC forward dataflow 保存活跃 `Tbc InstrRef`，不能只保存寄存器号；这样 `Close` 才能证明自己覆盖的每个声明都位于同一 numeric/generic-for 的 `body_scope_blocks`。候选还必须是集合偏序下唯一最内层 owner，close block 只能位于该 body 的 continue/control 边界、直达专属 exit 的 cleanup pad，或无外部 predecessor 的专属 exit 起始处。`Close.from` 不得低于 `NumericForInit.index` / `GenericForCall.iterator`，因此循环语法不会吞掉 loop base 以下的外层 local/upvalue；共享出口、内部普通 `do` scope、覆盖外层 TBC 或 owner 歧义都保留 `ExplicitTbcBoundary`。

56. **value-merge 叶身份可以穿过中间 Phi**：最终 merge 的物理 incoming 可以是上游 branch merge 产生的 Phi，不能要求短路 DAG 的源码值叶 block 与最终 predecessor 完全相同。Structure 以递归展开后的 `Entry/Def` 叶集合验证候选完整覆盖最终 phi，并允许写值叶经唯一后继的透明 jump/phi carrier 到达 merge；carrier 必须由候选根支配、不得含 branch 或普通写入，最终 incoming 必须包含该叶 SSA 身份，且 carrier 与其最终 predecessor 都纳入候选覆盖证明。所有物理 predecessor 必须由某个值叶到达，自递归或间接回到最终 phi 的 loop state 必须拒绝。`ShortCircuitValueIncoming` 记录 DAG 的真实写值叶，HIR 只消费这些前层事实，不再展开中间 phi。

57. **nested for 的正常出口不能伪装 terminal while-true**：外层单出口 natural loop 若暂定为 `WhileTrueLike`，但其源码 body 内 numeric/generic-for 的协议正常出口恰好就是该唯一出口，则该路径已经证明普通 post-loop 可达；即使 post-loop 以 return 结束，外层也必须降回 `Unknown` retry owner。若外层 backedge 的来源位于不同 header 的 nested loop 词法 body 内，该边通常跨越了一个源码 loop，应标成 `CrossLoopContinueLike` 并保留 edge phi copy；但若它同时是内层 loop 的直接 exit，且内层其余 exit 也只经透明 cleanup/jump pad 汇入同一 outer header，则该边是 `inner break + outer natural fallthrough`，应由内层 break owner 接管。same-header 候选仍由既有嵌套 loop owner处理，不据此制造 goto。

58. **generic-for 的运行时槽位变化进入 canonical SSA**：`GenericForPrep` 先登记 iterator/state/control/closing 四项 use，再分别为发生变化的 control/closing target 建 must-def；同一 InstrEffect 的 use-before-def 表达 Lua 5.5 的并行交换，Lua 5.4 identity 不制造机械定义。`GenericForCall` 读取具名的三个 runtime 槽并定义 bindings，其 side-effect summary 与普通调用同样标记 `Call`；`GenericForLoop` 读取首 binding，且在它与下一轮 control 不同槽时定义 `control_target`。这样 Lua 5.1--5.4、LuaJIT、Luau 的 loop-carried control 会在 header 形成真实 phi，Lua 5.5 的同槽 control 不产生伪 def；HIR 必须从 preheader source owner 取首轮值，不能把 header phi 当源码初值。

59. **repeat 条件两侧的 TBC cleanup 归同一词法 owner**：Lua 5.4/5.5 会在 `repeat` 尾条件的退出臂与回边臂各发射一次 `Close`，但源码 `<close>` local 的作用域覆盖 body 与 `until` 条件，两个物理 cleanup 只是同一轮词法结束的路径展开。只有 covered `Tbc InstrRef` 全部位于唯一最内层 `RepeatLike.body_scope_blocks`，且 `Close` 位于专属 exit 起始处、直达 exit 的 pad 或只回到该 repeat header 的 backedge pad 时，才能标成该 candidate 的 `LoopTbcBoundary`。多个 break/条件 cleanup 可先沿仅含 `Close* + Jump` 或 `Close* + fallthrough`、唯一后继的 candidate exit pad 汇入共同出口；反向链上只要出现普通语句或非当前 loop 的 reachable predecessor，就仍保留 `ExplicitTbcBoundary`，不能吞掉 repeat preheader、共享入口、外部 TBC、内部普通 `do` scope或歧义 owner。

60. **single-pass fence 只补没有 natural-loop owner 的结构缺口**：优化器可把 `repeat ... until true` 消成普通 branch；内层 escape 与两臂共享 fallthrough 会让严格后支配 merge 落到 fence 外。Structure 保留普通 `IfElse` 候选和 soft merge，只在没有 enclosing natural-loop owner 时附加 `SinglePassFenceFact { exit, escape_edges }`；escape edge 必须来自被单侧支配的 nested branch，且两条外臂都能到 soft merge。若某个 loop 的 body scope 完整覆盖 branch 两臂与 soft merge、strict merge 是其显式 exit，且全部 escape edge 都从该 body 直达其 exit，这些边就是现有 loop 的 break owner，不能再包一层 synthetic repeat。

61. **副作用摘要覆盖所有可观察求值**：`SideEffectSummary` 的空集合才表示当前查询可视为纯指令。Lua 5.5 `ErrNil` 在目标非 nil 时抛错，必须标成 `MayThrow`；`Tbc` 注册后续词法关闭并立即校验 `__close` 合同，必须同时标成 `RegisterClose + MayThrow`。除布尔 `not` 外的一元运算、全部二元运算与拼接既可能抛错，也可能调用带副作用的 metamethod，统一标成 `Metamethod + MayThrow`，即使结果没有寄存器 use 也不能删除或跨条件重排。`Close` 继续只表示执行 cleanup，`Call` 也不充当这些协议的模糊总类；条件 prefix 等消费者只查询统一摘要，不再按 opcode 补第二套可观察性名单。

62. **互不可达分支没有强制合流点也必须保留 owner**：branch 两臂入口互相不可达、且不存在共同后支配点时，区域大小不同可以选择较大的等价 guard continuation；大小相等只表示没有可读性偏好，必须产出 `IfElse { merge: None }`，不能把 header 留成 `Linear`。HIR 可用更严格的路径证明选择两臂都能到达的可选共享 continuation；否则分别降低两个完整 arm，不生成伪 merge，也不依赖目标方言的 goto/label 兜底。

63. **局部 producer 闭包直接查询 canonical SSA use 图**：HIR 等消费者要删除一组 def-producing 指令时，必须同时证明每个 fixed def 的全部直接 use 都属于该指令闭包、且没有继续流入 phi。Dataflow 通过 `def_uses_are_within` 提供这一集合查询；消费者不得只按线性 PC 扫描 producer 与当前 use 之间的区间，否则会漏掉同 block 后缀、跨 block 或 phi live-out。

64. **无出口循环内的 branch merge 按 CFG 偏序选择**：严格后支配在无限循环中可能为空；两臂都留在同一 loop owner 内时，Structure 可以用“不重新进入 loop header”的局部可达性补出 merge，但必须选择能严格到达其余全部合法候选的唯一最近点。候选不可比或处于同一 SCC 时保持未证明；`BlockRef`、物理布局和集合迭代顺序都不是 merge 优先级，不能把远端 tail 留给 HIR 再纠正。

65. **branch-exit 前缀选择增量维护出口事实**：同一条长 `IfElse` 链会从每个 root 收集后缀，但每个 root 内不能再为所有 prefix 重跑完整推断。Structure 一次前向扫描增量维护外部 target 多重集与 strict truthy/falsy 约束，仍选择最长合法 prefix，并保持同一 prefix 上 strict 优先于 relaxed；只有最终候选构造 nodes 与 blocks。该优化不得按预算截断后缀，也不得用 header 覆盖集合丢弃 candidate identity。

66. **SSA incoming 复用 CFG predecessor 槽位**：固定寄存器 phi 与 open-pack phi 都按同一份 reachable predecessor 顺序构造 incoming；Dataflow 应为每条 edge 一次建立目标 incoming 的稠密槽位，rename 直接按槽写入并校验 edge identity。不得再为每条入边、每个 phi 线性搜索 incoming，否则高扇入 merge 会从 `O(phi × indegree)` 退化为 `O(phi × indegree²)`；函数入口的虚拟 incoming 只增加统一槽位偏移，不能混入真实 edge 索引。

67. **loop membership 按 candidate identity 稠密投影**：goto 分析一次建立 `block -> core/body/exit owner[]` 与 candidate entry edges；入口边成本由真实 edge-membership 关联数决定，backedge 也只检查实际覆盖 source 的 body owner，不再与全部候选比较。索引值始终是稳定 candidate 下标；same-header、退化 for 与不同 blocks/backedges 的候选保持独立，不能为了压缩索引按 header 合并身份。

68. **value-merge 的 Phi 递归与叶身份按线性事实判定**：同一寄存器的顺序 branch 会形成不断引用前一项的 Phi 链；为每个候选重复执行 `value_contains` 和完整 `leaf_values` 会形成平方访问。Structure 对 Phi 依赖图一次做非递归 SCC 标记，直接拒绝自递归或间接递归的最终 Phi；普通值叶按最终 predecessor 保存 canonical SSA 身份，全部与对应 incoming 精确相同时直接通过。一个 predecessor 承载多个不同叶值或穿过中间 Phi 时，仍回退到完整 `Entry/Def` 叶集合比较，保持嵌套短路语义；不得常驻缓存每个 Phi 的展开叶集合，以免把时间平方改成内存平方。
