# Structure

> **职责**：从 low-IR 构建 CFG、图事实和 canonical SSA，并冻结为经过强校验的 `StructurePlan`。
>
> **不负责**：生成 HIR/AST、命名，或让后层重新选择结构候选。

## 入口与输出

```text
LoweredProto
  -> Cfg / GraphFacts / DataflowFacts
  -> structure evidence
  -> StructurePlan
  -> StructureFacts {
       outcome: Ready { plan, debug_bindings } | Failed(ProtoFailure),
       children
     }
```

入口为 `src/structure/analyze.rs::analyze_structure_proto`。proto tree 使用显式 postorder 调度；
父 proto 只在所有 child facts 完成后构建和验证自己的 plan。

## 模块 owner

```text
src/structure/
  analyze.rs / analyze/       阶段调度与输入事实整理
  cfg/                        CFG、GraphFacts、DataflowFacts
  branches.rs / branches/     branch evidence 与候选
  loops.rs / loops/           loop evidence 与候选
  short_circuit/              短路控制和值合流证据
  phi_facts.rs / phi_facts/   phi disposition 候选
  common.rs                   evidence 与 final plan 模型
  common/plan_access.rs       StructurePlan 只读查询
  plan.rs / plan/             arena、loop protocol、finalize 与 validator
  diagnostic.rs               proto 失败的紧凑诊断产物
```

CFG、SSA、region arena 和 validator 状态各自只有一个 owner。子模块按关注点拆分，但不能复制
事实或建立可独立漂移的候选选择路径。
CFG 的 `non_control_instr_range` 以 Transformer 的控制终结分类查询当前块的非控制前缀；
它只剥离块末控制指令，保留 Close 等清理事件，不授权移动、删除或改变 cleanup 的相对位置。
同一快照的 predicate_edges 查询统一按 BranchCond.negated 归一化正谓词真假边；
branch_edges 仍返回物理 BranchTrue/BranchFalse。短路候选和弧计划消费边身份，
实际执行的 polarity 仍取物理边类别，不从目标块是否相同反推方向。

GraphFacts 统一冻结 SCC 成员、block 身份、成环标记与 condensation 前驱。`SccId`
按拓扑序编号，跨 SCC 边只能从小到大；后层可以裁剪查询区间，不重新计算这些图事实。
不在 GraphFacts 或消费者缓存平方规模的 SCC 传递闭包。
`extend_dominance_frontier` 统一扩展定义及已有合流种子的迭代支配边界，固定值、开放尾包
与 Close epoch 共享此算法。活性裁剪、真实循环出口种子及扩展后的虚拟入口合流归各自
消费者；图查询不重建值、生命周期或 VM 协议，也不额外过滤调用方给定的种子。
DFS、SCC 与支配算法由 `src/graph.rs` / `src/graph/` 共享；Structure 仍负责自己的可达域、
正反向边、LCA 索引、稳定 block 顺序和 condensation 校验。后层改写后不能继续消费这份
旧 topology 的 SCC 身份或支配事实。

可信 debug binding 以 canonical SSA 为身份，并保留原 PC 区间及 `end_instr` exclusive low
边界；该边界消费 Transformer 的正式查询，不由 HIR 再扫 raw 映射。初始化写入点仍从同一
Def 身份查询，完整 initializer 窗口、词法物化权限和临时根结束证明由 HIR binding owner 负责。
PC 0 已存在的参数 scope 锚定到 `Entry(reg)`；首条指令即使覆盖参数，也不能把该重绑定
当作参数初始化，否则后层会丢失原参数身份。
`DebugBindingFacts::accepted()` 只读借出按唯一 SSA 身份排列的已接受事实，`for_value`
直接二分查询；HIR 不再重建名称映射或 debug Def 集合。名称借自 Transformer，只有最终
写入 HIR 命名提示时解码，屏障和词法窗口只消费 scope/SSA 身份。
Dataflow 的 `last_fixed_def_in_range` 以按寄存器排列的稀疏定义索引回答 exclusive low 区间内
最后一个 fixed Def；debug 入口消费该位置查询，不逐候选扫描块前缀。
该索引包含不可达块的固定定义，只回答线性位置，不推断跨块 reaching 或 open overwrite。
同条指令的 fixed Def 保留 effect 中按 Reg 递增的顺序，`instr_def_for_reg` 直接二分查询
精确身份，不为多结果调用或批量覆写逐槽扫描全部定义。
`InstrEffect` 在构造时排序去重并冻结固定读写域，以严格 Reg 顺序借出切片；membership、
读取后缀与固定写读交集由事实查询负责。后层需要增删的活性、条件依赖工作集自行构造，
不修改已冻结的指令事实，也不把开放包后缀混入固定寄存器集合。
open-value 分析只保存来源证明的 must/may 前缀端点，SSA 与活跃性分别查询固定集合和对应
前缀的有序并集，不复制或存储展开后的读取集合；该借用投影在 Dataflow 构建内消费完毕。
块内 fixed Def 枚举及其经 phi 传播后的读取逃逸也由 Dataflow 查询负责；只检查真实指令的
use-site，不把 phi 所在块视作逃逸。条件分析与 HIR 直接消费已有定义身份和查询结果。

Dataflow 逐寄存器冻结整个 proto 的按值、按引用捕获模式，两者可以同时存在；不可达
closure 也保留，子 proto 与 Upvalue 来源不混入当前 Reg 域。Structure 动作位置校验及
HIR 绑定、根保护直接查询这份事实，不重新扫描 closure 或复制捕获位表。全函数的捕获
模式不证明某个程序点仍有开放 cell，Close epoch 和路径敏感的开放状态由其分析单独持有。

`SideEffectSummary` 的有限标签集合内联保存，通过 `has_effect_tags` / `has_effect_tag`
查询；标签存在性与 `RootObservation` 分别表达。空标签不等于没有运行事件，例如
TailCall 仍有 FrameExit 合同；debug 视图按稳定的标签顺序输出。

Dataflow 在最终 SSA 上一次冻结透明 Move 的值根，`canonical_move_value` 以常数时间查询；
只穿透精确 Move 的真实 use，遇到 Entry/Phi 停止。不可达 Move 缺少源时仅该链返回未知，
不使整个 proto 失败。Structure 与 HIR 的 method、closure、global 和 promotion 直接消费，
不各自建索引。值恒等不证明物理 home 或允许延后读取；edge-action 入域、单跳、capture
及覆盖边界继续由原 action owner 校验。

## 观察期间的物理 root 事实

Dataflow 的 `SideEffectSummary::root_observation` 与副作用标签一同冻结：普通调用提供
callee base 以下的 caller-frame 边界；TFORCALL 和 TBC 只提供固定输入所证明的前缀下界；
普通可观察指令由寄存器读写摘要提供下界；Return/TailCall 与 Close 保留独立的生命周期事件。
前缀下界之外表示未知，不能当作已死亡；普通调用的 caller 边界也不排除被调用函数通过参数
持有相同对象。HIR Promotion 只能消费这些 typed facts，不能再次解析低层调用参数或结果范围。

`RootIntervalIndex` 在同一快照内归约开放覆写起点和普通观察的保活前缀，构建为线性成本，
区间查询为对数成本；同一次构建还按位置记录全部 GC/cleanup 观察，供无观察区间查询。
首次覆写查询同时消费已有 fixed-def 索引与开放结果后缀。保活前缀查询只覆盖首次写入之前，
没有普通观察与前缀不足是不同结果；无观察的释放证明则必须包含覆写本条指令的观察。
这些查询只回答线性区间事实；FrameExit、Close、控制边界及跨块路径闭合仍由消费者处理。
这些事实本身不证明 producer 可删除、scope 可延长或 root overwrite transaction 闭合。

Dataflow 还提供两项以 canonical def 为身份的查询：

- `def_overwritten_value` 返回写入前的 canonical 值。构建时按块记录 fixed/open 写入，
  缺少 SSA 入口快照的槽共享 `(block, reg)` 查询图，各边最多传播两次；消费端直接索引，
  不逐定义扫描指令前缀或 CFG。不同路径身份冲突或 open result 覆盖表示未知，不能视作
  入口 nil；回边参与判断。这是物理覆盖关系，不增加表达式 use 或 phi。
- `unobserved_root_overwrite_after_last_use` 返回最后一次值读取后、任何 GC/cleanup
  观察前的精确覆盖 def，复用首次覆写和观察位置索引，不逐 producer 扫描后缀。
  只签发同 basic block 且无 phi use 的证明；首次 open 覆写没有 fixed Def 时仍不签发。
  HIR 仍需验证当前 producer 单写/单读、捕获与求值顺序，不能把查询缺失视为 root 已死亡。

SSA 与 open rename 共用的 edge→incoming slot 索引随 Dataflow 一起冻结。`phi_incoming_for_edge`
按真实 EdgeRef 查询并核对输入的边身份，防止不同目标块的同 slot 混淆；合成函数入口不占
EdgeRef，不可达前驱不占 slot，同一前驱的多条物理边则各占一槽。phi 压缩只改变 PhiId 和
值引用，不改变保留 phi 的输入排列。最终计划的重复认领和 disposition 校验仍由 Structure
owner 承担，不能用数据流查询替代归属证明。

## Region 与 Island

`StructurePlan` 是分层控制流图，不强制把所有 CFG 压成树：

```text
containment tree
  Sequence | Branch | ValueDecision | Loop | Block
  Unstructured island -> island 内保留局部 CFG edge
```

- structured region 使用唯一父节点的 containment tree，并满足单入口和声明出口。
  分支的词法 continuation 属于当前循环迭代；若一臂必须跨回当前 natural-loop header
  才能最终退出，跨轮成立的 postdom 不得覆盖两臂之间唯一的真实 dominance-frontier 汇入。
  该选择消费已有 loop owner 和图事实，随后仍接受 region 的入口与范围校验。
- 无法满足结构约束的最小闭合区域成为 `Unstructured` island。
- island 可以包含已验证的 structured child，但每个 reachable block 仍只有一个直接 owner。
- 可规约结构不会因目标方言支持 `goto` 而主动降级；原源码拼写无法由 bytecode 唯一恢复时，只
  承诺控制语义，不承诺保留原始 `goto`/loop 写法。

## Final Plan 合同

| 索引 | 唯一事实 |
| --- | --- |
| `RegionId -> RegionPlan` | containment 与 island layout |
| `BlockRef -> BlockTerminatorPlan` | 指令范围和精确 successor edge |
| `EdgeRef -> EdgePlan` | transfer、forward route、phi copies 与目标入口 cleanup events |
| branch/loop/condition/value-decision ID | 已选且规范化的 payload |
| `LabelPlanId -> LabelPlan` | label、cleanup 相对位置、must-active barrier 与实际 entry cleanup origins |
| `PhiId -> PhiPlan` | 每个 incoming 的唯一 disposition |
| `InstrRef -> CleanupDisposition` | 原指令、全部入边或 loop/lexical owner 的唯一清理归属 |
| `PlanRequirements` | 目标语法能力与 unresolved 诊断 |

`RegionNavigation` 按最终 block owner 的 Euler 位置保存一份可达块序列，region 的子树
由前缀偏移借用连续区间；包含 ValueDecision 和 island 直接拥有的块，不按发射形态过滤。
该顺序只服务 containment，不代表源码执行顺序。HIR 区域分析与 Structure 的块数校验
共享这份索引，不逐 region 重扫 CFG 或另建子树统计；独立的块覆盖校验仍核对 arena claim。

`EdgePlan` 是控制、值与入边清理动作的唯一来源。透明 jump pad 只能通过冻结的 forward route
跳过；每条物理边内部的 copy、cleanup 按执行顺序各执行一次。`BeforeTrailingCleanup` 将 source
值动作放在 source 的 trailing cleanup 前，目标入口 cleanup 和后续 route 保持在它之后。
该位置由 canonical phi 与 iteration 动作完成后统一签发，再供 loop protocol 消费，
LoopBack 与 Goto 共用同一证明，已被条件或 ValueDecision 语法吸收的边不改时序。
只有整批 copy 的源 Def 已在当前块写入同一
目标槽、槽未被引用捕获且位于全部尾部显式 Close 边界之下时，才可提前；带特殊 iteration
动作、跨槽或跨 Close epoch 的写入不适用。Tbc 注册事件不属于 trailing cleanup。
VM-for 隐式消费的 control/binding copy 仍保留 canonical SSA 身份，并由精确 edge/phi origin
证明其 disposition。

循环 header 的合流事实从 `LoopCandidate.header_value_merges` 规范化为唯一的
`LoopPlanData.header_values`，phi ownership、循环协议和值动作、HIR 捕获绑定共同消费。
同 header 的候选只合并一次 incoming；循环出口的 `exit_values` 保持独立的出口身份。

`ConditionArcPlan` 保存完整物理路径和冻结扫描选定的 transfer 位置，边身份从同一路径派生。
路径与位置不对外开放修改；控制分区及验证直接消费该位置，不按 edge ID 反查。比如路径
前缀被条件吸收、transfer 的 forward route 覆盖后缀时，两部分由同一冻结边界划分。

每条 Close occurrence 独立拥有执行位置；相同 origins 不代表两条关闭事件可以互删。
可搬移的入口 Explicit Close 从每条真实入边的 may-out 与实际关闭 origins 顺序求交、kill；
frame cleanup 保持原位。TBC may/must 流由 plan 共享，label 的 must-active barrier 与
实际 entry cleanup origins 是不同事实；label payload 本身不再执行一次清理。

Loop exit-tail 只把终末连续 Close 后缀交给词法退出；更早的 Close 与中间可观察事件保持执行顺序。
正常尾部若在本轮资源的不同关闭边界之间继续执行其它事件，或跨控制分叉仍保持资源存活，
而又没有 normal-tail owner，候选不能签发 break 式 loop container；其块交给既有 residual
region，保留真实资源退出边界。for preheader 中在循环前创建的资源不属于迭代体。

## 构建阶段

1. 从 CFG、dom/postdom、SCC、canonical SSA 和方言 protocol 提取 branch、loop、短路、cleanup
   与不可规约 evidence。候选可以重叠，但 edge、phi incoming 和 cleanup 不能失去 owner。
2. 规范化 containment，合并同 header 的循环域，确定 branch continuation、loop partition、
   normal tail 与最小 island。候选间有归属歧义时不能按 block id 或遍历顺序任选。
3. 冻结每条 edge transfer、value action、cleanup、label 与目标能力 requirement。
4. 运行 final validator；只有完整通过的 plan 才发布给 HIR。

Region 导航先冻结不依赖兄弟顺序的拓扑，供 layout 排序使用；最终顺序确定后才冻结正常完成
路径。Sequence/island 只有末项的完成路径可以落底，不能把任意内部 block 视为整个 region
完成；edge 分类直接消费这一索引。
同一导航索引还提供 region 的后序排名，直接由子树终点与深度计算；HIR 的共享闭包词法
范围查询消费该排名，不再复制 region 到后序位置的反向表。
island 保留普通 item 的物理顺序，避免把已关闭资源后的可观察动作排进另一条仍活跃的路径。
只有真实显式 Close 构成的出口 pad 可稳定延至末端：既有 TBC may-out 必须为空，关闭的
origin 与可达入边来源必须直属同一无 loop 祖先的 island，唯一后继位于 island 外。
这些归属事实排除 loop cleanup/exit-tail 与 VM-for 隐式边，证明整个 pad 前缀由唯一
cleanup owner 移到入边；纯 Jump、仍携带 outer 资源的 pad 和声明入口不适用。

具体候选判据属于 `branches/`、`loops/`、`short_circuit/` 与 `plan/` 的文件头和代码注释，不在
本文逐形状列举。

## 必须成立的不变量

1. 每个 reachable block 恰有一个 containment owner，containment 无环。
2. structured region 单入口；所有跨边界 edge 都有声明的 transfer。
3. 多入口只存在于 island 的 `entry_ports`，且 layout、entry、exit 闭合。
4. 每条 CFG edge、phi incoming 和 cleanup 恰有一个 disposition。
5. label arena、goto transfer、cleanup/TBC barrier 与 capability requirement 相互一致。
6. forward route 连续、无环、不穿越禁止的 label/cleanup/scope boundary。
7. unresolved value 或控制需求只能成为显式 requirement，不能猜默认值。

违反合同返回 `StructureError`；用户输入不得触发 panic/assert/expect。

## 方言能力与失败

`ControlFlowCaps` 是 Structure 与 AST 共享的目标能力事实。可规约控制流优先结构化；真正不可
规约且目标方言无对应语法时，strict 返回 unsupported error，permissive 生成明确标记的诊断
伪源码，不引入 dispatcher/state-machine fallback。

final Structure 分析失败时，Permissive 可以发布 `ProtoFailure`；失败节点不携带半成品 plan。
CFG、GraphFacts 或 Dataflow 构建失败仍是 chunk 级错误，因为此时没有可信的最后完成事实。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| block/edge ownership 异常 | `plan/arena/` 与 `plan/validate/` |
| branch continuation 错误 | `branches/`、postdom 与 condition evidence |
| loop body/exit/copy 错误 | `loops/`、`plan/loop_protocol/` |
| 短路值或 phi 归属错误 | `short_circuit/`、`phi_facts/` |
| goto/cleanup scope 错误 | label/cleanup plan 与 validator |
| 查看 Structure 产物 | `unluac --debug --dump structure --stop-after structure <file>` |
