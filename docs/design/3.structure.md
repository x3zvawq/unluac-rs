# Structure

Structure 从 low-IR 构建图与数据流事实，选择控制结构并冻结为经过验证的 StructurePlan。
它决定控制和值转移的归属，不生成 HIR/AST，也不让后层重新选择候选。

## 入口与输出

[analyze.rs](../../src/structure/analyze.rs) 的 `analyze_structure_stage` 固定推进四个子阶段：

```text
LoweredProto -> CFG -> GraphFacts -> DataflowFacts
             -> evidence -> final plan -> validator
             -> StructureFacts { Ready(plan, debug_bindings) | Failed(ProtoFailure), children }
```

proto 树使用显式后序调度。低层事实与最终 plan 都属于对应 proto，不能混用兄弟函数的身份。

候选允许重叠，最终 owner 不允许歧义。不能按 map 覆盖顺序、block 编号或先发现者选取计划。
一次性 fence 的提前出口若全部由显式跳转区域承担，则沿用该区域的控制边，不再增加循环词法域。
控制区域及其内部值转移须在同一计划中拥有明确归属，HIR 不补做候选消歧。
不可规约区域同时拥有仅由区域内唯一前驱进入的纯跳转出口连接块；共享出口和含操作的块
保持外部归属。这样内部 branch 的边界不随编译器拆分出口 pad 改变，原边动作仍由最终计划验证。
一臂离开 SCC、另一臂留在 SCC 的分支发布为退出 guard；继续路径由 island 持有，不借用外部后支配点包成另一臂。

循环内 ValueDecision 可拥有本轮回边的结果写回；其唯一循环入口以显式 edge 身份保留给
loop 的 RegionInput，未改值回边仍由 LoopCarried 消费。冻结与验证分别核对这三类输入，
不能把循环初值当作决策叶子，也不能让 loop 的携带关系覆盖内部已选决策的具体写回。

嵌套值操作数须保留对区域入口 carrier 的物理覆盖责任；未建立退休交接时保留独立值计划。
操作数计划分别保留终边的物理 incoming 与沿冻结路径投影的逻辑叶值。共享终边前的内部
phi 按该路径的入边解析，不能作为未物化的 binding 交给 HIR；validator 同步核对两种来源。
源码 binding 的无读写入也属于决策闭合性要求，不能仅按 SSA 死值删掉其根覆盖。
冻结条件通过 `plan/branch_initializers.rs` 共享两臂单值写回、条件极性及汇合点；Boolean 和单次
比较查询在此基础上限制写入值及谓词形态。HIR 据此关联当前 continuation 的 SSA 身份，即使该 phi 还包含
外层初值；完整条件准备帧则须证明 phi 仅含这两臂。无读初始化查询在这份控制事实之上
继续要求未占用、未捕获且无读者，不能将一般写回事实直接当作新声明身份。
值决策吸收内层比较时，按该节点的两条冻结路径查询相同写回事实：两臂各写互斥 Boolean
并直接汇入决策结果。外层初值不冒充本次比较写入，物理槽与当前绑定仍由 HIR 核对。
相等比较的右值若已合流、左侧调用随后才求值，须保留右值的独立边界，不能嵌入后倒置顺序。
这项原 SSA/支配事实在最大 DAG 选择前和最终操作数校验中共用；拒绝大候选不遮挡后继较小值计划。

## Dataflow 的内部职责

数据模型与查询位于 [cfg/common/](../../src/structure/cfg/common/)；
构建顺序位于 [cfg/dataflow/mod.rs](../../src/structure/cfg/dataflow/mod.rs)。

| 模块 | 事实边界 | 主要消费者 |
| --- | --- | --- |
| effects | 单条指令固定读写、效果与 capture | SSA、活性、原操作查询 |
| slot_captures | Capture/Close 沿 CFG 传播的程序点开放状态 | 内部取值候选、HIR 槽 epoch 与完整调用帧，共享不可变结果 |
| liveness、ssa、moves | 活性、Def/Phi、COPY 与 canonical 值身份 | 结构值计划、debug binding、HIR Promotion |
| scalars | 原 SSA 的未捕获标量与 MOVE/phi 传播；仅 Luau 输入可跨观察保持 | Structure 操作数选择、HIR COPY 和原槽覆盖 |
| open | 开放结果定义及读取来源 | CALL、RETURN、VARARG 和 SETLIST 协议 |
| execution、scratch | 执行事件与入口/临时槽状态 | 观察分析与物理根恢复 |
| overwrites、root_exits | 原槽覆盖和根结束边界 | HIR 生命周期分析 |
| plain_tables | 私有表初始化归属与具体读取性质 | 条件和值决策依赖、HIR 初始化恢复及无元方法读取查询 |

`compute_dataflow_facts` 显式接收输入 chunk 的实际方言；标量事实不能按输出目标方言签发。
共享标量查询只描述原 CFG/SSA 的值，不替代物理 scratch 和捕获 cell 的证明。
Luau 的 LENGTH 正常结果按 VM 合同为 number；该结果沿 MOVE 和直接算术定义链
传播，普通算术的其它操作数也须具有数值证明。GC-inert 事实继续沿 MOVE/phi
传播；此数值链分析不扩展到常量算术或跨 phi 的类型推导。原求值、错误、物理
scratch 和捕获边界仍独立验证。
当前原型常量池持有的字符串具有 GC-inert 生命周期事实，沿同一 SSA 传播；
动态字符串结果不从常量池锚定事实取得许可。

逻辑活跃性与根保留需求共用一次指令 use/def 采集及 block defs，分别求解并发布；物理观察
只扩充根保留输入，不作为真实读取写入逻辑活跃性或 SSA use-site。

固定值、开放值包和物理残值是不同事实域。逻辑 Entry 未定义不等于物理槽是 nil；
入口清槽保证由 Transformer 发布。读取原值身份须调用 Dataflow query，
不能逐消费者回扫指令、重新跟踪寄存器，或把普通位置查询当成 reaching 证明。
固定读取集合与单条指令中的重复操作数分别保留；SSA use-site 数量不能代替表达式读取次数。
原 method setup 与调用的唯一配对由 [Dataflow 查询](../../src/structure/cfg/common/methods.rs)
证明；Structure 用它区分隐式 receiver 转交，HIR 将相同端点映射为方法协议。
配对不授权移动 lookup、改变参数顺序或延长物理根，完整帧仍负责这些证明。
条件和值决策共享 [区域依赖查询](../../src/structure/analyze/dependencies.rs)，
结果仅对当前 CFG/SSA 与调用方指定的区域有效。整函数 capture 与程序点开放 cell
是不同事实，消费者按所需身份和时间边界选择查询。
私有表初始化按原分配 Def 关联字段或列表写入：同块内尚未发布、没有别名或捕获，
并由原分配容量与批次协议证明可重建时，初始化 base 的读取不算重复求值。
依赖闭包同时包含这些写及其固定/开放输入；HIR 吸收内部节点时必须完整恢复初始化，
不能只发射空的分配 seed。结果 phi 的边转交仍由决策闭合性证明，不计为再次求值；
该事实不授权跨块移动、混排字段求值或消除物理根。

## 观察期间的物理 root 事实

Dataflow 描述原 VM 的物理槽残值、覆盖和观察点，HIR 负责把这些事实映射到源码生命周期。
原生调用结果宽度、数值循环写回、Close 和入口清槽都由显式协议驱动，不能从表面语法推断。

原值的逻辑使用结束、物理槽被覆写、源码 local 退出是三个不同事件。
后层只能通过原来源查询组合它们，不因 SSA 死值就删除仍可被 GC、弱表或闭包观察的根。
物理根的保留需求与逻辑读取活性独立表达；后层消费显式来源和覆盖关系，
不得伪造 SSA use 或把“没有逻辑读取”当作原槽已经清空。

资源 scope owner 复用 TBC 的 CFG may-flow，发布原指令执行前各槽的活动状态。
该程序点事实包括回边和分支汇合，不能以同一 home 曾被注册或 PC 顺序代替；
HIR Promotion 将它绑定到原固定定义，后续改写不重新从语句位置猜测资源身份。

## Region 与 Island

structured region 表达单入口控制结构；island 保留无法纳入该结构的多入口区域及显式布局。
island 的成员关系与直接 owner 分开，内部可规约部分仍可拥有自己的 Branch/Loop。

region 导航先确定拓扑与包含关系，再冻结布局及正常完成路径。
边的归属、loop 内外关系和正常尾路径必须消费这些正式查询，不能只按目标 header 判断。
island 也必须保存清理和作用域边界，不是任意重新排列基本块的许可。
控制条件与值决策的归属由 Structure 冻结，条件依赖关系不等于单次求值证明。
准备区中的共享值、源码初始化及原写入须有明确 owner；HIR 只按计划消费，
不根据表达式外形补回绑定或重新划分控制域。

分支布局、正常 continuation、循环出口与 cleanup 是不同事实。
候选改变控制端点时，最终计划必须保持这些关系一致；具体重算条件由 final-input owner 负责。
单遍围栏的共享尾域入口与正常完成块分别冻结；尾域可含提前 RETURN，但非函数出口必须
唯一，且只有一个正常完成边。围栏持有整个尾域，逃逸边只来自其前缀；原返回与资源边界
保持各自 owner，不能把正常完成块的位置当成尾域入口。
普通 if/else 的正常结果合流由原入边和值 phi 闭合证明持有；提前 RETURN 使严格后支配点
变为函数出口，不撤销已确认的正常合流，也不能据某个选值叶子的多入口形状建立围栏。
完整短路条件直接退出当前循环时，最终分支消费循环分区的出口与正文事实，
把正常路径保留为外围正文 continuation，避免原首分支的局部合流制造过早结束的词法域。
普通分支的最终 containment 由各臂支配域和条件区域共同限定；header 支配的共享出口
不因此归入单臂 guard。正常 continuation 的关闭边界由 scope owner 独立消费。
分支独占的直接回边块即使含有更新前缀，也由原 continue 臂持有；当另一臂绕过它汇入共享
tail 时，不能仅凭回边在 loop header 的 frontier 将此前缀选作正常 continuation。
直接进入已确认循环纯条件块的分支同样保留 continue 归属，不能把控制目标当成普通 merge，
使已退出本轮正文的路径继续执行外围分支之后的共享 tail。
原检查链的各条路径汇入 while 的同一纯回边时，最近 owner 发布显式 continue；共享
回边的短路项因此保持完整条件，链外正文与其它出口仍沿用原布局。转发路径仍须
通过既有作用域、边动作及循环归属验证，交叠循环不能按候选枚举顺序认领。
没有正常 continuation 的循环仍拥有只通向函数出口的闭合提前返回臂。正文中的共享
短路节点由完整条件 DAG 证明归属；条件安全分析同时向分量构建发布独立入口边界，
保留源码声明及谓词之外的原操作，避免先吞入正文后才截断条件而丢失闭合区域。

## Final Plan 合同

循环计划区分 VM 控制槽、源码 binding 和循环阶段；debug 绑定事实关联原初始化与 scope。
HIR 消费已接受的身份和发射位置，Naming 再决定名称，后层不按槽号或当前语句形状重建归属。
正常出口的词法边界同时消费 TBC 活动状态和 Capture/Close 程序点事实；内层捕获槽
关闭后的操作仍须保留在外层资源的原生命周期内。

`PhiPlan::loop_carried` 分别发布循环 owner 与可选的唯一入口值：多条正常或提前出口汇入
下一循环时，路径相关初始化仍可具有确定的循环归属。需要初始化身份的 debug/capture
消费者要求全部入口值一致；仅处理循环状态的消费者不以入口边数量否定该归属。
上游分支结果与后续兄弟循环入口共用 phi 时，header 身份归后续循环，上游写入仍在原边执行；
不能因结果来自分支而丢掉入口与回边共同证明的循环归属。已吸收原边的 ValueDecision
仍独立持有表达式写回，不能转成循环入口的额外边复制。

repeat 分区从已选完整条件 DAG 冻结 continue 入口，边分类、控制目标查询与循环 payload
共同消费它；候选的末叶不能替代整个 until 条件。短路分支的正文绕过证明使用语义出口，
不把同一条件内的后续节点当作被跳过的正文。退出值暂存消费条件入口的 canonical SSA，
保持提前 continue、正常完成与提前 break 各自的值来源。
条件入口同时持有下一轮状态写入时，末尾分支的正常汇入消费 Dataflow 的同槽回写和
导航层的完整 body 完成证明，避免制造 continue 并前移状态前缀；纯条件入口、已证明的
语义 continue 及经关闭或转发路径的词法退出仍保留原控制合同。

| 产物 | 生产者 | HIR 消费方式 |
| --- | --- | --- |
| RegionPlan / 导航 | arena、navigation | 递归执行选定结构 |
| EdgePlan / EdgeTransfer | arena、finalize | 在指定边发射唯一控制转移 |
| PhiPlan / value actions | value、loop_protocol | 执行已归属的并行复制及循环阶段写 |
| cleanup / action placement | cleanup、finalize | 在原求值与终结顺序中执行清理 |
| BlockEmissionPlan | terminator、finalize | 消费非控制前缀及已冻结的终结 |
| LabelPlan / requirements | arena、finalize | 保留必要 label 和目标能力要求 |
| DebugBindingFacts | analyze/debug_bindings | 消费已接受的 SSA 或分支初始化与 scope 的关系；名字仍由后层决定 |

debug 初始化身份与活动区间分开保存，零长度区间不等于不存在源码声明。
多个区间的归属或冲突由 `analyze/debug_bindings` 统一判定，不以扩大活动区间掩盖事实不足。
同起点的内联名称视图也须保留外层初始化 owner；只有只读、无引用捕获的严格内含区间才能共享该身份。
`readonly_view` 单独发布内嵌区间到已有初始化的只读关系，不为别名建立新的声明。
只读 debug 视图在稀疏 SSA 缺少入口值时，使用初始化支配子树内的固定定义索引及开放写入、
调用保活边界补证。子树外的同槽复用不否定本次初始化；视图仍须属于同一源码生命周期，
并由该初始化支配，不能只凭名称和物理槽认领参数身份。
HIR Promotion 保留原区间的存在性，并在 home 身份失效后停止提供该值。

最终验证必须保证：

- 每个 reachable block 恰有一个 containment owner，区域包含关系无环。
- structured region 单入口；island 的 entry、exit、layout 闭合。
- 每条 CFG edge、phi incoming 和 cleanup 恰有一个 disposition。
- loop 协议、normal tail、label、scope barrier 与能力要求一致。
- route 连续且不越过未获许可的控制、值或清理边界。
- unresolved 需求显式记录，不补默认值；验证失败不发布半成品 plan。

这些是层间不变量。具体候选识别、等形判定和 guard 由相应实现及回归负责。

## 方言能力与失败

`ControlFlowCaps` 是目标语法能力的共享事实。无法结构化且目标无法表达的控制流在
Strict 下显式失败，在 Permissive 下成为明确诊断；不引入隐藏 dispatcher。

final Structure 失败可发布 ProtoFailure，不能携带可消费的半成品 plan。
CFG、GraphFacts 或 Dataflow 失败仍属于 chunk 级错误。

## 排错

| 现象 | 首查 |
| --- | --- |
| 块或边缺失 | cfg/build |
| reaching 值、开放包或根错误 | cfg/dataflow |
| branch continuation / 短路方向错误 | branches、short_circuit、analyze/conditions |
| 循环分区、break/continue 归属错误 | loops、plan/arena、loop_protocol |
| phi / cleanup 重复或遗漏 | plan/value、cleanup、finalize、validate |
| debug binding 错误 | analyze/debug_bindings 与 Transformer DebugLocals |
| plan 正确但 HIR 错误 | HIR analyze/structure 的消费与 verification |

结构 dump 同时提供 CFG、图事实、Dataflow 与 final plan，命令见 [调试手册](../debug.md)。
