# Structure

> **职责**：从 low-IR 构建控制流、图事实、数据流事实，并把这些事实翻译成源码恢复候选。
>
> **不负责**：最终 HIR 语法决策、AST 语法糖、最终命名。
>
> **例子**：`branch_edges(B3) + phi_candidates_in(B5)` → `BranchCandidate { header: B3, merge: B5, arms: [B4a, B4b] }`

## 入口

```
src/structure/mod.rs
  analyze_structure_stage(state, context)      -- 依次写回 CfgGraph / GraphFacts / DataflowFacts / StructureFacts
```

CFG、GraphFacts、Dataflow 和 StructureFacts 是 Structure 内部固定子步骤；pipeline 外层只维护 `structure` 一个 stage / dump。

## 模块布局

```
src/structure/
  mod.rs          Structure 层入口 + 类型导出
  cfg/            CFG / GraphFacts / Dataflow 构建与调试
    build.rs        CFG 切块
    graph.rs        支配 / 后支配 / 回边 / 自然循环
    dataflow/mod.rs 数据流分析与事实组装
    common/         CfgGraph / DataflowFacts / GraphFacts 等共享类型
    dataflow/
      effects.rs    指令 use/def 与副作用
      liveness.rs   固定寄存器活跃性
      ssa.rs        pruned SSA 构建、重命名与 use graph
      open.rs       open result pack 的临时 SSA
    debug.rs        CFG / GraphFacts / Dataflow dump 片段
  common.rs       结构候选类型
  analyze.rs      StructureFacts 构建骨架
  helpers.rs      region / entry / exit / predecessor / reducible 共享查询
  phi_facts.rs    phi → 结构候选翻译
  branches.rs     branch 候选识别
  branch_values.rs  branch value merge 候选识别
  loops.rs        loop 候选识别
  goto.rs         GotoRequirement 识别
  regions.rs      region block 收集
  scope.rs        ScopeCandidate 识别
  short_circuit/  短路条件与值合流候选
  debug.rs        dump_structure
```

## 数据流

```
LoweredProto
  └─ cfg::build_cfg_graph
       └─ CfgGraph
          └─ cfg::analyze_graph_facts
             └─ GraphFacts
                └─ cfg::compute_dataflow_facts
                   └─ DataflowFacts
                      └─ analyze_structure_proto
                         └─ StructureFacts
```

固定寄存器只有一条 canonical SSA 管线：先基于真实 use/must-def 求活跃性，再用
iterated dominance frontier 放置 pruned phi，最后沿 dominator tree 重命名。
`SsaValue::{Entry, Def, Phi}` 是 block 边界、指令 use、branch/loop/short-circuit
候选共享的唯一值身份；`SsaRegMap` 只保存活跃寄存器，不按指令复制完整寄存器状态。
Dataflow 同时保存 `Def/Phi -> instruction/Phi use` 图，跨 phi 的逃逸查询直接遍历这张图。

open result pack 的宽度由消费点决定，不能伪装成固定寄存器 SSA。`open.rs` 在 Dataflow
内部建立独立的临时 pack SSA，合流时按实际来源解析 fixed-prefix use，最终只向公共事实
投影 `OpenUseSources { has_entry, defs }` 与 open liveness。多个 pack 来源具有不同起始
寄存器时，所有路径共有的 fixed prefix 才进入 canonical SSA use，路径条件下可能读取的
更宽 prefix 只进入 liveness；不能把 may-use 伪装成唯一 SSA use。固定寄存器 SSA 与
open pack 不维护平行的 reaching-def/value 解算器，也不保留没有生产者语义的 may-def 字段。

## 关键类型

| 类型 | 说明 |
|---|---|
| `CfgGraph` / `Cfg` / `BasicBlock` / `EdgeKind` | block、边、reachable successor 形态、唯一 predecessor 和基础控制流查询 |
| `GraphFacts` / `DominatorTree` / `NaturalLoop` | 支配、后支配、回边和自然循环 |
| `DataflowFacts` / `DefId` / `PhiId` / `InstrEffect` | def-use、phi、活跃性和副作用 |
| `StructureFacts` | 所有源码恢复候选的统一容器 |
| `BranchCandidate` / `LoopCandidate` / `ShortCircuitCandidate` | HIR 消费的结构候选 |
| `GotoRequirement` / `ScopeCandidate` / `GenericPhiMaterialization` | 必须保留的控制流约束和 fallback phi 物化候选 |

## 维护规范

1. **图和数据流事实属于 Structure**：后层需要稳定 block/edge/dataflow 查询时，优先补到 `src/structure/cfg/common/`，不要在 HIR 或 AST 重扫容器。
2. **结构证据应尽量前移**：HIR 需要的 phi 分类、merge arm、loop binding、short-circuit leaf 等事实优先补进 `StructureFacts`。
3. **候选与最终决策分开**：Structure 只回答“像不像 branch/loop/short-circuit”，最终语法选择交给 HIR。
4. **共享实现优先**：region、phi、短路和图查询先复用已有 helper；同类形状漏收时扩展 owner，不平行新建 pass。
5. **irreducible region 判定看入口目标**：同一个 SCC 可以有多条外部前驱边；只有外部入口落到 region 内多个不同 block 时，才标记为 irreducible 并要求 goto。`LoopCandidate` 只来自“目标支配来源”的 natural backedge；编译器把 latch 优化成不可达块时，退化 generic/numeric-for 也必须用 init/loop 指令身份和区域边界显式配对。Luau 的立即 `break` 还可能让不可达 numeric latch 的 exit 先经过单条 jump pad 再汇入 init exit；这种透明 pad 可视为同一边界，但不能放宽寄存器身份匹配。因此候选本身保证可规约，不再保存恒真的 `reducible` 状态；不可规约控制流由独立的 `IrreducibleRegion` 表达。
6. **generic phi 物化只排除已消费候选**：如果某个 short-circuit / branch 候选因 irreducible 等原因不会被 HIR 消费，它对应的 phi 仍要保留 generic 物化，避免候选被拒后 merge 值失去 owner。loop 静态排除 natural loop 必然接管的 header phi；如果更外层 branch 已完整覆盖某个 loop exit phi 的所有来源，该 phi 同样只归 branch，不再让 loop 重复物化。其余 exit phi 是否能复用 loop state 取决于 HIR 的初值和 target 对齐结果，因此保留 generic 候选，并在 HIR 成功安装 override 时动态抑制。Structure 同时标记 generic phi 的保守来源；只有所有 incoming 都等于 idom 出口值时才暴露 `IdomExit`，否则明确标成 `Unresolved`。
7. **同一区域候选必须稳定归并**：同一个 `(header, merge)` 可能同时被普通 branch region 和 guard/short-circuit 视角识别为 branch-value merge；Structure 应在前层归并为单一候选，先比较覆盖 phi 数，等长时优先保留 guard 的精确叶子分区。不同分析器产出的完全相同 short-circuit 候选应精确去重，但不能合并 arm 分区互相冲突的候选。
8. **for-binding 作用域属于 loop 候选事实**：`LoopCandidate.binding_scope_blocks` 除 natural loop body 外，还包含被 header 支配的提前退出 tail；HIR bindings 只消费这个集合，不重新用 CFG / DominatorTree 计算词法作用域。
9. **debug 分段不等于架构层**：`structure` dump 会按 CFG / GraphFacts / Dataflow / StructureFacts 分段输出，但外层仍只有 Structure。
10. **无出口循环的分支合流以本轮边界为准**：可规约无限循环没有严格后支配点；Structure 应先寻找两臂在重入 loop header 前的局部 merge，只有不存在局部合流且两臂都能回到同一 header 时才把 header 暴露为本轮 merge，避免普通可达性沿回边把 if/else 误判成单臂分支。
11. **loop header 不是候选唯一身份**：Luau 可能让外层 numeric-for body 与内层 while 共用同一个 CFG header。Structure 应先用精确匹配的 `NumericForInit/Loop` 认领外层回边与受支配区域，再处理剩余自然回边。普通 same-header natural loops 只有在内层包含 header 外的真实 body、内层所有结构出口仍属于组合后的外层、外层有真实出口，且 header 的两个 successor 分别进入内层 core 与 `outer - inner` 时才拆层；内层分支若直接退出整个组合区域，这些回边只是同一 loop 的 sibling latch。outer-only successor 可直接拥有无条件回边，或先执行任意 outer body，再由独立尾条件通过直接边或透明 Close/jump pad 在 header 与 loop exit 之间分流；body 中的赋值、调用和 early break 不属于条件依赖，不应阻断外层候选。单块 retry、无出口循环和提前 continue 等普通多回边形状也仍归并成一个候选。同 header 嵌套链的 header phi 只归最外层候选，不能在多个循环间重复消费。numeric latch 正常出口上的透明 jump pad 记录在 `LoopCandidate.control_blocks`，表示它已被 for 语法吸收而不是源码 body。
12. **歧义 repeat 需要候选关系证明**：`repeat ... until cond; break` 嵌在 for 内时，条件出口可能直接越过外层 for，使内层 natural loop 的 exits 看起来全是 terminal；repeat body 的一臂进入 nested loop 时，该入口也会落在 natural-loop core 外，使 body header 看起来像 while 条件。单看 backedge pad 无法排除真实 `while + 尾部 break`。Structure 应在候选齐全后用关系证据消歧：`WhileTrueLike` 只有与词法外层 numeric/generic-for 共享出口时才精化；`WhileLike` 还要求 core 外分支进入 `binding_scope_blocks` 内 nested loop 的 header/preheader，且独立尾条件与 header 分支读取相同的 predicate/operands，才精化成 `RepeatLike`。
13. **复制的单指令 return 可以规范化为同一 for 出口**：Luau 可能让 `NumericForInit` 的零轮出口和 `NumericForLoop` 的正常出口落到两个不同 block；只有两块都恰含一条且 `ReturnInstr` 完全相同时，Structure 才把 latch return 从 loop region 移出、保留 init 与 latch 两个语义出口，并把复制块记入 `control_blocks` 交给同一 numeric-for 吸收。带赋值、cleanup 或不同返回值的尾块不得套用此规则。
14. **短路 repeat 与退化 generic-for 依赖候选关系精化**：`repeat ... until a and b` 的 body prefix 可能与首个条件共用 loop header，回边前又有共享 jump pad；普通短路候选不足时，Structure 只为 loop 补充按 CFG 真假边收齐的无环候选，再用“短路两出口恰为 loop exit 与 backedge pad”把 `Unknown/WhileTrueLike` 精化为 `RepeatLike`，并记录被选中的条件入口。无自身回边的 generic-for 若 body 是唯一以该 header 为 preheader 的 nested loop，应把该 nested region 纳入候选；其 header 到 exit 的零次迭代边仍属于出口 phi 的外侧初值，不能按完整候选 blocks 误归为循环内写回。
15. **退化 branch 的同目标边不是未结构化 continue**：若 branch 的真假边都落到同一个 loop continue target，该条件不改变控制流，HIR 会按线性 successor 消费；goto 约束不得把其中任一边标成 `UnstructuredContinueLike`。只有两臂目标不同、且 branch/loop 候选都无法吸收的提前跳转才需要保留 goto requirement。
16. **相邻 loop 的边界 phi 归后继 header 所有**：前一 generic/numeric loop 的 exit 若正好是后一 while/repeat/for 的 header，同一个 phi 可能同时落入前者的 `exit_value_merges` 与后者的 `header_value_merges`。该 phi 只归后继 loop state；Structure 应从前一 loop 的 exit values 移除它，避免前层用后继回边值反推前一 loop 的初值。
17. **退化 numeric-for 可以与 nested loop 共用 header**：Luau 会把首轮必 break 的 numeric latch 变成不可达块；若 body 以 while/repeat 开头，`NumericForInit` 的 body target 同时也是 nested natural-loop header。精确匹配的 init/latch 仍应建立外层 `NumericForLike` 候选，只需排除该 header 已有另一个 numeric-for owner，不能因任意 grouped loop 占用 header 就丢弃 for 候选。
18. **跨层 escape 只能消费直接控制边**：loop 内 branch 的隐式 else 若直接落到外层 merge，可恢复为 escape；显式 else 臂在到达 merge 前仍可能包含语句或二次分支，HIR 不得跳过该 region 直接生成 `goto`，应退回普通 branch lowering 完整消费两臂。
19. **repeat 尾条件可以只有一个节点**：`continue`/`break` 会让 natural-loop header 偏离源码 repeat body，Structure 只要确认条件候选的两个出口精确对应 loop exit 与 backedge pad，就可把 `WhileTrueLike` 精化为 `RepeatLike`；普通 `until cond` 不应因短路节点数小于二被丢弃。Luau 的 `GenericForLoop body_target == exit_target`，或 `exit_target` 只经过单条透明 jump pad 便汇入 `body_target`，都表示 `for ... do break end`；应建立仅由 header 持有的退化 generic-for 候选，不能当作空 body 或无循环。
20. **numeric-for 的尾部 continue pad 属于源码 body**：Luau 会把仅以 `continue` 收尾的 numeric-for 编译成 `NumericForInit -> body pad -> NumericForLoop`，其中 latch 的 body edge 指回 latch，而 init 仍指向前置 body pad。Structure 应沿 latch 的直接 jump 前驱寻找唯一且状态/出口匹配的 init owner，用 body pad 作为候选 header 并认领自然回边；不能把 latch 自回边留下成独立 unknown loop。
21. **共享 backedge pad 的 continue 所有权落实到 edge**：branch 的某一臂可能先进入仅含 jump 的 natural-backedge source，再回到 loop header；只记录 `continue_target=header` 无法区分该 pad 属于哪个同层/嵌套候选。Structure 应在 loop 形态精化和 branch 候选齐备后，为“branch edge -> 当前候选真实 backedge pad/target”选择词法域最小的唯一 owner，并记录到 `LoopCandidate.continue_edges`；循环自身 continue target 的条件边、同目标退化 branch 和兼任条件求值的 `RepeatLike` backedge pad 不产生间接 continue edge。
22. **loop 内局部 break 不应把 one-arm merge 推到 loop exit**：branch 一臂含局部 break、另一条自然路径又穿过 nested loop 时，普通可达性会被外层回边污染，严格后支配点也可能落到 loop exit。若 loop-bounded 可达性证明一臂在本轮内进入另一臂，应优先恢复局部 one-arm merge；但进入单后继 backedge pad 的边表示 `continue`，不能借下一轮回边伪装成本轮局部可达。
23. **repeat body header 的 break pad 不是 while post-loop**：repeat body 若以条件 break 开头，natural-loop 会把 body header 暂时识别成 `WhileLike`，并把该条件的外侧入口列为候选 exit。Luau 的尾条件经唯一 jump pad 回边时，若 body header 的唯一外部入口不同于尾条件出口且被其严格后支配，应恢复 `RepeatLike`；Lua 5.1–5.5 的尾条件可能直接回到 header，此时若尾条件 exit 跳过 header-exit branch pad、直接进入该 pad 的既有 merge，也应恢复同一形态。真实 while 的 header 直接退出到公共 post-loop，不满足这两类关系。
24. **branch 外部臂与 loop backedge 可以组合拥有 header phi**：前置条件分支直接汇入 repeat/while header 时，同一个 phi 的外部 incoming 属于 BranchValueMerge，回边 incoming 属于 LoopCandidate。BVM 分臂应先认 then/else predecessor，再跳过该 header 已有 loop owner 的其余 incoming；不能因回边不属于任一 branch arm 就丢弃整个值候选，也不能把 branch arm 自身仅因位于 loop blocks 内而忽略。
25. **双臂 early return 的 soft merge 来自共同 dominance frontier**：if/else 两臂都含 early return 时，严格共同后支配点会被推到 synthetic exit，真实 fallthrough join 也不会出现在任一臂的 ipostdom 链。Structure 应从两臂 entry 的 dominance frontier 交集中排除 synthetic exit，并要求 branch header 支配候选，防止内层分支跨 owner 或跨循环迭代抢占外层 join；若剩余多个候选，只接受能支配其余候选的唯一最近 join。不能用全图绕路可达性猜 merge，也不能把未恢复的尾部 phi 留给 HIR generic fallback。
26. **repeat backedge pad 只承载透明控制**：branch 条件经 backedge pad 回到 header 时，pad 只有在前缀为空或仅含已由词法 scope 吸收的 `Close` 才能作为 repeat 控制。赋值、调用等普通前缀属于 while/retry body 尾部；Structure 若把它误认成 repeat 条件，HIR 会在降条件时跳过本轮副作用。
27. **loop-bounded 可达性按入口选择候选身份**：分支分类把已确认 loop 当作只通向显式 exits 的结构化节点；同一 header 存在多个候选时，必须用到达 header 的 predecessor 匹配唯一 preheader，只有单候选 header 才可省略入口证明。无法唯一选择时保持不可达，不能取列表首项或合并 exits；每个入口一次计算完整目标集，避免为不同 merge 重复遍历 CFG。
28. **dataflow 只保留 canonical SSA**：固定寄存器活跃性的 live-in 变化只重新排入 reachable predecessors；phi 由 pruned IDF 一次放置，值身份沿 dominator tree 重命名，不再运行 reaching-def / reaching-value 双固定点。block entry/exit 和真实 instruction use 只保存稀疏活跃值，不能恢复按指令复制全寄存器状态的实现。open pack 使用独立临时 SSA，公共结果必须同时保留函数入口来源与实际 `OpenDefId`；两者合流时不能丢掉 Entry 后误认成唯一 producer，也不能与固定寄存器值混成第二套通用 value solver。
29. **多出口 loop 的共同透明 continuation 仍是 exit owner**：同一 loop 的多条 `break` 可能先落到不同 exit pad，再在下游 block 合流；若每条路径只跨越前缀为 `Close`、末尾为 `Jump` 的透明 pad，Structure 应把共同 continuation 的 live-out phi 记入该 loop 的 `exit_value_merges`，并把这些 pad predecessor 视为 loop 内来源。赋值、调用、`Tbc` 或分支会改变值/作用域，不得跨越它们继续扩 owner。
30. **普通 one-arm 优先复用后支配事实**：一臂入口严格后支配另一臂时，可直接把前者认作 merge，无需重新遍历 CFG。early return 等不满足后支配关系的剩余形状再按 `(source, target)` 做早停可达性查询，并只缓存布尔结果；不能为每个 source 保存全图目标集。loop-bounded 分类会从同一入口反复查询多个候选，仍按规则 27 共享完整目标集。
31. **numeric-for 的 break/continue 分支以本轮 soft merge 为界**：branch 与 numeric-for 共用 header，且一臂 `break`、一臂 `continue` 时，严格共同后支配点会落到 loop exit，普通可达性还会沿 backedge 把下一轮入口误认成本轮 one-arm。Structure 只有在同一 `NumericForLike` owner 内才能把直接 exit 臂恢复为 guard，或从共同 dominance frontier 选择本轮 soft merge；若 backedge 让两臂的 merge predecessor 重叠，只按 entry dominance 剔除能唯一归属的污染 predecessor，歧义来源仍保留给保守路径。

32. **for binding 不跨越多出口的共同后继**：Lua 5.5 generic-for 可以让 `break` cleanup 与正常 cleanup 成为两个物理 exit，再共同进入 post-loop。`binding_scope_blocks` 仍包含每个 exit pad，但若所有 exit 都有同一唯一后继，该后继就是提前退出 DFS 的词法边界；不得把 for binding 带入循环外的寄存器复用块。后继不同或非唯一时保持原边界，不凭可达性猜测合流。

33. **loop 内 synthetic postdom 仍允许本轮单臂证明**：嵌套 branch 的 early return 可以把外层分支两臂的严格共同后支配点推到 synthetic exit，但其中一臂仍可能在当前迭代内自然进入另一臂。只要 enclosing loop 同时持有 header 与两个 entry，且 strict merge 是该 loop 物理 exit 或 synthetic exit，Structure 就使用已有 loop-bounded 查询截断回边后判定 one-arm。查询无法证明单向可达时仍保留 if/else 或 guard，不因 synthetic exit 直接改写候选。
34. **value-merge root 由 merge 的直接支配者唯一确定**：合法短路 DAG 的 root 既支配 phi merge 的所有 predecessor，又必须在两臂间产生分叉，因此就是 merge 的 immediate dominator；若该 block 不是 branch header，或 phi 含函数入口虚拟 incoming，就不存在值合流短路候选。不得再为每个 phi 枚举全部严格支配 branch。支配/后支配使用预序子树区间做 O(1) 祖先判断，避免顺序 branch 链退化成平方复杂度。

35. **canonical SSA incoming 直接表达本地 producer**：phi incoming 若在 predecessor 内最后写入结果寄存器，其值身份必为该 block 的 `Def`；`Entry` 或另一个 `Phi` 表示该 predecessor 没有本地 producer。Structure 应直接检查这个 SSA 身份，不能为每条 incoming 递归展开完整 leaf-def 链再反查来源。

36. **repeat 条件链入口支配最终回边源**：将 `WhileTrueLike/WhileLike` 精化成 `RepeatLike` 前，被选中的完整条件链入口必须支配真实 backedge source。`a and b` 的最终节点不必支配短路失败路径，因此不能拿任意单节点候选先占位；应继续寻找入口支配回边的完整补充候选。若连条件链入口都可被绕过，它表示 while 中的提前 `continue`，不能改写成 repeat。

37. **loop 内 if/elseif 的 merge 以本轮 soft join 为准**：严格后支配把外层候选误判成 one-arm，且被当作 merge 的下游 branch 明确退出同一最小 loop owner 时，Structure 才截断 loop header 验证两臂本轮互不可达，并从共同 dominance frontier 选择两臂本轮都可达的 soft merge，精化成 `IfElse`。普通 guard、布尔短路和没有下游 loop-exit owner 的分支不得套用该规则。

38. **带语句的 continue 臂由终端 edge 持有**：`if cond then update; continue end` 的分支边先进入带普通语句的线性臂，真正 continue 是该臂末端到 loop continue target 的 edge。若该单臂路径在到达 branch merge 前始终只有唯一后继，Structure 应把终端 edge 交给最小 loop owner；goto 分析不得再把已认领 edge 标成未结构化跳转。路径穿过 merge、分支或离开 loop blocks 时保持未证明。
