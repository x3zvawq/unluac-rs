# Structure

> **职责**：从 low-IR 构建 CFG、图事实和 canonical SSA，并冻结为经过强校验的 `StructurePlan`。
>
> **不负责**：生成 HIR/AST、命名，或让后层重新选择结构候选。

## 入口与输出

```text
LoweredProto
  -> Cfg / GraphFacts / DataflowFacts
  -> structure evidence
  -> StructurePlan
  -> StructureFacts {
       outcome: Ready { plan, debug_bindings } | Failed(ProtoFailure),
       children
     }
```

入口为 `src/structure/analyze.rs::analyze_structure_proto`。proto tree 使用显式 postorder 调度；
父 proto 只在所有 child facts 完成后构建和验证自己的 plan。

## 模块 owner

```text
src/structure/
  analyze.rs / analyze/       阶段调度与输入事实整理
  cfg/                        CFG、GraphFacts、DataflowFacts
  branches.rs / branches/     branch evidence 与候选
  loops.rs / loops/           loop evidence 与候选
  short_circuit/              短路控制和值合流证据
  phi_facts.rs / phi_facts/   phi disposition 候选
  common.rs                   evidence 与 final plan 模型
  common/plan_access.rs       StructurePlan 只读查询
  plan.rs / plan/             arena、loop protocol、finalize 与 validator
  diagnostic.rs               proto 失败的紧凑诊断产物
```

CFG、SSA、region arena 和 validator 状态各自只有一个 owner。子模块按关注点拆分，但不能复制
事实或建立可独立漂移的候选选择路径。

## Region 与 Island

`StructurePlan` 是分层控制流图，不强制把所有 CFG 压成树：

```text
containment tree
  Sequence | Branch | ValueDecision | Loop | Block
  Unstructured island -> island 内保留局部 CFG edge
```

- structured region 使用唯一父节点的 containment tree，并满足单入口和声明出口。
- 无法满足结构约束的最小闭合区域成为 `Unstructured` island。
- island 可以包含已验证的 structured child，但每个 reachable block 仍只有一个直接 owner。
- 可规约结构不会因目标方言支持 `goto` 而主动降级；原源码拼写无法由 bytecode 唯一恢复时，只
  承诺控制语义，不承诺保留原始 `goto`/loop 写法。

## Final Plan 合同

| 索引 | 唯一事实 |
| --- | --- |
| `RegionId -> RegionPlan` | containment 与 island layout |
| `BlockRef -> BlockTerminatorPlan` | 指令范围和精确 successor edge |
| `EdgeRef -> EdgePlan` | transfer、forward route 与 phi copies |
| branch/loop/condition/value-decision ID | 已选且规范化的 payload |
| `LabelPlanId -> LabelPlan` | label、cleanup 相对位置与 TBC scope barrier |
| `PhiId -> PhiPlan` | 每个 incoming 的唯一 disposition |
| `InstrRef -> CleanupDisposition` | cleanup 的唯一 region/scope owner |
| `PlanRequirements` | 目标语法能力与 unresolved 诊断 |

`EdgePlan` 是控制动作和值动作的唯一来源。透明 jump pad 只能通过冻结的 forward route 跳过，
route 上的 copy 按执行顺序复合且只执行一次。VM-for 隐式消费的 control/binding copy 仍保留
canonical SSA 身份，并由精确 edge/phi origin 证明其 disposition。

## 构建阶段

1. 从 CFG、dom/postdom、SCC、canonical SSA 和方言 protocol 提取 branch、loop、短路、cleanup
   与不可规约 evidence。候选可以重叠，但 edge、phi incoming 和 cleanup 不能失去 owner。
2. 规范化 containment，合并同 header 的循环域，确定 branch continuation、loop partition、
   normal tail 与最小 island。候选间有归属歧义时不能按 block id 或遍历顺序任选。
3. 冻结每条 edge transfer、value action、cleanup、label 与目标能力 requirement。
4. 运行 final validator；只有完整通过的 plan 才发布给 HIR。

具体候选判据属于 `branches/`、`loops/`、`short_circuit/` 与 `plan/` 的文件头和代码注释，不在
本文逐形状列举。

## 必须成立的不变量

1. 每个 reachable block 恰有一个 containment owner，containment 无环。
2. structured region 单入口；所有跨边界 edge 都有声明的 transfer。
3. 多入口只存在于 island 的 `entry_ports`，且 layout、entry、exit 闭合。
4. 每条 CFG edge、phi incoming 和 cleanup 恰有一个 disposition。
5. label arena、goto transfer、cleanup/TBC barrier 与 capability requirement 相互一致。
6. forward route 连续、无环、不穿越禁止的 label/cleanup/scope boundary。
7. unresolved value 或控制需求只能成为显式 requirement，不能猜默认值。

违反合同返回 `StructureError`；用户输入不得触发 panic/assert/expect。

## 方言能力与失败

`ControlFlowCaps` 是 Structure 与 AST 共享的目标能力事实。可规约控制流优先结构化；真正不可
规约且目标方言无对应语法时，strict 返回 unsupported error，permissive 生成明确标记的诊断
伪源码，不引入 dispatcher/state-machine fallback。

final Structure 分析失败时，Permissive 可以发布 `ProtoFailure`；失败节点不携带半成品 plan。
CFG、GraphFacts 或 Dataflow 构建失败仍是 chunk 级错误，因为此时没有可信的最后完成事实。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| block/edge ownership 异常 | `plan/arena/` 与 `plan/validate/` |
| branch continuation 错误 | `branches/`、postdom 与 condition evidence |
| loop body/exit/copy 错误 | `loops/`、`plan/loop_protocol/` |
| 短路值或 phi 归属错误 | `short_circuit/`、`phi_facts/` |
| goto/cleanup scope 错误 | label/cleanup plan 与 validator |
| 查看 Structure 产物 | `unluac --debug --dump structure --stop-after structure <file>` |
