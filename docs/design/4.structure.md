# 4. Structure（通用迭代控制流结构化）

> **职责**：将任意有向 CFG（包括不可规约图、复杂短路、多层嵌套循环）可靠地规约为一棵层次清晰的 `RegionTree`。
> **不负责**：表达式内联、变量声明布局、语法糖美化或文本渲染。

本层是保障复杂控制流还原率与目标方言合法性的核心引擎。设计参考现代反编译器成熟理论（Iterative Structural Analysis / Dream-style 条件聚合 + 受控尾复制 + 完备降级），原生支持全部 7 种方言（含不可规约图）。

## 核心思想：自底向上迭代区域规约

本层采用**自底向上迭代区域规约（Iterative Region Reduction）**：每规约出一个干净结构（短路条件、循环、分支、顺序块），就将其折叠成一个单节点继续向上规约；最后对极少数确实无法折叠的残余边，按 `ControlFlowCaps` 执行 100% 合法的完备降级。既避免多处候选边界交叠冲突，也保证绝不向无 `goto` 方言泄漏非法 `goto`。

## 核心输出：`RegionTree`（极简设计）

```text
RegionNode
  ├── Block(BlockId)                                       -- 单个基本块
  ├── Sequence(Vec<RegionId>)                              -- 顺序执行
  ├── If { cond: CondExpr, then_body, else_body }          -- 条件分支（支持复合短路 cond）
  ├── NumericFor { prep, header, body, exit }              -- 显式数值 for
  ├── GenericFor { prep, header, body, exit }              -- 显式泛型 for
  ├── While { cond: CondExpr, body }                       -- 前测试循环 / while true
  ├── Repeat { body, until_cond: CondExpr }                -- 后测试循环（含单遍 repeat..until true）
  ├── Break / Continue                                     -- 归属明确的结构化跳出/继续
  ├── Goto(LabelId) / Labeled(LabelId, RegionId)           -- 仅目标支持 goto 时使用（Lua 5.2+/LuaJIT）
  └── StateMachine { entry_state, states: Vec<StateArm> }  -- 仅目标无 goto 且遇真不可规约环时兜底
```

`CondExpr` 显式表示从条件跳转网络归约出的布尔条件树：
`Atom(BlockId, BranchCondition) | Not(CondExpr) | And(CondExpr, CondExpr) | Or(CondExpr, CondExpr)`。

## 两层结构化管线

```text
Normalized CFG + GraphFacts + LoopProtocolHints
  ──→ Phase 1: 通用结构化规约（语言无关，尽量全部消解成高级结构）
        1. 短路条件表达式聚合（Condition Folding）
        2. 自内向外循环规约（VM-for → Repeat / While → Break / Continue 边识别）
        3. 顺序块与分支规约（If/Else + Soft Merge + 受控小尾块复制）
        4. 单遍早退围栏（Single-Pass repeat ... until true）
  ──→ Phase 2: 残余控制流降级（仅当图未折叠成单根节点时触发，按 ControlFlowCaps 分流）
        - 支持 goto 的方言（Lua 5.2~5.5 / LuaJIT）→ 最小化合法 goto/label
        - 不支持 goto 的方言（Lua 5.1 / Luau）    → 局部 StateMachine 完备兜底
  ──→ 单根 RegionTree
```

## Phase 1：通用结构化规约详解

### 1. 短路条件折叠（消灭 80% 伪复杂控制流）

在 Lua 字节码里，`if (a and b) or (c and not d) then T else E end` 会展开成一张多入口条件菱形网。如果不先折叠条件，传统结构化算法会误以为它是“多入口不可规约分支”而吐出一堆 `goto`。

- **规则**：寻找仅包含纯条件测试（允许紧邻的小前缀求值，但无不可合并的多路副作用交错）的相连条件块：
  - 若 `A` 的真分支到 `B`、假分支到 `F`，且 `B` 的真分支到 `T`、假分支也到 `F`（且 `B` 仅有 `A` 一个前驱），折叠为 `A and B -> (T, F)`。
  - 若 `A` 的假分支到 `B`、真分支到 `T`，且 `B` 的假分支到 `F`、真分支也到 `T`（且 `B` 仅有 `A` 一个前驱），折叠为 `A or B -> (T, F)`。
  - 若某条件块有多个前驱但体积很小（仅单一条件测试）且属于同一复合条件子图，允许虚拟复制该条件节点，将其完整合入 `CondExpr`。
- 对 `BoolMaterializeHint`（`CMP + LOADBOOL false/true`）也采用同一短路折叠引擎，直接得到完整的逻辑值表达式。

### 2. 循环规约（由最内层循环向外迭代）

按循环嵌套深度从最内层向外逐个规约（每个循环规约完成后，在父层图中折叠为一个单入口单出口的超级节点）：

1. **显式 VM `for` 循环**：消费 `Analysis` 冻结的 `NumericFor` / `GenericFor` 协议，直接划定 `prep`、`header`、`body` 与 `exit`。
2. **自然循环分类**：
   - **前测试循环（`while cond do ... end`）**：`header` 本身是条件分支（或经短路折叠后的复合条件），一臂留在循环体内、另一臂跳到循环唯一主出口。
   - **后测试循环（`repeat ... until cond`）**：唯一回边源头（`latch`）是条件分支，一臂回到 `header`、另一臂跳到循环出口，且 `header` 不是立即退出测试。
   - **通用循环（`while true do ... end`）**：条件位于循环体中部或多出口循环；所有指向循环主出口的边标记为 `Break`。
3. **循环内回边与提前退出**：
   - 跳向当前循环主出口的边 → 抽象为 `Break`（在规约循环体时将该出口视作虚拟终止节点，从而让循环体内部彻底变成无环 DAG，极大简化内部分支规约！）。
   - 若存在多个不同循环出口（例如内层循环直接跳到外层循环外，或跳到两个不同后续块）：主出口用 `Break`，非主出口先留作跨层逃逸边；若目标方言支持 `goto` 可在 Phase 2 优雅处理，无 `goto` 方言可通过局部退出标记变量传递，确保语义 100% 准确。
   - 非尾部的回边（跳回当前循环 `header`）：
     - 若后续代码可自然放入对应分支的 `else` 块中，优先用 `if/else` 消去（这对 Lua 5.1 最友好、最自然！）。
     - 若目标方言支持 `continue`（Luau），直接标为 `Continue`。
     - 否则作为残余边交给单遍围栏或 Phase 2。

### 3. 顺序与分支规约（含 Soft Merge 与安全小尾块复制）

在无环子图上循环执行以下规约直到不动点：
- **Sequence**：`A -> B` 且 `A` 唯一出边是 `B`、`B` 唯一入边是 `A` → 合并为 `Sequence([A, B])`。
- **标准 If / If-Else**：对分支节点 `H -> (T, E)`：
  - 计算 `M = nearest_common_postdom(T, E)`。
  - 若 `M == E`（单臂）或 `M == T`（取反单臂），且臂内所有节点被 `H` 支配、除 `M` 外无外泄边 → 规约为 `If { cond, then_body, else_body: None }`。
  - 若 `M != T && M != E && M != exit_block` → 规约为 `If { cond, then_body, else_body: Some(...) }`。
- **Soft Merge（处理提前 `return` / `break`）**：
  - 真实脚本极其常见 `if a then return 1 end; ...`，或 `if a then if b then return end; foo() else bar() end; baz()`。此时 `postdom` 会退化到虚拟 `exit_block`。
  - 处理方式：
    1. 若一臂直接终止（`Return`/`TailCall`/`Break`）且不包含多路后继，直接形成单臂 Guard `if cond then <terminal> end` 后紧跟另一臂！
    2. 若两臂各有提前终止、但存在唯一的共同非退出 `dominance_frontier` 节点 `S`，将 `S` 视为 `soft_merge`，规约为双臂 `If/Else` 后顺序连接 `S`。
- **受控小尾块复制（Tail Duplication）**：
  - Lua 编译器经常把两条不同路径末尾相同的 `return nil`、`return x` 或单条 `break` 合并到同一个共享尾块，导致该块有多个前驱，阻碍外层 `If` 规约。
  - **规则**：若某终止块或极小纯跳出块（指令数 ≤ 阈值，默认 ≤ 3 条，且不含循环/大构造器）拥有多个前驱并阻塞外层分支规约，安全复制该小尾块到对应前驱。这一招能直接消除大量伪多入口结构，让 Lua 5.1 控制流自然收拢。

### 4. 单遍早退围栏（Single-Pass `repeat ... until true`）

当一段无环控制流中存在多个早退分支跳过同一段共享后缀（例如 `if a then goto done end; step1(); if b then goto done end; step2(); ::done::`），且共享后缀过大不适合尾复制时：
- 在无 `goto` 方言（Lua 5.1 / Luau）下，将其规约为 `Repeat { body, until_cond: true }`，并将所有跳过后缀的边标为 `Break`（前提：包裹范围内不存在指向外层循环的 `Break`/`Continue`，否则会被内层 `repeat` 误截获！）。
- 在支持 `goto` 的方言中，若原字节码确实形如单遍围栏也可按需使用，或交给 Phase 2 发射清晰的局部 `goto`。

## Phase 2：按 `ControlFlowCaps` 的完备残余降级

如果经过 Phase 1 全部规约后，图中仍存在未规约的 SCC（真正的不可规约多入口环，常见于 Lua 5.2+ 手写 `goto` 或手工/混淆字节码）或无法单遍结构化的跳跃边：

### 分支 A：目标支持 `goto`（Lua 5.2 / 5.3 / 5.4 / 5.5 / LuaJIT）
- 将未规约子图按 RPO 线性排布（保留内部已规约好的子区域）。
- 仅对**非自然落入下一项**的边发射 `Goto(label)`，并在对应目标前放置 `Labeled(label, node)`。
- 词法作用域合法性（Lua 禁止 `goto` 跳入 `local` 作用域）由后续 `Ast::polish` 阶段统一验证与自动 `do ... end` 隔离，绝不产出非法 `goto`。

### 分支 B：目标不支持 `goto`（Lua 5.1 / Luau）
- 仅对**最小未规约子图**（不扩散到整个函数！）生成局部 `StateMachine`：
  ```lua
  local _state = 1
  while _state ~= 0 do
      if _state == 1 then
          ...
          _state = cond and 2 or 3
      elseif _state == 2 then
          ...
          _state = 0
      end
  end
  ```
- **数学完备性**：该兜底对任意有限有向图都保证等价可编译。
- **质量监控**：正常编译器生成的 Lua 5.1 / Luau 字节码应当 99.9% 以上在 Phase 1 完成规约、`StateMachine` 计数为 0；一旦在普通测试或真实 Lua 5.1 语料中观察到 `StateMachine`，即将其视为 Phase 1 规约能力的改进线索，而非给用户抛出报错或非法 `goto`。
