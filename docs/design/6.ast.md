# AST

AST 层把已恢复的 HIR 降为合法的目标 Lua 语法，完成可读性整理、词法校验和命名。
它消费前层事实，不补做 VM 寄存器、控制流或生命周期恢复。

## 入口与数据流

入口：[mod.rs](../../src/ast/mod.rs) 的 `analyze_ast_stage`；
公开降低入口为 `lower_ast`。

```text
HirModule -> build -> AstModule
          -> readability fixed point
          -> goto scope verification
          -> naming -> AstModule + NameMap -> Generate
```

Strict 根据请求方言构建合法节点；Permissive 可保留明确诊断的 Error 或控制语法。
诊断产物不等于可重编译源码，所有前层退出要求只从 HirProto.exit_requirements 消费。

## 关键类型与共享设施

模型与权限集中在 [common.rs](../../src/ast/common.rs)。

| 类型 / owner | 含义与消费者 |
| --- | --- |
| AstModule / AstExpr / AstStmt | 目标语法树；Readability、Naming、Generate 共用 |
| AstBindingRef / AstNameRef | typed binding 与名字引用；不能按数字下标跨身份域替换 |
| AstLocalOrigin | 原 HIR local/temp 与 AST 合成 local 的来源区别 |
| AstRewriteAuthority | 前层保留要求的 AST 查询接口；各 rewrite 按动作申请权限 |
| AstTargetDialect | 请求方言及语法能力 |
| [traverse.rs](../../src/ast/traverse.rs)、[visit.rs](../../src/ast/visit.rs) | 统一子节点、词法边界与 NameAccess 事件 |
| [table_layout.rs](../../src/ast/table_layout.rs) | 当前字段语法到共享分配规则的投影 |
| [readability/walk.rs](../../src/ast/readability/walk.rs) | 通用可变遍历；各 pass 不复制树解释器 |

## 核心合同

- AST 只消费 HIR 已证明的控制、值包、capture、allocation 与 rewrite authority。
  不能因目标语法看起来合法就绕过前层保留要求。
- Local、Temp 与 SyntheticLocal 分属不同身份域。AST 物化 Temp 时保留来源，
  自建 local 不能用同号下标读取 HIR debug/capture 信息。
- 删除 binding、移动初始化、改变作用域、合并声明与使用声明糖是不同权限。
  PhysicalFramePrefix、debug、根与闭包身份等限制通过 AstRewriteAuthority 消费。
- 多返回位置与单值转换显式保留；语法糖不能改变求值顺序、错误、元方法或捕获时点。
  Luau `AstIfExpr` 消费 HIR 完整源码帧签发的条件选值许可，条件仅求值一次且仅执行选中臂，
  结果固定为单值；共享 DAG 或复用条件值的终端不能直接降低为该节点。
  已证明的 Luau 全局复合赋值保留完整 RHS 读取与运算供 visitor 消费，语法标记由 HIR
  传入并校验目标及左操作数一致；不凭相同变量名把普通赋值改成复合赋值。
- nil 范围清零可降低为逐槽写，避免大量 RHS 临时寄存器；HIR 已验证并签发的并列
  nil 赋值帧保留整组语法，AST 不凭相同字面值重做前层帧选择。
- Capture 从显式绑定发布为父函数引用。只遍历当前函数时仍需观察 capture，
  但不进入 child body 重新统计父级读写。
- 共享 visitor 区分 Read、Write、Declaration、LocalFunction 与 Capture。
  字段函数声明需要读取目标路径；不能把所有名字出现都当作同一种事件。
- initializer、local function、repeat 条件及 child body 的作用域进入/退出
  由统一遍历语义维护。pass 的状态必须随同这些边界保存和恢复。
- HIR 的方法、构造器及 closure 创建许可属于具体 occurrence；
  AST 改写保留其来源，不能把一次许可推广为同形节点的通用许可。
- Lua 5.5 global 与词法环境角色保持显式节点和身份；
  当前可见 global 属性由词法状态查询，不通过最终文本名重建。
  函数语法的 `global_declaration` 仅由原 global 声明传入；普通名字赋值使用
  `function name()` 时仍是写入，不打开新的 global 词法域。
- 表模板和批次性质仍约束字段追加与语法选择；容量相同不等于写入协议相同。
- Error、未解决值或不支持的 feature 不伪装成普通源码。

节点级语法条件、权限组合及具体反例见 build、common 和对应 pass 的实现。

## 排错

| 现象 | 第一入口 |
| --- | --- |
| 首份 AST 已不合法 | build/exprs、build/patterns 与 HIR 出口 |
| 函数自捕获或声明时点错误 | capture_scope、build/proto_bodies |
| HIR 正确但可读性下降 | Readability 的 before/after 与权限查询 |
| goto 跨入局部变量作用域 | goto_scope、goto_syntax_safety |
| local 数量超过目标限制 | readability/local_scope_limit |
| 名字碰撞或错误 capture 名 | Naming |
| AST 正确而文本错误 | Generate |

AST dump 包含 build、Readability 和 Naming 视图。命令见 [调试手册](../debug.md)。
