# AST

> **职责**：把 HIR 落成合法的目标 Lua AST，运行 AST readability，验证最终词法控制边界并分配名字。
>
> **不负责**：补 Structure/HIR 缺失事实、改变运行语义或决定文本布局。

## 入口与数据流

```text
src/ast/mod.rs
  lower_ast(hir_module, target, generate_mode)
  analyze_ast_stage(state, context)

HirModule
  -> AST build
  -> readability fixed point
  -> goto scope verification
  -> naming
  -> AstModule + NameMap
```

Strict 只构造请求方言可表达的合法节点。Permissive 可以保留明确诊断的 Error 节点以及用于展示
不可规约控制的 goto/label；含这些节点的产物是诊断伪源码，不是可重编译源码。
两种模式都只从 `HirProto::exit_requirements` 获取前层退出事实：AST 先按本次 target capability
判断 required control flow 是否可表达；Strict 对不满足的 requirement 或 unresolved residual
返回对应 typed error，Permissive 在根 AST 插入诊断节点。公共 `lower_ast` 与 pipeline AST
build 共用这一路径，后者不再旁路读取 `StructureFacts`。

## 模块 owner

```text
src/ast/
  common.rs              AST、binding、target dialect 与属性类型
  traverse.rs / visit.rs  共享子节点枚举、词法边界与只读名字事件
  table_layout.rs        当前字段语法到共享模板初始化规则的投影
  build/                 HIR 到 AST 的机械 lowering 和合法语法化
  capture_scope.rs       closure capture 与 local 声明顺序的层间合法性校验
  readability/           AST 形状收敛，见 7.readability.md
  naming/                命名证据、策略与分配，见 8.naming.md
  goto_scope.rs          readability 后的 label/goto 词法验证
  features.rs            最终方言特性与 Error 节点收集
  debug.rs / debug/      AST、Readability、Naming dump
  error.rs               AstLowerError
```

## 核心合同

- 只读分析共用 `ast/visit.rs`，由 `ast/traverse.rs` 维护子节点顺序与 `BlockKind`。
  `NameAccess` 区分读取、赋值、局部声明、local function 声明和 capture：`function t() end`
  写入 t，`function t.f() end` / `function t:m() end` 读取路径基址 t。
  capture 从显式 `captured_bindings` 发布，发生在子函数入口回调前；禁止进入 child body
  不会取消这项父级引用。调试编号只收当前函数源码引用，因此还需忽略 capture 事件；
  方言特性收集则进入所有子函数。名字回调的 `ControlFlow::Break` 立即停止后续子树，
  已进入的 statement/function 仍执行 leave hook；capture 短路时尚未进入 child function。
- AST build 只做语义保真的合法语法化；method/function/field sugar 和声明合并属于 Readability。
- 函数体按 HIR 当前闭包 occurrence 与 detached 诊断引用的后序构造，不递归进入 child proto。
  最后一次消费直接移动 body，实际重复 occurrence 才复制独立 AST；捕获元数据仍由每个
  occurrence 的父身份生成。构造失败留到原 closure 位置传播，保持逐语句诊断恢复边界。
- target capability 通过 `AstTargetDialect` / `AstDialectCaps` 集中控制，不在各节点散落版本判断。
- fixed/open/exact value pack 只消费 HIR 的明确 carrier；AST 不跨语句重建多返回协议。
- 本地绑定的等长全 nil 清零在 AST build 落成标量写入，避免源码多值赋值为整组 RHS
  另留临时寄存器；HIR 中的共同覆盖端点保留到本层消费。仅无事务证书的 Param/Local/Temp
  目标适用，不扩展到有地址求值或写元方法的目标，也不拆分有 RHS 读取或多返回的赋值。
- `<close>` 声明配对消费 `HirToBeClosed::declaration` 的借用视图，与 HIR 资源 scope 共用
  同一 Local 或整组 exact Temp 声明判定。AST 负责目标语法属性及值包 lowering，不重建配对规则。
- HIR-origin local declaration 通过 `HirInitializerRootProfile` 携带原始 value-pack 每个结果槽的
  stack-root relevance。AST cleanup、branch readability、inline-expression 等 rewrite 只能消费该
  profile；
  profile 缺失或槽位越界必须拒绝，不能再从已经树化的 Call/VarArg/literal AST 形状反猜 VM
  多返回或常量 owner。profile 只证明 initializer，若候选关心原 block fallthrough 的当前值，
  AST 还必须证明 declaration 到该 endpoint 之间没有对 binding 的写入；存在写入时保守拒绝，
  不分析赋值 RHS 的 AST 类型来续写一套 root 推导。需要放宽时由 HIR 发布更窄的 endpoint
  certificate。
- Lua 5.5 `global` 只从 typed `HirStmt::GlobalDecl` 降低；残余 `ErrNil` 仍是显式诊断，
  不与相邻 local/assign 重新拼成声明；声明名是否为请求方言的合法 identifier 也在此验证，
  不让 HIR 的协议识别依赖 AST 语法规则。
- 普通 global 引用与 `global` 声明都从 HIR raw `LuaString` key 提取 UTF-8 标识符。普通引用
  若不能写成裸名，PUC Lua 5.2+ 可退回同一词法环境的 `_ENV[key]` 索引表达；没有等价环境
  语法的目标才返回 typed `AstLowerError`。该基址使用独立 `AstNameRef::Environment`，生成时固定
  写作 `_ENV`，Naming 和 `global_decl_pretty` 不得把它当成普通 global。raw key 为 `_ENV` 时也
  必须保留环境基址访问（如 `_ENV._ENV`），不能误降为裸 `_ENV`。`global` 声明本身没有索引
  形式，非法名字直接报错。
- HIR upvalue 引用若属于当前 `HirProto::environment_upvalues`，AST build 将同一 `UpvalueId`
  语法化为 `AstNameRef::Environment`，并验证目标方言支持词法环境；普通 upvalue 保持
  `AstNameRef::Upvalue`。closure capture name 也按 owner proto 的同一 role 集合映射，保证 child
  对环境的写入仍能沿精确 capture identity 形成 barrier。这里不得按名字 `_ENV` 猜 role，也不得
  修改 `HirGlobalRef("_ENV")` 的路径；后者表示环境表中真实名为 `_ENV` 的字段。
- method raw key 仅在可作为目标 identifier 时降为 `AstMethodCallExpr`。AST build 可以消费
  已经规范化的 HIR method access；若后续 inline 才把 callee 恢复为同点求值的
  `receiver.field`，AST 只在 field base 与第一个 implicit receiver 参数完全相等时消费该参数，
  function-sugar 也只在 raw key、field 与 implicit receiver 三者完全一致时改写当前 call 节点，
  不删除 producer 或移动 lookup。非法 key 保留 indexed callee、implicit receiver 参数和 raw
  method provenance，不因放弃 colon sugar 而改变求值次数或调用语义。
  非终结 method callee 的物理根交接只消费 HIR 挂在同一 call occurrence 上的
  `callee_root_handoff`；AST 不得从 `method_key`、callee 形状或绑定名反向推断。
  terminal TailCall 不携带这种 post-call handoff；AST 可以独立证明其当前终结表达式是否能写成
  等价冒号调用，但不能把这项源码形状证明反向升级成普通调用的物理根生命周期许可。
  需要同时删除 method lookup assignment 时，AST build 只原样携带 HIR 已签发的
  `HirMethodRewriteTransactionId`。function-sugar 必须看到唯一 producer/call 两端、完全相同的
  token、紧邻语句，以及仍匹配的 target/callee/base/implicit receiver/raw key，才可原子替换为
  method call；唯一性按当前 proto 的完整 AST 统计，token 还必须与当前 proto 及 call 上的 method
  protocol 一致。缺端点、跨 block 重复端点、跨 nested function 移动、形状漂移或非法 identifier
  都拒绝，不能退回绑定级启发式。
  AST 不读取 temp、home、SSA use 或旧 target 生命周期，也不重新证明底层 method 协议。
- table constructor 的 record key 只消费 HIR 保留的语义表达式；AST build 根据本次 target
  dialect 将合法 UTF-8 字符串键写成 `AstTableKey::Name`，其它字符串或动态键降低为
  `AstTableKey::Expr`。这项选择只改变源码语法形状，不改变 key/value 的求值次序。
- binding 在 build/readability 中保持 typed identity，Naming 完成前不替换成字符串。
  `AstSyntheticLocalId::HirTemp` 保留已物化 HIR temp 的原身份；`Ast` 属于 AST 自建 local，
  二者同号也不相等。Deferred materialize 仍区分未物化 Temp 与可被 local 改写消费的名字，
  不改变来源。自建编号由 AstModule 持续分配，随完整快照克隆，跨子函数与改写轮次不重置；
  不通过扫描声明、引用或 capture 元数据重建分配进度。裸 index 只用于名字候选或显示，
  HIR debug/capture/lifetime 查询必须匹配 HirTemp 来源。
- `AstLabelId::Hir` 与 `Synthetic` 显式区分原 HIR label 和 AST continue 语法化产生的 label。
  两者分别输出 `L` 与 `C` 前缀，goto scope 校验和诊断保留完整身份；AST 不扫描前层最大
  编号来给自己的分配器让位，也不把两个命名空间压回裸整数。
- `AstLocalBinding::rewrite_authority` 与 `AstLocalOrigin` 正交：origin 只说明 debug/root 来源，
  authority 说明 AST 是否有权删除、移动声明起点或改变生命周期。HIR `Preserve` 必须原样穿过
  materialize-temp、`<close>` temp-pair lowering、statement merge 与 function sugar；AST 自建
  binding 使用 `AstOwned`。语法 lowering 只能在保留同一 `AstBindingRef` 的基础上设置 `<close>`
  等属性，不能用 diagnostic/recovered helper 重建普通 HIR binding 并把 authority 清成 Unknown。
  HIR `Unknown` 在正向 certificate 迁移完成前仍走既有 AST 可读性判断，但不能伪装成已获 HIR
  授权。正向 certificate 必须绑定具体 definition 与原子 transaction，不能绑定整个 TempId；
  它只携带 HIR 已证明的底层前提，AST 仍负责证明当前 Lua 候选的求值顺序、值宽和词法作用域合法。
  当前 exact multi-call 的整组新 PhysicalRoot owner 通过同一个
  `HirInitializerMergeTransactionId` 机械降低到相邻 `AstLocalDecl` / `AstAssign`；只有两端 token
  完全相同且候选形状仍匹配时，才可越过 PhysicalRoot 的 initializer-merge veto。任一 AST
  rewrite 改变协议形状都必须清除 token。
  stripped bytecode 的同一 home 可能被恢复成一个 `LocalId` 上的多次赋值；这类后续 definition
  不能借用首次声明的 binding 级正向许可。除上述整组 initializer transaction 外，机械
  assignment definition 仍是已确认的迁移切面；迁移时应让 exact definition transaction 可匹配，
  而不是把任意单目标 assignment 都升级成可删除候选。
- `AstRepeat::lifetime` 原样携带 HIR 针对该 repeat condition 边界发布的 typed binding 集。
  这不是 binding 级 `Allow`：只有当前 collective suffix 或尾 `do` 拍平候选实际缩短的
  HIR-origin 声明才查询 membership，`Preserve`、`<close>`、debug identity、条件直接引用和
  goto 仍由 AST 拒绝。两个 consumer 共用同一 identity adapter，不按 closure/赋值形状重建
  HIR 对象流或物理 home 生命周期。
  materialize 后只有 `SyntheticLocal(HirTemp(temp))` 可投影到
  `HirRepeatBinding::Temp(temp)`；`SyntheticLocal(Ast(_))` 在类型匹配时即排除，不能借用同号
  certificate。authority 仍独立限制改写权限，不用于推断身份来源。
- 函数的命名变参候选只消费 `HirProto::vararg_param_local`；AST 仍按签名种类与 binding 使用情况
  决定是否写入形参列表，不能把第一个 local 的位置当作身份。
- AST build 与命名直接消费 `HirBinding`，按 owner proto 投影名字及环境 role，
  不把任意表达式重新识别为捕获，也不为已合法的捕获保存缺失身份分支。
- `AstFunctionExpr::capture_names_by_upvalue` 由 AST build 按 HIR capture 顺序唯一生成，保留
  child `UpvalueId` 到父级 `AstNameRef` 的对应；必须使用 `AstNameRef` 而不是
  `AstBindingRef`，因为父级来源还可能是 param 或更外层 upvalue。Readability 若需判断闭包
  内具体 capture 的 write/escape，消费该映射；`captured_bindings` 集合只用于成员/存活事实，
  不得把任一 child upvalue 访问扩大成全部 capture。
- `<const>`、`<close>`、global attribute、`SingleValue`、vector 等语义差异必须是显式 AST 节点或
  属性，Generate 不负责猜测。
- Readability 可能移动声明或新建词法块，因此结束后必须重新验证 goto 不会跳入 local/TBC
  作用域。Strict 返回错误，Permissive 只能生成诊断节点。
- HIR `ProtoFailure` 在 Strict 中成为 residual；Permissive 保留阶段诊断和 child identity，不能
  把 detached child 的合成位置解释成原 closure 位置。
- AST 不得导入 Structure/Transformer 的 block、phi、register 或 requirement 类型来解释
  HIR 退出状态；这些底层事实必须在 HIR lowering 前或 lowering 中完成证明和蒸馏。
- `AstTableConstructor::allocation` 原样携带 HIR 分配事实。inline-exprs 将当前字段和
  数组下标和键身份投影给共享模板约束；若常量替换改变 Indexed 初始化、扩大已有
  Template 数组或引入原集合之外的模板键，整个 table
  use-site 与 producer 删除一起拒绝。HIR 发布的 `TableInitialization` binding 保留权限
  同样必须穿过 lowering，AST 不读取 TNEW/TDUP、不恢复原始寄存器或推断容量来源。

## 关键类型

| 类型 | 作用 |
| --- | --- |
| `AstModule` / `AstProto` | 模块与函数树 |
| `AstBlock` / `AstStmt` / `AstExpr` | 语法树主体 |
| `AstTargetDialect` / `AstDialectCaps` | 目标语法能力 |
| `AstLocalBinding` / `AstGlobalBinding` / `AstBindingRef` | 稳定 binding 身份 |
| `AstRewriteAuthority` | 区分 AST-owned、HIR Unknown 与 HIR Preserve 的重写权限 |
| `AstRepeat::lifetime` | 当前 repeat condition 边界可消费的 HIR 生命周期事实 |
| `AstFunctionExpr` | 函数体、capture 集合及 child upvalue 到父级名字的精确对应 |
| `AstSyntheticLocalId` | Readability 新建的 local 身份 |
| `AstLocalAttr` / `AstGlobalAttr` | 方言属性 |
| `LuaString` | 保留原始字节语义的字符串字面量 |
| `ReadabilityOptions` | 可读性展示预算 |
| `NameMap` | 最终字符串名字映射 |

## 排错

| 症状 | 首查位置 |
| --- | --- |
| HIR 节点落成错误语法 | `build/analysis.rs`、`build/exprs.rs` |
| 属性或目标方言能力丢失 | `build/patterns/`、`AstDialectCaps` |
| method/field/declaration 形状不理想 | `readability/` 对应 pass |
| goto 跳入 local/TBC scope | `goto_scope.rs` |
| 名字冲突或 hint 丢失 | `naming/` |
| 查看 AST 全部分段 | `unluac --debug --dump ast --stop-after ast <file>` |
