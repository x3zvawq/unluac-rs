# AST

> **职责**：把 HIR 落成合法 Lua 语法树，完成 AST 内部可读性整形，并把稳定 binding 身份映射成最终名字。
>
> **不负责**：补 Structure/HIR 缺失事实、改变已恢复语义、文本布局。
>
> **例子**：`HirIf { cond, then_block, else_block }` → `AstIf { cond: AstExpr, then_block: AstBlock, else_block: Option<AstBlock> }`

## 入口

```
src/ast/mod.rs
  lower_ast(hir_module, target_dialect, generate_mode) -> Result<AstModule, AstLowerError>
  analyze_ast_stage(state, context) -> Result<(), DecompileError>
```

`analyze_ast_stage` 是 decompile pipeline 的 AST 阶段入口：内部依次执行 AST build、
readability、最终 goto 作用域校验和 naming。Strict 按请求方言的真实能力 lowering 并在缺口处失败；
Permissive 只放宽 goto/label 以保留未结构化控制流，其他局部缺口用显眼的 Error 节点
保留位置和诊断信息。包含这些节点的最终产物不是可重编译源码。

可读性整形和命名是 AST 内部子步骤；`--dump ast` 会分段输出 AST / Readability / Naming：

```
src/ast/readability/mod.rs
  make_readable(state, context) -> ()
  make_readable_module(module, target, options, timings, dump_passes) -> AstModule
src/ast/naming/mod.rs
  collect_naming_evidence(hir_module) -> Result<NamingEvidence, NamingError>
  assign_names_with_evidence(ast, hir, evidence, options) -> Result<NameMap, NamingError>
```

```

  common.rs       所有 AST 节点类型
  error.rs        AstLowerError
  features.rs     最终方言特性与 Error 节点收集
  goto_scope.rs   readability 后的 label/goto 词法作用域校验
  build/mod.rs    lower_ast 骨架
  build/
    analysis.rs           HIR → AST lowering 分析
    exprs.rs              表达式与 value-pack lowering
    patterns/
      syntax.rs           合法语法化规则
  readability/mod.rs  make_readable 骨架 + pass 描述符 + 调度
  readability/    所有可读性 pass（见 7.readability.md）
  naming/         命名证据、词法事实、候选策略和冲突分配（见 8.naming.md）
  pretty.rs       共享 pretty 设施（被 generate 引用）
  traverse.rs     共享遍历

```

## 数据流

```
HirModule + AstTargetDialect + GenerateMode
  └─ lower_ast（显式事实 helper）/ lower_ast_for_generate（stage 入口）
       └─ build/analysis.rs + build/exprs.rs + build/patterns/
            └─ AstModule { protos: Vec<AstProto>, ... }
                  └─ make_readable / make_readable_module
                       └─ AstModule（经过可读性整形）
                          └─ verify_goto_scopes
                               └─ naming::assign_names
                                  └─ NameMap
```

## 关键类型（`src/ast/common.rs`）

| 类型 | 说明 |
|---|---|
| `AstModule` / `AstProto` | 模块树 |
| `AstBlock` / `AstStmt` / `AstExpr` | 基本结构 |
| `AstIf` / `AstWhile` / `AstRepeat` / `AstNumericFor` / `AstGenericFor` | 控制流 |
| `AstLocalDecl` / `AstAssign` / `AstCallStmt` / `AstReturn` / `AstGoto` | 语句 |
| `AstTargetDialect` / `AstDialectCaps` | 目标方言 + 能力控制 |
| `DecompileDialect` | 主反编译 dialect 枚举，AST 层在 `common.rs` 为它补充关键字与能力集语义 |
| `AstLocalAttr` / `AstGlobalAttr` | `<const>` / `<close>` 属性 |
| `AstLocalBinding` / `AstGlobalBinding` | binding 身份 |
| `AstBindingRef` | binding 身份与 `AstNameRef` 的纯转换 / 匹配入口 |
| `AstSyntheticLocalId` | Readability 引入的合成 local |
| `AstFunctionDecl` / `AstLocalFunctionDecl` / `AstFunctionExpr` | 函数节点 |
| `LuaString` | 字符串字面量的共享不可变字节/文本，字段/global 名称转换时才尝试 UTF-8 文本视图 |
| `ReadabilityOptions` | AST readability 与 HIR temp-inline 共享的源码形状阈值 |
| `NameMap` / `FunctionNameMap` / `NameInfo` | AST naming 产出的最终名字映射 |

## 应优先复用的共享设施

| 设施 | 用途 |
|---|---|
| `AstDialectCaps` | 语法合法性校验，集中控制，不散落到各节点处理 |
| `build/patterns/syntax.rs` | 合法语法化规则 |
| `build/exprs.rs::lower_value_pack` | fixed/open/exact tail 的统一机械 lowering |
| `readability/walk.rs` / `visit.rs` / `traverse.rs` | AST readability pass 共享遍历 |

## 维护规范

1. **build 只负责合法语法化与语义保真**：
   - 适合：`goto+close` 合法词法块、`SingleValue` 语义保真节点、保守 local/global 节点、hoisted temp 声明。
   - hoisted temp 按 block 内首次出现顺序排布，避免 `statement_merge` 因顺序错位无法下沉。
   - 不适合：method / function sugar、installer IIFE、field access sugar、local merge / stmt merge（这些属于 Readability）。
2. **target dialect 能力通过 `AstDialectCaps` 集中控制**：不在各节点处理代码散落版本判断。
3. **readability 只做 AST 形状收敛**：method sugar、field access sugar、local/statement merge 等放在 AST readability；branch value 语义合流仍回 HIR。
4. **naming 只产出名字映射**：不改变 AST 结构，不发明前层缺失 binding。
5. **binding 身份保持稳定**：AST build / readability 不把 `ParamId` / `LocalId` / `TempId` 等提前改成字符串。
6. **Generate 不替 AST 兜底**：`global *` / `global<const>` / `local <close>` / `SingleValue` 等必须在 AST 显式建模。
7. **宿主字面量保持显式节点**：Luau vector 以 `AstExpr::Vector` 保留位模式并参与普通纯表达式遍历；构造器名字不是 AST 语义事实，留到 Generate 根据调用方显式配置选择。
8. **vararg 参数名由实际 binding 需求决定**：Lua 5.5 的 `PF_VAHID` 同时可能来自匿名 `...`，也可能来自只经 `GETVARG` 索引的 `...name`，proto flag 无法单独还原源码拼写。AST 仅在 vararg 参数寄存器对应的首个 local 仍被函数体引用或写入时挂 `named_vararg`；完全未提及该 binding 时生成普通 `...`，避免给匿名变参发明名字，同时保证索引、赋值或 capture 仍有合法声明。
9. **硬关键字与上下文语法词分开判断**：PUC Lua 5.2+ 的 `goto` 禁止出现在标识符位置；LuaJIT `goto`、Luau `continue`、Lua 5.5 `global` 仅在对应语句上下文中有特殊含义，作为 global / field 名仍是合法裸标识符。Naming 可以继续保守地不主动分配这些名字，但 HIR 的环境访问不能因此伪造 `_ENV["name"]`。
10. **hoisted temp 下沉按同一语句收敛**：嵌套语句成功消费 pending 声明的一部分后，`statement-merge` 必须用剩余 binding 重试当前语句。若某 binding 在该子树写入、又在后续 sibling 读取，应把声明放在子树之前；不能前进到首次读取处才声明，否则此前写入会落成另一个作用域甚至全局。
11. **Lua 5.5 global 声明名来自探测与赋值目标**：AST build 只有在 probe value 与 assignment target 是同一个 `GlobalRef`、probe local 仅被 `ErrNil` 使用时才恢复 `global name = value`。`ErrNil.name` 若存在必须与该名字一致；`Bx=0` 合法地缺少诊断名，不能因此丢掉声明语义，也不能从任意 table key 猜 global。
12. **AST 不恢复 value-pack carrier**：AST build 只消费 `HirValuePack`。fixed 尾部的
    call/vararg 按所在列表目标数决定是否生成 `SingleValue`，open tail 保持展开；exact
    tail 只允许留在有明确目标数的声明/赋值列表。跨语句 carrier 消除、open producer 的
    唯一 owner 与求值顺序证明都属于 HIR，AST 不再通过相邻 local/call 形状重组源码。
13. **源码 local 资源在 Readability 末端收敛**：HIR 为保留调用、global lookup 和运算
    顺序而物化的 local 不能仅为规避编译器上限再做不安全内联。Deferred readability 在
    binding mention 和函数参数已经稳定后，沿词法树携带外层预算，仅把无属性、生命周期
    已闭合的声明包入有限 `do` 作用域；`<const>` / `<close>`、label/goto 边界和仍有后续
    mention 的 binding 不得越界。Generate 只输出既有作用域，不再维护 local 活跃性。
14. **同类逻辑长链在 AST build 时平衡深度**：HIR 的 `and` / `or` 长链可以由上千个
    二叉节点构成；机械递归复制会让 AST build 和后续递归 visitor 的调用深度随 operand
    数线性增长。build 应迭代收集连续同类逻辑节点，保持 operand 原有顺序，再构造
    对数深度的平衡 AST。同一逻辑运算符的结合方式不改变 Lua 的从左到右短路求值或返回值；
    遇到另一运算符或其它表达式边界时必须停止展平，不能借平衡过程改写 precedence。
15. **readability 后重新校验 goto 作用域**：Structure/HIR 记录的 scope barrier 约束是
    控制计划的输入，但 readability 仍可能移动或新建 local 词法块。最终 verifier 用词法树
    区间检查 label 可见性，并拒绝跳入 recovered local 或 `<close>` / TBC binding 的作用域。
    Strict 返回明确错误；Permissive 在对应位置生成 Error 诊断，因此结果只能作为伪源码，
    不能把非法跳转静默输出成可编译源码。
16. **Generate 的 plain field function 拼写必须有身份前提**：当 AST 已有
    `FunctionDecl(Plain(path))`，且 `path` 的根是 local/synthetic-local、函数体不捕获该根
    binding 时，Generate 可以输出 `path = function(...) ... end`，这只是等价的表字段表面形式。
    global、method、param/upvalue 根以及捕获根 binding 的声明必须保留原 declaration 形状；
    Generate 不得借此猜测缺失的 binding、改变 implicit-self 参数或移动函数求值位置。
17. **普通调用也保留 HIR method provenance**：`AstCallExpr.method_name` 只记录 HIR 已确认
    的 SELF/NAMECALL 字段名；它不把普通 `Call` 伪装成 `MethodCall`，也不允许 Generate
    重新查表。Readability 可用这份事实决定同一 fresh owner 的字段闭包是否让位给已有
    function-sugar 声明；若 receiver snapshot、PhysicalRoot 或多返回协议仍要求独立
    callee/local，普通调用的 AST 形状和求值顺序必须保持。`method_name` 也不等于
    return-self、callee identity 或旧 root 的 overwrite epoch；删除 field alias 只能消费
    HIR 另外提供的完整 snapshot/lifetime 证明，不能把 SELF 名称当作 AST 层的删除授权。

## 向后提供的事实

合法 Lua 语法树 / 目标 dialect capability 下允许的节点 / 稳定 binding 身份 / AST readability 收敛后的形状 / `NameMap`。

## 排错指引

| 症状 | 检查点 |
|---|---|
| 语法节点类型错误（如 while vs repeat） | `build/analysis.rs` HIR 节点分派 |
| `<close>` / `<const>` 属性丢失 | `build/patterns/syntax.rs` |
| hoisted temp 声明顺序错误 | `build/mod.rs` temp hoist 逻辑 |
| dialect 约束未生效 | `AstDialectCaps` 校验逻辑 |
| goto 跳入 local / TBC 作用域 | `goto_scope.rs` 最终词法区间校验 |
| method/field/local merge 不理想 | `readability/` 对应 pass |
| 名字冲突或 debug hint 丢失 | `naming/strategy.rs` / `naming/allocate.rs` / `naming/evidence/` |
| 想看 AST / readability / naming | `unluac --debug --dump ast --stop-after ast <file>` |
