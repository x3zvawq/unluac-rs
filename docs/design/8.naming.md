# AST Naming

Naming 将最终 AST 的稳定 binding 映射为合法、无歧义且确定的字符串名字，输出 NameMap。
它不改写 AST、不删除 binding，也不恢复前层缺失的身份。

## 三种命名模式

三种模式都优先使用合法 debug 名，并遵守 capture、语法固定名和词法避让规则。
模式决定缺少 debug 名时的候选来源，默认反编译选项为 `debug-like`。

| 模式 | 无 debug 信息时的行为 |
| --- | --- |
| `debug-like` | 使用带函数和 binding 编号的 `p1_0`、`r1_0` 等名称，方便对照；可关闭函数编号 |
| `simple` | 参数使用 `a/b/c`，普通 local 使用 `value/value2`；保留 `self`、循环角色、`fn` 和未使用 local 的 `_` 等基础角色 |
| `heuristic` | 在基础角色上消费表达式形状、字段读写用途、模块路径及调用名称；无可靠候选时退回通用名，未使用参数可显示为 `_` |

Heuristic 提示只是阅读建议，不是运行时类型或 callee 身份证明。所有候选都经过统一的
歧义处理与名称分配；标准库参数提示的事实来源集中在 `hints/stdlib.rs`。
候选识别、优先级及失效条件由对应实现维护，不授予语义改写权限。

## 入口与数据流

入口：[naming/mod.rs](../../src/ast/naming/mod.rs)。
`collect_naming_evidence` 收集 HIR 证据，
`assign_names_with_evidence` 验证并分配；pipeline 使用 `assign_names`。

```text
HIR capture/debug facts -> NamingEvidence / hints
final AST -> validation -> lexical/binding facts
          -> strategy -> allocation -> NameMap -> Generate
```

## 稳定合同

- Naming 在 Readability 后处理仍存在的 binding，Temp 泄漏由入口显式拒绝。
- 身份来自 typed origin；AST 自建 local 不以同号下标查询 HIR。
- capture provenance 保持父 binding 对应，子函数的提示名不能覆盖身份。
- debug 提示影响命名质量，不是正确性前提；stripped 输入也必须确定、合法。
- 词法可见性来自最终 AST，遵守 initializer、local function 和 repeat 的生效时点。
  不能使用改写前的 HIR 子树范围代替最终 AST 的词法关系。
- 名字同时避让同作用域冲突、目标关键字及会被后代捕获遮蔽的裸全局。
- VM 或语法要求的固定名优先于普通策略；词法环境角色通过显式身份处理。
- NamingEvidence 及索引只借用当前不可变输入；修改源树后不得继续使用。
- NameMap 按函数上下文组织，Generate 进入 child 时切换映射。
- 结果由输入与选项决定，不依赖 hash 或偶然遍历顺序。

候选优先级、suffix 规则、冲突查询和具体环境校验见各实现，不在设计文档复制分支条件。

## 排错

通用名退化先查 evidence/strategy；capture 名错误查 evidence；
冲突与遮蔽查 lexical/visibility/allocate；非法标识符查 support；
Temp 或函数身份错误回到 AST build/Readability。
