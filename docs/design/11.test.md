# 测试体系

本文定义仓库的公开测试协议、运行方式和失败分类。具体回归问题由最小源码 case 与实现注释记录，
不在设计文档维护 case 流水账。

## 测试分层

| 层次 | 路径 / 入口 | 责任 |
| --- | --- | --- |
| 单元测试 | `tests/unit-case/*.lua` | 常规语义、方言与可读性覆盖 |
| 回归测试 | `tests/regress-case/*.lua` | 已修复问题的最小源码复现 |
| 驱动器 | `xtask/src/unit_test.rs` | 筛选、并发、超时和汇总 |
| 支持库 | `packages/unluac-test-support/` | toolchain、manifest、验证与 diff |

各 crate 的 `src/`（含 CLI、WASM 和 xtask）只保留实现，不放 `#[cfg(test)]`、`#[test]` 或同目录
Rust 测试模块；新增单元与回归测试统一使用 Lua 样例。公开 case 必须是仓库官方
Lua toolchain 可编译的源码，不接受只提交 `.luac` / `.luau` 的 bytecode-only fixture。

## 验证流水线

```text
source execution
  -> official compile
  -> bytecode execution vs source
  -> decompile
  -> generated source compile + execution vs source
  -> optional recompile/decompile rounds
  -> semantic, source-kind, convergence and readability assertions
```

普通 case 必须覆盖真实用户路径。少数无法由普通小源码稳定产出的 VM 协议或宽度边界，可以由
manifest expectation 使用 pinned 官方 runtime 动态构造临时 chunk，但源码 baseline 仍必须存在；
临时 chunk 不提交到仓库，也不能成为 runner 内的 case 特判。

目标 Lua 源码确实无法等价表达的 VM carrier 可以声明 typed residual expectation。它必须绑定
精确不可表达性证明和最小源码入口，Strict 返回对应 residual，Permissive 返回同类
`DiagnosticPseudocode`；不得用 residual 掩盖可修复的 lowering 或 pass 证明缺口。

## 运行命令

### 按改动选择验证

- 纯文档、注释或技能指令修改：检查路径、链接、示例与实际入口是否一致，以及 `git diff --check`；SKILL 修改另检查 frontmatter 和触发范围。无需启动 Lua 全矩阵或 Rust 构建。
- Rust 修改：先运行能暴露当前问题的定向测试；交付前运行 `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`。反编译行为、语义合同或共享流水线变化，还需在完整主题收尾时运行一次 `cargo unit-test --jobs 8`，jobs 按可用资源调整，不要求每个编辑步骤重复全量。
- runner、CLI、WASM、JS 或 Web 的专项修改：运行对应包已有检查并覆盖实际受影响入口；跨入口影响再扩大范围。核心 API、feature 或依赖变化涉及 WASM 时验证相应构建目标。发布流程所要求的全量检查仍以工作流为准。
- case / manifest 修改：通过 `cargo unit-test --case-filter <case>` 验证注册后的实际实例与适用方言；测试协议或共享执行逻辑变化时扩大到受影响 suite。

已通过且未再受改动影响的检查不重复运行。出现新改动、新失败或尚未解决的具体疑点时才追加
验证；无法执行必要检查时明确说明未验证部分，不能宣称全部完成。失败基线应来自可核对的当前
证据，不能引用旧记录中的通过数替代本次运行，也不能仅凭失败总数相同判断没有新回归。

### 命令示例

```sh
cargo unit-test --jobs 8
cargo unit-test --suite unit --jobs 8
cargo unit-test --suite regression --jobs 8
cargo unit-test --case-filter <path-or-variant>
cargo unit-test --output verbose --case-filter <case>
cargo unit-test --recompile-rounds 1
```

`cargo test --test regression` 和 `tests/regression/` 不是测试入口。

`recompile_rounds` 是收敛预算：每轮先完成语义验证，再比较相邻两轮生成源码，首次相同即成功；
显式收敛 case 从首次生成起关闭 Generate 的元信息注释，避免产物路径、行号变化造成假失败；
debug 信息仍参与解析和命名，普通 debug/注释 case 保留默认注释输出，不在比较器中删除源码文本。
预算耗尽仍不固定则报告 convergence mismatch。不能通过增加轮数掩盖持续膨胀。只有明确的协议
压力 case 可以在 manifest 将其设为 `0`，且仍需完成首次生成、重编译与运行等价验证。

runner 路径必须消费同一次 Cargo build 的 `compiler-artifact.executable`，不得按默认
`target/debug`、环境变量或 profile 名重建。自定义 `CARGO_TARGET_DIR` 也必须启动刚构建的
同一产物；Cargo 未发布 executable 时直接报错，不能退回磁盘中的旧 runner。

manifest 在每个 suite 展开矩阵时签发独立的实例 ID，选项不同的条目拥有不同身份。
父驱动器从同一次构建的子 runner 列表获取 ID，并以 suite + ID 选择完整条目；
path、dialect 和 variant 标签只用于展示与筛选，不能重新匹配条目而丢弃 debug、expectation 等事实。
产物路径为 `target/unluac-tests/<suite>/<dialect>/case-<id>/<stage>/<case-path>`，所有阶段直接消费同一条目。
ID 只对应当前编译的 manifest 展开顺序，不能跨清单版本保存或作为持久 case 标识。
直接调试子 runner 时先使用 `--list`，再用 `--suite <suite> --id <id>` 执行该实例。

每个 case 由独立子 runner 执行。子 runner 的 panic 或异常退出必须保留状态与 stderr，归类为
该 case 的 `runner-crashed` 失败后继续执行其余 case；spawn、poll、pipe 读取等驱动器基础设施
错误才终止整批测试，并立即取消尚未开始的任务。stdout/stderr 必须在子 runner 执行期间持续
读取，不能等进程退出后再读取有界 pipe。
Windows 超时必须在 runner 仍存活时按其 PID 终止整棵子进程树，再等待退出和收集输出；
只终止 runner 会留下 Lua 进程及其继承的 pipe，使超时处理自身无法结束。

进度输出必须同时适用于交互终端和日志型调用方：TTY 可以原地重绘当前 case，但每完成 100 个
entry 仍要通过进度渲染器写入一条不会被后续重绘覆盖的持久里程碑；距离上次持久进度输出连续
10 秒时，必须写入包含 completed/total 与 active 数量的持久心跳，即使期间 worker event 一直
到达。这样慢 case、低吞吐波次或终端重绘被宿主折叠时都不会表现为无进度挂死。
`--progress off` 必须同时关闭重绘、里程碑和心跳。

## Lua Case 规范

- 一个文件围绕同一主题，可包含多个带稳定输出标签的子 case。
- 常规样例使用 `common_` / `lua51_` / `luajit_` 等前缀；回归样例使用 `regress_` 前缀。
- 回归源码必须最小化，避免复制大型真实文件或在 manifest 中重述实现细节。
- 同一源码的优化档位、命名模式或 debug 模式使用 manifest variant，不复制源码。
- 测试默认剥离 debug；只有协议或命名目标依赖 debug 时才显式 `retain_debug`。
- case、variant、expectation 的注册与执行顺序必须确定，不能依赖文件系统或 hash 顺序。

推荐用注释和输出首参标记子 case：

```lua
-- common_example#1: 多赋值保持求值顺序
local function test_assignment()
    local a, b = left(), right()
    print("common_example#1", a, b)
end

test_assignment()
```

## 可读性断言

可读性合同通过编译前解析的 `unluac:` 注释表达：

```lua
-- unluac: expect-contains [[local function test_assignment]]
-- unluac: expect-not-contains [[goto]]
-- unluac: expect-not-line [[local r0_2 = r0_1]]
-- unluac: expect-order [[if flag then]] [[else]]
-- unluac: expect-max-line-length [[120]]
```

`expect-not-contains` 匹配任意子串；禁止某一整行时使用 `expect-not-line`，比较时忽略行首缩进
和行末空白。例如禁止 `local x = y` 不会误伤 `local x = y()`，两种断言均用于首次生成及收敛轮次。

| 指令 | 含义 |
| --- | --- |
| `expect-contains` | 首次生成包含片段 |
| `expect-not-contains` | 首次生成和每轮 roundtrip 均不含片段 |
| `expect-order` | 首次生成中片段顺序固定 |
| `expect-max-line-length` | 首次生成和每轮 roundtrip 的物理行长度上限 |

正向形状断言不要求编译器 roundtrip 保留等价控制流的原始拼写。所有普通 case 在首次生成与每轮
roundtrip 都必须断言 `GeneratedChunkKind::Source`，诊断伪源码不能混入成功矩阵。

## 新增测试

1. 在正确 suite 新增或扩展最小 `.lua` 源码，并加稳定输出标签。
2. 需要保护源码形状时添加最小 `unluac:` 断言。
3. 只在需要非默认 dialect/options/variant/residual 时修改 manifest。
4. 先运行相关定向用例；同一完整主题集中修改、验证，收尾时运行一次 `cargo unit-test --jobs 8`，不逐次编辑重复全量。

失败时先区分：源码/toolchain、parse/lowering、反编译、生成源码编译、运行输出、source kind、
收敛或可读性断言。用 `--stop-after` / `--dump-pass` 找到首次丢失事实的层，在根因 owner 修复。
调试命令见 `10.debugging.md`。

Lua toolchain 位于 `lua/build/`，源码与构建说明见 `lua/README.md`。
