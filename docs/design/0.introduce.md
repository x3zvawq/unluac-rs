# 总览

本文只定义流水线边界和跨层维护原则。具体算法、拒绝条件与回归形状以源码注释和测试为准。

## 正式流水线

```text
Parse -> Transform -> Structure -> HIR -> AST -> Generate
```

| 层 | 输入 | 输出 | 责任 |
| --- | --- | --- | --- |
| Parser | bytecode | `RawChunk` | 按方言保真解析协议事实 |
| Transformer | `RawChunk` | `LoweredChunk` | 统一为方言无关 low-IR |
| Structure | `LoweredChunk` | CFG、数据流事实、`StructureFacts` | 选择并验证控制流与值流 plan |
| HIR | Structure 产物 | `HirModule` | 执行 plan，形成语义树并消除机械 carrier |
| AST | `HirModule` | `AstModule`、`NameMap` | 落成合法 Lua AST，整形并命名 |
| Generate | AST、NameMap | `GeneratedChunk` | 渲染目标方言源码或诊断伪源码 |

`Debugging` 和 `Test` 与正式流水线并行，负责观测与验证，不产生新的业务事实。

## 调度与状态

| 文件 | 职责 |
| --- | --- |
| `src/decompile/pipeline.rs` | 一次 decompile 调用的入口与收尾 |
| `src/decompile/stages.rs` | 固定阶段顺序、timing 与 dump 调度 |
| `src/decompile/state.rs` | 每层产物槽位与 `DecompileStage` |
| `src/decompile/contracts.rs` | 层间稳定类型别名 |
| `src/decompile/options.rs` | 顶层、调试、可读性、命名与生成选项 |
| `src/scheduler.rs` | HIR simplify 与 AST readability 共用的 invalidation scheduler |
| `src/recovery.rs` | proto 级失败事实与最后完成产物 |

阶段只能消费前层已经发布的事实。需要跨层信息时，先确认其自然 owner，再为后层提供稳定
query 或 carrier；不得在消费者中平行重建。

## 失败边界

`GenerateMode::Strict` 在首个无法表达或无法证明的错误处失败。`Permissive` 允许已具备可信
proto 边界的 Structure/HIR 失败转成 `ProtoFailure`，继续处理同一 chunk 的其他 proto；失败
节点保存失败层、最后完成层和紧凑产物 dump，不伪装成等价源码。

Parser、Transformer、CFG、GraphFacts、Dataflow 以及全模块 simplify/readability/naming/generate
错误目前仍是 chunk 级错误。不得通过跳读输入、空 plan、Error 节点或后层 fallback 擅自扩大
恢复边界。

## 跨层原则

1. 单一事实源：事实由最早能可靠证明它的层持有，后层只消费。
2. 结构优先：先修复缺失或错误的前层事实，不在后层堆形状特判。
3. 共享优先：复用已有 query、helper、walker、visitor 和 scheduler。
4. 输出层纯粹：Readability、Naming、Generate 不补前层恢复缺口。
5. 失败显式：非法输入、不变量破坏与目标方言不可表达必须返回 typed error 或诊断事实。
6. 身份稳定：proto、binding、edge、phi 和 cleanup 使用各自稳定 ID，不借别层 arena 下标。

## 定位问题

遇到异常时，从最早可能拥有该事实的层开始：

1. 用 stage dump 找到首次出现错误形状的层。
2. 检查该事实是否已由前层发布但未被复用。
3. 若事实缺失，补在自然 owner；若事实正确，再检查本层 plan 或 rewrite。
4. 用最小源码 case 同时验证运行等价、目标源码合法性与必要的可读性合同。

调试命令见 `10.debugging.md`，测试协议见 `11.test.md`，pass guard 规则见 `../design.md`。
