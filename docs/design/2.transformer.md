# Transformer / Low-IR

> **职责**：把 dialect-specific raw 指令穷尽翻译成统一 `LowInstr`，建立 raw 到 low-IR 的来源映射。
>
> **不负责**：CFG 切块、数据流推断、结构选择或 AST 语法糖。

## 入口与输出

```text
src/transformer/mod.rs
  lower_chunk(state, context)
  lower_raw_chunk(raw_chunk)
```

核心输出是 `LoweredChunk` / `LoweredProto`、统一 `LowInstr` 和 `LoweringMap`。`LoweringMap` 是
raw pc、low instruction、行号与 origin 回溯的正式接口；来源信息不重复塞入每种指令。
原 PC 边界通过 `low_instr_at_or_after_pc` 查询最早含有该 PC 或更晚来源的 low 指令。
映射与前缀最大 PC 索引在同一 lowering 事务冻结，查询为对数成本；多来源、空来源和乱序
PC 不改变语义，后层不假设 `pc_map` 单调或按每个 debug scope 重扫映射。

## 模块 owner

```text
src/transformer/
  mod.rs                      入口与 dialect 分派
  common.rs                   Low-IR、稳定索引与多值 carrier
  operands.rs                 operand 解构 helper
  dialect/lowering.rs         raw-pc、target 回填与 pending 协议状态
  dialect/puc_lua.rs          PUC-Lua 共有语义 helper
  dialect/puc_lua/            版本组共享 lowering
  dialect/{lua*,luajit,luau}/ 真实方言差异
  debug.rs                    low-IR dump
  error.rs                    TransformError
```

物理拆分不能制造第二套语义 owner：版本入口负责调度，共有 opcode 只由一个穷尽映射实现，独立
协议 helper 才进入具名子模块。

## 稳定合同

`NewTableInstr::allocation` 用 `TableAllocation` 区分空分配、索引预分配和模板复制。
LuaJIT TNEW 在本层解码正整数数组容量（扣除索引 0、处理饱和编码）与 hash 预分配位数；
TDUP 保留完整 `TableTemplate`，包括索引 0、nil 数组槽和 nil 值 hash 项的常量身份。
模板复制是一次分配初始化，不展开成空表后的独立 SetTable；丢弃占位键或容量会改变
nil-hole 的 `#table`。HIR 的语句与单次表达式入口共享同一模板 lowering。
PUC 的数组初始化由 SetList 批次表达，不签发索引式容量事实。

- 进入 CFG 前不再存在 dialect-specific instruction；无法表达的 opcode 返回 typed error。
- 同名 opcode 仍按各版本的真实编码与运行语义解析，不能按名字或数值位置猜测复用。
- owner/helper、method setup、fastcall、for-loop、closure capture 等多指令协议必须整体校验并冻结
  身份；不能丢弃 helper 后近似 lowering。
- 多值、open result、并行赋值和 call 参数用 `ValuePack` / `ResultPack` 等明确 carrier 表达，不能
  压成单值或连续寄存器猜测。
- 环境、raw table access、capture mode、closure reuse 等会影响运行语义的方言事实必须保留到
  low-IR；Transformer 不基于线性扫描推断后续 SSA provenance。
- PUC Lua 5.2+ 的词法环境是一个真实 upvalue cell：`UpvalueOperand::Env(UpvalueRef)`、
  `AccessBase::EnvironmentUpvalue` 与 `LoweredProto::environment_upvalues` 必须保留其索引身份。
  Lua 5.1、LuaJIT、Luau 全局 opcode 使用的无身份隐式环境继续由 `AccessBase::Env` 表示；两者
  不能合并成伪造的 `_ENV` global key。环境 role 与 upvalue identity 正交，后层的 mutation、
  capture 和生命周期分析仍以同一个 upvalue cell 为准。
- `CloseKind` 区分独立 cleanup 与原始 Return/TailCall 的 frame 协议，并保存配对终结指令身份。
  返回结果先确定再执行返回清理；独立 Close(0) 仍是后续求值前的关闭事件。尾调用只关闭旧 frame
  的 upvalue，受支持 Lua 的该路径没有待关闭 TBC。后层不按零槽或邻接 Return 重建这些事实。
- 常量保持原类型与不可变 payload，不改写成宿主 helper 调用。
- raw 与 dialect 契约不一致时 fail-fast，不静默忽略运行期 patch opcode 或非法 operand 组合。

## 数据流

```text
RawChunk
  -> dialect adapter
  -> shared lowering state / family semantics
  -> LoweredChunk { instrs, lowering_map, debug facts, child protos }
```

若多个 lowerer 出现相同逻辑，先判断它属于 Parser 协议事实、共享 lowering 状态、family 语义，
还是仅仅同名但不同义；只有前三类允许上提共享。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| low-IR 操作数或宽度错误 | 对应 dialect adapter/opcode lowering |
| raw pc、target 或 helper 归属错误 | `dialect/lowering.rs` 与 owner 协议 helper |
| call/method/fastcall 顺序异常 | 对应方言的 setup 与 call lowering |
| for binding 或 capture 身份错误 | family/dialect 的 protocol lowering |
| 查看 low-IR | `unluac --debug --dump transformer --stop-after transformer <file>` |
