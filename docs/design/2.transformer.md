# Transformer / Low-IR

> **职责**：把 dialect-specific raw 指令翻译成统一 `LowInstr`，建立 `LoweringMap`。
>
> **不负责**：CFG 切块、数据流分析、AST 语法选择。
>
> **例子**：`RawInstr::LoadK { dst: R0, k: 5 }` → `LowInstr::LoadConst { dst: Reg(0), src: ConstRef(5) }`

## 入口

```
src/transformer/mod.rs
  lower_chunk(state, context)      -- Transform 阶段入口，写回 LoweredChunk 槽位
  lower_raw_chunk(raw_chunk)       -- 显式事实 helper，按 dialect 版本分派到各 dialect lowerer
```

## 模块布局

```
src/transformer/
  mod.rs           入口 + 版本分派
  common.rs        统一 low-IR 类型（LowInstr / LoweredChunk / LoweredProto / LoweringMap 等）
  error.rs         TransformError
  operands.rs      define_operand_expecters! 宏
  debug.rs         dump_lir / format_low_instr
  dialect/
    lowering.rs         共享 lowering 状态：PendingLoweringState / WordCodeIndex / resolve_pending_instr_with
    puc_lua.rs          PUC-Lua 家族语义 helper 与共享 lowerer 入口
    puc_lua/
      lua52_53.rs       Lua 5.2/5.3 唯一 lowering owner
      lua52_53/adapter.rs  两版 typed raw 到共享指令视图的穷尽映射
      lua54_55.rs       Lua 5.4/5.5 唯一 lowering owner
      lua54_55/adapter.rs  两版 typed raw 与 operand 宽度到共享视图的穷尽映射
    lua51/ ... lua55/   版本入口或只保留真正方言差异的 lower.rs
    luajit/             lower.rs
    luau/               lower.rs
```

## 数据流

```
RawChunk
  └─ lower_raw_chunk
       └─ dialect::lua54::lower_chunk(raw_chunk)
            ├─ puc_lua.rs helpers
            ├─ lowering.rs PendingLoweringState
            └─ LoweredChunk {
                 main: LoweredProto {
                   instrs: Vec<LowInstr>,
                   lowering_map: LoweringMap,
                   debug_locals: Vec<DebugLocalFact>,
                   children: Vec<LoweredProto>,
                 }
               }
```

## 关键类型

| 类型 | 说明 |
|---|---|
| `LowInstr` | 统一低级指令，不含 dialect-specific 信息 |
| `LoweredChunk` / `LoweredProto` | 翻译后的模块树 |
| `LoweringMap` | raw pc → low-IR InstrRef 映射，排错回溯的正式接口 |
| `DebugLocalFact` | 方言无关的 local 名、寄存器、生命周期与 source/compiler-internal 分类 |
| `InstrRef` / `Reg` / `ConstRef` / `UpvalueRef` / `ProtoRef` | 稳定索引类型 |
| `ValueOperand` / `ResultPack` / `ValuePack` | 多值 carrier 表达 |

`LoweredProto` 保留 raw 常量池、source 和 debug 事实，但 `RawString` 的 bytes/text
是不可变 `Arc` payload。raw -> lowered 的结构 Clone 不能再深拷贝字符串内容。

PUC Lua 与 LuaJIT 按 local 生命周期入口处的活动局部顺序恢复寄存器；Luau 直接消费
显式 `local_regs`。只有协议定义的 `(for ...)` 名称会分类为 compiler-internal：它们可供
loop protocol 观察，但不得成为源码 binding 或阻止临时值消除。`LoweringMap.line_hints`
继续保存逐 low-instruction 行号；`LoweredProto.debug_name` 保存 Luau 显式 proto 名，供父
closure binding 在 local provenance 缺失时采用。缺失 debug 时上述事实自然为空。

## 应优先复用的共享设施

| 设施 | 用途 |
|---|---|
| `lowering.rs::PendingLoweringState` | raw pc / target 回填 / method hint / line hint，多 dialect 共用 |
| `lowering.rs::raw_pc_at` / `next_raw_pc` | word-len-bearing dialect 的 raw pc 查询，避免各版本 lowerer 复制索引样板 |
| `puc_lua.rs` | RK / `k` bit operand 转换、immediate 条件操作数、PUC-Lua jump target 计算、for-loop lowering 骨架、call / return / tailcall emit、env upvalue helper、`ADDI+MMBINI` family 恢复规则 |
| `define_operand_expecters!` | operand 解构成具名字段，不要手写 match arm |
| parser raw accessor | 已有 accessor 就优先消费，不直接匹配 `Dialect*Extra` |

## 维护规范

1. **版本文件只保留语义差异**：`lower.rs` 应只表达"这个 opcode 在 low-IR 里对应什么"和"与共享 family 的真正差异"。
2. **low-IR 不保留 dialect-specific instruction**：进入 CFG 前必须已经翻译成统一 `LowInstr`。
3. **`LoweringMap` 是正式契约**：排错 / 回溯通过 `LoweringMap`，不把 raw pc / line / origin 再塞进 low-IR 主体。
4. **语义事实优先前移**：如果某个 helper 在多个 lowerer 里平行出现，判断它是否属于 parser 协议事实 / 共享 lowering 状态 / PUC-Lua family 语义 helper。
5. **错误边界清晰**：输入 raw 与 dialect 契约不符时直接返回 `TransformError`，不静默忽略。
6. **同名 opcode 也要按版本语义处理**：例如 `LOADNIL` 在 Lua 5.1 使用结束寄存器语义，而 Lua 5.2/5.3/5.4/5.5 的 `B` 是从 `A` 开始的偏移量。lowering 时应先确认 raw 指令协议，不要因为 opcode 名相同就复用相同 range 计算。
7. **method hint 按寄存器写入失效**：method setup 与最终 `CALL` 之间可能夹着参数求值调用，例如 `obj:method(f())`；pending method hint 只能在 callee/self slot 或返回值写入范围被覆盖时失效，不能因为中间出现普通 `CALL` 就全局清空。`TESTSET` 这类条件写入也必须保守失效，否则合流后的 `CALL` 可能误用只在另一条路径成立的 method hint。call 消费时必须显式传入方言真实首参槽，PUC/Luau 是 `callee+1`，LuaJIT 则是 `callee+1+fr2`。
8. **常量类型不在 lowering 重写**：Luau vector 等已进入 `RawLiteralConst` 的稳定字面量继续走普通 `LoadConst`；Transformer 不把它伪装成宿主构造器调用，否则会错误引入调用副作用并改变优化边界。
9. **PUC-Lua 5.4+ 二元 helper 与 owner 成对消费**：寄存器算术 `ADD..SHR + MMBIN`、`ADDI/SHLI/SHRI + MMBINI` 和 `*K + MMBINK` 必须校验相邻 helper 的寄存器、常量或立即数、metamethod event 与 `k` flip，并把两条 raw 指令共同映射到一个 `BinaryOp`；不能先按 owner 的编码顺序 lowering、再静默丢弃 helper，独立 helper 必须 fail-fast。
10. **LuaJIT compare 完整消费 D operand**：`ISLT..ISNEP` lowering 对寄存器、KGC、KNUM 和 primitive 右操作数都必须读取 parser 已解码的 16-bit `D`；不能退回 ABC 的低 8-bit `C`，否则大常量池中的比较会生成另一个合法但错误的值。
11. **Lua 5.1 VARARG 的 B 包含协议偏移**：`B == 0` 表示 open results；固定结果的实际数量是 `B - 1`，与 5.2/5.3 相同。Transformer 不能把编码字段 `B` 直接当作 `RegRange` 长度，否则会多覆盖相邻寄存器并改变后续 local 值。
12. **Lua 5.2/5.3 共有 lowering 只保留一个 owner**：parser 继续用独立 typed opcode 描述协议边界，`lua52_53/adapter.rs` 通过两个穷尽 match 归一共有指令外形，`lua52_53.rs` 只实现一次 Low-IR 语义。不得用 opcode label 字符串猜测分类，也不得为两版复制整套 lowerer；5.3 的整除和位运算在共享 opcode 视图中显式保留。
13. **Lua 5.4/5.5 共有 lowering 只保留一个 owner**：`lua54_55/adapter.rs` 穷尽映射两版 typed opcode 与 operand kind，`lua54_55.rs` 只实现一次 Low-IR 语义。`ivABC`、Lua 5.5 专属 vararg opcode、`SELF` key 协议、for 绑定偏移与 `EXTRAARG` 倍率仍通过 typed dialect 属性显式区分，不得按 opcode 数值位置或 label 字符串猜测。
14. **根环境身份不能由 debug 名字决定**：Lua 5.2+ 根 proto 的首个 upvalue 是运行时环境，子 proto 只沿非 in-stack upvalue 描述符继承该身份。debug 中名为 `_ENV` 的 in-stack upvalue 可能只是捕获父函数的同名局部表，必须保留普通 upvalue/table access；否则生成裸 global 会脱离原词法环境并改义。
15. **环境身份必须穿过普通 upvalue 读写**：Lua 5.4/5.5 的 `GETTABUP/SETTABUP` 只有 8-bit key；常量索引超出后，官方编译器会改发 `GETUPVAL _ENV + LOADK + GETTABLE/SETTABLE`。`GetUpvalue/SetUpvalue` 的 low-IR operand 必须区分 `Env` 与普通 upvalue，让 Dataflow/HIR 沿定义恢复环境表访问；不能只在直接 table-upvalue 指令保留环境身份，也不能在线性 Transformer 中维护寄存器 provenance。
16. **GETIMPORT 与 method setup 保留协议身份**：Luau 会把源码 call 的 callee import setup 调度到末位 open 参数 producer 之后；`GETIMPORT` 虽展开为一到多条统一 `GetTableInstr`，每段仍须标记为 `GetTableKind::Import`。HIR 只消费该前层事实识别 import setup，不能从 `Env + 常量 key` 形状反猜方言 opcode，也不能把普通全局/表读取误当成可跨越事件。`SELF/NAMECALL` 同理由 `Method` 分型持有，并先把 receiver 复制到隐式 self 槽，再以该快照槽作为 method lookup base；这样 lookup 元方法即使改写原 binding，隐式首参仍是 lookup 前的 receiver。LuaJIT 没有独立 `SELF`，Transformer 只接受官方 `MOV self,obj; TGETS callee,obj,key` 或大常量 `MOV; KSTR; TGETV` 槽位协议；setup 内部必须没有显式入边，lookup 完成后到 `CALL*` 只允许来自该完成点之后的内部入边。普通 `obj.f(obj, ...)` 的 lookup/copy 顺序相反，保持 `Normal`。`Method` 只标协议，不表示 lookup 可删除。
17. **branch subject 不表达非法组合**：`BranchCond` 的 `BranchSubject` 只允许 `Truthy(operand)` 或 `Compare { Eq/Lt/Le, lhs, rhs }`。各 dialect 必须通过 `truthy/compare` 构造完整条件，不能把 predicate 与 unary/binary operands 分开放进两个可任意组合的枚举；Dataflow/HIR 因而可以穷尽匹配合法条件，不保留 unary-compare 或 binary-truthy 的后层 unresolved fallback。
18. **LuaJIT 内建类型守卫不是条件分支**：`ISTYPE/ISNUM` 来自官方 `LJLIB_LUA` 的 `CHECK_*` fixup，类型不符会进入 `lj_meta_istype` 抛参数错误，string/integer/number 还可能原地隐式转换。Transformer 必须把已知 type id 归一成 `TypeGuard` 并保留一次可观察 guard；Dataflow 把这三类成功路径冻结为 subject 的新 SSA def，function/table 只读取。官方矩阵只接受 `ISTYPE {str,func,tab,int}` 与 `ISNUM num`；`ISTYPE num` 和未知 type id 立即报 `TransformError`，不能把精确 tag 检查与 numeric fast path 混成一种语义。后层在没有精确 Lua 源码表达时只能显式保留诊断残差，不得把 guard 当作 no-op 或伪造 helper `JMP`。
19. **闭包捕获方式属于统一语义事实**：Luau `CAPTURE VAL` 在创建闭包时复制寄存器当前值，`CAPTURE REF` 才共享父级可写词法槽位。Transformer 必须分别降低成 `CaptureSource::ByValue` / `ByReference`；PUC Lua 与 LuaJIT 的栈槽捕获使用 `ByReference`。不得把两种 Luau capture 压成同一个寄存器来源，否则后续物理寄存器复用会被 HIR 误写进快照 upvalue。
20. **generic-for 显式区分源码 pack 与运行时槽位**：`GenericForCall` 以具名 `iterator/state/control` 表达真实调用读取，`GenericForLoop` 以 `control_target + bindings` 表达首结果到下一轮 control 的写回。Lua 5.4/5.5 的 `TFORPREP` 另降成 `GenericForPrep`；它同时保存交换前的四项源码 pack 与交换后的 control/closing target，Lua 5.4 是 identity，Lua 5.5 是 `A+2/A+3` 并行交换。不能再用连续三寄存器 range 同时冒充源码 owner 和 runtime call，也不能把 closing 注册伪装成显式源码 `Tbc`。
21. **LuaJIT raw 表访问保留协议身份**：`TGETR/TSETR` 是对整数键的 raw 读写，分别绕过 `__index/__newindex`；Transformer 必须用 `GetTableKind::Raw` / `SetTableKind::Raw` 保留该差异，不得与 `TGETV/TSETV` 合并成普通表访问。`raw-get-table` / `raw-set-table` 的 LIR dump 名称也必须可见，便于沿官方 `table.remove` 等 `LJLIB_LUA` 内建的 dump 核对协议；是否能源码化由 HIR 根据目标语言合同决定。
22. **LuaJIT 反向关系比较保留逻辑取反**：`ISGE` / `ISGT` 分别是 `ISLT` / `ISLE` 的条件取反，必须降低成 `not (lhs < rhs)` / `not (lhs <= rhs)`；不得通过交换操作数伪装成 `rhs <= lhs` / `rhs < lhs`。两者在 NaN 下真值不同，table/userdata 比较还会选择不同 metamethod 与参数顺序。源码 `>=` / `>` 自身需要的操作数交换已由 LuaJIT 编译器编码，Transformer 只还原当前 opcode 的真实 predicate 与 polarity。
23. **运行期 patch opcode 必须拒绝而不是静默近似**：Luau `BREAK` 依赖 VM 的原指令 shadow 与 debugger hook，`NATIVECALL` 依赖已安装的 native `execdata`，都不是可删除的源码级 hint；LuaJIT `JFORL/JITERL/JLOOP` 的 `D` 已由 jump offset 改写成 trace id，也不能和 `FORL/ITERL/LOOP` 共用 lowering。官方序列化器通常不会写出这些运行期形态，但一旦输入中出现就必须 `UnsupportedOpcode` fail-fast，不能把 trap/native dispatch 丢掉或把 trace id 当跳转偏移。
24. **Luau AUX 计数不能退化为空语义**：`GETIMPORT` 的路径长度只能是 `1..=3`，`FORGLOOP` 的变量数只能是 `1..=255`。顶位/低八位给出零值时必须在 Transformer 报 `UnexpectedOperands`；不能让空 import path 消费指令却不定义目标寄存器，也不能构造零结果、零 binding 的 generic-for owner。
25. **closure 创建方式与 child 实例是两项独立事实**：所有普通 `CLOSURE` / `FNEW` 与 Luau `NEWCLOSURE` 都是 `Fresh`，每条静态指令获得独立的 `LoweredProto` child 实例；Luau `DUPCLOSURE` 是带父 proto 局部 `SharedClosureRef` 的 `Reusable`，同一引用的多条指令共享一个实例。不能仅按原 child slot 合并，否则不同 fresh occurrence 会混合 capture provenance；也不能把每条 `DUPCLOSURE` 展成独立函数，否则会改变闭包对象相等性。统一实例化 helper 保持原 child 位置，只把额外 occurrence 追加到 children，克隆量与实际源码闭包 occurrence 数量同阶。带 capture 的重复 shared 引用继续完整进入 HIR；Transformer 不静态 alias，也不因第二个 site 提前拒绝。共同词法 factory、capture dependency DAG 与无法证明时的 fail-fast 统一由 HIR 按 CFG/Dataflow 事实决定。

## 排错指引

| 症状 | 检查点 |
|---|---|
| low-IR 指令语义与源码不符 | `transformer/dialect/puc_lua.rs` family 规则是否正确匹配 opcode 组合 |
| method hint 丢失 | `lowering.rs::PendingMethodHints` 是否正确传递 |
| for-loop 变量错位 | `puc_lua.rs` for-loop lowering 骨架 |
| 想看 low-IR | `unluac --dialect lua54 --debug --dump transformer --stop-after transformer <file>` |
