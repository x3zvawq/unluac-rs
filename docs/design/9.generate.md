# Generate

> **职责**：把 Readability 后的稳定 AST 与 `NameMap` 渲染成最终 Lua 源码文本。纯输出层。
>
> **不负责**：结构恢复、命名策略、可读性 sugar、补缺失语法节点。
>
> **例子**：`AstIf { cond, then_block } + NameMap` → `"if cond then\n  ...\nend"`

## 入口

```
src/generate.rs
  generate_chunk(state, context) -> Result<(), DecompileError>
```

`generate_chunk` 是 decompile pipeline 的 Generate 阶段入口：它直接从 `DecompileState` 读取
Readability AST、NameMap 和 HIR 元信息，注释 metadata 从 HIR 中已经稳定提取的 source /
line / signature 等事实构造，并把 `GeneratedChunk` 写回 state。

## 模块布局

```
src/generate/
  common.rs     GeneratedChunk / GeneratedChunkKind / GenerateOptions / GenerateMode / NumberFormat / QuoteStyle / TableStyle / LuauVectorConstructor / LuauVectorSize
               GenerateCommentMetadata / GenerateChunkCommentMetadata / GenerateFunctionCommentMetadata
  error.rs      GenerateError
  doc.rs        Doc IR（布局中间层）
  render.rs     Doc → String（行宽折行 / 缩进 / 着色）
  emit/
    mod.rs      generate_chunk 骨架
    expr.rs     AstExpr → Doc（含运算符优先级与括号规则）
    stmt.rs     AstStmt → Doc
    syntax.rs   标点 / 关键字 / 通用语法片段（含 long-bracket 字符串规则）
    names.rs    读取 NameMap
  debug.rs      dump_generate
```

## 数据流

```
DecompileState(Readability AST + NameMap + HIR) + DecompileContext
  └─ generate_chunk(state, context)
       ├─ emit/stmt.rs + emit/expr.rs   AST → Doc
       └─ render.rs                     Doc → String
            └─ GeneratedChunk { kind, source }
```

Strict 只生成请求方言可表达的源码。Permissive 可以序列化未结构化 goto/label 和 Error
占位；Generate 扫描最终 AST，只要存在目标方言不支持的特性或 Error 节点，就把产物标为
`diagnostic-pseudocode`，并在首行输出 `-- [unluac error]` 说明。该提示属于产物本身，不再
另外写入 stderr，便于用户保存、阅读和反馈完整诊断上下文。

## 应优先复用的共享设施

| 设施 | 用途 |
|---|---|
| `emit/names.rs` | 读取 `NameMap`，获取当前函数上下文的 binding 名字 |
| `emit/syntax.rs` | 标点 / 关键字 / long-bracket 字符串选择（`[[...]]` vs `[=[...]=]`）/ quoted 字符串控制字符按 UTF-8 byte escape 输出 / 非 UTF-8 字节串按 `\ddd` escape 输出；多字节编码的可读文本视图仅影响展示，不影响 `LuaString` 语义 / numeric-for 步长省略 |
| `NumberFormat` | 控制整数数字字面量的十进制 / 十六进制输出；不改变 AST 数值语义，`i64::MIN` 会强制用 hex，避免 Lua 5.3+ 十进制重编译成 float |
| `format_number` | 浮点字面量输出；整数值 float 会保留 `.0`，避免 Lua 5.3+ 重编译成 integer |
| `is_default_numeric_for_step_for_target` | numeric-for 默认步长省略；Lua 5.3+ 不省略 `1.0`，避免 loop 变量从 float 变 integer |
| `doc.rs` | 布局 IR，布局策略通过 Doc 而非直接拼字符串 |

## 维护规范

1. **Generate 不补前层丢失信息**：AST 中没有的节点（`global *` / `global<const>` / `SingleValue` / `local <close>`），Generate 不自行发明。
2. **优先级由 Generate 统一维护**：运算符优先级与括号规则集中在 `emit/expr.rs`，不让调用方依赖 AST "刚好安全"。
3. **布局与语义分开**：语义选择（emit）与行宽折行 / 缩进（Doc / render）不混在同一个函数里。
4. **`NameMap` 始终按函数上下文读取**：进入嵌套函数时切换到正确上下文，不用模块级平铺表。
5. **共享输出规则落到 `emit/syntax.rs`**：如字符串 long-bracket 选择、numeric-for 步长省略等，统一在此，debug / generate 收敛到同一套文本约定。
6. **Luau vector 构造器与维度必须由宿主显式提供**：bytecode 只有四个分量，没有原源码的库名、构造器名或 VM 的三维/四维编译配置；四维 `w = 0` 与三维 vector 无法从常量区分。遇到 `AstExpr::Vector` 时，Generate 严格按 `GenerateOptions::luau_vector_constructor` 中的 `LuauVectorSize` 输出三或四个参数；未配置或名字不是 Luau 合法标识符时直接报错，不能从 `w` 猜维度，也不能猜 `Vector3.new`、`vector.create` 等运行环境 API。
7. **LuaJIT complex 必须是可重编译的纯虚 numeric token**：官方 lexer 的 `i` 是 numeric token 后缀，complex 常量的实部固定为正零；有限虚部直接输出 `Ni`，正负无穷分别输出 `1e999i` / `-1e999i`。`(1/0)i` 不是合法词法，非零或负零实部、NaN 虚部也没有等价的纯 LuaJIT 字面量，遇到这类手工 chunk 必须 fail-fast，不能拼出会编译失败或运行报错的算术伪表示。
8. **负数字面量按一元运算维护优先级**：整数、浮点、LuaJIT int64 / complex 等文本只要以前导 `-` 输出，就必须使用 unary precedence；尤其作为幂运算底数时要保留括号，不能把 `(-2) ^ x` 改成 `-2 ^ x`。已经自行带括号的非有限数表示仍按 literal 处理。
9. **以括号开头的调用必须与前句显式分隔**：赋值、带值声明、调用或带值 `return` 后若紧跟 `({...})()` / `(function() end)()` 等调用，换行不会终止前一表达式，必须在两句之间输出分号，不能让布局改变 AST 语义。
10. **long-bracket closing 不能跨内容边界提前闭合**：选择等号层级时，既要排除内容内部已有的完整 closing，也要排除内容以后缀 `]` 加同层级等号结尾；否则该后缀会与追加 closing 的首个 `]` 组成更早的结束符并截断字符串。

## 向后提供的事实

`GeneratedChunk`（含 `source: String` 最终源码文本）。

## 排错指引

| 症状 | 检查点 |
|---|---|
| 括号多余或缺失 | `emit/expr.rs` 运算符优先级 |
| 字符串输出格式错误 | `emit/syntax.rs` long-bracket / 转义规则 |
| 函数内变量名错误（名字来自外层） | `emit/names.rs` 函数上下文切换 |
| numeric-for 步长不该出现但出现了 | `emit/syntax.rs` 默认步长省略判断 |
| 想看 Generate 结果 | `unluac --debug --dump generate <file>` |
