# 6. Naming 与 Generate（命名与源码渲染）

> **职责**：
> - `Naming`：为最终稳定 `AstModule` 中的每个绑定分配合法、确定、无遮蔽冲突的字符串名称，输出 `NameMap`。
> - `Generate`：将 `AstModule + NameMap` 排版渲染为符合目标方言语法与格式选项的 Lua 源码文本。
>
> **不负责**：修改控制流、消除变量、验证编译器内联成本模型或补救前层恢复缺口。

这两层位于流水线末端，专注可读命名、精准语法发射与美观排版，不耦合控制流分析或特定编译器优化假设。

## Naming（变量与绑定命名）

支持三种命名模式（默认 `heuristic`，可切换 `simple` 与 `debug-like`）：

| 模式 | 无 debug 名时的命名策略 |
| --- | --- |
| `heuristic`（默认） | 结合表达式形状、字段读写、标准库调用签名、动词前缀函数名（如 `get_player` / `GetPlayer` / `GET_PLAYER` → `player`）与 `self` 接收者模式推断语义化名字，歧义时回退通用名 |
| `simple` | 参数用 `a/b/c`，普通局部用序号变量或基础角色名（`self`、`i`/`k`/`v`、`_`） |
| `debug-like` | 生成带函数与绑定序号的 `p1_0`、`r1_0`（可选关闭函数序号），便于对照字节码 |

### 核心合同

- **直接消费 `AstModule`**：debug 名字提示、闭包捕获关系（父子 binding 对应）作为只读元数据附在 `AstProto` 上，Naming 仅做只读查询。
- **确定性与词法安全**：
  - 优先保证有效 debug 名与显式语义名不被匿名启发式猜测抢占。
  - 启发式 `self` 还原仅在首参无 debug 名、函数体实际将其作为表接收者访问且函数内不存在其他显式 debug `self` 冲突时生效；Generate 仅在 `path` 含成员段且首参最终分配名为 `self` 时渲染为 `function a.b:method(...)`。
  - 所有绑定名严格避让目标方言关键字（按 `DecompileDialect::is_keyword`）、同作用域重名，以及会遮蔽子闭包中裸全局变量引用的外层局部名。
  - Upvalue 名字严格继承其父级被捕获绑定的最终名字，保证嵌套闭包读写同一身份。
  - 结果完全确定，不依赖 `HashMap` 随机迭代顺序。

## Generate（纯粹排版与渲染）

```text
AstModule + NameMap + 原 chunk 浮点宽度 + GenerateOptions
  ──→ emit (优先级括号、字面量精度、方言语法)
  ──→ Doc (Wadler 风格布局 IR，含表格对齐)
  ──→ render (按缩进与行宽输出最终文本，同时记录 proto_line_spans)
  ──→ GeneratedChunk { dialect, kind: Source | DiagnosticPseudocode, source, proto_line_spans }
```

### 核心能力

- **外部 Emitter + `Doc` 布局树**：AST 保持纯数据，括号与运算符优先级由 `emit/expr.rs` 统一管理，折行/紧凑布局由 `doc.rs` + `render.rs` 决定，布局变化绝不改变语法分组。
- **字面量严格往返**：
  - 数字尊重原 chunk 的浮点宽度（f32 / f64）与 Lua 5.3+ 整型/浮点区分，极端值采用科学计数法确保重编译数值位一致。
  - 字符串支持 `readable_strings`（优先输出可读 UTF-8 文本，保留不可打印字节转义）与原字节保真开关；内部比较与关键字判断仍基于原始字节。
- **表格对齐布局**：完整支持对齐网格与键值等号对齐特性（见 [table-alignment.md](../table-alignment.md)），适合阅读游戏大型配置表。
- **注释分层（`CommentStyle`）**：默认 `Minimal` 仅输出精简文件头与存在有效源码行号时的函数标注；`Full` 附带每函数 `proto#N params=...` 统计注释；`None` 关闭全部注释（兼容布尔开关 `true`/`false`）。
- **函数行号映射（`proto_line_spans`）**：渲染阶段同步记录每个 proto 在最终源码中的起止行号，供 Web 工作区函数大纲与源码高亮跳转使用。
- **清晰区分 `Source` 与 `DiagnosticPseudocode`**：仅当 `Permissive` 模式下存在 AST 错误诊断节点（`AstStmt::Error` / `AstExpr::Error`）或目标方言不支持的语法特性时，才标记为 `DiagnosticPseudocode` 并加注文件头注释；普通 `Source` 保证目标方言语法合法。
