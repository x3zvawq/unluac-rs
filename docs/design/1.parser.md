# 1. Parser（字节码解析）

> **职责**：将输入字节流保真解码为方言相关的 `RawChunk`，完整校验二进制协议布局。
> **不负责**：指令语义统一、CFG 构建、数据流分析或源码结构恢复。

本层实现位于 `src/parser/`，覆盖全部 7 种受支持 Lua 方言（Lua 5.1 ~ 5.5、LuaJIT 2.1、Luau）。

## 入口与数据流

```text
bytes
  ──→ detect_dialect(bytes) / 显式 dialect
  ──→ dialect parser + shared family helpers
  ──→ RawChunk { header, main: RawProto }
```

核心入口位于 `src/parser/mod.rs`：
- `detect_dialect(bytes)`：按 magic（`\x1bLua`、`\x1bLJ`）与 Luau 版本前缀识别真实方言。
- `parse_chunk_with_dialect(dialect, bytes, options)`：分派到对应方言解析器，在 `ignore_debug` 模式下先完整校验再清除 debug 段。
- `parse_input(state, context)`：流水线阶段适配器。

## 模块组织

```text
src/parser/
  mod.rs                 统一入口与方言分派
  reader.rs              大小端、varint 与有界读取
  limits.rs              嵌套深度、proto 数量与内存预算
  strings.rs             RawString 原始字节保存与按需编码解码
  options.rs / error.rs  ParseMode / StringEncoding 选项与 ParseError
  raw/                   对外公开的 RawChunk / RawProto 模型
  family/puc_lua/        Lua 5.1 ~ 5.5 共享二进制骨架
  dialect/               lua51~lua55、luajit、luau 各自解析器与 opcode 定义
  debug/                 parser 阶段 dump（受 decompile-debug feature 控制）
```

## 稳定合同

- **自动探测仅在输入边界发生**：解析完成后，后续所有阶段只消费确定的具体方言。
- **原始字节与展示文本分离**：`RawString` 以原始字节作为语义身份，编码解码后的 UTF-8 文本仅用于展示与命名。
- **多字指令与辅助字归属明确**：Luau 的 `AUX`、PUC 的 `EXTRAARG` 在本层与主指令绑定，不以孤立空指令泄漏到下游。
- **防御性资源边界**：所有计数、常量表、proto 树深度在分配前均受 `limits.rs` 约束，防止恶意或损坏文件导致 OOM/栈溢出。
- **失败显式**：非法头部、截断或越界索引返回 `ParseError`；`ParseMode::Permissive` 仅容忍已知的非标准但可安全读取的头部差异，不盲目跳读错位字节。
