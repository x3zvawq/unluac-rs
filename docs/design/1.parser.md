# Parser

> **职责**：把输入字节流解析成保真的方言 raw 模型，并完整校验协议布局。
>
> **不负责**：指令语义统一、CFG、数据流或源码结构推断。

## 入口与输出

```text
src/parser/mod.rs
  detect_dialect(bytes)
  parse_input(state, context)
  parse_chunk_with_dialect(dialect, bytes, options)
```

输出 `RawChunk` / `RawProto` 保存 header、typed opcode、operand、常量、proto 关系及可用 debug
信息。后层只通过 `src/parser/raw/` 的公开模型和 accessor 消费这些事实。

## 模块 owner

```text
src/parser/
  mod.rs                 入口与方言分派
  reader.rs              endian、varint 与有界字节读取
  limits.rs              深度、展开量与输入资源预算
  strings.rs             RawString 构造与解码
  options.rs / error.rs  选项与 typed error
  raw/                   对外 raw 模型、方言 extra 与格式化
  family/puc_lua/        Lua 5.1~5.5 共享 chunk 骨架
  dialect/               各真实方言的 parser 与 typed opcode
  debug/                 parser dump 与公共展示
```

PUC-Lua 版本共享 family 层；LuaJIT 和 Luau 保留独立协议边界。共享只针对真实相同的编码骨架，
不能抹掉 typed opcode、operand 宽度、常量池或 proto 组织差异。
所有方言的调试视图直接消费 `src/debug/focus.rs` 的 proto 前序身份与焦点计划；公共 literal
池的独立常量视图由 `parser/debug/common` 输出，方言文件保留自身布局、header、extra 与指令展示。

## 稳定合同

- 自动探测只发生在输入边界；一旦解析完成，后层消费确定的真实 dialect。
- `ProtoSignature` 分别保留 Lua 5.1 的 HASARG 槽与 NEEDSARG 建表事实；后层核对源码
  变参前缀时同时保留入口分配，不能从隐式槽存在推断是否创建旧式 `arg` 表。
- 公共字面量池在解析结束时冻结为 `Arc<[RawLiteralConst]>`，发布后只读；所有字面量索引
  已在冻结前确定，后层与 raw clone 共享载荷，不保留可变容量或复制完整列表。
- LuaJIT 表模板的 array/hash 项与 KGC Literal 只保存公共池索引，不另存一份值；独立描述符比较的是
  索引关系，完整常量池仍比较实际载荷。模板 debug 从该池读取值，Transformer 只投影索引。
- 所有计数在用于分配或循环前都要结合剩余字节与全局预算验证。
- 深 proto 与 Luau flat-DAG 展开使用显式工作栈和 occurrence budget，不能依赖宿主调用栈。
- helper word、AUX、EXTRAARG 等必须与 owner 指令绑定，不能作为独立空语义指令泄漏到后层。
- `RawString` 的原始 bytes 是语义事实，解码文本只是展示与命名视图；不可逆解码不能覆盖 bytes。
- debug local 的半开生命周期与 `RawInstr::pc` 使用相同坐标。Luau 保留包含 AUX 的 word PC，
  仅校验其是指令边界或代码终点，不转换为压缩后的指令 Vec 下标。
- `ignore_debug` 在完整读取和校验后清除 debug 事实，不得改变 parser 严格度或输入消费路径。
- 非法 header、长度、索引、枚举值或协议组合返回 `ParseError`，不跳读、不猜默认值。

## 数据流

```text
bytes
  -> dialect detection / explicit dialect
  -> dialect parser + shared family helpers
  -> RawChunk { header, main proto tree }
```

新增协议事实时，先判断它是跨方言 raw 事实、某 family 共有布局，还是单一 dialect extra；放到
最窄且真实的 owner 中，并通过 accessor 提供给 Transformer。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| header、长度或字符串错位 | `reader.rs`、对应 dialect parser |
| opcode/operand 解码错误 | `dialect/*/raw.rs` 与 opcode table |
| child proto 数量或顺序异常 | 对应 proto/section reader 与 `limits.rs` |
| debug 生命周期异常 | 对应 debug section parser；确认 `ignore_debug` 时机 |
| 查看 raw 产物 | `unluac --debug --dump parser --stop-after parser <file>` |
