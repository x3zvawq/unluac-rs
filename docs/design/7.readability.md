# AST Readability

> **职责**：在 AST 已合法且语义事实完整的前提下，把机械语法收敛成稳定、可读的源码形状。
>
> **不负责**：重建 HIR value flow、补 Structure 控制事实、发明 binding 或修复前层不等价。

## 入口与调度

```text
src/ast/readability/mod.rs
  make_readable(state, context)
  make_readable_module(module, target, options, timings, dump_passes)
```

Readability 使用与 HIR 相同的 invalidation scheduler。pass 声明 `AstInvalidation` 的依赖和产出；
Normal 收敛后运行 Deferred，Deferred 改变形状时重新触发 Normal。收敛预算耗尽返回错误。

当前 pass 名称只作为调试导航：

| Phase | Pass |
| --- | --- |
| Normal | `cleanup`、`statement-merge`、`branch-pretty` |
| Normal | `field-access-sugar`、`inline-exprs`、`literal-fold` |
| Deferred | `materialize-temps`、`installer-iife`、`function-sugar` |
| Deferred | `global-decl-pretty`、`goto-syntax-safety`、`local-scope-limit` |

具体候选、证明、拒绝条件和改写示例见对应源码文件头与 guard 行注释。

## 共享设施

```text
src/ast/readability/
  walk.rs                         AST rewrite，子节点与只读遍历复用 ast/traverse.rs、ast/visit.rs
  binding_flow/                     读写、capture 与 use-site 事实
  binding_tree.rs                   词法 binding 树
  control_flow.rs                   AST 级控制边界查询
  expr_analysis.rs                  表达式事件、复杂度与上下文事实
  stmt_plan.rs                      语句级候选 plan
```

pass 应复用这些设施，不各自实现 scope walker、binding use 扫描、表达式副作用判断或 plan/apply
协议。跨 pass 的新事实应放到明确的共享 owner，而不是通过节点文本形状暗示。
名字与 binding 的身份转换、匹配直接消费 `ast/common.rs` 中的 `AstBindingRef` 方法。

`expr_analysis` 将当前 AST 投影到 [共享正常结果域](5.hir.md#simplify-调度)，布尔性、truthiness
和候选结果的 GC 惰性使用同一份 Lua 短路选择规则；不消费改写前 HIR 的值快照。`SingleValue`
只投影其单值结果，Decision 与路径假设仍归 HIR。常量锚定不等于可以复制源码字面量：LuaJIT
cdata 的重复物化可能改变身份，复制/事件 guard 仍独立证明；原 VM 根类别继续消费 HIR profile。

通用表达式存在性、复杂度与 context-safe/stable 查询消费 `visit::expr_nodes` 的先序事件，
不进入 child body。复杂度仍计裸 record key 和函数直属语句的成本；stable 在一次遍历中
同时检查节点安全与名字稳定性，只在根部允许单值 vararg，不向内部 logical/not 节点推广。

method alias 的有序改写先保存首个先序匹配的 child ordinal 路径与借用替换物，再沿该路径
验证求值前缀、短路和分配边界；首候选不获许可时整体拒绝，不转向后续匹配。路径只属于
当前不可变 AST，提交至多复制 sink 一次；各层前缀子树互不相交，继续消费共享稳定性查询。
owner 布尔查询与正式改写共用完整候选许可，包含 binding 删除、根存活、后缀写与使用次数；
布尔查询不构造替换 AST。`method_plan` 借用表达式或 CallKind 根，避免临时包装复制；计划不跨
Normal/Deferred 阶段保存，未替换的外层调用保留全部 provenance。

函数声明 target 查询只负责名字路径与方言语法，不复制函数体。forwarded 与 method chain
先验证已有 binding/capture/root 删除许可，再构造输出；不能声明的动态 target 仍保留赋值。

constructor handoff 按 binding 身份索引 active local，一次扫描直属实参的首次出现，要求
首次位置保持声明顺序；重复实参不更新首次位置，不能用寻找下一个 expected 的贪心匹配
放宽顺序许可。sink 先完成表达式许可再复制语句；直属 call 借用原节点并保留调用 provenance。
function-sugar 在 nested rewrite 后的当前原始语句快照发布 constructor 连续单声明段边界，
借用潜在终端 callee 排除不可能起点，再复制需要试改写的参数值。索引越过 Assign/FunctionDecl
仅寻找必要终端，字段接线、容量和删除许可仍由原 owner 验证；各起点独立处理，不假设 binding
唯一，也不借用 Normal inline 的候选资格或旧快照。其他 owner 消费前缀时保留原 ordinal。
字段接线从语句一次读取目标 binding、字段和借用函数，首次需要时索引每个 binding 的首个
table 实参；接线期间值种类不变，索引只属于该候选。已接入其他表的实参仍参与字段查询，
首个匹配 table 不允许追加时直接拒绝；嵌套表接线的首个任意实参规则保持独立。

带状态的 rewrite walker 由 `RewriteScope` 保存和恢复词法位置；`VisibleGlobals` 记录当前层
的命名属性变化，local 预算直接保存计数，不在每条语句或每层嵌套复制祖先环境。临时 statement
状态覆盖 children 与最终 rewrite 回调，回退后才按改写后的语句推进后继状态。global function
自名在函数体前生效，普通 declaration initializer 使用前域；repeat body 的最终状态持续到
`until`，处理完条件才回退。扩域许可比较复用同一回退状态，按共享 visitor 顺序逐次比较访问
许可，不复制祖先环境或另写语句解释器。

名字事件与函数边界遵守 [AST 共享 visitor 合同](6.ast.md#核心合同)。
读取统计只消费 Read/Capture，提及统计消费所有角色，写入索引消费赋值与独立的函数声明。
`function t() end` 写入 t，`function t.f() end` 和 `function t:m() end` 读取路径基址 t；
function-sugar 改变语法后必须保留这项读取，不能只统计函数的 capture 而漏掉声明目标。
构造器追加函数字段或嵌套表还需逐项消费[原分配的键许可](5.hir.md)，并在完整候选上
统一核对批次容量，不能在 HIR 已保留独立写入后根据 AST 终端形状绕过这些事实；
open tail、capture 和现有根证明仍分别适用。
当前函数的 binding 收集器消费 capture 事件，不进入 child body 重新统计。
集合引用和布尔读写查询共用 `binding_flow/refs.rs` 的名字谓词：`reads` 只计 Read，`uses`
计 Read/Capture，赋值只计 Write；不为存在性查询构建计数或位置索引。候选集合查询在名字
访问时查询已有容器，不按每个候选重复遍历表达式，首次命中即结束本次入口遍历。

`binding_flow::BindingWriteIndex` 按名字保存当前快照的稀疏赋值位置，binding 查询只转换 typed
身份，不另建一套索引；区间查询二分定位，交接查询只遍历实际写入位置。local function 声明
单独登记，删除声明时查询重绑定，不能将它混入 inline 的赋值边界；普通 local/for 初始化
与 child function 的潜在 capture write 不属于这份赋值事实。批次消费者使用原始顶层下标，
提交表达式改写或生成新语句列表时不得将旧索引解释为改写后的语句位置。

`inline_exprs/run_facts.rs` 保存当前不可变快照的完整候选识别结果与连续段终点，包括身份、
debug 来源、initializer root 属性和借用的 RHS；各 run 消费者从下一起点重试时复用这些事实。
逐步改写表达式的 stable-copy 则即时识别当前声明，共用后续写入检查而不复用旧 RHS。
后续 call-result 位置与候选声明位置按需索引；声明身份
来自 candidate 识别，不从 RHS 读取推断。相同身份的多个声明保留各自位置，成员查询必须
限定当前 run 的区间。试改写使用 sink 副本，原始位置只在 plan 提交前有效。
机械 run 用消费点类型区分末尾 local 与后继语句，共享候选读取、改写及事务提交过程；
末尾 local 的持续 root 与普通消费点的生命周期、展示条件分别判断。两轮按上述顺序执行，
每轮重新读取当前语句快照，不将前一轮改写前的位置用于后一轮。

block 外部入边检查消费[共享词法索引](../design.md#pipeline-总览)，目标和来源均投影嵌套语句，
不为每个候选区间重新合并 label 集合并扫描区间外的 goto。

repeat 顶层语句的 label/goto/continue 与落空摘要在一次语句结构遍历中归约，跳过表达式与
child function；父块直接消费子块摘要，保留含跳转块的保守落空边。支配树消费共享图算法；
嵌套语句内部路径仍由 handoff 候选证明。stable-copy 批次只替换表达式，声明删除延迟到批末，
因此可按需共用一次当前 AST 的支配分析，以子树区间回答查询；这不授权复用前层的旧 CFG。

`branch-pretty` 的 single-pass repeat 候选只对当前 If/Do 树后序生成一次 flow 计划，许可检查
与提交共享该计划。直属语句顺序及子块计划随原树移交，计划不跨改写保存，也不覆盖提交时
下沉的新 continuation；完整许可通过后才移动 AST。嵌套 loop 在当前 break 的 flow 域中保持
不透明，goto/label/Error 预检仍检查其内部，原有作用域与 root 生命周期许可独立保留。

## 稳定边界

- Readability 只能消费 AST/HIR 已显式保存的身份和 provenance，不重新扫描 low-IR/CFG。
- 所有改写都保持求值次数、从左到右顺序、多返回宽度、短路条件和 metamethod 可观察顺序。
- debug/source identity、PhysicalRoot、capture、`<close>`、goto/label 与 lexical lifetime 不是普通
  展示成本；是否可删除必须消费明确事实。
- AST 可以比较候选改写前后的源码求值顺序和临时 handoff，但不能据此重建原 VM home 的 root
  区间；值在首次消费后仍须跨事件存活时，必须由 HIR 的 PhysicalRoot/provenance 先行表达。
- 普通 call 的 callee、receiver 或 argument 源码位置不构成 root handoff：动态 callee 可以不接收
  对应参数，callable object 的 `__call` 也可以不保留 implicit receiver。只有唯一 return call
  终结 caller frame、顶层 return value，或 HIR 为同一 call occurrence 签发的窄 handoff 才能
  作为相关 AST 内联的生命周期证明；generic-for iterator/header 不能替代这项证明。
- `statement-merge` 对 PhysicalRoot 空声明默认拒绝 initializer merge。唯一例外是声明与紧邻赋值
  携带相同 `HirInitializerMergeTransactionId`，且 AST 重新证明无 debug identity/attribute/
  `Preserve`、targets 与 bindings 逐项一致、RHS 不自引用并满足 Lua 值调整规则。合并产物清除
  token；缺一端、token 不同或形状漂移都保守拒绝，不能退化为通用 Assign fallback。
  空声明沉入嵌套子块前，后缀读取与写入均须为空；只有赋值的后缀同样需要原声明支配，
  否则赋值会落入全局环境。各入口共用读取/写入索引，不以值已死代替词法作用域证明。
- `function-sugar` 删除 method lookup producer 时必须消费同一
  `HirMethodRewriteTransactionId` 的唯一 assignment/call 双端。HIR 负责原始 SELF/NAMECALL 协议、
  definition/use、物理 home 与旧 target 根生命周期；AST 只复核当前两条紧邻语句仍可写成
  `receiver:method(args)`，并原子消费两端。raw method key、`callee_root_handoff` 或 LocalId 匹配
  都不是 producer 删除许可。事务端点唯一性按完整当前函数统计，遍历在 nested function 停止；
  子函数进入自身 proto 后另建索引，不能跨函数借用 token。
- `global-decl-pretty` 的 repeat collective 只对实际 suffix 中的 HIR-origin 直属声明查询
  `AstRepeat::lifetime`；`cleanup` 删除 repeat 尾 `do` 时也只对候选内的 HIR-origin binding
  查询同一 owner-scoped 集合。两个 pass 共用 binding identity adapter；该集合绑定当前 repeat
  condition 边界，不是 binding 级通用许可。
  AST 仍证明直接条件引用、`<close>`、debug identity、incoming goto 与 global gate 词法作用域；
  对象身份、弱引用可观察性、closure capture/escape 和多返回值调整由 HIR finalization 统一
  证明，cleanup 不再以“包含 closure/PhysicalRoot”作为替代证明。materialize 不改变来源，
  certificate 本身不随 AST 名字改写；身份分域与 authority 合同见 [AST](6.ast.md#核心合同)。
- repeat body 末尾新建的 `do + global *` 不覆盖 `until` 条件。事实收集必须区分 body 与
  condition 的 missing observations；collective 成功后只清除 body 已覆盖部分，条件缺失名仍
  由 repeat 共享作用域里的逐名声明恢复。
- inline 的复杂度阈值是展示策略，不是语义证明。先完成语义与生命周期证明，再应用用户预算。
- plan/apply 必须原子化：应用前重新验证的形状不一致时不得部分删除或部分提交。
- materialize 只处理最终仍存在的 Temp；它不能掩盖 HIR 应消除的 value carrier。
- `local-scope-limit` 只能通过合法词法块缩短已闭合 local 生命周期，不能用不安全内联规避编译器
  local 上限。
- Readability 完成后由 `goto_scope.rs` 复核最终 AST 的跳转作用域。

pass guard 分类与固定检索命令见 `../design.md#pass-guard-合同`。

## 新增或修改 pass

1. 先确认职责确属 AST 展示形状；若需要 SSA、loop owner 或多返回来源，回到 HIR/Structure。
2. 复用共享遍历与 binding/expr/control facts，定义候选与原子提交边界。
3. 在 descriptor 中声明最小 `depends_on` / `invalidates`，并选择 Normal 或 Deferred phase。
4. 按 Pass guard 合同标记拒绝与接受缺陷，使用最小源码 case 验证语义和形状。
5. 用 `--dump-pass` 检查前后快照及 fixed-point 行为。

## 排错

| 症状 | 首查位置 |
| --- | --- |
| 声明/赋值未合并或作用域错误 | `statement_merge.rs`、`local_scope_limit.rs` |
| field/method/function sugar 缺失 | 对应 sugar pass 与 binding facts |
| 表达式未内联或顺序变化 | `inline_exprs/`、`expr_analysis.rs` |
| 常量 branch 未简化 | `literal_fold.rs`、`branch_pretty.rs` |
| Temp 进入 Naming | `materialize_temps.rs`；同时回查 HIR owner |
| 查看 pass 变化 | `unluac --dump-pass <pass-name> <file>` |
