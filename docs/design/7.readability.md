# AST Readability

> **职责**：把已经合法的 AST 收敛成更接近源码、适合进入 Naming 的稳定形状。
>
> **不负责**：补前层事实、替 AST build 修结构、替 Naming 发明 binding 身份。
>
> **例子**：`local __t = obj["n"]` → `local __t = obj.n`（field-access-sugar pass）

## 入口

```
src/ast/readability/mod.rs
  make_readable(state, context) -> Result<(), DecompileError>
  make_readable_module(module, target, options, timings, dump_passes) -> AstModule
```

## AST Readability Pass 清单

调度器由 `src/scheduler.rs::run_invalidation_loop` 驱动，5 个 invalidation tag（`AstInvalidation`）：
`StatementAdjacency` / `ControlFlowShape` / `ExprShape` / `BindingStructure` / `TempPresence`。

| pass 名 | phase | 主要作用 |
|---|---|---|
| `cleanup` | Normal | 空 block / 冗余节点清理 |
| `statement-merge` | Normal | hoisted temp 声明下沉回首次赋值附近（尊重 goto/label 词法边界） |
| `branch-pretty` | Normal | 已结构化 if 的展示整理、已证明常量 arm 收回与 guard-return |
| `field-access-sugar` | Normal | `obj["key"]` → `obj.key` |
| `inline-exprs` | Normal | 局部变量内联（受 ReadabilityOptions 阈值控制）；多候选 run 需通过可观察事件前缀证明，单值终态 return 另有相邻 alias 规则与有限拼接/短路展示预算 |
| `literal-fold` | Normal | 只收回严格原始字面量比较、Boolean `not`，以及布尔值语境的 `x and true` / `x or false` |
| `materialize-temps` | Deferred | 残留 temp → synthetic local（边界 pass） |
| `installer-iife` | Deferred | installer / 复杂 IIFE → 有界局部函数声明 |
| `function-sugar` | Deferred | 函数声明 sugar + 有独立 receiver 快照的 method-call sugar |
| `global-decl-pretty` | Deferred | global 声明美化（Lua 5.5 `do + global *` 最小 canonical 形状） |
| `goto-syntax-safety` | Deferred | goto 方言的块尾终止语句合法化 |
| `local-scope-limit` | Deferred | 按外层预算把短生命周期 local 分组到有限 `do` 作用域，避免生成源码超过编译器 local 上限 |

**重要**：多个 pass 可能在同一个 dirty 循环内多次执行——这是设计预期，不是重复。例如：
- `field-access-sugar` 会在 `inline-exprs` 之后再跑一轮（inline 暴露了新字符串索引）。
- `statement-merge` 会在 `branch-pretty` 之后再跑一轮（控制流收敛后新暴露 hoisted temp）。
- `branch-pretty` 会在 `literal-fold` 之后再跑一轮（`ExprShape` 暴露了可消费的
  `Boolean` 条件）；它不自行从普通 truthy 表达式猜常量。
- `statement-merge` 把空 local 声明与后续赋值合成 initializer 前，必须确认 RHS 不读取或 capture 这些 binding；Lua 的 local 在自身 initializer 内尚不可见，合并会改变闭包捕获和同名读取的词法绑定。

调度器只有在完整一轮没有 pass 继续改写时才算收敛；达到轮数上限会作为 AST stage
错误返回，不能把中间态交给 Naming。

### 新增 pass 步骤

1. 在 `readability/mod.rs::PASS_DESCRIPTORS` 添加 `PassDescriptor { name, phase, depends_on, invalidates }`。
2. 在 `PASS_ENTRIES` 添加 `ReadabilityPassEntry { apply: xxx::apply }`（与描述符一一对应）。
3. 新建 `readability/xxx.rs`，优先使用 `walk.rs` / `visit.rs` / `traverse.rs` 共享设施。
4. **优先判断是否已有同类 owner**：如果只是现有 pass 约束过窄漏收了某种形状，应扩展现有 pass 而不是新建。

## 应优先复用的共享设施

| 设施 | 用途 |
|---|---|
| `walk.rs` | rewrite pass，默认先完整递归所有子节点再执行当前 hook，不短路 |
| `visit.rs` | 只读 collector |
| `traverse.rs` | 共享子节点递归骨架，不要为单个 pass 复制一整套递归样板 |
| `binding_ref.rs` | `AstNameRef` 与 `AstBindingRef` 的双向纯身份转换和匹配 |
| `binding_flow.rs` / `binding_flow/refs.rs` | binding use 统计 / mention 集合 / binding 集合引用查询；`refs.rs` 只回答 stmt/block/expr 是否引用一组 binding，供下沉和合并类 pass 做边界检查 |
| `binding_tree/` | stmt/expr/lvalue 的 binding 位置查询；`rewrite.rs` 只替换已完成语义校验的表达式 use-site，不改写 binding 生命周期 |
| `expr_analysis.rs` | 复杂度 / 内联安全性 / 屏障判断 |
| `inline_exprs/use_sites.rs` / `candidate.rs` | use-site 判定共享逻辑 |

**walker 契约**：所有子节点必须先完整递归；不能因为前一子树 `changed=true` 就短路跳过后续；当前节点 hook 也必须总是执行。

## 维护规范

1. **新 pass 默认先接共享 walker/visitor**：不复制专用递归框架。
2. **binding / 表达式约束复用共享 helper**：binding use 统计、mention 集合、替换、access-base 安全判断、单值判定等，补到共享 helper 而不是分散在 pass 内。
   - 多 binding membership 查询先构造 `BindingRefSet` 并复用，不在每个 name reference 上线性扫描 local binding 列表。
3. **`materialize_temps` 是边界 pass**：Readability 结束后不应再把原生 `TempId` 留给 Naming。它通过共享 walker 覆盖声明、循环 binding、函数名、命名变参、capture metadata、lvalue 与表达式引用，不维护第二套 collector/递归框架；Naming 前校验必须覆盖同一组身份位置。依赖原生 temp 的新 pass 应放在它之前。
4. **branch-local 值壳回 HIR**：`local x; if cond then x=a else x=b end` 这类，如果前层已经足以证明是"给同一 binding 选值"，应回 HIR 用 `Decision->Expr` 处理，不在 AST 层重新发明。
5. **参数 alias 不在 AST 收回**：`local L = param` / `local L; L = param` 这类 binding 身份收敛属于 HIR `locals` 的后置步骤，Readability 不把 local 重新改写成参数写回。
6. **`statement_merge` 尊重 goto/label 边界和前缀读取**：不能把 `local` 下沉到 forward goto 之后，否则生成"跳进 local 作用域"的非法 Lua；也不能把 hoisted temp 下沉到已经读取过该 binding 的语句之后，否则 fallback/goto 回边会读到尚未进入作用域的新 local。
7. **binding 生命周期只由 HIR 收敛**：carried/seed local 的身份合并、writeback 与 closure capture 边界统一由 HIR `carried-locals/locals` 证明；Readability 不根据 AST 语句形状重写 binding 身份，也不裁剪伴随的多目标写回。
8. **`function_sugar` 统一承接有 receiver 快照的 method-call sugar**：`local r = recv; local f = r.field; f(r, ...)` 等形状由同一 owner 判断。`inline_exprs` 发现相邻调用准备 run 属于 method-alias 形状时只让位，不提前把 receiver / field alias 内联掉；第一轮相邻单项扫描也必须保留完整的 receiver + field + sink transaction，不能先吞 field alias 而销毁 method 证据。无独立 field alias 的 `local r = recv; r.field(r, ...)` 要求 sink 中恰好两次读取同一 binding，分别作为字段基底和首个 self 实参；generic-for iterator run 仍归 `inline_exprs`。
8.1. **method provenance 不能在 AST 边界丢失**：HIR 的 `method_name` 即使因 receiver/callee 快照不满足 `method_receiver()` 而只能落成普通 `Call`，也必须随 `AstCallExpr` 保留。它可以作为字段函数声明的既有 method 事实，沿嵌套 closure 传给同一个 `function_sugar` owner；terminal-constructor 在同一 fresh owner 上遇到该 owner 已能证明为 method 的字段闭包时，延后构造器折叠，让 `direct` 生成 `function obj:field(...)`。这里恢复的是与字段写完全等价的 canonical spelling，不声称找回原始冒号源码；若 round-trip 后该调用已变成普通点调用，字节码不再提供这份事实，仍允许回到字段函数形状。
9. **method-call sugar 不能合并两次可观察 receiver 求值**：`local r = make(); local x = make().method(r)` 不能折成 `local x = make():method()`；`recv.field(recv)` 也不能只凭 AST 名称相同折成 `recv:field()`，因为字段查询可能通过 `__index` 改写 `recv`，两者传入的 receiver 不同。只有前层的显式 method fact，或已经独立物化且不会被字段查询改写的 receiver 快照，才能生成冒号调用；LuaJIT 的 `MOV+TGET*+CALL*` split protocol 也必须由 Transformer 冻结，HIR/AST 不从点调用形状反猜。
10. **链式 method-call 只能吃掉死 local**：`local x = a:b(); x:c()` 折成 `a:b():c()` 前，必须确认 `x` 在后续语句没有继续作为 receiver、字段基底或闭包捕获被读取；若还要顺带吞掉前置 unused local，该 local 的初始化式必须是 `is_discard_safe_expr` 认可的确定无副作用表达式。
11. **inline-exprs 不重排可观察求值**：`local v = side(); if guard() == v then` 不能折成 `if guard() == side() then`。如果候选表达式本身会观察求值序，它只能内联到下一条语句的第一个运行时求值位置；例如 `local v = side(); local x = callee().method(v)` 必须保留 `v`，不能改成 `callee().method(side())`。`repeat` 条件在 body 之后求值，因此也不能接前置可观察表达式。多候选 run 会把多条声明统一搬入 sink；必须递归展开候选依赖，并证明调用、lookup、全局读取、运算与构造器等可观察事件仍按声明顺序组成 sink 的运行时求值前缀，且中间没有 retained 可观察候选，否则整段拒绝折叠。
12. **method 声明 sugar 不能遮蔽全局 `self`**：冒号语法把首参固定为 `self`，无法由 Naming 改名；若函数体当前层含裸全局 `self`，应保留点号函数声明及显式首参，让 Naming 为参数避让全局名。嵌套函数各自拥有词法边界，不参与当前方法的判定。
13. **AST 不重新综合短路语义**：纯逻辑表达式的等价验证与规范化归 HIR decision/logical owner，包括依赖恒真值证明的 `not a and x or y` 臂交换。Readability 不维护第二套 truthiness 事实，也不把每个 AST 子表达式转回 HIR 后枚举环境和候选；这种逆向跨层不仅重复 HIR 工作，还会让一棵表达式的每个后缀分别承担候选数乘环境数开销。`literal-fold` 只消费 AST 已经显式暴露的严格事实：同类型 integer/有限 number/string 的 `==`、`<`、`<=`，以及 boolean/nil 的 `==` 可直接变成布尔字面量；已经保证产出布尔值的 `x and true` / `x or false` 可收回 `x`，`not true` / `not false` 只做对应 Boolean 字面量归一。它不推断普通 truthy 原子，不跨 NaN、不同数值表示、vector/complex、lookup 或元方法边界。
14. **末尾 return call 不提前物化**：`local callee = object.call; return state, callee()` 中，调用可以改写前置 return value 读取的 binding。Readability 不把末尾 call 提前塞回 callee local；保留原顺序即可表达正确语义，也不需要另一个补偿 pass。
15. **未使用 local 不能吞掉全局读取**：`is_discard_safe_expr` 只接受字面量和非全局 binding 引用；`AstNameRef::Global` 即使只是 RHS，也可能通过环境表 `__index` 产生副作用或错误。Readability 不能因 local 无读取者而删除这次求值。
16. **AST 不恢复 goto/label 控制壳**：前向 guard、terminal-goto else 和相邻 nop goto/label 统一由 HIR `branch-control` 消费。`branch-pretty` 只整理已经结构化的 if/else，并消费前层显式产出的 `Boolean` 条件；不得在 `GlobalDecl` 等方言声明节点已经生成后再搬动线性尾部或维护第二套 label 引用统计。
17. **AST pass 不用结构相等推断改写命中**：AST 同样含 `f64` 数值字面量，带 `NaN` 的未改写语句与自身克隆比较也不相等。`function-sugar` 等候选式改写应返回 `Option<AstStmt>`，只有规则真实命中时才报告 changed；fixed-point 调度不能依赖整棵 AST 的派生 `PartialEq` 判断 pass 是否改动。
18. **terminal guard 只提升实质主体**：`branch-pretty` 可把函数尾的 `if cond then BODY; return end` 取反为 early-return 再提升 `BODY`，但 `BODY` 不能只是一条无值 `return`。提升后的主体若含 local/local function、属性 local、`GlobalDecl` 或 label/goto，必须由 `lifted_tail_stmts` 保留 `do` 词法边界；否则会改变 debug/捕获/`<close>`/global 声明生命周期。单独的空 `return` 没有可提升内容，取反只会补出另一条函数尾空 return，而 `cleanup` 下一轮又会删除它，形成条件极性永久振荡。
19. **local 资源限制不能改写求值顺序**：大量顺序调用若因 conservative lowering 形成数百个
    源码 local，`local-scope-limit` 只能在 binding 最后 mention 之后闭合作用域，不能把调用、
    global lookup、比较或算术重新内联到后续 sink。pass 必须携带外层活跃 local 上界，进入
    嵌套函数时按该函数参数重新计数；无属性声明可分组，`<const>` / `<close>` 与顶层
    label/goto 是硬边界。外层已经耗尽全部预算时，子块不能把同一声明反复包进新的 `do`；
    这种身份膨胀应由 HIR home-slot compaction 前层解决，AST 只停止无进展改写。该 pass 位于
    Deferred 末端且不触发 cleanup，保证新增资源作用域不会被展示层清理再次展开。
20. **带属性的 local 不是可丢弃机械声明**：`cleanup` 只能删除无属性、单 binding、单个可安全丢弃 RHS 且没有使用者的 recovered local。`<close>` 即使没有普通读取，词法域结束仍会调用 `__close`；`<const>` 也保留显式源码属性身份。Readability 不得把属性当成零 use，也不得以 RHS 本身纯净为由删除声明。尾部 `do ... end` 展开同样必须保留直接声明 `<close>` local 的资源边界；`repeat` body 与 `until` 条件共享外层作用域，拍平内层资源块会把关闭时点错误推迟到条件之后。
21. **普通 binding 读取是有时点的值快照**：local/upvalue/param/temp/synthetic local 读取本身没有副作用，但 `local snapshot = state` 保存的是定义点的值，不能内联到会改写 `state` 的调用之后。`inline-exprs` 的相邻候选与多候选 run 都必须把这类 RHS 纳入有序快照证明：快照只能落到 sink 中第一个可能改写或观察状态的事件之前；反过来，待移动的调用/lookup/运算也不能越过 sink 已有且可能被改写的快照。upvalue 天然共享，当前函数的 local/param/temp 只有被内层 closure capture 后才会被调用改写；未捕获的固定结果不应成为虚假屏障。被删除的纯 alias/literal 候选也必须先按 RHS 展开，不能把旧 sink 中即将消失的名字误判成快照。不得把所有变量读取标成一般可观察副作用，否则会无谓阻止纯 alias 收敛。
22. **method alias 只进入无条件同频 sink**：`local r = make(); local f = r.m; local x = outer(f(r))` 折成嵌套 method call 前，目标位置之前的 callee、操作数和参数必须都是不会触发用户代码、也不会被 receiver/lookup 改写的稳定前缀；capture provenance 与 `inline-exprs` 共用同一份 mutable snapshot 事实。逻辑短路右臂、table constructor、outer method 参数不满足无条件前缀；`while`/`repeat` 会把一次 alias 求值改成逐轮求值，始终禁止。赋值 sink 还要求全部 target 都是纯名称，不能越过 table lvalue 地址计算。
23. **nested hoisted-local 按唯一 owner 下沉**：`statement-merge` 先一次性收集条件、各分支与循环体的 binding mention；条件、循环头以及同时出现在多个分支的 binding 是硬边界。对 suffix-dead pending run，候选顺序仍从 run 起点和各真实 mention 起点展开，但每个起点只尝试 owner 改变前的最大连续切片；未被提及的中间 binding 必须随组保留，以维持并行赋值的声明/RHS 词法边界。一次改写后不前进当前扫描位置，让同一 nested stmt 立即继续接收剩余组；block 改写完成后再由 fixed-point 下一轮重建 use index。
24. **block 重建必须转移不变语句的所有权**：`statement-merge` 与 `inline-exprs` 会在 fixed-point 中递归访问整棵 AST；不命中的语句直接 move 到新 block，不能 clone 包含深层 closure 的完整子树。只有需要回滚的局部候选可以 clone trial sink，且失败后必须保留原语句、成功后只提交该次改写结果。
25. **repeat 尾 temp 不在 AST 删除**：删除 body 尾写入并把 RHS 移入 `until` 会改变表达式 owner、求值位置与可能的循环状态身份，属于 HIR `temp-inline` 的语义收敛。AST `inline-exprs` 只收回已证明安全的 numeric/generic-for alias run，不根据已物化的 Temp/SyntheticLocal 形状补做 repeat-tail fallback。
26. **loop header alias 归并到通用内联 owner**：HIR `temp-inline` 先收回原生 temp，其中 numeric-for 连续准备 run 内唯一用于 header 的稳定字面量可越过保留的状态赋值；AST `inline-exprs` 再统一处理已恢复 local 的 numeric/generic-for 与其它 sink 前机械别名。AST 多候选 run 要求至少两个候选、唯一使用、后缀 dead 与完整的可观察顺序证明；单调用 generic-for 只额外收回紧邻、唯一使用的 recovered method-receiver binding 别名，并复用同一求值顺序证明。若迭代器仍引用待物化 temp，则必须保留到下一轮与整个准备包一起收回；lookup/call RHS 和 debug-hinted 源码 local 也不能走单项规则。Readability 不保留另一个 loop-header pass，避免同一 binding run 被两套扫描与改写规则竞争。
27. **原生 temp 的表达式内联只归 HIR**：`inline-exprs` 只收敛已恢复或已物化的 local alias，不把 `TempId` 赋值重新当作 AST 候选。原生 temp 的 producer/use、结构边界与 capture 生命周期只能由 HIR `temp-inline` 证明；未能在 HIR 消除的 temp 由 `materialize-temps` 变成稳定 synthetic local，再按普通 local 可读性规则处理。
28. **内联不能删除仍有后续写入的 local 声明**：binding read index 故意不把简单 name target 当作读取；`inline-exprs` 删除 initializer 前必须另查当前函数内的 direct name write（包括无字段 function target）。索引按顶层语句一次冻结最后写入位置，嵌套 block 归外层语句、嵌套函数止步，不能为每个候选重新扫描 suffix；否则保留下来的赋值会被 Generate 渲染成全局写。
29. **源码 debug binding 是不可消除身份**：AST build 延续 HIR 的 debug-backed local
    origin；`cleanup` / `inline-exprs` 不得删除、合并、扩大作用域或内联这类真实源码
    local。compiler-internal 槽位没有该保护，仍可按普通机械 binding 简化。Readability
    不用行号或 debug 生命周期补做控制流推断。
30. **未使用的调用结果只转成调用语句**：`cleanup` 可以把无属性、无 debug 身份、无后续
    使用或 capture 的 recovered `local t = f(...)` 转成 `f(...)`，保留调用及其求值顺序；
    只处理普通调用/方法调用，不把任意有副作用表达式当成可丢弃值，也不触碰真实源码
    local、`<const>` 或 `<close>` binding。
31. **物理根 global callee 只允许紧邻普通调用**：`local f = assert; f(value)` 在 AST
    中可收回为 `assert(value)`，因为调用帧在参数求值期间继续持有同一 callee，且普通
    call 的 callee-before-argument 顺序不变。若中间还有 producer、逻辑赋值、table
    lvalue、method lookup 或 generic-for setup，global lookup 的原快照时点不能由 AST
    猜测，PhysicalRoot 必须保留；该规则不等价于“全局名不可变”。
32. **repeat 条件属于正文 block 的尾随读取**：Lua 的 `repeat` 正文与 `until` 条件共享
    词法作用域。共享 walker 必须把条件交给正文 block 的专用 hook；`cleanup`、
    `statement-merge`、`inline-exprs` 与 `local-scope-limit` 都把它计作正文之后的读取。
    否则 pass 可能删除仍被条件读取的声明，或把声明缩进 `do` / 分支后移出条件可见范围。
33. **多值 return 只内联稳定顶层 alias**：相邻 recovered `local a = x; return a, ...`
    可以收回为 `return x, ...`，但 `x` 必须是 context-safe 表达式；另外，比较结果为
    布尔值且两个操作数都属于 context-safe/单值 vararg 子集的表达式，
    也可在同一规则下收回。后者不会把对象结果或多返回值带入 return 列表，比较协议仍在
    原有相对位置执行。upvalue 或被闭包捕获的 binding 仍作为有序快照，由 eval-prefix
    证明读取没有越过更早的调用、lookup 或运算；任何调用、lookup、构造器或不确定的
    comparison operand 都继续保留。
34. **复杂 IIFE 的名字必须有界**：独立调用语句中的匿名函数去掉机械尾 `return` 后，只有
    包含多条语句或一条复合控制语句时才值得物化名字；单条简单 `return` / call 等短 IIFE
    保留原样。改写保持“创建 closure → 求调用参数 → 调用”的顺序，并把新增 local function
    与调用包在最小 `do` 作用域中，使 closure 及其 captured value 在原调用点后立即失活。
    `cleanup` 不得把这个 closure scope 当作尾部机械 `do` 展开；安装器 IIFE 已有的导出规则
    仍可沿用父 block 局部名，由其自身用途证明生命周期。具有返回值的复杂 closure callee
    则由 HIR 保留原 producer binding；`function-sugar` 的 terminal-constructor 规则不得再把
    该 binding 连同 constructor 参数一起吞回表达式。两层共享同一 substantial-body 阈值，
    短 callee 与纯 constructor wiring 仍保持原优化。
35. **恒真 single-pass fence 只在唯一后缀路径上收回**：Structure/HIR 为无标签 `break`
    归属物化的 `repeat ... until true`，可在 AST 控制流已经固定后改回 `if/else`。
    `branch-pretty` 只允许一个 arm 继续执行线性后缀，不复制后缀；两个 arm 都可能
    fallthrough、`do` 作用域内仍有 fence break、或出现 `continue/goto/label` 时保留原
    fence。后缀进入某个 arm 前，该 arm 也不能含会被延长生命周期的直接 local 声明。
    嵌套真实循环的 break 不属于 fence，始终保持原 owner。
36. **跨语句 copy 只替换稳定 binding 读取或 primitive literal**：`local alias = source`
    可以越过无关语句收回到唯一后续 use，但 `alias` 必须是 recovered local，`source` 只能是
    当前词法域内的 local/synthetic local，二者都不能被 closure capture，且声明后不得再
    直接写入任一 binding。`nil/boolean/integer/有限 number/string` 没有运行时求值事件，也可在同一
    唯一 use 规则下直接替换；字符串常量仍由当前 Proto 常量表持根。规则不接受
    global/upvalue/param、lookup、call、运算、constructor、非有限 number 或
    Int64/UInt64/Vector/Complex；非有限 number 生成 `(0/0)` / `(±1/0)`，后四类在对应方言
    可能物化 cdata/vector，都不能当作无运行时求值事件的 primitive 搬动。因此规则不会改变求值
    顺序、lookup 快照、多返回值宽度或最后对象 root。表达式是否可安全替换与复杂度阈值分开
    判定；这里的展示成本恒为一次名字或字面量读取。参数 alias 仍归 HIR `locals`，不在 AST
    扩张身份收敛边界。
    唯一例外是 repeat body 内的精确 root handoff：source 在唯一 use 前无写，use 是单目标
    direct-copy assignment，target 未捕获、之后无写且由 `until` 条件读取，并且正文没有 label/goto。
    此时 target 从 handoff 到 alias 词法域结束持续持有同一个值，source 才可在 use 后写入；
    任一条件缺失都继续保留 alias，不能只凭值等价缩短 GC root。
37. **相邻自调用更新只折叠单次 receiver/callee 读取**：`local x = first(); x = x:next()`
    或 `local x = first(); x = x()` 可以收回初始化式，并连续吸收同形更新；初值必须是普通
    call/method-call，声明只能有一个无属性、非 debug binding，每条更新也只能是紧邻的单目标、
    单 RHS 赋值，且 RHS 中恰好一次读取 `x` 并固定出现在直接 callee 或 method receiver 位。
    两边都在单值上下文，调用和 lookup 的顺序不变；原 local 持有的结果在折叠后由下一次调用
    的 callee/receiver 求值槽持有到调用结束，因此这条精确链也适用于 PhysicalRoot，但不放宽
    其它物理根内联。binding 声明本身仍保留，后续读取、写入与 capture 不改；若初始化式提到
    自身，或更新的参数/closure 还读取自身（如 `x = x(x)`），必须拒绝，避免改变 local
    初始化式的词法可见性。若自调用链之后还存在把下一次结果查表并写回旧 root home 的
    `call→field→call` 协议（例如 `a = b.value_text; sink(a, b)`），则该链不属于本规则：
    原始 `SELF` 虽然会在 lookup 前用 `MOVE (A + 1) <- B` 覆盖隐式 self 槽，但当前 HIR
    在 temp-inline 后未必还把这次覆盖与 lookup 的 intra-call 时点配对。只把 field alias 换成冒号调用，或
    只删除其中一个 local，可能把旧 root 的覆盖提前、延后，甚至让它跨过 lookup；弱表、
    `__gc`、自动 GC 和 lookup metamethod 都能观察到差异。因此必须保留 HIR 标出的
    PhysicalRoot 与精确 overwrite partner；只有前层提供完整 snapshot/overwrite provenance
    并在同一事务中重建整条 method chain 时，才能另开规则。`method_name` 本身不放宽这条门槛。
38. **exact nested-if 只合并等价短路条件**：`if A then if B then body end end` 只有在
    outer then 恰好只有一个 inner if、双方都没有 else 时，才能收回为
    `if A and B then body end`。两种形状都先单值求值 `A`，且只在 `A` truthy 时求值 `B`；
    被删除的中间 block 没有其它语句，body local 与 `<close>` 资源仍在同一个 then 末端退出。
39. **repeat 尾 continue/break 对只在 latch 路径精确时收回**：正文末两句恰为
    `if G then continue end; if B then break end` 时，可改成 `until (not G and B) or C`。
    `G` 为真时两种形状都跳过 `B` 后求值 `C`；`G` 为假且 `B` 为真时都跳过 `C` 退出；
    其余路径按顺序求值三者。prefix 中任意层 `continue/goto/label/error` 都拒绝，尤其更早的
    当前循环 continue 原本只进入 `C`，不能让它新增 `G/B` 求值。两条 if 必须无 else 且
    分别只含 direct continue/break；`not G` 与原 latch 完全相同时也保留控制壳，避免生成
    重复条件而降低可读性。repeat body local 在 latch 中仍处于同一词法作用域。
    body 含残留 goto/label 时保留原层级，避免展示阶段改变 fallback 的词法跳转深度。
40. **单值终态 return 只收回相邻 recovered alias**：`local value = expr; return value` 仅在
    local 为 recovered、声明后无 direct write、后缀唯一 use 恰为下一条单值 `return`，且
    `expr` 不含自身 binding/capture 时改写。纯 context-safe 表达式也可作为复杂 `return`
    表达式的唯一嵌套值收回。裸 `Call` / `MethodCall` / `VarArg` 可能在 return 列表展开，
    必须保留；`SingleValue` 是 lowering 已确认的单值边界。字段/索引、
    运算、短路、构造器和全局读取可以收回，因为它们只把同一条紧邻求值从 local initializer
    移到 return，不跨越其它事件；现有 eval-prefix、write/capture、复杂度阈值仍是最终门槛。
    多值 return、loop/repeat 尾条件、PhysicalRoot、debug local、method receiver 快照不在
    这条规则内，不能因表达式看起来只有一次读取而猜测绑定生命周期。
41. **单值 return 短路前缀只收回必达布尔 alias**：若 `local value = comparison; return
    value and A or B` 中 binding 只出现在短路树的最左、无条件求值前缀，可复用多值 return
    的布尔比较证明收回 alias。逻辑右臂明确不放行，因为搬入右臂会把比较协议从“必定先执行”
    变成受前置 truthiness 控制；比较操作数仍只能是 context-safe/单值 vararg，且保留
    origin、write/capture 与 eval-prefix 门槛。
42. **终态查表值只收回无事件短路尾**：`local value = table[key]; return value or 0`
    只有在查表 local 为 recovered、无属性/写入/capture/PhysicalRoot，且后缀唯一 use 恰为
    紧邻的单值 return 时才可折叠。binding 必须位于逻辑树最左必达前缀，索引与查表基底
    仍受 lookup-safe 约束；其后的 `and/or/not` 尾部只能由 context-safe binding/字面量组成，
    不得含调用、全局读取、另一层 lookup、比较或构造器。这样同一次 lookup 仍在同一返回
    表达式的第一个求值位置执行，临时表达式栈在 truthiness/return 完成前继续持有结果；
    一旦尾部存在可观察事件，通用 eval-prefix 会拒绝改写。debug local 与物理根仍不可消除。
43. **终态 concat alias 只放宽展示成本**：规则 40 的 `local value = E; return value` 证明仍是
    唯一安全门槛；当 `E` 的顶层是有限段数的 `..` 链时，`inline-exprs` 可以按拼接段数而非
    整棵 AST 节点数计费。当前实现最多 10 段，且每个叶段复杂度不超过 3；这只是防止
    `type(x)` 等小段把机械结果留成 local 的展示预算，不是新的 HIR 语义事实。recovered、
    唯一相邻单值 return、write/capture/eval-prefix、方言、单值/多值、debug/PhysicalRoot、
    `<close>`/GC root 与控制流约束都不放宽；低 `return_inline_max_complexity` 仍按用户预算拒绝。
44. **终态短路 alias 只放宽展示成本**：同一规则 40 的安全门槛下，顶层有限 `and`/`or` 树可以
    按叶子项计费，而不按整棵 AST 节点数计费。当前最多 12 个有限叶子，单个叶子复杂度最多 3；
    这只覆盖 HIR 已经收敛出的短路值合流（例如参数/字面量组合），不重建 truthiness 或改变
    结合树。候选仍必须是 recovered、唯一相邻单值 return，现有 write/capture/eval-prefix、
    bare call/method/vararg 的单值边界、debug/PhysicalRoot、`<close>`/GC root、goto/loop
    作用域保持不变；该规则本身不依赖方言，unsupported feature 仍由 Generate 的目标方言
    合同处理。若叶子含有调用、global/lookup 或元方法，事件顺序仍由既有 eval-prefix
    证明决定，展示成本 helper 本身不会放行它们。
45. **常量 if 只收回显式 Boolean arm**：`literal-fold` 已把无元方法的原始字面量比较
    收回 `Boolean` 后，`branch-pretty` 才能选择对应 arm；它不从普通 truthy 原子或文本
    形状重新推断条件。两臂含 `Error`、label、goto、break、continue、方言 `GlobalDecl`，
    或 DebugHinted/PhysicalRoot/local-function/captured binding 等身份边界时保留整个控制
    壳，避免丢失诊断、让外部跳转绕过原 block、改变 loop owner，或把 global 的词法声明范围
    搬到外层。选中 arm 含普通 recovered local 时用 `do ... end` 保持原 lexical scope、
    `<close>` 退出点和 captured local 的 GC/root lifetime；无这些边界时才能直接提升语句。条件是字面量
    Boolean，不产生运行时 lookup、call、metamethod 或多返回事件，保留 arm 内语句的原有
    求值顺序和单值/多值协议。
46. **终态 fixed nil pack 由 HIR 收回**：`Temp, Temp, ... = nil, nil, ...; return Temp, Temp, ...`
    只有在同一 block 中紧邻、固定返回宽度且无 open/exact tail 时，才可改成 `return nil, nil, ...`。
    目标必须全是 recovered 的临时槽，trusted `(home, close epoch)` 互不冲突、无 debug/capture、
    每个目标只有这一次 return 读取；proto 级 `<close>`/`Close` 与 home compaction 任一存在时
    整条规则停用。两种形状都只执行 nil literal、内部槽写/读和同一固定宽度 return，不移动
    call/lookup/global/metamethod/运算或短路事件；nil 不携带对象 root，且没有 cleanup 可在 return
    前观察槽位差异。参数/local/upvalue/table 目标、PhysicalRoot、不可信 home 和带 tail 的
    多返回继续保留机械写入，AST 不根据 `local ... = nil` 文本自行猜测。
