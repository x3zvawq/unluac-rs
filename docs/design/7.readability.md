# AST Readability

Readability 在 AST 已合法、前层语义事实已齐备的前提下整理源码形状。
它不重建 HIR 值流、Structure 控制归属或 VM 槽位。

## 入口与调度

入口为 [readability/mod.rs](../../src/ast/readability/mod.rs) 的
`make_readable` / `make_readable_module`。输入是 AstModule、目标方言与展示选项，
输出仍是同一身份体系下的 AstModule；Naming 在其后运行。

调度复用 [scheduler.rs](../../src/scheduler.rs)。
Normal 收敛后运行 Deferred；后者改变形状时重新触发依赖者，预算耗尽返回错误。
`PASS_DESCRIPTORS` 是阶段、顺序和失效关系的唯一执行定义。

## 共享设施

| Owner | 生产 / 提供 | 消费与失效边界 |
| --- | --- | --- |
| [ast/visit.rs](../../src/ast/visit.rs)、[ast/traverse.rs](../../src/ast/traverse.rs) | 子节点与名字访问角色 | 全部只读分析；遵守 [AST 核心合同](6.ast.md#核心合同) |
| [walk.rs](../../src/ast/readability/walk.rs) | rewrite 和词法状态进入/退出 | 各 pass 回调；不自行复制遍历规则 |
| [binding_flow/](../../src/ast/readability/binding_flow/) | 读写、capture、use-site 与稀疏写位置 | 内联、声明与函数恢复；位置索引只对应当前语句快照 |
| [binding_tree/](../../src/ast/readability/binding_tree/) | binding 的词法归属 | 声明与作用域调整 |
| [control_flow.rs](../../src/ast/readability/control_flow.rs) | 当前 AST 控制边界、支配与落空 | 需要 AST 路径证明的 pass；不复用改写前 CFG |
| [expr_analysis.rs](../../src/ast/readability/expr_analysis.rs) | 当前表达式事件、稳定性、复杂度与正常结果域 | 内联、逻辑与字面量整理；不使用旧 HIR 值快照 |
| [stmt_plan.rs](../../src/ast/readability/stmt_plan.rs) | 语句候选与提交协议 | 批次改写；提交前验证，失败不部分删除 |
| [repeat_lifetime.rs](../../src/ast/readability/repeat_lifetime.rs) | repeat body/尾条件生命周期查询 | 作用域与尾块调整 |
| [ast/common.rs](../../src/ast/common.rs) | AstRewriteAuthority、typed binding、来源 | 所有动作权限查询，不能以一般“可内联”替代 |

共享 label/goto 区间查询复用 [graph/](../../src/graph/) 中的词法引用索引。
对象、capture 或声明身份来自显式节点；语句位置只用于当前快照的区间定位。

## 稳定边界

- 表达式结果等价与求值事件可移动分开证明。名称稳定、字面量外形或重复文本不自动许可复制。
- binding 删除、初始化移动、作用域变更、相邻声明合并与函数声明糖分别查询权限。
  保留 PhysicalFramePrefix 或 debug 身份时，不绕过其对应动作限制。
- 方法糖与构造器追加消费 HIR 留下的 occurrence/protocol/allocation 事实；
  不从 AST 表面相似重新签发原 CALL/SELF 或 SETLIST 的许可。
- 单值与开放多值的语法位置、原始字节、闭包创建身份和 cleanup 仍是语义合同。
- child function 是独立读写域；父级分析从 capture 事件读取关系，不重复遍历子函数体。
- 普通 initializer、local function、自名函数和 repeat 条件使用统一词法状态；
  状态变化不能泄漏到兄弟块。
- pass 的候选、借用和位置索引只在所属快照内有效。树或声明顺序变化后重新取得事实，
  批量提交必须按实际替换数量撤销 producer。
- 改写方向应形成稳定规范形，不能由两个 pass 轮流恢复相反外形。

## 新增或修改 pass

先检查共享设施和已有 owner，再修改对应 pass 的候选与提交。
仅在依赖或产出变化时同步描述符；新增独立 pass 时同步本页导航。
具体接受证明、拒绝原因与反例写在源码和已注册 Lua 样例，
规则分类见 [Pass guard 合同](../design.md#pass-guard-合同)。

## 排错

先比较 AST build 与 Readability 输出，确定变化来自哪个 pass；
再读该 pass 的候选、AstRewriteAuthority 和共享 binding/expr query。
若缺的是原指令来源或生命周期事实，追到 HIR owner；若只是当前 AST 分析漏覆盖，在本层补齐。
调试命令见 [调试手册](../debug.md)，验证协议见 [测试体系](11.test.md)。
