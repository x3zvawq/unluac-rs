# 3. Analysis（CFG、图事实与标准 SSA 数据流）

> **职责**：从统一 `LoweredProto` 构建规范化控制流图（CFG）、经典图论事实、标准 SSA 形式及语言级数据流摘要。
> **不负责**：选择 `if`/`while`/`repeat` 语法结构、生成 AST、分配变量名或模拟 VM 物理栈槽布局。

本层对 chunk 中每个 proto 独立分析（显式迭代遍历 proto 树，避免深嵌套函数引发栈溢出），并保留与 Web 工作区兼容的 `CfgGraph` 结构。

## 数据流

```text
LoweredProto
  ──→ 1. CFG 构建（切分基本块、连边、删除不可达块）
  ──→ 2. CFG 前置规范化（跳板折叠、显式 for 协议标注、布尔物化识别）
  ──→ 3. GraphFacts（支配树、后支配树、支配边界、SCC、自然循环）
  ──→ 4. Register / SSA 构建（Close-Epoch 切分 + Cytron Phi 插入 + 重命名）
  ──→ 5. DataflowFacts（Def-Use、活性、副作用屏障、多值包配对、捕获/Close 事实）
  ──→ ProtoAnalysis { cfg, graph, ssa, dataflow }
```

## 1. CFG 构建与前置规范化

### 基本块与边模型

`Cfg` 采用紧凑数组索引（`BlockId(usize)`、`EdgeId(usize)`），保持对 `packages/unluac-wasm` 视图的稳定投影：
- `entry_block`（函数入口）与虚拟 `exit_block`（汇聚所有 `Return` / `TailCall` 出口，便于统一计算后支配树）。
- `EdgeKind` 区分：`Fallthrough`、`Jump`、`BranchTrue`、`BranchFalse`、`LoopBody`、`LoopExit`、`Return`、`TailCall`。
- 所有可达块按逆后序（RPO, Reverse Post-Order）存储在 `block_order` 中，作为后续数据流迭代与结构化遍历的确定性顺序。

### 前置规范化（化繁为简的关键）

在进入图论和结构化之前，先消除 Lua 编译器机械生成的噪声形状：

1. **空跳板折叠（Jump Threading）**：
   - 若某基本块不含任何非跳转指令且只有一条无条件 `Jump` 出边（且不是循环 header），将指向它的入边直接重定向到最终目标（注意防止自环死循环）。这能大幅减少编译器多级跳转造成的假分支层级。
2. **显式 VM 循环协议标注（`LoopProtocolHint`）**：
   - Lua VM 的 `NumericForPrep`/`NumericForLoop` 与 `GenericForPrep`/`GenericForCall`/`GenericForLoop` 自带清晰的循环边界与控制槽。本层直接识别并记录这些显式循环的 `prep_block`、`header`、`latch`、`exit_block` 及内部控制槽（供结构化阶段直接成环，无需猜测）。
3. **布尔物化模式识别（`BoolMaterializeHint`）**：
   - PUC Lua（5.1～5.3）和 LuaJIT 常将 `local b = (x > 0)` 编译成：`CMP/TEST -> LOADBOOL(r, false, skip=1) -> LOADBOOL(r, true)`。
   - 本层识别这类标准两值菱形写入，将其标记为候选布尔物化点，供 `Structure` 阶段直接折叠为布尔表达式，避免退化成冗余的 `if ... then r = true else r = false end`。

## 2. GraphFacts（通用图算法）

通过 `analysis::graph` 通用图算法模块，为任意有向 CFG（含不可规约图）计算：
- **支配树（Dominator Tree）**：Cooper-Harvey-Kennedy 迭代算法，记录 `idom`、前序区间（$O(1)$ 查询 `dominates(a, b)`）及支配边界（`dominance_frontier`）。
- **后支配树（Post-Dominator Tree）**：在反向 CFG 上以 `exit_block` 为根计算，提供 `nearest_common_postdom(a, b)`（分支合流点判定核心）。
- **强连通分量（SCC, Tarjan 算法）**：识别所有环及**不可规约多入口区域**（存在多条从分量外进入不同节点的边）。
- **自然循环（Natural Loops）**：对每条满足 `dominates(target, source)` 的回边，反向搜索收集循环体基本块集合，构建循环嵌套树。

## 3. 标准 SSA 与变量槽位模型

Lua 是寄存器机，同一个物理寄存器 `r3` 在一个函数里会被反复复用为不同临时值、局部变量甚至不同作用域的 upvalue。如果把所有寄存器都当成“可变局部变量”，就会满屏中转变量；如果把所有寄存器都无脑当成纯 SSA 值，则会弄丢被闭包捕获的可变变量身份。

本层采用清晰稳健的**两类身份 + Close-Epoch** 模型：

### 槽位分类

| 类别 | 判定条件 | SSA 处理方式 |
| --- | --- | --- |
| **Pinned Variable（固定具名槽）** | 被按引用捕获（`CaptureMode::ByReference`）、带 `<close>`/`<const>` 属性、或具有明确源码 `DebugLocal` 声明 | 保留显式变量身份（可多次读写），不强行折叠消除其声明 |
| **SSA Temp（普通值定义）** | 其余所有寄存器写入（指令结果或控制流汇合 `Phi`） | 赋予唯一 `ValueId`，按标准 SSA Def-Use 流转；满足内联条件时直接树化消除 |

### Close-Epoch（轻量解决寄存器复用与闭包捕获）

Lua VM 在执行 `CLOSE rX` 后，会将 `rX` 及以上的寄存器重新分配给后续作用域的新变量（可能再次被新闭包捕获）。
- 只需在 CFG 上按线性/支配序追踪每个寄存器的 `close_epoch`（遇到覆盖该寄存器的 `CLOSE` 时自增），用 `(Reg, epoch)` 作为变量槽的区分键即可。
- 整个逻辑紧凑高效，彻底解决“同号寄存器不同闭包捕获混成同一变量”的问题，无需追踪物理帧历史。

### SSA 构建步骤

1. 统计每个寄存器在基本块中的定义（Def）与使用（Use），注意把 `Closure` 捕获、隐式参数槽、循环控制槽均纳入真实读写。
2. 利用支配边界（Cytron 算法）在合流块插入 `Phi(reg, incoming: [(pred_edge, ValueId)])`；仅对活跃寄存器插 Phi（Pruned SSA），大幅减少大型函数中的死 Phi。
3. 沿支配树前序重命名，构建精确的 `ValueId -> DefSite` 和 `ValueId -> Vec<UseSite>` 索引。

## 4. DataflowFacts（仅保留 5 项真语义事实）

数据流分析不模拟物理 GC 根或死栈槽布局，仅发布 5 项真正决定源码语义的紧凑事实：

1. **Def-Use 索引**：每个 `ValueId` 的定义指令/Phi、总使用次数、是否跨基本块使用、是否仅在同一块内单次使用。
2. **指令副作用分类（`EffectClass`）**：
   - `Pure`：字面量加载、无元方法风险的构造（如 `LoadNil`/`LoadBool`/`LoadConst`/`Closure` 等纯读/纯值）。
   - `ReadsState`：读取可变局部变量、upvalue 或全局/表字段（受后续写操作影响）。
   - `MayObserveOrWrite`：调用、`GetTable`/`SetTable`、算术/比较/拼接/`#t`（可能触发元方法）、写入 upvalue/全局、`Close`/`ErrNil`。
   - 用途：决定表达式树化时，一个值能否跨过中间指令向使用点移动而不改变求值顺序。
3. **多值包配对（`OpenPackLink`）**：
   - 将产出开放结果包的指令（`Call` / `VarArg`）与唯一消费该开放包的后继指令（外层 `Call`、`Return`、`SetList`）显式配对，确保开放多返回绝不会被误截断或错位。
4. **捕获与资源边界**：
   - 每个 `Closure` 指令捕获的精确变量身份（栈槽 `(Reg, epoch)` 或父 `UpvalueRef`）及捕获模式（按引用 / 按值）。
   - 每个 `ToBeClosed` / `Close` 对应的变量身份与词法结束边界。
5. **Debug 绑定提示**：
   - 将 `Transformer::DebugLocals` 的半开区间关联到对应 `(Reg, epoch)` 与初始化点，作为 `Ast` 阶段变量声明与 `Naming` 的首选命名提示；区间冲突或异常时安全忽略提示，不导致反编译失败。

## 复杂度与大脚本约束

- CFG、支配树、Pruned SSA 与 Def-Use 索引构建均控制在线性或 $O(N \log N)$（$N$ 为指令/基本块数），使用 `Vec` 稠密索引而非大 `BTreeMap` 嵌套扫描。
- 面向商业游戏脚本中常见的数千指令单函数、上千项配置表初始化，本层可在毫秒级完成分析，不成为性能瓶颈。
