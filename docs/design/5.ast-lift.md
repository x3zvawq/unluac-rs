# 5. AST Lifting & Polish（表达式提升、语句恢复与轻量语法糖）

> **职责**：消费 `ProtoAnalysis`（SSA 与数据流）和 `RegionTree`（控制树），直接构建目标方言合法的 `AstModule`，并完成轻量、快速收敛的语法整形与词法校验。
> **不负责**：重新修改 CFG 拓扑、分配最终字符串名字或格式化文本布局。

本层直接将 `RegionTree + SSA` 提升为干净的 `AstModule`，不引入多余的重型中间语法树或复杂多轮固定点调度，从根源消除冗余中转变量。

## 整体流程

```text
ProtoAnalysis (SSA + Dataflow) + RegionTree
  ──→ 1. Variable Planning（确定哪些 SSA/Pinned 槽需要物化为 local，以及最窄声明块）
  ──→ 2. Expression & Statement Lifting（沿 RegionTree 自顶向下提升语句、正向内联表达式、聚合表/方法/多赋值）
  ──→ 3. Lightweight Polish（最多 2 轮收敛的纯语法糖与词法校验：elseif、local function、字段糖、goto 作用域、200 local 保护）
  ──→ 4. Naming（消费稳定 AstModule 生成 NameMap，见第 6 章）
```

## 1. 变量物化原则（彻底消除“莫名中转变量”）

本层采用**“默认内联、按需物化”**策略，避免把纯临时表达式过早锁死为中转变量。

### 一个 SSA `ValueId` 何时物化为 `local`？

一个值**必须**物化为独立 `local` 变量，**当且仅当**满足下列 5 条语义/可读性条件之一：

1. **显式源码或捕获身份**：属于 Pinned 槽（被 `Closure` 按引用捕获、带 `<close>`/`<const>` 属性，或对应有效 `DebugLocal` 声明）。
2. **多次使用（`use_count >= 2`）**：且不是轻量纯常量（`nil`/`bool`/`number`/`string` 字面量可直接复写内联，除非带 debug 声明或被捕获）。
3. **跨控制流汇合（Phi）**：跨分支/跨循环汇合的状态值，且未能被折叠为合法的短路/三元表达式（见下节）。
4. **存在求值顺序或副作用屏障**：定义点到唯一使用点之间存在可能观察到副作用变化或改写其读取状态的指令（详见下方“紧邻顺序消费”规则）。
5. **可读性复杂度上限**：表达式深度/节点数超过 `ReadabilityOptions` 阈值（防止超大表达式变成极长单行或触碰 Lua 语法解析器嵌套深度上限）。

**凡不触发以上 5 条的临时值，一律直接树化内联进消费者表达式！**

### 紧邻顺序消费规则（为什么 `f(a(), b(), c())` 零中转变量）

Lua 的函数调用、表构造、二元运算、拼接与多赋值均按固定的从左到右顺序求值。
- 设基本块内依次出现：
  ```text
  t1 = expr1   (可能有副作用)
  t2 = expr2   (可能有副作用)
  t3 = call(f, t1, t2)
  ```
- 若消费者读取临时操作数的顺序，与它们在块中紧邻求值的顺序**严格一致**（即按消费序从右向左回溯栈式弹出时正好匹配最近的未消费定义，中间没有插入其他有副作用语句），则内联**完全不改变任何求值顺序与元方法触发时机**，直接一次性折叠成 `f(expr1, expr2)`！
- 这套“顺序消费栈（Ordered Pending-Expr Stack）”在经典 Lua 反编译器（如 unluac）和现代 SSA 提升器中都被证明极其简单、线性 $O(N)$、且几乎 100% 还原人类手写的表达式结构。

## 2. 必须死守的 5 大 Lua 语义陷阱

轻量不等于粗糙。以下 5 条是真实 Lua 运行语义红线，Lifting 与 Polish 必须严格遵守：

1. **多返回值展开与单值截断 `(expr)`**：
   - `Call` 与 `VarArg` 在以下“多值尾位置”展开全部返回值：函数调用最后一个实参、表构造器最后一个数组项、多赋值/`local` 声明最后一个 RHS、`return` 最后一个表达式。
   - 若原指令只消费该开放调用的 **1 个结果**（例如 `ResultPack::Fixed(1)`）且它落在了上述尾位置，必须显式包裹 `AstExpr::SingleValue(expr)`（渲染为 `(f())`），防止语义变成多返回！
2. **`a and b or c` 的 falsy 陷阱**：
   - 将 `if cond then x = b else x = c end` 折叠为 `x = cond and b or c` 时，**仅当静态确认 `b` 绝不为 `false` 或 `nil`**（例如非 nil/非 false 字面量、表构造器 `{...}`、函数表达式、数值/字符串拼接/长度运算结果）才允许折叠！
   - 若 `b` 的真假未知（例如变量或函数调用），在 Lua 中 `true and false or c` 会错返回 `c`，此时必须保留 `if/else`！
   - 注：对于 Luau，若目标方言支持 `if cond then b else c` 表达式，可直接用原生 `AstExpr::IfExpr`（不受 falsy 陷阱影响）。
3. **浮点 `NaN` 比较取反陷阱**：
   - `not (a == b)` 严格等价于 `a ~= b`。
   - `not (a < b)` 与 `a >= b` 在 `a` 或 `b` 为 `NaN` 时结果相反（前者为 `true`，后者为 `false`）！因此**禁止**在 Polish 中随意把 `not (a < b)` 改写为 `a >= b`（除非本身就是字节码 `LT`/`LE` 指令原生极性位决定的直接条件）。
4. **表构造器 `{ ... }` 聚合边界**：
   - `NewTable(t)` 后紧跟连续的 `SetTable(t, k, v)` / `SetList(t, ...)` 时，按线性窗口直接吸收为 `AstTableConstructor` 的字段，前提是：
     - `t` 尚未逃逸给外部调用、其他表或闭包，且 `k`/`v` 的表达式不引用未构造完成的 `t` 自身。
     - 严格保持原有键/值求值顺序，不越过其他带副作用语句重排。
   - 这样既能用 $O(N)$ 单遍完美还原剑三等商业脚本中的数千行超大配置表，又能 100% 保证动态键求值顺序正确。
5. **Upvalue 捕获与 `repeat ... until` 作用域**：
   - `local f; f = function(...) f() end` 可合并为 `local function f(...) f() end`；但 `local f = function(...) f() end` 若初始化右侧**没有捕获自身**则正常声明，若函数体捕获了尚未声明的同名外层变量，严禁误合并成 `local function`（会改变捕获目标）。
   - Lua 独有规则：`repeat <body_stmts> until <cond>` 的 `until` 条件处于 `body` 作用域内，可以直接读取在 `body` 顶层声明的 `local`；计算声明下沉位置时必须识别这一特例，避免把变量错误上提到 `repeat` 外部。

## 3. 声明下沉与 200 Local 上限保护

大型商业 Lua 5.1 函数很容易出现几十上百个局部变量，而 Lua 5.1/LuaJIT/Luau 的单函数活动寄存器/局部变量上限通常为 **200**。

- **最窄支配声明下沉**：每个需要物化的 `local` 变量，不盲目全堆在函数开头，而是声明在**支配其所有定义点与使用点的最深共同块（LCA Block）**中首次写入之前；若首次写入本身就在该块顶层且不在循环内，直接合并为 `local x = init`。
- **循环与大函数保护**：
  - 声明仅在块结束时退出作用域；如果某函数内同时存活的 `local` 数量逼近上限（`SOURCE_LOCAL_LIMIT = 180`），对不再跨后续语句存活的局部段自动包裹最小 `do ... end` 块及时释放槽位，或合并互不重叠生命周期的匿名临时 `local`，确保生成源码能够顺利通过目标 Lua 编译器重编译。

## 4. 轻量 Polish（最多 2 轮收敛）

Lifting 完成后，AST 已经 100% 语义正确且基本无冗余临时变量。Polish 只做少量确定、局部、最多 2 轮即可收敛的纯语法整形：

1. **控制流整形**：`else { if ... }` 展平为 `elseif`；清理冗余空 `do ... end` 与末尾无意义裸 `return`；消除空 `then` 分支（取反条件转为单臂，注意遵守 NaN 规则）。
2. **语法糖**：
   - `t["valid_ident"]` → `t.valid_ident`（按目标方言 `is_identifier_name` 校验关键字）
   - `local x; x = expr`（紧邻且 `expr` 未引用 `x`）→ `local x = expr`
   - `local f; f = function(...)` → `local function f(...)`（严格校验自捕获）
   - `t.f = function(self, ...)` / `t.f = function(...)` 视条件转为 `function t:f(...)` / `function t.f(...)`
   - Luau 复合赋值（`x += y`）、字符串插值；Lua 5.4 `<close>` / `<const>` 属性；Lua 5.5 `global` 声明语法。
3. **`goto` 词法作用域校验与自动修复（Lua 5.2+ / LuaJIT）**：
   - 检查所有 `goto L` 是否跨入了在 `L` 处仍存活的新 `local` 作用域（Lua 语法禁止向前跳入 `local` 作用域）。
   - 若存在此类跨越，将 `goto` 与 `::L::` 之间受影响的局部声明区域自动收束进 `do ... end` 块（或将该局部声明上提到 `goto` 之前并初始化为 `nil`），确保输出 100% 通过编译校验。

## AST 节点设计原则

`AstModule`、`AstStmt`、`AstExpr` 保持纯粹、面向目标语法：
- 仅保留干净的绑定身份（`ParamId`、`LocalId`、`UpvalueId`、`ProtoId`）与目标语法直接需要的属性（如 `<const>`/`<close>`、单值截断 `SingleValue`、方法调用 `MethodCall`、原始 `LuaString`）。
- 不在 AST 节点上混杂物理栈帧权限、事务 token 或特定编译器内联元数据。
