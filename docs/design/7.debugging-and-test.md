# 7. Debugging 与测试体系

本文定义 5 阶段调试设施与分层测试协议。日常 CLI 调试命令速查见 [debug.md](../debug.md)。

## 5 阶段调试设施

主流水线固定为 5 个可观测阶段，均支持 `--stop-after <stage>`、`--dump <stage>`、`--proto <id>` 与 `--proto-depth <n>`：

| Stage 名 | 对应层 | Dump 内容 |
| --- | --- | --- |
| `parser`（兼容 `parse`） | Parser | header、常量池、proto 树、原始字节码与 debug 段 |
| `transformer`（兼容 `transform`） | Transformer | 统一 `LowInstr`、`LoweringMap`、归一化 `DebugLocals` |
| `analysis` | Analysis | CFG 基本块/边、支配与循环事实、Pruned SSA、Def-Use/副作用/捕获摘要 |
| `ast` | Ast | `RegionTree` 控制结构摘要、提升后的 `AstModule`、Polish 后 AST 与 `NameMap` |
| `generate` | Generate | 最终源码文本与 `GeneratedChunkKind` |

### 工程约束

- **零侵入业务代码**：`decompile-debug` 和 `timing-report` 保持为独立 Cargo feature；关闭 debug 的 WASM 发布构建仍保留核心反编译能力与单函数错误诊断。
- **聚焦与稳定编号**：各阶段复用 `src/debug/focus.rs` 的 DFS 先序 proto 编号，方便在任意两层之间精准对比同一子函数。
- **Web 工作区对接**：`packages/unluac-wasm/src/rich.rs` 从 `DecompileState` 投影 `raw_chunk`、`lowered`、`analysis.cfg` 与 `generated`（含 `proto_line_spans`），向前端提供源码、函数大纲、调用树与交互式 CFG 视图。

## 测试体系与用例分层

项目基于官方 7 方言 Lua 工具链构建端到端验证流水线（`xtask` + `packages/unluac-test-support` + `cargo case-test`）：

```text
原始 Lua 源码运行（baseline）
  ──→ 官方编译器编译为字节码
  ──→ 字节码运行校验（与 baseline 一致）
  ──→ unluac 反编译生成源码
  ──→ 生成源码经官方编译器再编译并运行（验证语法合法 + 运行输出与 baseline 完全一致）
  ──→ 可选 roundtrip 收敛检验 + 可读性/结构断言
```

### 用例分层与覆盖重点

1. **核心端到端语义与结构门禁（`cargo case-test`）**：
   - 覆盖 7 种方言（Lua 5.1 ~ 5.5、LuaJIT 2.1、Luau）与 stripped / retained debug 组合的完整回归矩阵：控制流（`if`/`elseif`/`while`/`repeat`/`for`/`break`/`continue`/`goto`）、短路逻辑、运算符与 `NaN` 比较、多返回值与单值截断、表构造与元方法、闭包与 upvalue 捕获、`CLOSE` / `<close>` / `<const>`、Lua 5.5 `global`、LuaJIT/Luau 专有语法、启发式命名与压力测试。
   - **目标语法合法性门禁**：所有普通样例的首次生成和再编译均要求 `GeneratedChunkKind::Source`；Lua 5.1 用例绝不允许出现 `goto` / `::label::`，正常编译器产物监控 `StateMachine` 兜底次数为 `0`。
2. **真实场景与专项契约**：
   - **大型脚本实战模式**：大型嵌套配置表（千级字段）、深层 `if/elseif` 与短路嵌套、复杂循环与早退共享尾、逼近 200 local 上限的大函数、全 stripped 脚本。
   - **不可规约图专项（Lua 5.2+ / LuaJIT vs Lua 5.1）**：验证支持 `goto` 方言输出作用域合法的最小 `goto`，不支持 `goto` 方言在手工构造不可规约图上正确触发局部状态机且重编译运行等价。
   - **白盒单元测试与 CLI 集成测试（`cargo test --workspace`）**：对核心算法、边界保护与 CLI 参数、批处理和 JSON 输出做毫秒级快速回归。
3. **明确的测试非目标**：
   - 不将“弱表 GC 死槽回收时序”“特定编译器 `-O2` 内联指令数复刻”或“stripped 字节码 `debug.getlocal` 物理槽号反射”纳入语义门禁（详见 [0.overview.md](./0.overview.md)）。

### 可读性断言精简原则

保留有价值的 `-- unluac:` 结构断言（如 `expect-not-contains [[goto]]`、`expect-ast-min/max`、`expect-name`），但**避免过度脆弱的逐字符或精确绑定计数断言**；重点守住：
- 无多余中转变量（`expect-ast-max [[empty-local]]` / `expect-not-line`）
- 正常控制流不退化为 `goto` 或 `StateMachine`
- 表达清晰、行宽可控、可重编译且运行语义 100% 等价。
