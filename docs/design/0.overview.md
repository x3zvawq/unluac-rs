# 0. 总览与语义合同

本文定义 unluac-rs 的核心架构目标、语义等价边界与跨方言控制流策略。

## 架构目标

unluac-rs 采用清晰的五阶段反编译架构（`Parser -> Transformer -> Analysis -> Ast -> Generate`）：
- **统一协议底座**：通过 `Parser`（7 种方言保真解码）与 `Transformer`（统一寄存器级 `LowInstr`）屏蔽不同 Lua VM 的二进制与指令差异。
- **现代中段核心**：基于 **CFG 规范化 + 标准 SSA + 迭代区域规约 + 直接表达式树化** 完成控制流与表达式恢复，用紧凑数据结构与线性/近线性算法兼顾**高成功率、自然人类可读性、大脚本性能与小 WASM 体积**。
- **纯粹命名与渲染**：`Naming` 与 `Generate` 仅消费稳定 `AstModule` 与只读元数据，专注启发式可读命名、精确字面量往返与配置表对齐排版，统一支撑 Rust 库、CLI、WASM/JS 与 Web 工作区。

## 语义等价合同（核心防火墙）

反编译的目标是恢复**等价且自然可读的高级源码**，而非还原逐字节相同的 VM 二进制布局。

### 必须保证的语义（Hard Guarantees）

| 类别 | 具体要求 |
| --- | --- |
| **控制流语义** | 所有可达路径、分支条件真假方向、循环次数、`break`/`continue`/`return`/尾调用完全一致 |
| **求值顺序与副作用** | 保留可观察的求值顺序与求值次数；不跨调用、表读写、upvalue 写入或潜在元方法重排有副作用的表达式 |
| **多值协议** | 显式保留开放多返回（`CALL`/`VARARG`）的展开位置与 `(expr)` 单值截断语义 |
| **数值与比较边界** | 严格保留字面量精度（含 f32/f64、整型/浮点区分、原始字节串）；严守浮点 `NaN` 比较语义（不把 `not (a < b)` 错改写为 `a >= b`）；严守 `a and b or c` 的 falsy 陷阱 |
| **闭包与变量生命周期** | 精确区分按引用捕获（可变 upvalue）与按值捕获（Luau）；同一寄存器经 `CLOSE` 后的复用必须切分为独立变量；严格保持 Lua 5.4 `<close>` 退出顺序与 `<const>` 语义 |
| **方言专有特性** | 正确支持 Lua 5.5 `global` 声明与 `_ENV` 词法角色、LuaJIT 64 位整数/复数/模板表、Luau 复合赋值/字符串插值/向量/共享闭包等 |
| **目标语法合法性** | 产出的 `Source` 必须是目标方言 100% 合法可编译代码；特别地，**Lua 5.1 绝不输出 `goto`/`::label::`**；大函数不因冗余中转变量触发 200 local 上限 |
| **Debug 信息尊重** | 存在有效 debug 信息时优先保留原参数与局部变量名；stripped 字节码产出确定、合法、不遮蔽全局的名称 |

### 明确不保证的非目标（Explicit Non-Goals）

以下事项**不属于** unluac-rs 的语义合同，实现与测试不得为它们牺牲可读性或引入专用补丁：

1. **重编译字节码同构**：不要求反编译源码重编译后的寄存器号、栈帧大小（`freereg`）、常量表顺序或指令条数与原 chunk 一致。
2. **死栈槽的 GC/弱表观察时序**：一个临时值在语言级逻辑使用结束后，不为了模拟 VM 物理寄存器尚未被覆写而保留无意义的 `local _tmp` 或插入合成 `x = nil` 语句。
3. **编译器优化逆向还原**：不试图把 Luau `-O2` 已经内联展开的代码硬塞回原函数调用并靠发射 `--!optimize 2` 赌编译器再次内联；按展开后的真实字节码恢复为干净等价的源码即可。
4. **Stripped 字节码的栈槽反射**：无 debug 信息时，不承诺 `debug.getlocal(1, idx)` / `debug.setlocal` 能观察到与原字节码一致的数字槽位布局。

## 方言能力与失败降级策略

不同 Lua 方言的控制流表达能力由共享的 `ControlFlowCaps` 描述：

| 方言 | `goto` / `::label::` | `continue` | 控制流降级优先级（遇到常规规约无法直接吸收的残余跳转时） |
| --- | :---: | :---: | --- |
| **Lua 5.1** | ❌ | ❌ | 单遍 `repeat ... until true` + `break` → 局部状态机分发器（保证合法可编译） |
| **Luau** | ❌ | ✅ | 循环回跳优先 `continue` → 单遍 `repeat ... until true` → 局部状态机分发器 |
| **Lua 5.2 ~ 5.5 / LuaJIT** | ✅ | ❌ | 单遍 `repeat`（可选） → 最小化且词法作用域合法的 `goto` / `::label::` |

### 两种生成模式（`GenerateMode`）

- **`Strict`**：遇到损坏字节码、无法识别的协议或内部严重异常时直接返回 typed error；只要是合法字节码，完备结构化与状态机/`goto` 兜底机制应确保绝大多数合法输入在 `Strict` 下也能成功产出 `GeneratedChunkKind::Source`。
- **`Permissive`（CLI / Web 默认）**：允许单个子函数（proto）失败时以错误诊断节点（`AstStmt::Error`）占位，同时正常反编译同文件中的其余函数；绝不因降级把非法语法（如 Lua 5.1 的 `goto`）伪装成 `Source`。

## 跨方言能力覆盖

CFG、SSA、迭代区域规约与残余降级统一面向**任意有向图（含不可规约图）**和完整 `ControlFlowCaps` 设计，原生覆盖全部 7 种方言：

- **PUC Lua 5.1**：无 `goto`/`continue` 下完整结构化、高 local 密度保护、大配置表与 stripped 脚本支持。
- **LuaJIT 2.1**：原生支持 `ISNEXT`/`ITERC`/`TNEW`/`TDUP`、split method、64 位整数/复数字面量与词法作用域合法的 `goto` 隔离。
- **PUC Lua 5.2 ~ 5.5**：覆盖 `_ENV` 词法环境、不可规约图最小 `goto`、位运算与整型/浮点区分（5.3+）、`<close>`/`<const>` 属性（5.4+）、`global` 声明与具名变参（5.5）。
- **Luau**：覆盖 `FASTCALL`、`continue`、复合赋值、字符串插值、向量常量、按值捕获与共享闭包。
